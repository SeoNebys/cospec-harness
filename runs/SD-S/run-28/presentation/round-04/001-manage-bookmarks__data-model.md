# Data Model: Bookmark Manager

**Date**: 2026-09-27  
**Storage**: SQLite with foreign keys enabled and WAL journaling

All timestamps are UTC ISO-8601 strings with millisecond precision. Application IDs are UUIDv7 strings. Every bookmark query and mutation includes `user_id`; globally unique IDs are not an authorization mechanism.

## Authentication-Owned Tables

Better Auth owns its generated user, account, session, verification, and password-reset-compatible schema. Its migration output is checked into `db/migrations/` alongside the application migrations rather than generated during ordinary application startup.

### User

| Field | Type | Rules |
|---|---|---|
| `id` | text | Primary key; generated by Better Auth |
| `name` | text | Required display name; 1–100 characters |
| `email` | text | Required; unique after provider normalization |
| `email_verified` | integer/boolean | Managed by Better Auth |
| `image` | text/null | Not used by this release but retained for auth compatibility |
| `created_at` | timestamp | Required |
| `updated_at` | timestamp | Required |

Better Auth's account/session records reference the user with cascading cleanup according to its generated schema. Password hashes, session tokens, and reset tokens are never exposed through bookmark DTOs.

## Application Tables

### Bookmark

Represents one saved web resource owned by one user.

| Field | Type | Rules |
|---|---|---|
| `id` | text | Primary key, UUIDv7 |
| `user_id` | text | Required foreign key to user; indexed |
| `url` | text | Required normalized HTTP(S) address, maximum 2,048 characters |
| `normalized_url_hash` | blob | SHA-256 of normalized URL; indexed with `user_id` for duplicate checks |
| `title` | text | Required, 1–300 characters |
| `title_source` | text enum | `metadata`, `fallback`, or `user` |
| `description` | text/null | Retrieved plain text, maximum 1,000 characters |
| `notes` | text/null | User-authored plain text, maximum 5,000 characters |
| `icon_asset_id` | text/null | Foreign key to IconAsset; `ON DELETE SET NULL` |
| `metadata_status` | text enum | `complete`, `partial`, or `failed` |
| `metadata_message_code` | text/null | Stable non-sensitive reason code for partial/failed retrieval |
| `is_favorite` | integer/boolean | Required; default false |
| `status` | text enum | `active` or `archived`; default `active` |
| `archived_at` | timestamp/null | Required exactly when status is `archived` |
| `version` | integer | Required; starts at 1 and increments on every user-visible mutation |
| `created_at` | timestamp | Required; immutable |
| `updated_at` | timestamp | Required; changes on mutation |

**Indexes**:

- `(user_id, status, created_at DESC, id DESC)` for the default and archive lists.
- `(user_id, normalized_url_hash)` for duplicate detection; deliberately not unique because explicit duplicates are allowed.
- `(user_id, status, is_favorite, created_at DESC, id DESC)` for favorite filtering.

**Constraints**:

- `title_source`, `metadata_status`, and `status` are restricted to their declared values.
- `archived_at IS NULL` for active records and is non-null for archived records.
- If `title_source = user`, subsequent metadata updates may change description/icon/status but cannot change title.
- Changing `url` updates its hash and increments `version`; page metadata is not automatically refreshed because the approved scope retrieves details on initial save only.

### Tag

Represents a reusable, user-owned organizational label.

| Field | Type | Rules |
|---|---|---|
| `id` | text | Primary key, UUIDv7 |
| `user_id` | text | Required foreign key to user; indexed |
| `name` | text | Required display form, 1–50 characters |
| `normalized_name` | text | Trimmed Unicode case-folded form |
| `created_at` | timestamp | Required |

**Constraints**:

- Unique `(user_id, normalized_name)` prevents capitalization-only duplicates.
- Creation fails with a limit response when the user already owns 500 distinct tags.

### BookmarkTag

Join entity associating bookmarks and tags.

| Field | Type | Rules |
|---|---|---|
| `bookmark_id` | text | Foreign key to Bookmark; cascade delete |
| `tag_id` | text | Foreign key to Tag; cascade delete |
| `created_at` | timestamp | Required |

**Constraints**:

- Composite primary key `(bookmark_id, tag_id)`.
- Application transaction verifies bookmark and tag have the same owner.
- Maximum 25 tags per bookmark.
- A tag left with no bookmark associations is retained so it remains available as a filter/label until a future tag-management feature explicitly deletes it.

### IconAsset

Deduplicated safe raster icon content retrieved during initial metadata extraction.

| Field | Type | Rules |
|---|---|---|
| `id` | text | Primary key; lowercase hex SHA-256 of content |
| `media_type` | text enum | `image/png`, `image/jpeg`, `image/gif`, or `image/webp` |
| `content` | blob | Required; 1–131,072 bytes |
| `byte_length` | integer | Required and checked against blob length |
| `created_at` | timestamp | Required |

The icon endpoint serves `ETag: <id>`, immutable caching, `X-Content-Type-Options: nosniff`, and the stored media type. A cleanup maintenance command removes assets with no bookmark references; bookmark deletion does not synchronously remove a shared asset.

### BookmarkSearch (FTS5 virtual table)

Derived search index, not a source-of-truth entity.

| Column | Content |
|---|---|
| `bookmark_id` | Unindexed bookmark identifier |
| `user_id` | Unindexed owner identifier used as a required query predicate |
| `title` | Current bookmark title |
| `url` | Normalized address |
| `description` | Retrieved description or empty string |
| `notes` | User notes or empty string |
| `tags` | Space-delimited normalized tag names |

The repository updates this row in the same transaction as Bookmark, Tag, or BookmarkTag changes. A maintenance command can rebuild the complete FTS table from source tables.

## Relationships

```text
User 1 ─── * Bookmark * ─── * Tag
                │
                └── 0..1 IconAsset

Bookmark 1 ─── 1 BookmarkSearch (derived)
```

- Deleting a user cascades through bookmarks, tags, bookmark-tag associations, sessions, and derived search rows.
- A bookmark belongs to exactly one user.
- A tag belongs to exactly one user and can label many bookmarks belonging to that same user.
- Many bookmarks may reference the same icon asset.

## Bookmark State Transitions

```text
                  archive
ACTIVE ─────────────────────────> ARCHIVED
  │                                  │
  │ permanent delete                 │ restore
  ▼                                  ▼
DELETED (row removed) <─────────── ACTIVE
  ▲
  │ permanent delete
ARCHIVED
```

- Creation begins in `active` with `version = 1`.
- Archive sets `status = archived`, records `archived_at`, updates `updated_at`, and increments `version`.
- Restore sets `status = active`, clears `archived_at`, updates `updated_at`, and increments `version`.
- Permanent deletion requires the current version and removes source, join, and search rows atomically.
- Favorite/unfavorite and content edits do not affect lifecycle state, but increment `version`.

## Metadata Outcome Rules

| Result | `title_source` | `metadata_status` | Description/icon |
|---|---|---|---|
| Title plus every published optional detail retrieved | `metadata` | `complete` | Stored when safe and valid |
| Title retrieved but an advertised optional detail fails or is unusable | `metadata` | `partial` | Store only valid details |
| No usable title or page retrieval fails | `fallback` | `failed` | Omitted unless independently validated before failure |
| User edits title | `user` | Existing status retained | Later metadata cannot replace title |

`metadata_message_code` uses a closed set such as `timeout`, `unreachable`, `unsafe_destination`, `unsupported_content`, `too_large`, `no_title`, or `parse_error`. API responses map codes to user-safe messages without exposing network topology or raw upstream errors.

## Validation and Transaction Boundaries

- Create bookmark: duplicate check, metadata result, bookmark row, tags, associations, optional icon, and search row commit together. A validation/database error commits none of them.
- Update bookmark: compare `version`, validate ownership, modify fields/tags, rebuild search row, then increment version in one transaction.
- Favorite/archive/restore: compare version and ownership, update source and search-visible state in one transaction.
- Delete: compare version and ownership, delete bookmark plus cascades and search row in one transaction.
- Tag normalization occurs before lookup or creation. Tag display casing is the casing from its first creation.
