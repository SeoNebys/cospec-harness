Scenario ID: SCN-001
Title: Save a link with auto-filled title and description, reviewed before saving
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client pastes a web address into an input at the top of the page and presses
"Add". The app takes a brief moment to "read the page", then presents a Title and
a Description that are already filled in from the page's own metadata. Both are
editable. The client may adjust them or leave them as-is, then presses "Save
bookmark". The bookmark then appears at the top of the "Saved" list, showing its
title, address, and (if present) description.

Confirmed sub-decisions:
- Pre-save review: the auto-filled fields are shown for review/tweaking BEFORE the
  bookmark lands in the list, not saved instantly with edit-after. (client approved)
- The description field is shown by default as an editable box at save time and is
  considered helpful, not clutter. (client approved)

## Gherkin
Feature: Saving a link with auto-filled metadata

  Scenario: Paste a known link and save it after reviewing pre-filled fields
    Given the client is on the bookmarks page
    When the client pastes a web address and presses "Add"
    Then the app reads the page
    And presents an editable Title and Description pre-filled from the page
    When the client optionally edits the Title or Description
    And presses "Save bookmark"
    Then the bookmark appears at the top of the Saved list
    And shows its title, address, and description

  Scenario: Pre-fill falls back when the page metadata is unavailable
    Given the client pastes a web address whose page metadata cannot be read
    When the app reads the page
    Then the Title is pre-filled with a best-effort value derived from the address
    And the Description is left empty for the client to fill in if desired

## Assumptions
- The web address is well-formed (malformed-address handling not yet explored).
- "Reading the page" retrieves at least a title and, when available, a short
  description. Icon/thumbnail retrieval is NOT part of this scenario (backlogged).
- Labeling at save time is NOT part of this scenario (being explored next).
