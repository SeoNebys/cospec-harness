Scenario ID: SCN-016
Title: Require a name before saving a reusable view
Type: Error Case
Approval status: approved
Approval session: SESSION-016
Approval cycle: 1

## Approved behaviour

When the client tries to save a reusable view without a name, the naming window stays open, the current search text, tag filter, and sort order remain intact, and nothing unnamed is added to the sidebar. A message beside the name field explains that a name is required so the client can correct it and finish.

## Gherkin

Feature: Name saved bookmark views

  Scenario: Reject an unnamed saved view without losing its configuration
    Given the user has configured search text, a tag filter, and a sort order
    And has opened the "Save this view" window
    When the user leaves the name empty
    And tries to save the view
    Then the naming window remains open
    And the configured search text, tag filter, and sort order remain unchanged
    And no saved view is added to the sidebar
    And a message beside the name field says that a name is required

## Assumptions

- Every saved view requires a non-empty user-provided name.
- A naming error does not clear or alter the view being saved.
