Scenario ID: SCN-009
Title: Fallback when a page title cannot be retrieved
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the app cannot read a saved page's title (page is down, blocks it, or the read
fails), the link is still saved. The web address is shown as a temporary title, which
the user can rename anytime via the edit pencil. Saving is never refused and the
title is never left blank because the fetch failed.

Confirmed via text (the live fetch failure cannot be reliably reproduced in the
prototype; the rule is what matters — see session-log.md).

## Gherkin
Feature: Title retrieval fallback

  Scenario: Save succeeds even if the title cannot be read
    Given the page's title cannot be retrieved
    When the user saves the link
    Then the link is saved with its web address shown as the title
    And the user can rename it later

## Assumptions
- Title retrieval happens server/app-side in the real implementation; a transient
  failure does not block saving. A later retry mechanism is out of scope this cycle.
