Scenario ID: SCN-002
Title: Re-saving an already-saved link opens the existing entry for editing
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the user pastes a link that is already in the collection and clicks Save,
the app does not add a second copy. Instead it shows a short note that the link
is already saved, and jumps to (scrolls to and highlights) the existing entry,
opening it in edit mode so the user can adjust it.

Two addresses count as the same page when they differ only by a leading "www.",
by capitalisation of the domain, or by a trailing slash. The rest of the address
(the path) is case-sensitive: e.g. example.com/Article and example.com/article
are treated as two distinct pages.

## Gherkin
Feature: Save a link

  Scenario: Duplicate link is caught and existing entry is opened for editing
    Given a link is already saved
    When the user pastes an address that resolves to the same page and clicks Save
    Then no new entry is added
    And a note states the link is already saved
    And the app scrolls to and highlights the existing entry in edit mode

  Scenario: Domain-only differences are treated as the same page
    Given "https://example.com/article" is already saved
    When the user saves "https://WWW.Example.com/article/"
    Then it is treated as the same page (duplicate)

  Scenario: Path capitalisation differences are treated as distinct pages
    Given "https://example.com/article" is already saved
    When the user saves "https://example.com/Article"
    Then it is treated as a distinct page and a new entry is added

## Assumptions
- Duplicate matching normalises host (lowercase, strip "www.") and trailing
  slash only; the path (and query) retains its capitalisation.
