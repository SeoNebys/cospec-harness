Scenario ID: SCN-005
Title: Keep a deliberate "Read later" queue and track reading state
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Every bookmark is either in the "Read later" queue or is an ordinary saved/
reference bookmark. In the review step when saving, an "Add to my Read later list"
choice is offered, unticked by default (adding to the queue is a deliberate opt-in);
if ticked, the new bookmark starts in the queue, otherwise it is an ordinary
bookmark.

Above the list a filter offers All / To read / Read, each showing a live count.
- All: every bookmark; ordinary and queued items are equally prominent (no dimming).
  Queued items carry a small "To read" label; the per-item action button also
  distinguishes state.
- To read: only queued items (the focused reading queue).
- Read: only ordinary/read bookmarks.

Each item's action button reflects its state: a queued item shows "Mark as read"
(which removes it from the queue); an ordinary item shows "Read later" (which adds
it to the queue). Toggling updates the counts immediately.

Opening (clicking) a link never changes its reading state; state changes only via
the button. Editing a bookmark does not include the read-later choice; the item
button controls it.

## Gherkin
Feature: Read later queue

  Scenario: Read-later is a deliberate opt-in when saving
    Given the client is at the review step for a new link
    Then the "Add to Read later" choice is unticked by default
    When the client leaves it unticked and saves
    Then the bookmark is an ordinary bookmark shown at full prominence with a "Read later" button
    When the client instead ticks it and saves another link
    Then that bookmark is in the queue, tagged "To read", with a "Mark as read" button

  Scenario: Filter to the focused reading queue
    Given a mix of queued and ordinary bookmarks
    When the client selects the "To read" filter
    Then only queued bookmarks are shown
    And the filter counts reflect All / To read / Read

  Scenario: Toggle reading state from the list
    Given a queued bookmark
    When the client presses "Mark as read"
    Then it leaves the queue and the counts update
    Given an ordinary bookmark
    When the client presses "Read later"
    Then it joins the queue and the counts update

  Scenario: Opening a link does not change its state
    Given a queued bookmark
    When the client clicks the link to open it
    Then its reading state is unchanged
