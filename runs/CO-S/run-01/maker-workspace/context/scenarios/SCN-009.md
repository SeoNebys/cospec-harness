Scenario ID: SCN-009
Title: Permanently delete a bookmark, with confirmation
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark, in every view (All, Read later, Archived), offers a "Delete"
action separate from Archive. Pressing "Delete" does not remove anything
immediately; it shows an inline confirmation on the card ("Delete permanently?
This can't be undone.") with "Delete" and "Cancel". "Cancel" leaves the bookmark
unchanged. Confirming "Delete" removes the bookmark entirely — it does not go to
Archived and cannot be restored.

## Gherkin
Feature: Permanent delete

  Scenario: Delete asks for confirmation
    Given a bookmark in any view
    When the user presses "Delete"
    Then an inline confirmation appears on the card
    And the bookmark is not yet removed

  Scenario: Cancel keeps the bookmark
    Given the delete confirmation is showing for a bookmark
    When the user presses "Cancel"
    Then the bookmark remains unchanged

  Scenario: Confirm removes the bookmark permanently
    Given the delete confirmation is showing for a bookmark
    When the user presses "Delete" to confirm
    Then the bookmark is removed from the collection entirely
    And it does not appear in the Archived view

## Assumptions
- Delete is available in all three views (client-confirmed).
- Confirmation is an inline two-step affordance rather than a modal pop-up
  (client-confirmed).
- Delete is irreversible; Archive remains the reversible "keep out of the way".
