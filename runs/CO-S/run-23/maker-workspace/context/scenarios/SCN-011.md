Scenario ID: SCN-011
Title: Recognize obvious variations of an already saved page
Type: Edge Case
Approval status: approved
Approval session: SESSION-011
Approval cycle: 1

## Approved behaviour
The client confirmed that an address differing from a saved page only through common newsletter tracking information or a jump to a section of that page should be treated as the same bookmark. The app should show the already-saved result instead of creating a near-duplicate. The client characterized catching obvious cases as desirable but said obscure variations occasionally slipping through are not release-blocking.

## Gherkin
Feature: Save bookmarks

  Scenario: Save an obvious tracking variation of an existing bookmark
    Given a bookmark already exists for a page
    When the user saves an address for that page with only common tracking information added
    Then no additional bookmark is created
    And the already-saved result is shown

  Scenario: Save a link to a section of an existing bookmark
    Given a bookmark already exists for a page
    When the user saves an address that only jumps to a section of that page
    Then no additional bookmark is created
    And the already-saved result is shown

## Assumptions
- Common newsletter and campaign tracking information can be ignored when comparing addresses.
- A jump-to-section ending does not identify a separate bookmark.
- Exhaustively recognizing every possible address variation is not required for initial acceptance.
