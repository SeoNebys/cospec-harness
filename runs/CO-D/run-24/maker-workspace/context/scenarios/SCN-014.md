Scenario ID: SCN-014
Title: Automatic preserved copy of each page (PDF-aware) with optional Internet Archive
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Every newly saved bookmark automatically gets a preserved copy of its page, so the
original version is protected without the client doing anything extra. During
capture the card shows a brief "Saving copy…" indicator; on success it shows a
"Saved copy" badge and the Edit screen shows it dated and captured automatically,
with options to View or Refresh the copy.

The preserved copy lets the client revisit the page even if the original changes
or disappears. For a PDF link, the actual PDF file is preserved (Edit shows
"Preserved PDF"); for other links, a copy of the page is preserved.

Failure is visible but non-blocking: if automatic capture fails, the bookmark is
still saved safely and the card shows a clear "Copy failed — retry in Edit" badge.
The client can retry from Edit; retry can succeed. The bookmark itself is never at
risk from a capture failure.

Internet Archive is a separate, optional, per-bookmark choice (a checkbox in Edit,
off by default), so ordinary saves are never sent there. It is an external service;
its real availability is a runtime dependency (the prototype used a stand-in).

Note: the preserved-copy content and Internet Archive link were stand-ins in the
Phase 1 prototype; the client approved the proposed behaviour on that basis. Real
capture requires backend capability (recorded for Phase 2 design / NF backlog).

## Gherkin

Feature: Preserved copy

  Scenario: Automatic capture on save
    When the client saves a new bookmark
    Then a preserved copy is captured automatically
    And the card shows progress then a "Saved copy" badge

  Scenario: PDF preserved as PDF
    Given the saved link points to a PDF
    When the copy is captured
    Then the actual PDF file is preserved

  Scenario: Capture failure is visible and retryable
    Given automatic capture fails
    Then the bookmark is still saved
    And the card shows a clear "copy failed" state
    And the client can retry preservation from Edit

  Scenario: Optional Internet Archive copy
    Given a bookmark
    When the client opts in per bookmark
    Then a copy is also kept in the Internet Archive
    And bookmarks not opted in are never sent there

## Assumptions

- Auto-capture runs for every new bookmark; not gated on a user action.
- Failure never risks the bookmark; retry available from Edit.
- PDFs preserve the file; other links preserve the page.
- Internet Archive is per-bookmark, opt-in, off by default; external dependency.
