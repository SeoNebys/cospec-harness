Title: Precise searches — tags, phrases, and boolean combinations
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The same search box supports precise queries:
- `#tag` matches bookmarks that carry that tag, by whole-tag exact match
  (`#css` matches the tag "css" but not "css-tricks").
- Text inside double quotes is matched as an exact phrase.
- `AND`, `OR`, `NOT` combine conditions, and parentheses `( )` group them.
- Operator words are recognised in any capitalization; to search for one of
  those words literally, the user quotes it (e.g. `"and"`).
- Parsing is forgiving: an unfinished query (e.g. a dangling operator or an
  unclosed parenthesis) narrows as far as it sensibly can instead of showing an
  error.
All matching remains case-insensitive.

## Gherkin
Feature: Precise search queries

  Scenario: Tag filter with exact whole-tag match
    Given bookmarks with various tags
    When the user searches "#reference"
    Then only bookmarks carrying the exact tag "reference" are shown
    And a bookmark whose tag merely contains "reference" as a substring is not matched

  Scenario: Exact phrase
    Given a bookmark whose text contains "chocolate chip"
    When the user searches for "chocolate chip" in quotes
    Then only bookmarks containing that exact phrase are shown

  Scenario: Boolean OR
    When the user searches "cooking OR testing"
    Then bookmarks matching either condition are shown

  Scenario: Boolean NOT
    When the user searches "#reference NOT css"
    Then bookmarks with the reference tag that are not about css are shown

  Scenario: Grouping with parentheses
    When the user searches "(cooking OR testing) AND #tools"
    Then the grouped condition is evaluated before the AND

  Scenario: Operator words are commands unless quoted
    When the user types AND, OR, or NOT in any capitalization
    Then they act as operators
    And quoting such a word searches for it literally

  Scenario: Forgiving of unfinished input
    When the user has typed an incomplete query such as a dangling operator or unclosed parenthesis
    Then the app narrows as far as it can without showing an error

## Assumptions
- `#tag` uses whole-tag exact match (client-confirmed).
- Operator keywords are case-insensitive; literal search requires quoting
  (client-confirmed).
- Implicit AND still applies between adjacent terms (from SCN-003).
