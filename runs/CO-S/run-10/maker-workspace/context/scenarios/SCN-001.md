Scenario ID: SCN-001
Title: Quickly save a link and see its details filled in automatically
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

From the main screen, the client pastes a web address into a single input box
and presses Save. Without any further typing, the link is added to the top of a
top-to-bottom list (newest first). Each saved link shows details that were
filled in automatically: a title, the site name, the web address, a small site
icon, a short description, and how long ago it was saved. The client confirmed
these details are enough to recognise the link later, that newest-first ordering
is right, and that saving felt quick and straightforward.

Note: in this prototype the automatic detail lookup is simulated. The approved
behaviour is that details appear automatically without the client typing them;
the exact text of a detail is not part of the approval.

## Gherkin
Feature: Save a link

  Scenario: Save a link and have its details filled in automatically
    Given the client is on the main bookmarks screen
    When the client enters a web address and presses Save
    Then the link is added to the top of the saved-links list
    And the link shows an automatically filled title, site name, web address,
        site icon, short description, and the time since it was saved
    And the client did not have to type any of those details

  Scenario: Newest saved link appears first
    Given the client already has saved links
    When the client saves another link
    Then the newly saved link appears above the previously saved links

## Assumptions
- The "basic details" the client wanted are: title, site name, web address,
  site icon, short description, saved time.
- A single paste-and-Save interaction is the primary way to add a link.
- Ordering is newest-first by default.
- Detail lookup happens automatically from the link's page (simulated in the
  prototype).
