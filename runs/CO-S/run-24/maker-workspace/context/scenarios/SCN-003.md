Scenario ID: SCN-003
Title: Keep an opt-in read-later list separate from the main collection
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Saving a link does NOT automatically put it in the reading queue — not every
bookmark is something to read later. The user intentionally adds specific links
to a reading list via a "＋ Reading list" action on a card. A separate "Reading
list" view shows only the links the user has added, distinct from the "All links"
view of the whole collection. Working through the queue: pressing "Done" on an
item removes it from the reading list while keeping it saved in the main
collection. The reading-list view shows a count of items remaining.

(Chosen over an alternative where every saved link carried a to-read/read status
and the queue was simply all unread links. The client wanted the queue to be a
smaller, hand-picked list, not everything unread.)

## Gherkin
Feature: Read-later list

  Scenario: Saving does not queue a link for reading
    Given the user saves a link
    Then the link is in the main collection
    And the link is not in the reading list

  Scenario: Add a link to the reading list intentionally
    Given a saved link that is not in the reading list
    When the user presses "＋ Reading list" on it
    Then the link appears in the reading list
    And it remains in the main collection

  Scenario: The reading list is a distinct view
    Given some links have been added to the reading list
    When the user opens the "Reading list" view
    Then only the added links are shown
    And a count of items in the reading list is shown

  Scenario: Marking a reading-list item Done keeps it saved
    Given a link is in the reading list
    When the user presses "Done" on it
    Then the link is removed from the reading list
    And the link is still present in the main collection

## Assumptions
- "Done" means "no longer in my reading queue"; it does not delete or archive the
  link. (Whether the user wants a record of "read" items is not required here.)
- A link can be re-added to the reading list after being marked Done.
- Reading-list ordering (e.g. order added) is not yet settled — candidate for
  edge/interaction exploration.
