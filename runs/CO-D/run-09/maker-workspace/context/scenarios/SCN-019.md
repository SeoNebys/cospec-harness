Scenario ID: SCN-019
Title: Notes support simple formatting, displayed properly
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The personal note supports simple formatting: headings, bold, italic, bullet lists,
numbered lists, inline code, and links. In the editor a small toolbar (Heading, Bold,
Italic, • List, 1. List, Link) helps apply the formatting, and a live preview shows how
the note will look. On the card, the note is displayed with its formatting rendered
properly (not as raw markup). Formatting entry is lightweight text-based markup so a plain
note still reads naturally.

To keep the list calm, a long note is shown as a short rendered preview on the card with a
"Show more" control to expand the full formatted note in place (and "Show less" to collapse
it again). Short notes show in full with no control.

## Gherkin
Feature: Formatted notes

  Scenario: Write a formatted note with preview
    Given the user is editing a link's note
    When the user applies bold, italic, a bullet list, or a link
    Then a live preview shows the formatted result

  Scenario: Display a formatted note
    Given a saved link has a formatted note
    When the link is shown in the list
    Then the note is displayed with its formatting rendered (not raw markup)

  Scenario: A plain note still reads naturally
    Given a note with no formatting
    When it is displayed
    Then it appears as ordinary text

  Scenario: Long note is previewed with expand
    Given a saved link has a long note
    When it is shown in the list
    Then only a short rendered preview is shown with a "Show more" control
    And expanding shows the full formatted note in place, with "Show less" to collapse

## Assumptions
- Formatting is expressed as lightweight markup (headings, bold, italic, bullet and
  numbered lists, inline code, links).
- Note text remains searchable (SCN-006).
- Rendering is safe (user input is escaped before formatting is applied).
