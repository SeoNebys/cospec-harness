Scenario ID: SCN-019
Title: Browse a large library without losing context
Type: Edge Case
Approval status: approved
Approval session: SESSION-019
Approval cycle: 1

## Approved behaviour

When the library contains hundreds of bookmarks, it is divided into numbered pages containing eight bookmarks each, with Previous and Next controls and a visible range so the client can keep their place and jump between pages. Long titles and descriptions are shortened to a scannable number of lines on cards, and extra tags collapse into a count. Opening the bookmark still exposes its complete saved content and wording.

## Gherkin

Feature: Browse a large bookmark library

  Scenario: Move to the next page of a large library
    Given the library contains 347 bookmarks
    And the first eight bookmarks are visible on page 1
    When the user chooses "Next"
    Then page 2 is selected
    And bookmarks 9 through 16 are shown
    And Previous becomes available

  Scenario: Keep unusually long bookmark cards scannable
    Given a bookmark has a very long title, description, and more tags than fit on its card
    When the bookmark appears in the library list
    Then its title and description are limited to a few visible lines
    And the extra tags are represented by a count
    When the user opens the bookmark
    Then the complete saved content and wording remain available

## Assumptions

- Each library page contains eight bookmarks.
- Numbered pages are used instead of an ever-growing list.
- Card shortening affects only the list presentation and never discards saved content.
