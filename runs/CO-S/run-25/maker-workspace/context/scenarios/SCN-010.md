Title: Sort and bulk-manage a large collection with scoped selection
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The library can be sorted by Newest first, Oldest first, or Title A–Z; the chosen
order applies to the currently shown list.

The client can select multiple links via per-card checkboxes. When at least one is
selected, an action bar shows the selection count and states that actions apply
only to those selected links. The client can also "Select all N in <this view>",
where the affordance names the exact count and scope (current tab and/or search),
so a bulk action is never applied to the whole library by accident. Selection can
be cleared.

Bulk actions apply only to the current selection:
- Read later (mark to-read) / Mark read (clear to-read)
- Add tag / Remove tag — remove names a tag to strip from the selection; links that
  don't have that tag are unaffected; the remove prompt lists tags present on the
  selection
- Archive, or Restore when viewing the Archive
- Delete, which asks for confirmation showing the count and warns it is permanent

## Gherkin
Feature: Sort and bulk management

  Scenario: Sort the library
    When the client chooses Newest first, Oldest first, or Title A–Z
    Then the shown links reorder accordingly

  Scenario: Select specific links and act on them
    Given several links are selected via checkboxes
    Then the action bar shows the count and that actions affect only the selection
    When the client runs a bulk action
    Then only the selected links are affected

  Scenario: Select all in the current scope
    Given a search or tab is active
    When the client chooses "Select all N in <this view>"
    Then exactly the links in that filtered scope are selected, with the count named
    And a bulk action affects only that scope, not the whole library

  Scenario: Bulk add and remove tags
    Given links are selected
    When the client bulk-adds a tag
    Then the tag is added to selected links that lack it
    When the client bulk-removes a tag
    Then the tag is removed from selected links that have it, others unaffected

  Scenario: Bulk read/unread, archive/restore, delete
    Given links are selected
    Then the client can mark them to-read or read, archive them (or restore in the
         Archive view), or delete them with a confirmation showing the count

## Assumptions
- Selection is explicit (checkbox or scoped "select all"); the bar always shows
  count and scope.
- Sort options: Newest, Oldest, Title A–Z.
- Bulk delete uses the same permanent-with-confirmation safeguard as single delete.
