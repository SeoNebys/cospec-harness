Scenario ID: SCN-005
Title: Find a saved bookmark by searching what I remember
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A search box (shown once at least one bookmark exists) filters the list live as
the client types, with a small count of how many bookmarks match. Searching is
case-insensitive and looks across the title, the page's description, the client's
own note, the tags, the site name, and the full link address — so any fragment
the client remembers, including a word buried in the address, will find the
bookmark.

The client can refine a search with a small query language:
- Plain words are matched as substrings; multiple words require all of them
  (implicit AND).
- "Quoted text" matches that exact phrase; an operator word placed in quotes
  (e.g. "AND") is searched as ordinary text, not as an operator.
- #tag matches only bookmarks carrying that exact tag.
- AND, OR, NOT combine conditions, and round brackets ( ) group them — for
  example: rome (#article OR #book), or #book NOT rust.

When no bookmark matches, a calm "no matches" message is shown instead of an
empty screen. When a query is malformed (e.g. an unclosed bracket), the app does
not go blank: it falls back to matching on the individual words and shows a
visible message explaining that the search operators could not be understood.
Clearing the search (the × button) restores the full list.

## Gherkin

Feature: Finding a bookmark

  Scenario: Search across all remembered details including the address
    Given several saved bookmarks
    When I type a word that appears in a bookmark's title, page description,
         personal note, tag, site name, or full link address
    Then the list narrows to the bookmarks that contain that word
    And a count of the matches is shown
    And matching ignores letter casing

  Scenario: Multiple words require all of them
    When I type two ordinary words
    Then only bookmarks containing both words are shown

  Scenario: Exact-tag search
    When I search for #recipes
    Then only bookmarks carrying the exact tag "recipes" are shown

  Scenario: Quoted phrase and neutralised operator
    When I search for a "quoted phrase"
    Then only bookmarks containing that exact phrase are shown
    And when I put an operator word such as "AND" in quotes
    Then it is searched as ordinary text rather than as an operator

  Scenario: Boolean operators with grouping
    When I search using AND, OR, NOT and round brackets, e.g. rome (#article OR #book)
    Then the list shows exactly the bookmarks satisfying that logical combination

  Scenario: No matches
    When my search matches no bookmark
    Then a calm "no matches" message is shown instead of an empty screen

  Scenario: Malformed query falls back gracefully
    Given a search whose operators/brackets cannot be parsed
    When I run it
    Then the app matches on the individual words instead of showing nothing
    And a visible message explains that the search operators were not understood

  Scenario: Clearing the search
    Given an active search
    When I clear the search box
    Then the full list of bookmarks is shown again

## Assumptions

- Search operates over the currently saved bookmarks (later interaction with the
  read-later / archive views is explored separately).
- #tag is an exact tag match; plain-text search remains substring-based for
  broader recall.
- Operator words are case-insensitive (AND/and/And).
