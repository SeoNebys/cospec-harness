Scenario ID: SCN-008
Title: Guard messy input — block invalid addresses and prevent duplicate saves
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Invalid address: if the entered text is not a plausible web address, saving is
blocked and a gentle inline message suggests the correct format (e.g.
"example.com/article"). Ordinary addresses without a scheme are still accepted —
a missing "https://" is added automatically. An empty box prompts the user to
paste an address first. The message clears as the user edits the box.

Duplicate: if the entered address matches one already saved (compared ignoring
"www.", a trailing slash, and letter case), no second copy is created. Instead an
inline notice says "You've already saved this," and offers a "Show it" link that
switches to the right view, clears filters, scrolls to the existing bookmark, and
briefly highlights it. If the existing copy is archived, the notice says so and
"Show it" opens it in the Archived tab (where the user can edit or restore it).

## Gherkin
Feature: Guard messy input

  Scenario: Block a clearly invalid address
    Given the user enters text that is not a plausible web address
    When the user tries to save
    Then nothing is saved and an inline hint shows the expected format

  Scenario: Accept an address without a scheme
    Given the user enters "example.com/article"
    When the user saves
    Then it is saved with "https://" added automatically

  Scenario: Prevent a duplicate save
    Given a link is already saved
    When the user tries to save the same address (ignoring www., trailing slash, case)
    Then no duplicate is created
    And an inline notice offers to show the existing bookmark

  Scenario: Point to an archived duplicate
    Given the matching existing link is archived
    When the user tries to save it again
    Then the notice says it is archived and can open it in the Archived tab

## Assumptions
- Duplicate comparison uses host (without www.) + path (without trailing slash) +
  query, case-insensitive. Fragments (#...) are ignored for matching.
- Validity check is lightweight (a parseable host containing a dot), not a reachability
  check.
