Scenario ID: SCN-004
Title: Find links by searching across title, address, and tags, combinable with tag browsing
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A search bar sits under the save box. As the user types, the list narrows live to
links whose title, web address, or tags contain the query. Matching text is
highlighted in results. The section heading shows 'Results for "<query>"'. A clear
(×) control empties the search.

Search combines with tag browsing: if a tag is active, search narrows within that
tag, and the heading shows 'Results for "<query>" in #<tag>'. The active tag stays
visibly highlighted in the Browse row so it is clear why some links are excluded.

When search matches nothing, a friendly "No matches" empty state is shown (not a
blank screen), naming the query (and active tag, if any).

Saving a new link clears both the search and the active tag so the new link is
visible.

## Gherkin
Feature: Search bookmarks

  Scenario: Search across title, address, and tags
    Given saved links exist
    When the user types a query in the search bar
    Then only links whose title, address, or tags contain the query are shown
    And matching text is highlighted
    And the heading shows the query

  Scenario: Search within an active tag
    Given a tag filter is active
    When the user types a query
    Then results are limited to links carrying that tag AND matching the query
    And the active tag remains visibly highlighted and named in the heading

  Scenario: Search with no matches
    Given saved links exist
    When the query matches no link (within the current tag, if any)
    Then a friendly "No matches" message is shown naming the query

  Scenario: Clear search
    When the user clears the search
    Then the full list (respecting any active tag) is shown again

## Assumptions
- Search is case-insensitive and matches substrings.
- Search currently covers title, address, and tags. If descriptions/notes are
  added later (see LCR-002), search is expected to cover them too.
- Search results respect reverse-chronological order.
