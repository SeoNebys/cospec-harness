## Approved behaviour
Tag filtering supports both include (a link must have all included tags) and
exclude (a link must have none of the excluded tags). Clicking a tag on a card
adds it as an include filter; each active filter chip has a toggle to flip
between include and exclude, and an × to remove it. When any search or tag filter
is active, a "Save this view" control appears; the client names it and it becomes
a reusable saved-view chip shown in a row at the top. A saved view stores only
the search words plus the included and excluded tags — not a reading state.
Applying a saved view resets to the full active library (All) and applies its
conditions; the client can afterwards still narrow by To read / Reference.
Saved-view results are dynamic: they re-evaluate the stored conditions each time,
so newly saved or edited links appear automatically whenever they match. Saved
views can be deleted from their chip.

## Gherkin
Feature: Saved views

  Scenario: Build an include/exclude filter
    Given links with overlapping tags
    When the client includes tag "longread" and excludes tag "personal"
    Then only links tagged longread and not personal are shown

  Scenario: Save and reuse a view
    Given a search and/or tag filter is active
    When the client saves it with a name
    Then it appears as a saved-view chip
    And applying that chip later restores the same search and included/excluded tags over the full library

  Scenario: Saved views are dynamic
    Given a saved view is applied
    When a new link is saved (or an existing link edited) that matches the view's conditions
    Then it appears in the view automatically

  Scenario: A saved view does not pin a reading state
    Given a saved view is applied over All
    When the client switches to To read or Reference
    Then the results narrow further, and the saved view itself stored no reading state

## Assumptions
- A saved view = search text + included tags + excluded tags (no reading state, no sort).
- Applying a view resets the base view to All before applying conditions.
- Views are evaluated live (dynamic membership), not frozen snapshots.
