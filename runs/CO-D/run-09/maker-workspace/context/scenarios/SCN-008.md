Scenario ID: SCN-008
Title: Change a saved link's read status later
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each saved-link card carries an explicitly labelled button to change its read
status: "Mark as read" when it is in the "to read" state, and "Move back to
“To read”" when it is finished. Using it flips the link's status. Changing
status never deletes the link — it simply moves between the status views. The card
shows a status tag ("Read later" while to-read, "Read ✓" when finished).

The explicit-button form was chosen from three compared alternatives (a round check
control, a clickable status tag, and an explicit labelled button). The client chose
the explicit button because its wording removes any guesswork about what will happen.

## Gherkin
Feature: Managing read status

  Scenario: Mark a to-read link as read
    Given a saved link is in the "to read" state
    When the user clicks its "Mark as read" button
    Then the link becomes "finished"
    And the link is not deleted

  Scenario: Move a finished link back to to-read
    Given a saved link is "finished"
    When the user clicks its "Move back to To read" button
    Then the link returns to the "to read" state

## Assumptions
- A newly saved link starts as "to read" when "Read later" was on at save (SCN-001).
- The status control is an explicitly labelled button naming the resulting action.
