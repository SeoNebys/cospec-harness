Scenario ID: SCN-002
Title: Organise a saved link with free-form, reusable tags
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
On a saved link, the client can add free-form tags they type themselves. Tags
are lower-cased so that differently-cased words do not become duplicates, and
each tag is shown as a rounded chip on the link with a small "×" to remove it.
Tags are added per link on the saved item (not during the initial save). While
typing a tag, a small drop-down lists the client's already-used tags that
contain the typed text (and are not already on that link); clicking a
suggestion reuses that exact tag, avoiding near-duplicates. Typing a word that
matches nothing and pressing Enter simply creates it as a new tag. The same tag
cannot be added twice to one link.

## Gherkin
Feature: Tagging saved links

  Scenario: Add a free-form tag to a link
    Given a saved link
    When the client adds a tag by typing a word and confirming
    Then the tag is stored in lower-case and shown as a removable chip on the link

  Scenario: Reuse an existing tag via suggestions
    Given the client has previously used the tag "article"
    And the client is adding a tag to another link
    When the client types text contained in "article"
    Then "article" is offered as a suggestion (unless already on that link)
    And choosing the suggestion adds exactly that existing tag

  Scenario: Create a new tag when nothing matches
    Given the client is adding a tag
    When the client types a word that matches no existing tag and confirms
    Then the word is added as a new tag

  Scenario: Remove a tag
    Given a saved link with a tag chip
    When the client clicks the chip's "×"
    Then that tag is removed from the link

  Scenario: Prevent duplicate tag on the same link
    Given a link that already has the tag "python"
    When the client adds "python" again
    Then the link still shows the tag only once

## Assumptions
- Tags are free-form words chosen by the client (no fixed vocabulary).
- Tags are normalised to lower-case.
- Tagging occurs per link on its card, after the link is saved.
- Suggestions are drawn from tags already used across the client's links and
  match by substring of the typed text.
- Suggestions exclude tags already on the current link.
