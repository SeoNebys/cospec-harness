Scenario ID: SCN-016
Title: Block malformed bookmark addresses
Type: Error Case
Approval status: approved
Approval session: SESSION-016
Approval cycle: 1

## Approved behaviour

When the client enters text that is not a complete web address, the application keeps the add-bookmark window open, visibly flags the address field, explains what is wrong with an example of a complete address, and returns focus to the field so it can be corrected. Nothing is added to the collection.

## Gherkin

Feature: Validate bookmark addresses before saving

  Scenario: Submit text that is not a complete web address
    Given the add-bookmark window is open
    And the address field contains text that is not a complete web address
    When the user tries to save the bookmark
    Then no bookmark is added to the collection
    And the add-bookmark window remains open
    And the address field is visibly flagged
    And the application shows an example of a complete web address
    And focus returns to the address field

## Assumptions

- A complete address uses HTTP or HTTPS and includes a host name.
- This validation occurs before attempting to retrieve page details.
