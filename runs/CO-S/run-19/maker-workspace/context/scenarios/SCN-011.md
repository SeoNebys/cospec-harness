Scenario ID: SCN-011
Title: Prevent a duplicate bookmark for the same page
Type: Edge Case
Approval status: approved
Approval session: SESSION-011
Approval cycle: 1

## Approved behaviour

When the client tries to save a page that is already bookmarked, the app recognizes it even if the new address contains harmless tracking text. It does not create a second bookmark, keeps the existing bookmark's details and original saved date unchanged, and points the client to that existing item.

## Gherkin

Feature: Prevent duplicate bookmarks

  Scenario: Recognize an existing page despite tracking text
    Given a page is already saved as a bookmark
    And the bookmark has existing details and an original saved date
    When the user saves the same page using an address with tracking text
    Then no additional bookmark is created
    And the existing bookmark's details remain unchanged
    And the existing bookmark's saved date remains unchanged
    And the app points the user to the existing bookmark

## Assumptions

- Harmless tracking information in an address is ignored when identifying the underlying page.
- A duplicate save is blocked rather than offering an easy bypass.
- Duplicate detection does not refresh or overwrite the existing bookmark.
