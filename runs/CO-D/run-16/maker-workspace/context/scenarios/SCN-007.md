Title: Advanced search query language
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The search box supports a query language for harder searches:
- `#tag` matches the exact tag only (e.g. `#news` matches a bookmark tagged
  "news" but not one tagged "newsletter").
- Multiple space-separated terms narrow results together (implicit AND).
- Boolean operators `AND`, `OR`, `NOT` combine terms, with parentheses for
  grouping, e.g. `rome (#article OR #book)` and `rome NOT #travel`.
- A quoted `"exact phrase"` matches that phrase exactly.
- A quoted operator word, e.g. `"AND"`, is treated as ordinary search text
  rather than as an operator.
All matching is case-insensitive.

## Gherkin
Feature: Advanced search queries

  Scenario: Exact tag filter
    When the client searches "#news"
    Then only bookmarks whose exact tag is "news" match
    And a bookmark tagged "newsletter" does not match

  Scenario: Implicit AND between terms
    When the client searches "rome #travel"
    Then only bookmarks matching both "rome" and the tag "travel" appear

  Scenario: Boolean operators with grouping
    When the client searches "rome (#article OR #book)"
    Then bookmarks matching "rome" and either tag "article" or tag "book" appear
    And "NOT" excludes matches, e.g. "rome NOT #travel"

  Scenario: Exact phrase
    When the client searches with a quoted phrase
    Then only bookmarks containing that exact phrase match

  Scenario: Quoted operator treated as text
    When the client searches "\"AND\""
    Then bookmarks containing the literal word "and" match
    And it is not interpreted as the AND operator

## Assumptions
- Operator precedence: NOT binds tightest, then AND (including implicit AND),
  then OR.
- A lone unquoted operator with no operands does not act as a text search.
