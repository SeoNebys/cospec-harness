Scenario ID: SCN-008
Title: Write a personal note on a bookmark, with Markdown formatting
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark has a personal note, kept separate from the page's auto-filled
description. The client writes the note in the bookmark's editor. The note
supports simple Markdown — headings, bulleted and numbered lists, links, bold,
italics, inline code and code blocks — and is displayed as formatted text on the
bookmark card (not the raw symbols). The note is included in search (see
SCN-006), and search matches are highlighted within the rendered note. Any HTML
typed into a note is shown as text, not executed.

## Gherkin
Feature: Personal note

  Scenario: Note is separate from the page description
    Given a bookmark with a page description
    When the client writes a personal note
    Then the note is stored and shown separately from the description

  Scenario: Markdown is rendered
    Given a note written with simple Markdown (headings, lists, links, bold,
          italics, inline code, code blocks)
    Then the bookmark shows the formatted result, not the raw symbols

  Scenario: Note is searchable and highlighted
    When the client searches for a word that appears in a note
    Then the bookmark is found and the word is highlighted within the note

  Scenario: Notes cannot inject markup
    Given a note containing HTML
    Then the HTML is displayed as plain text, not executed

## Assumptions
- Supported Markdown: headings, unordered/ordered lists, links (http/https),
  bold, italics, inline code, fenced code blocks (client confirmed this covers
  "simple Markdown").
- Links open in a new tab.
