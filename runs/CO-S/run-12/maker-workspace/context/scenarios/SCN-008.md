Scenario ID: SCN-008
Title: Save a bookmark when page details cannot be retrieved
Type: Error Case
Approval status: approved
Approval session: SESSION-008
Approval cycle: 1

## Approved behaviour
When automatic page-detail retrieval fails, the app preserves the submitted link and clearly explains the failure. The client can retry retrieval or enter details manually. A manual title is required so the bookmark remains recognizable; the description is optional. Once a title is supplied, the bookmark can still be saved.

## Gherkin
Feature: Recover from unavailable page details

  Scenario: Fall back to manual details after retrieval fails
    Given the user has submitted a valid web address
    When the app cannot retrieve usable page details
    Then the submitted web address is preserved
    And a clear explanation is shown
    And the user can retry retrieval
    And the user can enter a title and optional description manually
    But saving remains unavailable until a non-empty title is provided

  Scenario: Save after supplying a required title manually
    Given page-detail retrieval has failed
    And the submitted web address is preserved
    When the user supplies a non-empty title and saves
    Then the bookmark is added using the preserved address and manual details

## Assumptions
- A bookmark must always have a recognizable title.
- Automatic retrieval may be retried without re-entering the address.
- Failure to retrieve metadata does not imply that the page address is invalid.
