Scenario ID: SCN-008
Title: Saving an already-saved link opens the existing bookmark, no duplicate
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client tries to save a link whose (normalised) address already exists,
no second copy is created. Instead the app informs the client, switches to the
view where that bookmark lives (the main list, or the Archived view if it is
archived), clearing any active search/tag filter so it is visible, and opens the
existing bookmark's editor so the client can immediately adjust its note, tags,
or details.

## Gherkin
Feature: Duplicate handling

  Scenario: Re-saving an existing link opens it for editing
    Given a bookmark for a given address already exists
    When the client enters the same address and presses Add
    Then no new bookmark is created
    And the app shows a message that it is already saved
    And it switches to the view containing that bookmark, clearing active filters
    And it opens the existing bookmark's editor

  Scenario: Re-saving a link that is archived
    Given the existing bookmark is archived
    When the client re-enters its address and presses Add
    Then the app switches to the Archived view and opens that bookmark for editing

## Assumptions
- Duplicate detection is by normalised address equality.
- Address normalisation for matching is to be refined during edge-case
  exploration (e.g. trailing slash, scheme, case of host).
