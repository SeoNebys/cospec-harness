Scenario ID: SCN-003
Title: Re-pasting an already-saved link opens it for editing
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user pastes a link that is already saved, the app does not create a second
copy. Instead it opens the existing saved link in an editor whose heading makes
clear it is one the user saved before, so the user can update it. No separate
duplicate warning is shown; the heading provides the context. Addresses are matched
ignoring differences in the leading protocol, a leading "www.", and a trailing
slash.

## Gherkin
Feature: No duplicate saves

  Scenario: Paste a link that is already saved
    Given a link is already saved
    When the user pastes the same link again (ignoring protocol, leading www., and trailing slash)
    Then no second copy is created
    And the existing saved link opens in an editor
    And the editor heading indicates it was saved before

## Assumptions
- Address matching normalises protocol, a leading "www.", and a trailing slash.
