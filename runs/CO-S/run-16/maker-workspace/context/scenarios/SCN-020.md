Scenario ID: SCN-020
Title: Refresh captured page details only when requested
Type: Edge Case
Approval status: approved
Approval session: SESSION-020
Approval cycle: 1

## Approved behaviour

Captured page details remain as the client remembers them even if the original web page changes later. The application does not update a card automatically. The client can choose Refresh page details to retrieve the current title, preview, description, and reading time. Refreshing visibly updates those captured fields while always preserving the client's personal note and tags.

## Gherkin

Feature: Keep saved bookmark context stable over time

  Scenario: Original page details change after a bookmark was saved
    Given a bookmark has captured page details, personal tags, and a personal note
    And the original page later changes its details
    When the user views the saved bookmark before requesting a refresh
    Then the card continues to show the previously captured page details
    And the personal tags and note remain unchanged
    When the user chooses Refresh page details
    Then the card updates its captured title, preview, description, and reading time from the page
    And the personal tags and note remain unchanged
    And the application confirms that the page details were refreshed

## Assumptions

- Refreshing page details is always initiated by the client and never automatic.
- If a refresh cannot reach the page, the current saved details remain intact.
- Manually entered titles on basic cards are personal data and are not overwritten without confirmation.
