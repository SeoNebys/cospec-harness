Scenario ID: SCN-015
Title: Edit the saved address, with validation and uniqueness protection
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The bookmark editor includes an Address field, so the client can correct the
saved link itself, not only its title/description/tags/note. On save:
- An empty or invalid address is refused with a notice; the bookmark is unchanged.
- If the new address matches an existing bookmark (by the same normalisation as
  duplicate detection), the change is refused, naming the conflicting bookmark
  (and noting if it is archived); both bookmarks are left untouched — no automatic
  merge of details.
- A valid, non-conflicting address is saved and the item's icon follows the new
  address.

## Gherkin
Feature: Edit saved address

  Scenario: Change to a valid, unique address
    Given a saved bookmark
    When the client edits its Address to a valid link not used by another bookmark
    And saves
    Then the bookmark's address (and icon) update

  Scenario: Refuse an invalid address
    Given the client is editing a bookmark's address
    When the client enters an empty or invalid address and saves
    Then the change is refused with a notice
    And the bookmark is unchanged

  Scenario: Refuse a conflicting address
    Given another bookmark already uses a given address
    When the client edits this bookmark's address to match it and saves
    Then the change is refused
    And the message names the conflicting bookmark
    And both bookmarks are left unchanged

## Assumptions
- Address uniqueness uses the same normalisation as SCN-012.
- No automatic merging of details on conflict (client confirmed).
