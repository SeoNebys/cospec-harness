Scenario ID: SCN-015
Title: Save and reopen a named search (text plus included/excluded tags)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The user can save the current search expression under a name and reopen it later.
A saved search stores the search expression only — free-text words plus included
tags (#tag) and excluded tags (NOT #tag) — using the same search rules as the
normal search box. It does not store the current view or sort.

Saving: with a non-empty search, the user clicks "Save this search", names it
(the query text is suggested as the default name), and saves. It appears as a
named chip in a "Saved searches" row. Attempting to save with an empty search
prompts the user to type a search first.

Saved-search names must be unique. If the user reuses an existing name, the app
prompts them to choose another rather than silently creating a duplicate chip.

Reopening: clicking a saved-search chip applies its expression to the search box
(filtering the collection), while leaving the user's current view and sort
unchanged. A saved search whose tag no longer exists simply returns no results
(it is not "broken") and starts matching again if that tag is used later. Each
saved chip has a control to delete it.

## Gherkin
Feature: Saved searches

  Scenario: Save the current search
    Given a non-empty search expression
    When the user saves it with a name
    Then it appears as a named saved-search chip

  Scenario: Reopen a saved search without changing view/sort
    Given a saved search and a current view and sort
    When the user clicks the saved search
    Then its expression is applied to the search box
    And the current view and sort remain unchanged

  Scenario: Delete a saved search
    When the user removes a saved-search chip
    Then it no longer appears

  Scenario: Empty save is prevented
    Given the search box is empty
    When the user tries to save a search
    Then a prompt asks them to type a search first

  Scenario: Saved-search names are unique
    Given a saved search named N exists
    When the user tries to save another search with name N
    Then the app prompts for a different name and does not create a duplicate

  Scenario: Saved search with a since-removed tag
    Given a saved search referencing tag T and no bookmark currently has T
    When the user opens it
    Then it returns no results without being marked broken
    And it matches again once some bookmark uses T

## Assumptions
- Included tags are expressed as #tag and excluded tags as NOT #tag within the
  same query language (SCN-004).
