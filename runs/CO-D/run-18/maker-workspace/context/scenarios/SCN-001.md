Scenario ID: SCN-001
Title: Save a bookmark with fetched and editable page details
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A person pastes a complete web address and asks the app to get its details. The app presents a preview containing the page's site name, title, description, site icon when supplied by the page, and thumbnail when supplied by the page. The title and description can be edited directly in the preview. Saving adds the bookmark with those final edited values and confirms the exact title and description that were saved.

## Gherkin
Feature: Save a bookmark

  Scenario: Preview fetched page details before saving
    Given the personal library is open
    When the user submits a complete web address whose page supplies a title, description, site icon, and thumbnail
    Then a preview shows the page's site name, title, description, site icon, and thumbnail
    And the bookmark has not yet been added to the library

  Scenario: Edit fetched details and save the bookmark
    Given a fetched bookmark preview is displayed
    When the user changes the title and description and saves the bookmark
    Then the bookmark is added with the edited title and description
    And the confirmation displays that exact edited title and description

  Scenario: Omit unavailable page imagery
    Given the personal library is open
    When the user fetches a page that supplies no site icon or thumbnail
    Then the preview does not show fake or blank imagery in their place

## Assumptions
- The app is a private, single-person web app.
- Saving begins from a prominent web-address field on the library's main screen.
- A preview is shown before the bookmark is committed.
- Page imagery is optional and is shown only when actually supplied by the page.
