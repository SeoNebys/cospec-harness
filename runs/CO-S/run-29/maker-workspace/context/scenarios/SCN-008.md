Scenario ID: SCN-008
Title: Reject missing and duplicate collection names
Type: Error Case
Approval status: approved
Approval session: SESSION-008
Approval cycle: 1

## Approved behaviour
Creating a collection without a name is blocked. The selected bookmarks remain selected, the form stays open, and a clear message beneath the name field asks for a name. Creating a second collection whose name matches an existing collection is also blocked; the selected bookmarks and form are preserved, and the message directs the user to add the bookmarks to the existing collection instead.

## Gherkin
Feature: Validating collection names

  Scenario: Reject an unnamed collection
    Given two bookmarks are selected for grouping
    And the create-collection form is open
    When the user leaves the collection name empty
    And tries to create the collection
    Then no collection is created
    And the form remains open
    And both bookmarks remain selected
    And a message beneath the field asks for a collection name

  Scenario: Reject a duplicate collection name
    Given the “Web development” collection already exists
    And two bookmarks are selected for grouping
    And the create-collection form is open
    When the user enters “Web development” as the collection name
    And tries to create the collection
    Then no second “Web development” collection is created
    And the form remains open
    And both bookmarks remain selected
    And a message says the collection already exists
    And the message directs the user to add the bookmarks to the existing collection

## Assumptions
- Collection names are required.
- Collection names are unique.
- A blocked create attempt preserves the user’s selection.
