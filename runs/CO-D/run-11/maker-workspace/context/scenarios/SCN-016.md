Scenario ID: SCN-016
Title: Save an offline copy of a bookmark (page snapshot / PDF) and optional Internet Archive
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Saving an offline copy is an optional, per-bookmark choice (not automatic for
every page). For an ordinary web page, the app stores a local snapshot as a
single self-contained HTML file (all assets inlined) so it can be moved or backed
up without missing pieces. For a PDF, the app stores the original PDF file itself.
Once saved, the bookmark shows a saved-copy indicator with the capture date and a
way to view it; the copy can be updated or removed. Independently, the client may
also preserve the page publicly via the Internet Archive, which yields a link to
the web.archive.org capture. The local saved copy and the Internet Archive copy
are two separate, independent options. The saved copy and archive link remain
openable even if the original page later changes or disappears. If a capture
fails (e.g. the site is unreachable), the bookmark is never removed or blocked;
the failure is shown and the client can retry.

## Gherkin
Feature: Offline copy

  Scenario: Save a local copy of a web page
    Given a bookmark for a web page
    When the client saves a local copy
    Then a single self-contained HTML snapshot is stored
    And the bookmark shows a saved-copy indicator with its date and a view action

  Scenario: Save a PDF
    Given a bookmark for a PDF
    When the client saves a copy
    Then the original PDF file is stored and can be viewed

  Scenario: Copy is optional per bookmark
    Then copies are only made when the client chooses, per bookmark, not automatically

  Scenario: Independent Internet Archive preservation
    When the client preserves via the Internet Archive
    Then a web.archive.org capture link is recorded, independent of the local copy

  Scenario: Copy survives the original changing
    Given a saved copy or archive link
    When the original page later changes or disappears
    Then the saved copy / archive link still opens the captured version

  Scenario: Failed capture never blocks the bookmark
    Given a capture attempt fails
    Then the bookmark is kept, the failure is shown, and the client can retry

## Assumptions
- Local web-page snapshot = one self-contained HTML file with assets inlined;
  PDF stored as the original file (client confirmed).
- Local copy and Internet Archive are independent options (client confirmed).
- Capture is per-bookmark and optional (client confirmed).
- Live fetching, single-file archiving and archive.org submission could not be
  reproduced in the offline prototype; the states/actions were shown and the
  fetch/storage behaviour confirmed by description (recorded in session log).
