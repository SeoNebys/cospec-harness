Scenario ID: SCN-007
Title: Mark a read-later bookmark as read
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

From the focused read-later view, the client can use a plainly labeled "Mark as read" action. It immediately leaves that view because its read-later flag has been cleared, but the bookmark remains in the full collection. No separate reading-history record is required. This explicit clearing action complements the checkbox used to show and set read-later state in the full collection.

## Gherkin

Feature: Complete the read-later loop

  Scenario: Mark a read-later bookmark as read without deleting it
    Given a bookmark is flagged for later
    And the client is viewing the focused read-later list
    When the client selects "Mark as read" on the bookmark
    Then the bookmark's read-later flag is cleared
    And the bookmark is no longer shown in the read-later list
    And the bookmark remains in the full collection

## Assumptions

- Marking an item as read only clears its read-later flag.
- The app does not maintain a separate reading-history record.
- The focused read-later view uses an explicit "Mark as read" action; the full collection uses the checkbox approved in SCN-006 to show and set flag state.
