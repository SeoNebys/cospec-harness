Scenario ID: SCN-002
Title: Open a saved link, and rename its name in place
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each saved link's name is shown as a clickable headline. A normal single click
on the name opens the linked page. To rename, the user hovers over the link's
row, which reveals a small pencil (✎) control; clicking the pencil turns the
name into an editable field in place (right where the name sits). The user types
a new name and confirms with Enter or by clicking away, which keeps the new name;
pressing Escape cancels and restores the previous name. If the field is left
empty, the previous name is kept. The address underneath is unchanged by
renaming.

## Gherkin
Feature: Opening and renaming a saved link

  Scenario: Open a saved link
    Given a saved link shown in the list
    When the user clicks the link's name
    Then the linked page opens

  Scenario: Rename a saved link's name in place
    Given a saved link shown in the list
    When the user hovers over the link's row
    Then a pencil (rename) control becomes visible
    When the user clicks the pencil
    Then the name becomes an editable field in place
    When the user types a new name and confirms with Enter or by clicking away
    Then the new name is kept as the link's name
    And the link's address is unchanged

  Scenario: Cancel a rename
    Given the user is editing a link's name
    When the user presses Escape
    Then the previous name is restored

  Scenario: Empty rename keeps the previous name
    Given the user is editing a link's name
    When the user confirms with an empty field
    Then the previous name is kept

## Assumptions
- A single click on the name is reserved for opening the link (primary action).
- Rename is a secondary action triggered by a hover-revealed pencil control.
- Editing happens inline, in place, not in a separate dialog.
- Renaming changes only the display name, never the saved address.
