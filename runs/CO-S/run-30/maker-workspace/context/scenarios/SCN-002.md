Scenario ID: SCN-002
Title: Update an existing bookmark instead of duplicating it
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client tries to save a web address already in the library, an inline notice appears without obscuring the list. The existing bookmark remains visible and no duplicate is created. The client can keep the bookmark unchanged or update its title and description from the page.

## Gherkin
Feature: Preventing duplicate bookmarks

  Scenario: Recognize an already-saved web address
    Given one bookmark exists for a web address
    When the client tries to save the same web address again
    Then an inline notice says that the link is already saved
    And the existing bookmark remains visible
    And no second bookmark is created
    And the client can keep the existing bookmark unchanged
    And the client can choose to update the existing bookmark

  Scenario: Keep a repeated bookmark unchanged
    Given the duplicate-link notice is visible
    When the client chooses to keep the bookmark as it is
    Then the existing bookmark is unchanged
    And the library still contains only one bookmark for that web address

  Scenario: Refresh a repeated bookmark
    Given the duplicate-link notice is visible
    When the client chooses to update the bookmark
    Then its title and description are refreshed from the page
    And the library still contains only one bookmark for that web address

## Assumptions
- Re-saving the same web address means the client wants either to preserve or refresh the existing bookmark.
- Updating a repeated bookmark refreshes its title and description rather than creating a separate copy.
- The duplicate notice is shown inline with the bookmark list.
