Scenario ID: SCN-002
Title: Add tags and a formatted personal note; both editable later
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

While reviewing a bookmark before saving (and later when editing it), the user
can add their own tags and a personal note, kept separate from the page's own
description.

Tags (approved interaction — "Option C"):
- Chosen tags appear as removable pills (click × to remove).
- As the user types in the tag box, tags they have used before that match the
  typed text are suggested beneath the box; picking one adds it as a pill.
- If the typed text is not an existing tag, a "Create '<text>'" option lets the
  user add a brand-new tag. New tags become part of the suggestion pool.

Note (approved interaction — "Option 2"):
- The user writes the note using simple formatting marks: headings (### ),
  bullet lists (- ), bold (**...**), italics (*...*), and links ([text](url)).
- A live preview renders the formatting beside the input as the user types, so
  mistakes are easy to catch.
- When viewing the saved bookmark, the note is displayed rendered (heading, list,
  emphasis, working link) in a distinct band, visibly separate from the page
  description.

Later editing:
- Tags and the note are editable later in the same edit affordance as the title
  and description (all four editable together).

## Gherkin

Feature: Personal tags and a formatted note

  Scenario: Add an existing tag by typing and picking a suggestion
    Given the user is adding tags to a bookmark
    When the user types text that matches a previously-used tag
    Then that tag is offered as a suggestion
    And selecting it adds it as a removable pill

  Scenario: Create a new tag
    Given the user types tag text that is not an existing tag
    When the user chooses the "Create" option (or presses Enter)
    Then a new tag is added as a pill and becomes available for future suggestions

  Scenario: Remove a tag
    Given a bookmark has a tag pill
    When the user clicks the pill's remove control
    Then that tag is removed from the bookmark

  Scenario: Write a note with formatting and see it rendered
    Given the user writes a note using simple formatting marks
    Then a live preview renders the formatting as they type
    And the saved bookmark displays the note rendered, separate from the page description

  Scenario: Edit tags and note later
    Given a saved bookmark with tags and a note
    When the user edits the bookmark
    Then the title, description, tags and note are all editable together
    And saving applies the changes

## Assumptions

- Note formatting is a small, well-known set (headings, lists, bold, italics,
  links); exact rendering fidelity is an implementation detail.
- Tag suggestions are drawn from tags the single user has previously used.
- The note is stored/displayed distinctly from the page's auto-filled description.
