Scenario ID: SCN-005
Title: Filter bookmarks by tags (match all selected)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A filter bar lists only the tags actually in use. Each tag is a three-state
control: tap once to INCLUDE it (shown in the accent colour), tap again to
EXCLUDE it (shown struck-through in red), tap a third time to clear it. Included
and excluded states are visually distinct. The list shows bookmarks that have all
included tags AND none of the excluded tags. A "clear" control resets the tag
filter. When no bookmark matches, an explanatory empty state is shown. (Updated
SESSION-001: originally include-only match-all; extended to include/exclude.)

## Gherkin
Feature: Filter by tags

  Scenario: Only used tags appear as filters
    Given bookmarks with various tags
    Then the filter bar shows only tags that are in use

  Scenario: Narrow by multiple included tags (match all)
    Given several tags are available
    When the client includes two tags
    Then only bookmarks that have both included tags are shown

  Scenario: Exclude a tag
    Given a tag is set to excluded
    Then bookmarks carrying that tag are hidden

  Scenario: Three-state cycle
    When the client taps a tag repeatedly
    Then it cycles include -> exclude -> off, with include and exclude visually distinct

  Scenario: Clear the filter
    Given one or more tags are selected
    When the client clears the filter
    Then all bookmarks are shown again

  Scenario: No bookmark matches the selected tags
    Given a combination of selected tags that no bookmark has
    Then an explanatory empty state is shown

## Assumptions
- Multiple selected tags combine with AND / match-all (client confirmed).
- Only in-use tags are offered as filters (client confirmed).
