Scenario ID: SCN-003
Title: Find a bookmark by searching any remembered part of it
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Above the bookmark list there is a search box. As the client types, the list
filters immediately (no separate search button). A bookmark is shown if the typed
text appears in any of: its title, description, site name, full web address, tags,
or personal note. Matching ignores capitalization. Matching text is highlighted
in the results, and the count reads "showing X of Y". If nothing matches, a clear
"No bookmarks match ‘…’" message is shown instead of a blank area. Clearing the
box restores the full list.

## Gherkin
Feature: Searching bookmarks

  Scenario: Filter the list as I type
    Given I have saved bookmarks
    When I type text into the search box
    Then the list immediately shows only bookmarks whose title, description, site,
         web address, tags, or note contain that text
    And the matching text is highlighted
    And the count shows how many of the total are shown

  Scenario: Search ignores capitalization and matches partial text
    Given a bookmark whose web address contains "tldr-pages"
    When I type "TLDR-PAGES" in the search box
    Then that bookmark is shown

  Scenario: No matches
    Given I type text that matches no bookmark
    Then a "No bookmarks match" message is shown

  Scenario: Clearing the search
    Given the search box contains text
    When I clear the search box
    Then the full list of bookmarks is shown again

## Assumptions
- Search covers title, description, site, full web address, tags, and note.
- Matching is case-insensitive substring matching.
- Filtering happens live as the client types.
