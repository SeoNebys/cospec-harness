Scenario ID: SCN-030
Title: Recognize harmless address variations as duplicates
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When an entered address points to an existing saved page but adds known tracking information or a jump to a section within that page, it is treated as the existing bookmark. No near-duplicate is created, the collection count stays unchanged, and the person is returned to the existing bookmark. Address parts that genuinely select different content remain distinct.

## Gherkin
Feature: Avoiding duplicate bookmarks

  Scenario: Save an existing page with harmless address extras
    Given a page is already bookmarked
    When the person saves its address with known tracking information and a page-section ending
    Then no new bookmark is created
    And the collection count is unchanged
    And the person is told the page is already saved
    And the existing bookmark is brought into focus

  Scenario: Save an address that genuinely identifies different content
    Given an address differs from an existing bookmark in a way that selects different content
    When the person saves it
    Then it is treated as a distinct bookmark

## Assumptions
- Known tracking parameters and fragment identifiers are ignored for duplicate comparison.
- Other address parameters are preserved when they may identify different content.
