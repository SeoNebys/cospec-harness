Scenario ID: SCN-004
Title: Tag a bookmark, reusing existing tags via suggestions
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A bookmark can carry several tags at once (it is not forced into a single
folder). From a bookmark the client adds a tag by typing; as they type, existing
tags that match are suggested so the client can reuse one instead of creating a
near-duplicate, and a "create new" option is offered for a genuinely new tag. The
tag entry stays open so the client can add several tags in a row. Tags are stored
in lowercase, so differently-cased spellings (e.g. "Python"/"python") are treated
as the same tag. A tag can be removed from a bookmark.

## Gherkin
Feature: Tag a bookmark

  Scenario: Add a tag with reuse suggestions
    Given a saved bookmark
    When the client starts typing a tag
    Then existing tags matching the typed text are suggested for reuse
    And an option to create a new tag is offered
    And choosing a suggestion or creating a new tag adds it to the bookmark

  Scenario: Add several tags in a row
    Given the client is adding a tag to a bookmark
    When the client confirms a tag
    Then the tag entry stays open for adding more tags

  Scenario: Tags are case-insensitive
    Given a bookmark tagged "python"
    When the client adds "Python"
    Then it is treated as the same tag (stored lowercase, no duplicate)

  Scenario: Remove a tag
    Given a bookmark with a tag
    When the client removes that tag
    Then the tag is no longer on the bookmark

## Assumptions
- A bookmark may have multiple tags (client chose tags over folders).
- Tag matching/storage is lowercase (client confirmed).
