Scenario ID: SCN-012
Title: Reuse an existing tag regardless of capitalization
Type: Edge Case
Approval status: approved
Approval session: SESSION-012
Approval cycle: 1

## Approved behaviour

When the client enters a tag name that already exists with different capitalization, the existing tag is assigned to the bookmark instead of creating a near-duplicate. The established spelling is preserved, the existing sidebar count increases, and the application confirms that the existing tag was reused.

## Gherkin

Feature: Keep personal tags consistent

  Scenario: Assign an existing tag using different capitalization
    Given the sidebar contains a tag named "Design"
    And a bookmark is not assigned to that tag
    When the user enters "design" while adding a tag to the bookmark
    Then the existing "Design" tag is assigned to the bookmark
    And its sidebar count increases by one
    And no separate tag named "design" is created
    And the application confirms that the existing tag was reused

## Assumptions

- Tag-name comparison ignores letter capitalization.
- The spelling of the first-created tag remains the canonical display spelling.
