Scenario ID: SCN-009
Title: Cancel deletion and handle deleting the final bookmark
Type: Edge Case
Approval status: approved
Approval session: SESSION-009
Approval cycle: 1

## Approved behaviour
The deletion confirmation lets the user safely back out. Choosing “Keep it” closes the confirmation and leaves the bookmark, count, current list, and notifications unchanged. When the user confirms deletion of the only remaining bookmark, the count becomes zero, a deletion confirmation is shown, and the collection returns to the same welcoming empty state with an action to add the first bookmark.

## Gherkin
Feature: Deletion boundaries

  Scenario: Cancel deletion without changing the collection
    Given the collection contains six bookmarks including “Weeknight recipes”
    And the user is being asked to confirm deletion of “Weeknight recipes”
    When the user chooses “Keep it”
    Then the confirmation closes
    And “Weeknight recipes” remains in the list
    And the count remains 6 bookmarks
    And no deletion confirmation is shown

  Scenario: Delete the final bookmark
    Given “MDN Web Docs” is the only remaining bookmark
    When the user chooses its delete control
    And confirms the deletion
    Then the bookmark count becomes 0
    And a “Bookmark deleted” confirmation is shown
    And a welcoming empty state is shown
    And the empty state includes an action to add the first bookmark

## Assumptions
- Cancelling deletion leaves all visible collection state unchanged.
- The empty state after deleting the final bookmark uses the same interaction as the initial empty state.
