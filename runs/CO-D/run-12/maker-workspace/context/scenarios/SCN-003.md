Scenario ID: SCN-003
Title: Return to an existing bookmark instead of saving a duplicate
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user enters a web address that is already saved, the app does not create a second bookmark. It tells the user that the link was already saved, brings the existing bookmark into focus, and preserves any title or description corrections already made to that bookmark.

## Gherkin
Feature: Saving bookmarks

  Scenario: Recognize an already-saved web address
    Given one bookmark exists for a web address
    And the bookmark has a title corrected by the user
    When the user asks the app to get details for the same web address
    Then the collection still contains one bookmark for that web address
    And the app explains that the link was already saved
    And the app brings the existing bookmark into focus
    And the corrected title remains unchanged

## Assumptions
- Duplicate recognition occurs when the app is asked to get details for the entered address.
- An existing bookmark is visually brought into focus in the current collection view.
- User-authored corrections take precedence over newly obtained page details.
