Scenario ID: SCN-001
Title: Find a saved bookmark back by typing whatever you remember
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The client opens the page and sees a list of everything they have saved. Each
item shows the page's title, the readable name of the site it came from (e.g.
"The New York Times", "Serious Eats" — not the raw web address), a short
description of what it is about, and when it was saved.

There is a search box at the top. As the client types, the list narrows live to
only the items that match. Finding is deliberately forgiving, because the client
is usually working from partial memory:

- Typing a word from the **title** finds the item.
- Typing a word that only appears in the **description** finds the item (so
  "roughly what it was about" is enough — e.g. "procrastinate" finds an article
  whose title doesn't contain that word).
- Typing the **readable site name** finds the item (e.g. "new york times" finds
  the item saved from The New York Times).
- The query is treated as **a set of words, not one exact phrase**: spaces are
  fine, and word order does not matter ("bread no-knead", "structure react" both
  work with the words reversed).
- Each typed word must match **from the start of a word**, so a short word does
  not get dragged out of the middle of an unrelated longer word ("read" finds
  "reading"/"a long read", but not "bread").
- The parts of each item that caused the match are highlighted, so it is clear
  *why* a result appeared — including when the match is on the site name alone.

When nothing matches, the client sees a plain "nothing matched" message rather
than an empty screen.

The client confirmed a strong preference for the readable site name over the raw
address on the list, on the condition that the friendly name is genuinely tied
to the real underlying address so a click always reaches the true page.

## Gherkin

Feature: Finding a saved bookmark

  Background:
    Given the client has several bookmarks saved
    And each bookmark has a title, a readable site name, a description and a saved date

  Scenario: See everything when the search box is empty
    Given the search box is empty
    Then all saved bookmarks are shown
    And each shows its title, readable site name, description and saved date

  Scenario: Find by a word in the title
    When the client types a word that appears in a bookmark's title
    Then only bookmarks matching that word are shown
    And the matching text is highlighted

  Scenario: Find by a word only in the description
    Given a bookmark whose title does not contain the word "procrastinate"
    But whose description does contain "procrastinate"
    When the client types "procrastinate"
    Then that bookmark is shown

  Scenario: Find by the readable site name
    Given a bookmark saved from "The New York Times"
    When the client types "new york times"
    Then that bookmark is shown
    And the site name is highlighted to show why it matched

  Scenario: Word order and spaces do not matter
    Given a bookmark titled "How to structure a large React application"
    When the client types "structure react"
    Then that bookmark is shown

  Scenario: Matching is from the start of a word, not mid-word
    Given a bookmark whose only occurrence of the letters "read" is inside "bread"
    And another bookmark containing the standalone word "read"
    When the client types "read"
    Then the bookmark containing the standalone word "read" is shown
    And the bookmark containing only "bread" is not shown

  Scenario: Nothing matches
    When the client types a query that matches no bookmark
    Then a "nothing matched" message is shown for that query
    And no bookmarks are listed

## Assumptions

- The list shows title, readable site name, description, and saved date. (Client
  approved this composition.)
- The readable site name is displayed instead of the raw web address on the
  list, and must be reliably tied to the real address so clicking reaches the
  true page. (Client approved, with the trust condition.)
- Every typed word must match (AND across words), matching from the start of any
  word within the title, description, or readable site name.
- Search is case-insensitive and updates live as the client types.
