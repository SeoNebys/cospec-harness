Scenario ID: SCN-014
Title: Recognize safe variations of an already-saved address
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
An exact repeat of a saved address must always return the existing bookmark without creating a duplicate or overwriting its user-authored title, note, or labels. The app should also recognize harmless variations such as a trailing slash or known referral text when it can do so confidently. If it cannot be confident that two addresses represent the same page, it keeps them separate rather than wrongly merging different pages.

## Gherkin
Feature: Preventing duplicate bookmarks

  Scenario: Enter an exact saved address again
    Given a bookmark exists for a web address with user-authored details
    When the user enters the exact same address again
    Then no duplicate bookmark is created
    And the existing bookmark is shown
    And its user-authored title, note, and labels remain unchanged

  Scenario: Enter a confidently equivalent address
    Given a bookmark exists for a web address
    When the user enters an address that differs only by a safely recognized trailing slash or referral addition
    Then no duplicate bookmark is created
    And the existing bookmark is shown unchanged

  Scenario: Address equivalence is uncertain
    Given a bookmark exists for a web address
    When the user enters a different address that cannot be confidently identified as the same page
    Then the app does not merge it with the existing bookmark

## Assumptions
- Exact address equality is the mandatory duplicate check.
- Near-identical recognition is conservative and never takes precedence over avoiding a false merge.
- Known referral additions may be ignored only when the remaining address confidently identifies the same page.
