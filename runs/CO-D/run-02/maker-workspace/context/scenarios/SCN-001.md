## Approved behaviour

The client pastes a link's address into a single "Add" field and chooses Add.
The app gathers the page's information automatically — its real title, a short
description, the site's small icon, and the page's preview image when one is
available — and presents a review panel pre-filled with them. The title and
description are editable, so the client can simply confirm them or correct them
before saving. On Save, the bookmark is added to the top of the list (newest
first). The saved card shows, from top to bottom: the preview image (when the
page has one), the title, the client's description, the link address, and a
quiet source line carrying the site icon and site name — styled as source
context, clearly distinct from the client's own tags rather than as a tag pill.

When a page has no preview image, the card is shown without an image area at all;
no placeholder box is used, keeping the layout calm.

The overall experience is a calm, uncluttered single column.

## Assumptions

- Auto-collected details (title, description, icon, preview image) are read from
  the target page in the real application; the Phase 1 prototype simulates the
  title/icon/preview to demonstrate the flow, not the fetch accuracy.
- The page's description and the client's own note are separate fields (see
  SCN-013); the description is the page's summary, the note is the client's own.
- Newest-first ordering.
