Scenario ID: SCN-024
Title: Display preferences (default sort, items shown, text size)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A Display settings panel offers three preferences:
- Default sort: the starting sort order (same four options as the sort control).
  The ad-hoc sort dropdown by the list still lets the client change sort for the
  moment; the default sets the starting preference.
- Items shown at a time: how many bookmarks are drawn at once (e.g. 10/25/50/100
  or All), with a "Show more" button revealing the next batch. This affects
  display only.
- Text size: Small / Medium / Large, scaling the app's text.

The item-shown limit affects display only and never the scope of a whole-view
bulk action: "Select all in this view" still selects every bookmark matching the
current tab and search, including matches not yet revealed by "Show more", and
never bookmarks outside that filter.

## Gherkin
Feature: Display preferences

  Scenario: Default sort preference
    Given a default sort is chosen in Display settings
    Then the list starts in that order
    And the ad-hoc sort control can still change it for the moment

  Scenario: Items shown with Show more
    Given the items-shown limit is set to N
    When there are more than N matches in the current view
    Then only N are drawn with a "Show more" control to reveal the next N

  Scenario: Text size
    Given a text size is chosen
    Then the app's text scales accordingly

  Scenario: Limit does not shrink whole-view action scope
    Given the items-shown limit hides some matches behind "Show more"
    When the client uses "Select all in this view"
    Then all matches in the current tab and search are selected
    And matches outside the current filter are not selected

## Assumptions
- "Items shown" is a show-more model, not numbered pages.
- Default sort is a starting preference; ad-hoc sort remains available.
