## Approved behaviour
The search box understands a query language:
- `#tag` matches a specific tag rather than any text.
- `"quoted phrase"` matches that exact phrase.
- `AND`, `OR`, `NOT` combine terms, recognised in any capitalisation; adjacent
  terms without an operator combine as AND (implicit).
- Parentheses group terms.
- Operator precedence is NOT, then AND, then OR; parentheses override.
- Any operator placed inside quotes is treated as an ordinary word, not an
  instruction.
- A malformed query does not error; it quietly falls back to a plain search of
  the meaningful words.

## Gherkin
Feature: Advanced search

  Scenario: Tag term
    When the client searches "#python"
    Then only bookmarks tagged python are shown

  Scenario: Exact phrase
    When the client searches "\"perfect pasta\""
    Then only bookmarks containing that exact phrase are shown

  Scenario: Boolean combination with grouping
    When the client searches "space AND (#article OR #video)"
    Then results match "space" and carry at least one of those tags

  Scenario: Operators are case-insensitive
    When the client uses "and", "And" or "AND"
    Then each is treated as the AND operator

  Scenario: Quoted operator is literal
    When the client searches "\"AND\""
    Then the ordinary word "and" is searched, not the operator

  Scenario: Malformed query falls back
    Given a malformed query (e.g. an unclosed bracket)
    Then a plain search of the meaningful words is performed instead of an error

## Assumptions
- Precedence NOT > AND > OR; implicit AND between adjacent terms (client
  confirmed).
- Case-insensitive operators (client confirmed).
