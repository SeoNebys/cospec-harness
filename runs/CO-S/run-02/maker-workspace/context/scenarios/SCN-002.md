Scenario ID: SCN-002
Title: Page title is fetched on paste and is editable before saving
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user pastes/enters a link, the app automatically looks up the page's
real title and fills it into the name field before the link is saved, showing
a brief "looking up…" indication while it works. The user can then keep that
title, edit it, or replace it entirely with their own wording before saving —
because the real page title is often not how the user would think of the link
later. If the user has already typed their own name, the automatic lookup does
not overwrite it. On save, whatever is in the name field at that moment is what
is stored and shown in the list.

## Gherkin
Feature: Automatic title assistance when saving a bookmark

  Scenario: Title is fetched automatically after entering a link
    Given the user is on the bookmarks screen
    When the user enters a link and the name field is empty
    Then a brief lookup indication is shown
    And the name field is filled with the fetched page title
    And the user may edit the name before saving

  Scenario: User edits the fetched title before saving
    Given the name field has been auto-filled with a fetched title
    When the user changes the name to their own wording
    And the user saves
    Then the bookmark is stored and shown with the user's wording

  Scenario: A name the user already typed is not overwritten
    Given the user has typed their own name
    When the automatic title lookup completes
    Then the user's typed name is preserved and not overwritten

## Assumptions
- The lookup happens shortly after the link is entered (on paste), not only at
  save time (client chose this "Version B" behaviour over on-save fill).
- The user's own typed name always takes precedence over the fetched title.
- The stored name is whatever is in the name field at the moment of saving.
- (Prototype note) The title lookup is simulated offline in the prototype; the
  real network lookup is an implementation concern for Phase 2. Failure/blank
  results are deferred to edge-case exploration.
