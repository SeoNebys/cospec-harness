## Approved behaviour
A "Topics" bar sits above the library listing every label the client has used,
each with a count — a table of contents for the library. Clicking a topic
narrows the library to links with that label and shows a clear "Showing links
in X — Show all again" bar (the escape hatch). Clicking a second topic narrows
*further* (AND): only links carrying all selected topics remain. This
stack-to-narrow is the everyday move.

Once two or more topics are selected, a quiet "all of these / any of these"
switch appears, defaulting to "all" (narrow). Switching to "any" pulls the
piles together (OR) — the rare exception; the switch stays hidden until two
topics make it relevant. Clicking a selected topic again removes it; "Show all
again" clears everything.

In "narrow" mode, topics that would leave no results are dimmed (dead-end
prevention). An impossible combination shows a plain-language empty message with
a nudge, never a blank screen.

## Gherkin
Feature: Narrow the library by topic

  Scenario: Stacking topics narrows further
    Given links labelled "recipes" and some also "baking"
    When the client selects "recipes"
    Then only recipe links are shown
    When the client also selects "baking"
    Then only links in both recipes and baking remain

  Scenario: Switching to match-any pulls piles together
    Given two topics are selected in narrow mode
    When the client switches to "any of these"
    Then links in either topic are shown

  Scenario: Dead-end prevention and empty state
    Given "recipes" is selected in narrow mode
    Then a topic with no overlap is shown dimmed
    And selecting an impossible combination shows a plain-language empty message

  Scenario: Clearing the filter
    When the client selects a chosen topic again
    Then it is removed from the filter
    And "Show all again" clears all topics

## Assumptions
- Default multi-select semantics = AND (narrow). (client confirmed)
- OR ("any") is a hidden exception revealed only at 2+ topics. (client confirmed)
- Dead-end dimming and plain-language empty state are helpful, not noise.
  (client confirmed)
