Scenario ID: SCN-010
Title: Prevent an exact duplicate bookmark
Type: Edge Case
Approval status: approved
Approval session: SESSION-010
Approval cycle: 1

## Approved behaviour

When the client tries to save the exact address of a bookmark already in the collection, the application does not create a second copy. It clearly says that the link is already saved and offers a View existing action that closes the add flow and takes the client directly to the original bookmark card.

## Gherkin

Feature: Keep the bookmark collection free of exact duplicates

  Scenario: Submit the exact address of an existing bookmark
    Given a bookmark with a particular web address already exists in the collection
    When the user submits that exact address from the add-bookmark window
    Then no additional bookmark is created
    And the application says that the link is already saved
    And the application offers an action to view the existing bookmark
    When the user chooses to view the existing bookmark
    Then the add-bookmark window closes
    And the existing bookmark card is brought into view and highlighted

## Assumptions

- Duplicate detection compares normalized exact addresses; similarity between different pages is not treated as duplication.
- Existing notes, tags, and collection state are not changed by the duplicate attempt.
