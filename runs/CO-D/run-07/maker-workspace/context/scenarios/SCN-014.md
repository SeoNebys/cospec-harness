Title: Save a search + included/excluded tags as a reusable view
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A tag filter can be included or excluded: clicking a tag adds it as an included
filter (blue); clicking the filter chip's label switches it to excluded (red
"−#tag"); the × removes it. Included tags must all match; excluded tags must not
match; both combine (AND) with the search text.

When any search text or tag filter is active, a "★ Save this view" action lets the
client name and save the current combination. Saved views are a reusable RULE —
search text plus which tags are included and excluded — not a frozen set of
bookmarks; reopening a view re-runs it against the current collection, so newly
saved matching bookmarks appear. Saved views persist between visits and are
reached from a "☆ Views" menu, where each can be applied or deleted.

Read/finished status and sort order are deliberately NOT part of a saved view;
the client chooses those after opening the view, keeping the view focused on the
search-and-tag combination (and would name it accordingly).

The client confirmed: reusable rule that updates as the collection changes; all
included tags required, any excluded tags removed, combined with search text;
status and sorting kept out of saved views for now.

## Gherkin
Feature: Saved views

  Scenario: Include and exclude tags
    When I click a tag it is included
    And when I switch the filter chip it becomes excluded
    Then only bookmarks having all included tags and none of the excluded tags
         (and matching the search text) are shown

  Scenario: Save the current view
    Given a search and/or tag filter is active
    When I choose "Save this view" and name it
    Then it is stored and appears in the Views menu

  Scenario: Reapply a saved view as a live rule
    Given a saved view exists
    When I open it from the Views menu
    Then the search text and included/excluded tags are restored
    And the results reflect the current collection (not a frozen list)

  Scenario: Saved views persist and can be deleted
    Then saved views remain available on a later visit
    And each can be deleted from the Views menu

## Assumptions
- A saved view stores only: search text, included tags, excluded tags.
- Status and sort are chosen separately after opening a view.
- Views persist per person (prototype uses browser local storage as a stand-in).
