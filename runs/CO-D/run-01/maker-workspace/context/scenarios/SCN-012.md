Scenario ID: SCN-012
Title: Prevent duplicate bookmarks for the same address
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When a person tries to save a destination address that is already in the collection, the app does not create another bookmark. It clearly explains that the link was already saved, brings the existing bookmark into focus, and offers to edit it. Duplicate identity comes from the destination web address rather than the editable title.

## Gherkin
Feature: Duplicate bookmark prevention

  Scenario: Submit an already saved address
    Given a bookmark exists for a destination web address
    When the person submits that destination address again
    Then no additional bookmark is created
    And the app explains that the link was already saved
    And the existing bookmark is brought into focus
    And the person can open that bookmark for editing

## Assumptions
- Editing a bookmark's title does not affect duplicate recognition.
- Duplicate recognition uses the destination address after ordinary address normalization.
