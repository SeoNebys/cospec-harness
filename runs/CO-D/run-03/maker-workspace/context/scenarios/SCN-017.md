Scenario ID: SCN-017
Title: Edge cases for import/export, bulk actions, Internet Archive, and dead links
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Invalid import file:
- If the chosen file cannot be read as a bookmarks file, NOTHING is imported, the
  library is unchanged, and the app clearly asks for the correct bookmarks HTML
  file.

Partially valid import:
- Usable bookmarks are imported; lines with no valid web address are skipped, and
  already-existing ones (matched by URL) are skipped as duplicates. A clear
  summary reports counts (imported / already existed / skipped).

Large bulk action:
- Acting on a large selection (including select-all-matching) shows its scope and a
  progress indicator, and runs without freezing the app; the user can keep working.

Internet Archive submission:
- Submitting shows a truthful "submitting…" state; on success the archive link
  appears; if archive.org is unavailable it reports the failure and allows retry.
  Success is never claimed falsely.

Dead original link:
- Opening a bookmark whose original page no longer exists still navigates to it
  (the browser shows its own not-found); the preserved local copy remains
  available as the fallback. (Automatic dead-link detection is a later-cycle idea,
  LC-1, not in this cycle.)

## Gherkin

Feature: Edge cases for new features

  Scenario: Invalid import changes nothing
    When the user imports a file that is not a valid bookmarks file
    Then nothing is imported and the library is unchanged

  Scenario: Partial import keeps valid entries and summarises
    When an import file has some invalid lines and some duplicates
    Then valid new bookmarks are imported
    And a summary reports imported, already-existing, and skipped counts

  Scenario: Large bulk action shows progress without freezing
    When the user applies an action to a very large selection
    Then a scope + progress indicator is shown and the app stays usable

  Scenario: Internet Archive reports true state
    When the user submits a page to the Internet Archive
    Then a submitting state is shown
    And on success the archive link appears, or on failure a retry is offered
    And success is never reported unless it happened

  Scenario: Dead original link
    When the user opens a bookmark whose original page is gone
    Then the browser navigates to it (showing its own error)
    And the preserved local copy remains available

## Assumptions
- Copy storage capacity/retention remains a non-functional concern (NF-1).
