Scenario ID: SCN-008
Title: Saving a link whose page details cannot be fetched
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When automatic detail-fetching fails (unreachable host, dead link, no network),
the bookmark is still saved — saving the link is more important than fetching its
details. The card shows a gentle warning that the page's details couldn't be
fetched; the link itself stands in as the title, description is empty, and the
site's favicon/host are still derived from the URL. The client is given a "Try
again" action (for a temporary failure) and the normal "Edit" action to fill in
the title/description manually. The client confirmed this recovery model.

## Gherkin
Feature: Resilient saving when detail fetch fails

  Scenario: Fetch failure still saves the link
    Given the client saves a link whose page cannot be reached
    When the automatic detail fetch fails
    Then the bookmark is still saved (not discarded)
    And the card shows a warning that details could not be fetched
    And the link is used as a fallback title

  Scenario: Retrying a failed fetch
    Given a saved bookmark whose details failed to fetch
    When the client chooses Try again
    Then the app attempts to fetch the page details again
    And on success the card fills in with the fetched details

  Scenario: Manual recovery
    Given a saved bookmark whose details failed to fetch
    When the client edits it
    Then the client can set the title and description manually

## Assumptions
- A failed fetch never blocks or discards the save.
- Retry re-attempts the same fetch; manual edit is always available.
