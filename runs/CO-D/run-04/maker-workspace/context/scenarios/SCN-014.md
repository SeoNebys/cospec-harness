Scenario ID: SCN-014
Title: Sort the library, and the order travels across lenses
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A compact "Sort" dropdown (chosen over always-visible buttons — sorting is set
occasionally, not fiddled with constantly, so it stays folded away) offers four
orders: Newest first (default), Oldest first, Name A–Z, Name Z–A. The chosen
order is a single global setting: it persists across every lens and filter — the
To-read pile, a topic filter, and mid-search all honour it, and switching lenses
never resets it to newest.

Explicitly out of scope (client): manual drag-to-arrange (would become a chore
the client would never maintain — the whole point is the app orders it on
demand) and a "recently opened" order (not worth the clutter).

## Gherkin
Feature: Sort the library

  Scenario: Choose a sort order
    When the client picks an order from the Sort dropdown
    Then the visible list reorders accordingly

  Scenario: The order persists across lenses and filters
    Given the client has chosen "Oldest first"
    When the client switches to the To-read pile, a topic, or a search
    Then that order still applies
    And switching lenses does not reset it to newest

## Assumptions
- Dropdown over segmented buttons (toolbar is busy; sorting is occasional).
  (client confirmed)
- Four named orders are the complete set. (client confirmed)
- No manual ordering; no "recently opened". (client confirmed)
- Date-based orders use each link's true save date, incl. original dates carried
  in on import (SCN-015), so "Oldest first" reflects real history.
- Dates display friendly-relative for recent saves ("2 days ago") and switch to
  an actual date for older ones ("19 Aug 2019"). (client confirmed)
