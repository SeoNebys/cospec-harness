Scenario ID: SCN-002
Title: Update an existing bookmark when the same page is saved again
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user starts the familiar save flow from a library that already has bookmarks and provides the address of a page already in the library, the app plainly says the page was saved before and opens the existing bookmark's details for editing. Updating those details changes the single existing bookmark and confirms that no duplicate was created.

## Gherkin
Feature: Prevent duplicate bookmarks

  Scenario: Recognize and update an already-saved page
    Given the personal library already contains a bookmark for a web page
    When the user tries to save that same web address again
    Then the app tells the user the page was saved before
    And the app shows the existing bookmark's editable details
    When the user updates the bookmark
    Then the existing bookmark reflects the changes
    And the library still contains only one bookmark for that page
    And the app confirms that no duplicate was created

## Assumptions
- Equivalent versions of the same address are treated as the same page.
- The duplicate path uses the same save entry point as a new bookmark.
- The existing user's title and description are preserved for editing instead of being replaced by newly gathered page text.
