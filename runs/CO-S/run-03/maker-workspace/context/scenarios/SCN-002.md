Scenario ID: SCN-002
Title: Put a link into one or more groups while saving
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
While saving a link, the user attaches groups by typing a group name and pressing
Enter; each entered name becomes a small removable tag ("chip"). Typing a name
that already exists reuses that group; typing a new name creates the group on the
spot. The user may attach several groups to one link — a link can belong to more
than one group at once (e.g. a recipe article in both "Recipes" and "Read later").
Groups are optional; a link may be saved with none. The client confirmed the
type-and-Enter interaction "felt totally natural".

## Gherkin
Feature: Grouping a link

  Scenario: Attach an existing group by typing its name
    Given the user is saving a link
    When the user types the name of an existing group and presses Enter
    Then that group is attached to the link as a removable tag

  Scenario: Create a new group on the spot
    Given the user is saving a link
    When the user types a group name that does not yet exist and presses Enter
    Then a new group with that name is created and attached to the link

  Scenario: Attach multiple groups to one link
    Given the user is saving a link
    When the user attaches two or more groups before saving
    Then the saved link belongs to all of those groups

  Scenario: Save with no group
    Given the user is saving a link
    When the user attaches no group
    Then the link is still saved

## Assumptions
- A link belongs to zero or more groups (multi-group), NOT a single folder. This
  supersedes the earlier single-folder assumption from the grouping exploration.
- A removable chip UI represents attached groups before saving.
- Group names are matched by exact typed text (case/duplicate handling deferred to
  edge-case exploration).
