Scenario ID: SCN-003
Title: Find bookmarks by browsing labels, combining labels (AND), and full-text search
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client can find saved bookmarks two first-class ways, which also stack together.

Browse by label:
- A sidebar lists all labels the client has, each with a count of how many
  bookmarks carry it.
- Clicking a label filters the list to bookmarks carrying that label ("everything
  filed under recipes").

Combine labels (AND / narrowing):
- Selecting a second label narrows to bookmarks that carry BOTH labels
  (e.g. "recipes" + "dinner" -> only bookmarks with both). This is the client's
  mental model of "combine": fewer results.
- Clicking a selected label again removes it from the filter.

Search:
- A search box matches across titles, descriptions, web addresses, and label names.
- Multiple typed words all must match (each term narrows further).
- Matching text is highlighted in the results so the client can see WHY an item
  matched (valued explicitly by the client).
- Search and label filters stack: a selected label plus a typed word narrow together.

Active filters (labels + query) are shown as removable chips with a "clear all"; a
result count is shown; when nothing matches, an empty-state message invites removing
a label or a word.

## Gherkin
Feature: Finding saved bookmarks

  Scenario: Browse everything under one label
    Given the client has bookmarks with various labels
    When the client selects the label "recipes"
    Then only bookmarks labeled "recipes" are shown

  Scenario: Narrow by combining two labels (AND)
    Given the label "recipes" is selected
    When the client also selects "dinner"
    Then only bookmarks labeled both "recipes" and "dinner" are shown

  Scenario: Full-text search inside all captured text
    Given a bookmark whose description contains the word "index"
    When the client types "index" in the search box
    Then that bookmark appears in the results
    And the matching word is highlighted

  Scenario: Search and labels stack
    Given the label "recipes" is selected
    When the client also types a search word
    Then results must satisfy both the label and the search word

## Assumptions
- Default label combination is AND (narrowing). OR / NOT combining is a separate,
  non-default capability being explored (see pending combining-modes scenario).
- Search currently covers title, description, web address, and label names. Personal
  notes are NOT yet a captured field; once added they must also be searchable
  (pending notes scenario).
- Default result ordering is not yet settled (pending sort scenario).
