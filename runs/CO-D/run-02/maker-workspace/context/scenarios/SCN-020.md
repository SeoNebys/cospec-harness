Title: Display preferences — default sort, how many to show, and text size
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

From a "Preferences" panel (opened from a header button) the client sets personal
display choices:

- Default sort order — the order new views start in (Newest first, Oldest first,
  Recently updated, Title A–Z, Title Z–A). The per-session Sort control still
  overrides it at any time; the preference is only the starting default.
- How many to show at once — the number of bookmarks shown before a "Show more"
  button loads the next batch (10 / 25 / 50 / 100 / All). Importantly, searching
  and bulk "Select all" always act on the full matching set, never merely the
  bookmarks currently on screen.
- Text size — Small, Normal, or Large reading size for the whole app.

The finished application remembers these preferences between visits.

## Gherkin

Feature: Display preferences

  Scenario: Default sort preference
    Given a default sort order set in preferences
    When I open a view
    Then it starts in that order
    And I can still change the per-session Sort control

  Scenario: Show-more paging with a display limit
    Given a "how many to show" limit
    When a view has more matches than the limit
    Then only that many are shown with a "Show more" button that loads the next batch
    And searching and bulk Select all still cover the full matching set

  Scenario: Text size
    When I choose Small, Normal, or Large
    Then the whole app is shown at that reading size

## Assumptions
- Preferences are remembered per user between visits (persistence is provided by
  the finished app; the prototype keeps them for the session).
