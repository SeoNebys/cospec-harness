Scenario ID: SCN-002
Title: Reject an unusable web address
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client tries to save text that is not a usable web address, the app
does not save anything. The save box shows an error state and a clear message
inviting a valid address (e.g. "nytimes.com" or "https://example.com/article").
Shorthand such as "nytimes.com" (no scheme) is accepted and later opens the real
site.

## Gherkin
Feature: Address validation on save

  Scenario: Refuse text that is not a usable web address
    Given the save box contains "this is not a link"
    When the client presses Save
    Then no link is added to the library
    And the save box shows an error message explaining a valid address is needed

  Scenario: Accept a scheme-less shorthand address
    Given the save box contains "nytimes.com"
    When the client presses Save
    Then the address is accepted as "https://nytimes.com/"
    And the saved card opens the real site

## Assumptions
- Validity requires a parseable http/https URL with a dotted hostname; entries
  with whitespace or without a dotted host are rejected.
