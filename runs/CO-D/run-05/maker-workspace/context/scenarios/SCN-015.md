Scenario ID: SCN-015
Title: Bring in my existing bookmarks in one go
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client hands over the file their browser produces when it "exports bookmarks" (the
bulk of their pile lives in the browser). They press one button and the whole pile arrives
— no per-link work (the client was firm: if it's one-at-a-time, they won't do it and the
whole product fails for them).

A PREVIEW step comes first and is required: before anything changes, the app shows, in
real numbers, exactly what it will do — nothing is committed until the client presses the
button. The client called this look-before-you-leap pause essential for handing over a pile
they care about.

The import honours all of these, shown in the preview and then done:
1. Keep the titles the client already gave their bookmarks (don't re-guess them).
2. Turn folders into labels — and:
   - match against existing labels IGNORING capitalisation (a "Work" folder joins the
     existing "work" label; never a "Work"/"work" split). Same protection as typing a
     label by hand.
   - keep BOTH levels of nested folders ("Recipes → Italian" → both "recipes" and
     "italian"); the outer level is never lost.
   - do NOT turn browser container wrappers ("Bookmarks bar", "Bookmarks Menu", "Other
     Bookmarks", etc.) into labels.
3. Preserve each bookmark's original save date so "oldest first" stays meaningful; do not
   stamp everything "today".
4. Skip duplicates using the same smart rule as pasting (ignores tracking junk; keeps the
   existing copy and its nicer title). Also merges same-URL entries appearing under
   multiple folders into one link carrying multiple labels.
5. Take hundreds+ in stride, all at once, with progress shown and no babysitting.

## Gherkin
Feature: Importing existing bookmarks

  Scenario: Preview before committing
    Given I have chosen my exported bookmarks file
    When the app reads it
    Then it shows what it will do and changes nothing until I confirm

  Scenario: Folders become labels, capitals merged, nesting kept
    Given a bookmark in folder "Recipes → Italian" and an existing label "recipes"
    When I import
    Then the bookmark carries labels "recipes" and "italian"
    And no separate "Recipes" label is created

  Scenario: Container folders are not labels
    Given bookmarks under a "Bookmarks bar" wrapper
    When I import
    Then "Bookmarks bar" does not become a label

  Scenario: Dates preserved
    Given imported bookmarks with original save dates
    When I sort oldest-first
    Then the earliest originals appear first, not everything dated today

  Scenario: Duplicates skipped
    Given a bookmark that matches one already saved (even with tracking junk)
    When I import
    Then it is skipped and my existing copy and title are kept

## Assumptions
- Input is the standard browser bookmarks export (Netscape HTML). Other sources (texted/
  emailed links, open tabs) are out of scope for this flow; browser file is the bulk.
