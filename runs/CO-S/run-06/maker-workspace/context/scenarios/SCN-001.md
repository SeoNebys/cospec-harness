Title: Quick-save a link with auto-filled details, optional tags and note
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The user pastes a web link and requests its details. The tool automatically
fills in a title and a short description for that link. The user can edit the
suggested title, optionally add one or more tags (each entered and shown as a
removable chip), and optionally add a short free-text note for context. On
saving, the bookmark appears at the top of the saved list showing its title,
link, note and tags. Editing the fetched title, tag chips, and the optional
note were all explicitly confirmed as the right amount of effort/interaction.

## Gherkin
Feature: Quick-save a bookmark

  Scenario: Auto-fill details for a pasted link
    Given the user is on the bookmark tool
    When the user pastes a valid web link and requests its details
    Then a suggested title and short description for that link are filled in
    And the suggested title is presented in an editable field

  Scenario: Save a bookmark with an edited title, tags and a note
    Given a link's details have been auto-filled
    When the user edits the title
    And adds one or more tags as removable chips
    And optionally adds a short note
    And saves the bookmark
    Then the bookmark appears at the top of the saved list
    And it shows its title, link, note and tags

  Scenario: Remove a tag before saving
    Given the user has added one or more tag chips
    When the user removes a tag chip
    Then that tag is no longer attached to the bookmark being saved

## Assumptions
- The fetched title is editable; the description is shown for context only.
- Tags and note are both optional.
- Newest saved bookmark appears at the top of the list.
- (Prototype) detail fetching is simulated; real metadata retrieval is a
  Phase 2 implementation concern, not a behaviour change.
