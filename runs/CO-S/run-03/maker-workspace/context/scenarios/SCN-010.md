Scenario ID: SCN-010
Title: Handle problems while saving a bookmark
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
An incomplete address is not saved, remains available for correction, and gets
a clear inline example of a complete address. If a valid link's page details
cannot be retrieved, the link is still saved with its website and address as
fallback information, a warning explains what happened, and it can be edited.
If the same complete address is already saved, no duplicate is created and the
existing bookmark is identified.

## Gherkin
Feature: Saving bookmarks safely

  Scenario: Reject an incomplete web address
    Given an incomplete web address is in the save box
    When the person tries to save it
    Then no bookmark is created
    And the address remains in the save box
    And an inline message shows an example of a complete address

  Scenario: Preserve a valid link when page details cannot be retrieved
    Given a valid web address is in the save box
    And its page details cannot be retrieved
    When the person saves it
    Then the bookmark is created
    And its website and address are used as fallback information
    And a warning explains that the title and summary were unavailable
    And the fallback details can be edited

  Scenario: Avoid creating a duplicate bookmark
    Given a complete web address is already saved
    When the person tries to save the same complete address again
    Then no second bookmark is created
    And the existing bookmark is identified

## Assumptions
- Duplicate detection compares complete saved addresses.
- Failure to retrieve page details does not make the address itself invalid.
- Save errors are shown beside the save box.
