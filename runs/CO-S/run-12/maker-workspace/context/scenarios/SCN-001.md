Scenario ID: SCN-001
Title: Save an enriched bookmark and reopen it
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client pastes a web address into a prominent save box. The app retrieves and previews the page image, icon, site name, title, and description. The client can edit the title and description before saving. Saving takes the client to the collection, where the new bookmark is immediately visible as a recognizable card. Selecting its title opens the original page in a new browser tab while leaving the collection open in the existing tab.

## Gherkin
Feature: Save and revisit a bookmark

  Scenario: Review and save automatically retrieved page details
    Given the personal bookmark collection is ready to accept a web address
    When the user submits a web address
    Then the app presents the retrieved page image, icon, site name, title, and description for review
    And the title and description can be edited before saving

  Scenario: See a newly saved bookmark in the collection
    Given retrieved bookmark details are being reviewed
    And the user has optionally edited the title or description
    When the user saves the bookmark
    Then the app displays the bookmark collection
    And the newly saved bookmark is immediately visible as a card
    And the card shows its page image, site identity, title, and description

  Scenario: Reopen a saved page without losing the collection
    Given a bookmark card is visible in the collection
    When the user selects the bookmark title
    Then the original page opens in a new browser tab
    And the bookmark collection remains open in the existing tab

## Assumptions
- The app is a personal desktop-oriented web app with no multi-user sign-in.
- Page details are reviewed before the bookmark is committed.
- The most recently saved bookmark is immediately visible after saving.
- The bookmark title is the control used to open the original page.
