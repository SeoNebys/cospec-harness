Scenario ID: SCN-006
Title: Saving when automatic details fail, and refusing an invalid link
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
If a link's details cannot be fetched automatically, the app does not block the
user: it tells them details couldn't be retrieved and lets them type their own
title (and optional note/tags) and save anyway. If the user saves without typing
a title, the link itself is kept as the title so nothing is lost. Conversely, a
completely invalid entry that is not a link is refused with a brief message and
is not saved.

## Gherkin
Feature: Robust saving

  Scenario: Details cannot be fetched automatically
    Given the user enters a valid link whose details cannot be retrieved
    When the user requests details
    Then the app indicates details could not be fetched
    And the user can enter a title and save the bookmark
    And if no title is entered, the link is used as the title

  Scenario: Refuse an invalid entry
    Given the user enters text that is not a valid link
    When the user requests details
    Then the app refuses with a brief message
    And no bookmark is saved

## Assumptions
- "Valid link" is judged by being parseable as a web address with a host.
- A failed auto-fill never prevents saving.
