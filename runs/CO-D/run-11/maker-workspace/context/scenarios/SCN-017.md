Scenario ID: SCN-017
Title: Save, reuse and delete named views (search + included/excluded tags)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client can save the current combination of search text plus included and
excluded tags as a named, reusable view. Saved views appear as named chips;
clicking one restores exactly that search + tag combination, and the chip is
highlighted while its filter is active. A view can be deleted from its chip.
Saved views persist across sessions. A view remembers ONLY the search text and
the included/excluded tags — not the read/archive status view, sort order, amount
shown, or text size, which remain separate display choices.

## Gherkin
Feature: Saved views

  Scenario: Save the current filter as a named view
    Given a search text and/or included/excluded tags are set
    When the client saves the current view under a name
    Then a named view is stored capturing the search text and included/excluded tags

  Scenario: Reuse a saved view
    Given a saved view
    When the client selects it
    Then the search text and included/excluded tags are restored exactly
    And the view's chip is highlighted while active

  Scenario: Delete a saved view
    When the client deletes a saved view
    Then it is removed from the list

  Scenario: Views persist
    Then saved views are available again when the client returns

  Scenario: Views exclude display preferences
    Then a saved view does not capture read/archive status, sort, amount shown or
         text size

## Assumptions
- A view stores only search text + included/excluded tags (client confirmed).
- Include/exclude come from the three-state tag control (see SCN-005).
