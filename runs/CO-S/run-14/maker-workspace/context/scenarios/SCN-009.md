Scenario ID: SCN-009
Title: Saving a link already saved takes the user to the existing bookmark to edit
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the user saves a link that is already saved (matching an existing
non-archived bookmark by its address, ignoring case, "www." and a trailing
slash), the app does **not** create a duplicate. It shows a gentle notice ("You've
already saved this") with a **"Show the one you saved"** action. Following that
action scrolls to and highlights the existing bookmark and **opens it in an
editable state** (Title, Description, tags and note editable) so the user can
update it.

## Gherkin
Feature: Duplicate link handling

  Scenario: Re-saving an existing link
    Given a bookmark with the same address already exists and is not archived
    When the user saves that link again
    Then no duplicate is created
    And a notice offers to show the existing bookmark

  Scenario: Jump to the existing bookmark to edit
    Given the duplicate notice is shown
    When the user chooses to show the existing bookmark
    Then the app highlights it
    And opens it with its title, description, tags and note editable

## Assumptions
- Address matching normalizes case, a leading "www." and a trailing slash.
- Duplicate detection considers non-archived bookmarks.
