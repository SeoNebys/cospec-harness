Title: Find links with live search and a precise query language
Type: Happy Path

## Approved behaviour
The client finds saved links with a single search box that filters the library
live as they type. By default, search looks across all of a link's information at
once: title, description, note, site, and tags. Matching words are highlighted in
the results, and a result count is shown. When nothing matches, a clear "no links
match" message is shown instead of an empty screen.

Casual and precise searching coexist in the same box:
- Plain words: multiple ordinary words must ALL match (narrowing).
- `#tag`: matches links carrying that exact tag.
- "quoted phrase": matches the exact phrase.
- AND / OR / NOT (typed in capitals) combine conditions; adjacent terms without an
  operator are combined with implicit AND.
- Parentheses ( ) group conditions for precedence.
- All matching is case-insensitive. Because operators must be capitalised,
  lowercase "and/or/not" are treated as ordinary search words.

## Gherkin
Feature: Search the library

  Scenario: Live keyword search across all fields
    Given the library contains several saved links
    When the client types ordinary words in the search box
    Then the list narrows live to links whose title, description, note, site, or
         tags contain all of the words
    And matching words are highlighted
    And the result count is shown

  Scenario: No results
    Given a search that matches no link
    Then a clear "no links match" message is shown

  Scenario: Tag filter with #tag
    When the client types "#<tag>"
    Then only links carrying that exact tag are shown

  Scenario: Exact phrase with quotes
    When the client types a quoted phrase
    Then only links containing that exact phrase are shown

  Scenario: Boolean combination with precedence
    When the client combines terms with capitalised AND, OR, NOT and parentheses
    Then results reflect the boolean expression with parentheses grouping first,
         then NOT, then AND, then OR

  Scenario: Case-insensitive matching
    When the client types a query in any capitalisation
    Then matching ignores letter case
    And lowercase and/or/not are treated as ordinary words, not operators

## Assumptions
- Default field scope is all fields (title, description, note, site, tags).
- Operator precedence: parentheses > NOT > AND > OR; implicit AND between adjacent
  terms.
- Highlighting covers plain-word and phrase terms (negated terms are not
  highlighted).
- Search operates over the client's own library only.
