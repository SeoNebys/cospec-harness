Scenario ID: SCN-006
Title: Complete a bookmark from the Read later list without deleting it
Type: Happy Path
Approval status: approved
Approval session: SESSION-006
Approval cycle: 1

## Approved behaviour

The client marks a bookmark using a clearly labeled Read later button. The button changes to show that the bookmark is in Read later, the sidebar count increases, and the bookmark remains in the main library. Choosing Read later in the sidebar opens a dedicated list with the waiting bookmark and count. Marking it as read removes it from that list and reduces the count without deleting it; returning to All bookmarks shows it alongside the other bookmarks, no longer flagged for later.

## Gherkin

Feature: Manage a Read later list

  Scenario: Mark a bookmark to read later
    Given a bookmark is in the main library and is not waiting to be read
    When the user chooses its labeled Read later action
    Then the action states that the bookmark is in Read later
    And the Read later sidebar count increases
    And the bookmark remains in the main library

  Scenario: Review bookmarks waiting to be read
    Given one bookmark is marked for later
    When the user chooses Read later in the sidebar
    Then the dedicated Read later view shows only that bookmark
    And it shows a count of one bookmark
    And the bookmark offers a Mark as read action

  Scenario: Mark a waiting bookmark as read without deleting it
    Given a bookmark is shown in the Read later view
    When the user marks it as read
    Then it is removed from the Read later view
    And the Read later sidebar count becomes zero
    And the view states that the bookmark remains in All bookmarks
    When the user returns to All bookmarks
    Then the bookmark is shown with the other bookmarks
    And it is no longer marked for later

## Assumptions

- Read later is always visible in the sidebar with its item count.
- The primary marking control is a clearly labeled button rather than an unlabeled icon or checkbox.
- Completing a Read later item clears its waiting flag and never deletes the bookmark.
