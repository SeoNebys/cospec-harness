Scenario ID: SCN-001
Title: Save a link; its real page title is fetched and can be renamed
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client enters or pastes a web link and saves it. The link immediately
appears at the top of the "Saved links" list (newest first). While the page's
real title is being looked up, the item shows an interim "Fetching page title…"
message; once fetched, the item displays the page's actual title above the web
address. The client can correct the title afterwards via a clear "Rename"
button: pressing it turns the title into an editable field, and confirming
("Save name") updates the displayed title. Being able to correct the title is
the most important part.

## Gherkin
Feature: Save a bookmark with its page title

  Scenario: Save a valid link
    Given the saved-links list
    When the client enters a valid web link and saves it
    Then the link appears immediately at the top of the list (newest first)
    And an interim "Fetching page title…" state is shown for that item

  Scenario: Page title is resolved after fetching
    Given a link has just been saved and its title is being fetched
    When the page title lookup completes
    Then the item displays the page's actual title above the web address

  Scenario: Rename a saved link's title
    Given a saved link showing a title
    When the client presses "Rename", edits the title, and confirms with "Save name"
    Then the item displays the client's corrected title
    And a non-empty title is required to replace the existing one

## Assumptions
- Newest saved link is shown at the top of the list.
- Each item shows a readable title above the raw web address.
- Renaming is offered via an explicit "Rename" button (not click-to-edit).
- An interim fetching state is acceptable because fetching a real title is not
  instant.
- The real application will fetch the actual page title over the network; the
  Phase 1 prototype simulated this lookup.
