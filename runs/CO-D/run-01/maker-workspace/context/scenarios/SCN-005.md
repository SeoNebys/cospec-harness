Scenario ID: SCN-005
Title: Find a saved link by searching across title, summary and address
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A single search box lets the client find saved links by typing whatever they
remember. The list filters live as they type — no button to press. The search
looks everywhere at once: the title, the auto-filled summary, and the web
address (later also the client's own notes and labels). The client does not
choose which field to search — one box looks everywhere.

Matching uses "word variations": searching a word also finds its close word
forms (e.g. "Rome" finds "Roman", "cook" finds "cooking"), but does not pull in
merely similar-starting but unrelated words (e.g. "Rome" does not match
"Romania"). Matched words are highlighted so the client can see why a link
turned up. When nothing matches, an empty-results message is shown.

## Gherkin
Feature: Search saved links

  Scenario: Search matches inside the summary, not only the title
    Given the client has a link whose summary mentions "empire" but whose title does not
    When the client types "empire" in the search box
    Then that link appears in the results
    And the matched word is highlighted

  Scenario: Live filtering as the client types
    Given the client has several saved links
    When the client types into the search box
    Then the list narrows to matching links without pressing a button
    And clearing the search restores the full list

  Scenario: Word-variation matching
    Given the client has a link whose summary says "Roman"
    When the client searches "Rome"
    Then that link appears (word forms are treated as the same idea)
    And a link about "Romania" does not appear (no over-matching)

  Scenario: No matches
    Given the client searches a word that appears nowhere
    Then an empty-results message is shown explaining search looks inside titles and summaries

## Assumptions
- One box searches title + summary + address together; the client cannot/need
  not choose a field. Notes and labels join the searchable text once they exist.
- Multi-word query: every typed word must be found (across any field).
- "Word variations" matching is the approved default (proper stemming in the
  real app; demo-tuned in the prototype).
- Boolean (exclude / OR) and quoted exact-phrase search are parked for later
  (see goals parking lot) and are NOT part of this scenario.
