Scenario ID: SCN-006
Title: Saving a link whose page name cannot be found
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the app cannot automatically determine a page's name for a saved link, it
does not block the save or show an error. It saves the link anyway, shows the
web address itself as a stand-in name, and marks the item with a small
"name not found — rename?" nudge so the user knows to give it their own name.
Renaming (via the pencil) works as normal; once the user renames it, the nudge
goes away.

## Gherkin
Feature: Fallback when a page name cannot be found

  Scenario: Save proceeds without a found name
    Given the user saves a link whose page name cannot be determined
    When the save completes
    Then the link is still saved
    And its web address is shown as a stand-in name
    And a "name not found — rename?" nudge is shown on the item

  Scenario: Renaming clears the nudge
    Given a saved link showing the "name not found" nudge
    When the user renames it to their own name
    Then the new name is shown
    And the nudge is no longer shown

## Assumptions
- A missing page name is never a hard error; the link is always kept.
- The stand-in name is the web address until the user renames it.
- The nudge is informational, prompting (not forcing) a rename.
