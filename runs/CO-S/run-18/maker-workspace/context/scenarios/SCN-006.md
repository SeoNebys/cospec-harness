Scenario ID: SCN-006
Title: Archive and restore a bookmark
Type: Happy Path
Approval status: approved
Approval session: SESSION-006
Approval cycle: 1

## Approved behaviour
Archive appears in each bookmark card's actions menu alongside permanent Delete. Choosing Archive removes the bookmark from All bookmarks and places it in a separate Archive section without deleting it. If it was also in Read later, it leaves that queue. From an archived card's menu, Restore to All bookmarks returns it to the main library only; Read later remains off unless the person chooses it again.

## Gherkin
Feature: Archiving bookmarks

  Scenario: Set a bookmark aside without deleting it
    Given a bookmark appears in All bookmarks
    When the person chooses Archive from its card menu
    Then the bookmark is removed from All bookmarks
    And it appears in the separate Archive section
    And it remains available to restore

  Scenario: Restore an archived bookmark
    Given a bookmark appears in the Archive section
    When the person chooses Restore to All bookmarks from its card menu
    Then the bookmark is removed from the Archive section
    And it appears in All bookmarks again

  Scenario: Archive a bookmark that is in Read later
    Given a bookmark appears in All bookmarks and Read later
    When the person archives it
    Then it is removed from All bookmarks
    And it is removed from Read later
    And it appears in Archive

  Scenario: Restore does not recreate reading-queue membership
    Given an archived bookmark was in Read later before it was archived
    When the person restores it
    Then it appears in All bookmarks
    And it does not appear in Read later
    And the person may choose to add it to Read later again

## Assumptions
- Archive and Delete are grouped in the bookmark card's actions menu.
- Archive is a reversible state, not a deletion.
- Section counts update when a bookmark moves.
- Archiving clears Read later status rather than pausing it.
