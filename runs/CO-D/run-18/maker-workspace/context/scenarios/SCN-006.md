Scenario ID: SCN-006
Title: Mark bookmarks to read later and view them separately
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each library card has a labeled “Read later” control. Selecting it changes the card's control to “Saved for later,” clearly showing the marked state. A “Read later” item in the library sidebar shows only marked bookmarks. Removing the mark while in that view immediately removes that bookmark from the view while leaving other marked bookmarks in place. The client chose the labeled control after comparing it with a heart-shaped icon, which was understood as a favorite rather than read-later action.

## Gherkin
Feature: Read-later bookmarks

  Scenario: Mark a bookmark to read later
    Given an unmarked bookmark is visible in the library
    When the user selects its "Read later" control
    Then the bookmark is marked to read later
    And its control reads "Saved for later"

  Scenario: View only read-later bookmarks
    Given the library contains marked and unmarked bookmarks
    When the user opens "Read later" from the library sidebar
    Then only the marked bookmarks are visible

  Scenario: Unmark a bookmark from the read-later view
    Given more than one bookmark is visible in the read-later view
    When the user selects "Saved for later" on one bookmark
    Then that bookmark is no longer marked
    And it immediately leaves the read-later view
    And the other marked bookmarks remain visible

## Assumptions
- Marking and unmarking are available directly on library cards.
- The approved interaction uses explicit text labels rather than an icon alone.
