Scenario ID: SCN-004
Title: Save a new bookmark quickly, in your own words, without duplicates
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Saving is deliberately light: the client's rule is "it has to stay out of my way
or I won't do it."

Adding:
- An "Add bookmark" affordance opens a small panel.
- The client pastes the link. The app **reads the page and fills in the title,
  the readable site name, and a description automatically** (each marked "filled
  in for you"). The client does not have to type them, though they can edit any.

Two voices in the description (the client's phrase: "two different voices"):
- The auto-filled **page summary** ("what it's about, from the page") is a
  starting point.
- A separate **"your own note"** field lets the client describe it in their own
  words (e.g. "the cake I'm making for Sarah's birthday").
- On the card, the page summary shows normally and the client's own note shows
  with a distinct coloured left border, so it reads as the client talking versus
  the page's own words.
- **The client's own note is included in search**, so they can find an item by
  their own words, not only the page's. (This was the make-or-break requirement:
  saving "sarah's birthday" as a note must let "sarah" find it.)

Labels at save time:
- The client types labels; existing labels are offered for reuse.
- **As the client types, suggestions narrow to their existing labels** (typing
  "rec" points at the existing "recipe"), to prevent splitting into near-
  duplicate piles like "recipe" vs "recipes".
- Labels are optional; saving can be as little as paste → Save.

No duplicates (the client's phrase: "keeps me out of the mess I started in"):
- If the client pastes a link they have **already saved**, the app recognises it
  and does **not** create a second copy. It says "you already saved this one"
  and offers to open the existing one instead.
- Duplicate identity ignores superficial differences in the link (protocol,
  "www.", trailing slash, letter case).

After saving, the new item appears at the top of the list and is immediately
searchable and roundup-able like everything else.

## Gherkin

Feature: Saving a bookmark

  Scenario: Save with almost no effort
    Given the client opens the add panel
    When the client pastes a link
    Then the title, readable site name and a page description fill in automatically
    And the client can save without typing any of them

  Scenario: Add a personal note in the client's own words
    When the client writes a personal note while saving
    Then the note is stored alongside the page's own summary
    And both are shown on the card, visually distinguished

  Scenario: Find an item by the client's own words
    Given a bookmark whose personal note contains "sarah's birthday"
    And whose page summary does not contain "sarah"
    When the client searches "sarah"
    Then that bookmark is found

  Scenario: Reuse an existing label instead of creating a near-duplicate
    Given the client already uses the label "recipe"
    When the client types "rec" in the label field
    Then the existing "recipe" label is suggested to reuse

  Scenario: Do not create a duplicate of an already-saved link
    Given the client has already saved a given link
    When the client pastes the same link again
    Then no second copy is created
    And the client is told they already saved it
    And the client is offered to open the existing one

  Scenario: Links that differ only superficially are the same
    Given a saved link "https://smittenkitchen.com/olive-oil-cake"
    When the client pastes "http://www.smittenkitchen.com/olive-oil-cake/"
    Then it is recognised as already saved

## Assumptions

- The app can read a page to auto-fill title/site/description. (Simulated in the
  prototype; the client approved the *behaviour* — "the details just appear".)
- Auto-filled fields are editable before saving.
- A bookmark's identity for duplicate detection is its normalised link.
- The personal note is part of what search matches (with title, page summary and
  readable site name, per SCN-001).
- Labels are optional and free-typed, with reuse suggestions that narrow as you type.
