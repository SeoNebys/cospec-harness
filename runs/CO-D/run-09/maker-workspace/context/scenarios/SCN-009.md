Scenario ID: SCN-009
Title: Focus the list by read status
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A filter with three views — "All", "To read", and "Finished" — lets the user focus
the list. Each view shows a count of how many links it contains. "To read" shows only
unfinished links; "Finished" shows only finished links; "All" shows both. The filter
works together with search: the counts and the list reflect the current search.
Finished links appear slightly dimmed in the "All" view so attention stays on what is
still pending, but appear at normal prominence in the "Finished" view so that view
does not look faded. Each view has a calm empty state (e.g. "Nothing left to read —
you're all caught up." for an empty "To read" view).

## Gherkin
Feature: Focusing by status

  Scenario: Focus on links still to read
    Given saved links with mixed read status
    When the user selects the "To read" view
    Then only unfinished links are shown
    And each view shows its count

  Scenario: Focus on finished links
    Given saved links with mixed read status
    When the user selects the "Finished" view
    Then only finished links are shown
    And they appear at normal prominence (not dimmed)

  Scenario: Finished links are de-emphasised in the All view
    Given the "All" view is selected
    When both finished and unfinished links are shown
    Then finished links appear slightly dimmed

  Scenario: Filter combines with search
    Given a search term is active
    When a status view is selected
    Then the counts and the shown links reflect both the search and the status view

  Scenario: Empty status view
    Given no links are in a selected view
    When that view is shown
    Then a calm view-specific empty message is shown

## Assumptions
- View counts reflect the current search results.
- The three views are mutually exclusive; "All" is the default.
