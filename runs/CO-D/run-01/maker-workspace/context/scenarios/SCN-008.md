Scenario ID: SCN-008
Title: Flag links to read later, see just that pile, and tick them off
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A link can be flagged "Read later" — a state separate from labels ("I mean to
read this" is not a topic). A flagged link shows a "To read" marker in the main
list and can still carry labels at the same time. A "To read" tab (with a live
count of the backlog) collapses the view to only the flagged links. Ticking a
link off in that view clears its flag and removes it from the pile, but keeps
the bookmark saved (read ≠ deleted); it rejoins the ordinary saved links. There
is deliberately no separate "already read" archive — the pile stays short and
holds only what is still waiting.

## Gherkin
Feature: Read-later pile

  Scenario: Flag a link to read later
    Given a saved link
    When the client presses "Read later" on it
    Then the link is marked "To read"
    And the "To read" count increases
    And the link keeps any labels it already has

  Scenario: See only the reading pile
    Given some links are flagged to read
    When the client opens the "To read" tab
    Then only flagged links are shown

  Scenario: Tick a link off once read
    Given a link is in the reading pile
    When the client ticks it off
    Then it leaves the reading pile and the count decreases
    And the link remains saved in the main list (not deleted)

  Scenario: Empty reading pile
    Given no links are flagged to read
    When the client opens the "To read" tab
    Then a friendly "nothing left to read" message is shown

## Assumptions
- "Read later" is an independent flag; a link can be both flagged and labeled.
- Ticking off clears the flag only; the bookmark is retained.
- No "already read" history/archive list (client explicitly declined).
