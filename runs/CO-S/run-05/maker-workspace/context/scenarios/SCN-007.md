Scenario ID: SCN-007
Title: Prevent duplicate saves and jump to the existing link
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
If the user saves a link that is already saved, no duplicate is created.
Instead the app tells the user it is already saved and takes them to the
existing entry in the list (highlighting it). The client valued being taken to
the existing one so they could adjust its tags if desired.

## Gherkin
Feature: Saving a link

  Scenario: Save a link that already exists
    Given a link is already saved
    When the user saves the same link again
    Then no duplicate entry is created
    And the app indicates it is already saved
    And the existing entry is highlighted/brought into view

## Assumptions
- Duplicate detection compares links ignoring scheme (http/https), a leading
  "www.", and a trailing slash. Query strings/fragments are treated as part of
  the link for now.
- CANDIDATE (not yet a feature): editing an existing link's tags. The client
  mentioned tweaking tags on the jumped-to entry as "a nice touch". Editing
  saved links is NOT in the current approved scope; flagged for a later cycle.
