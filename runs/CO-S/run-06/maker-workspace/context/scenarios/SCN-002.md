Scenario ID: SCN-002
Title: Find a saved bookmark by broad search and by tag filter
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The user can find previously saved bookmarks in two complementary ways. Typing
in a search box narrows the list as they type, matching across the bookmark's
title, note, link and tags together (broad matching, explicitly desired because
the user may remember a word from their note rather than the title). Separately,
tag chips can be clicked to filter the list to bookmarks carrying that tag, and
clicked again to clear the filter. The two methods can be used depending on what
the user remembers; both are wanted alongside each other. The list heading
reflects the number of results while searching/filtering.

## Gherkin
Feature: Find a saved bookmark

  Scenario: Narrow the list by typing a search term
    Given the user has saved bookmarks
    When the user types a term in the search box
    Then the list shows only bookmarks whose title, note, link or tags contain
         that term
    And the result count is reflected in the list heading

  Scenario: Filter the list by clicking a tag
    Given the user has saved bookmarks carrying tags
    When the user clicks a tag chip
    Then the list shows only bookmarks carrying that tag
    When the user clicks the same tag chip again
    Then the tag filter is cleared and the full list returns

  Scenario: Search matches a word remembered from the note
    Given a bookmark whose note contains a word not present in its title
    When the user searches for that word
    Then that bookmark appears in the results

## Assumptions
- Search matching is case-insensitive and matches partial substrings.
- Search term and active tag filter combine (both narrow the list).
- Ordering of results follows the saved-list order (newest first).
