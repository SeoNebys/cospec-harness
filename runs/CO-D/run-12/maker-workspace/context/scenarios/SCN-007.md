Scenario ID: SCN-007
Title: Assign and revise labels on a bookmark
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
While reviewing a new bookmark, the user can assign one or more labels beside its title and description. As the user types, existing matching labels are suggested with their usage counts so they can be confidently reused; the user can deliberately create a new label when needed. Selected labels are visibly attached before saving, appear on the saved card, and remain selected when the bookmark is opened for editing, where labels can be added or removed.

## Gherkin
Feature: Organizing bookmarks with labels

  Scenario: Reuse an existing label while saving
    Given an existing label is already used by saved bookmarks
    And the user is reviewing a new bookmark before saving
    When the user types part of the existing label name
    Then the matching label is suggested with its bookmark count
    When the user selects the suggestion and saves the bookmark
    Then the label is displayed on the saved bookmark card

  Scenario: Create a new label while saving
    Given the user is reviewing a new bookmark before saving
    When the user enters a label name that does not match an existing label
    And chooses to create it
    Then the new label is selected on the bookmark before saving

  Scenario: Revise labels later
    Given a saved bookmark carries one or more labels
    When the user opens the bookmark for editing
    Then its labels remain visibly selected in the review fields
    And the user can add or remove labels
    And saved changes are reflected on the bookmark card

## Assumptions
- The label control appears beside title and description during review and later editing.
- A selected label is shown as a removable tag before changes are saved.
- Existing-label suggestions show their current bookmark counts.
