Scenario ID: SCN-009
Title: Reject input that isn't a web link
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user tries to save text that isn't a plausible web link (e.g. "just some
random text", no domain), the app does not save it and shows a gentle inline note
explaining it doesn't look like a web link, with an example of the expected form.
The client confirmed refusing-and-explaining is the desired reaction. (Saving with
an empty box does nothing.)

## Gherkin
Feature: Validating the saved link

  Scenario: Refuse non-link text
    Given the user has typed text that is not a plausible web link
    When the user tries to save
    Then nothing is saved
    And a gentle note explains it doesn't look like a web link

  Scenario: Empty input does nothing
    Given the link box is empty
    When the user tries to save
    Then nothing happens

## Assumptions
- "Plausible web link" = parses as a URL with a dotted hostname; a missing
  scheme is tolerated (https:// is assumed). Precise validation strictness is an
  implementation detail; the behaviour (refuse + explain) is what's approved.
