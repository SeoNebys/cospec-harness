Scenario ID: SCN-012
Title: Import and export bookmarks (JSON backup and browser HTML)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
From Settings → Your data the client can export and import bookmarks.
- Export JSON: a complete backup of every bookmark with all fields (title, address,
  description, tags, note, reading state, archive state, saved-copy/Internet-Archive
  references, date added and last edited).
- Export HTML: a standard, browser-compatible bookmarks file as a flat list (no
  invented folders), preserving each bookmark's title, tags (TAGS attribute), and
  original date added (ADD_DATE).
- Import a file: accepts a JSON backup (restores the rich fields) or a browser HTML
  bookmarks file (creates bookmarks from its links, preserving title, tags, and date
  added). Import MERGES into the existing collection and SKIPS duplicates using the
  same "same link" rule; invalid links are skipped. It reports how many were imported
  and skipped. There is deliberately NO "replace everything" import (avoids
  accidental loss).

## Gherkin
Feature: Import and export

  Scenario: Export a full JSON backup
    When the client exports a backup
    Then a JSON file with every bookmark and all its fields is downloaded

  Scenario: Export browser-standard HTML
    When the client exports bookmarks as HTML
    Then a flat browser-compatible file is downloaded preserving title, tags and date added

  Scenario: Import merges and skips duplicates
    Given existing bookmarks
    When the client imports a JSON or HTML file
    Then new bookmarks are added and links already present are skipped
    And the client is told how many were imported and skipped
    And existing bookmarks are never wiped

  Scenario: HTML round-trip preserves title, tags, date added
    When bookmarks are exported to HTML and imported again elsewhere
    Then each bookmark's title, tags, and original date added are preserved

## Assumptions
- Merge-and-skip only (no replace-all), by client's choice, to avoid data loss.
- HTML is a flat tagged list rather than folders.
