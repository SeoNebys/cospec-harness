Scenario ID: SCN-008
Title: Save-time guards — duplicate link and non-link input
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Duplicate: when the user tries to save a link that is already saved (same address,
ignoring trailing slash / letter case), the app does NOT create a second copy.
It tells the user "you've already saved this link" and takes them to the existing
one (clears any active search/filter, scrolls to it and briefly highlights it).

Non-link input: when the user tries to save text that isn't a plausible web
address (e.g. "dinner ideas", empty input), the app does not create a broken
entry. It shows a clear message ("that doesn't look like a web address" /
"please paste a link first") and keeps what the user typed so they can fix it.

Bare domains without a scheme (e.g. "example.com/x") are accepted and treated as
https.

## Gherkin
Feature: Save-time guards

  Scenario: Duplicate link is not copied
    Given a link is already saved
    When the user saves the same address again
    Then no second copy is created
    And the user is told it is already saved and taken to the existing link

  Scenario: Non-link text is rejected with a message
    Given the user enters text that is not a web address
    When the user presses Save
    Then no entry is created
    And a clear message explains it isn't a web address
    And the entered text is preserved for correction

  Scenario: Empty input is rejected with a prompt
    When the user presses Save with an empty box
    Then a message asks them to paste a link first

## Assumptions
- Duplicate detection compares normalised addresses (trailing slash and case
  ignored). Finer normalisation (e.g. tracking parameters) is out of scope this cycle.
- A "plausible web address" = has a domain-like host with a dot.
