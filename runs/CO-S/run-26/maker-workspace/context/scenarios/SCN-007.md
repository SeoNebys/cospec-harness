Scenario ID: SCN-007
Title: Saving errors — malformed address, unreadable page, duplicate link
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Malformed address: if what the client tries to save is not a valid web address
(does not start with http:// or https://), saving is blocked and the field shows
an inline message ("That doesn't look like a web address…"). Nothing is saved.

Unreadable page: if the page's details cannot be read, the link is still saved
(the client does not lose it). Its card shows the best title/site the app could
work out from the address, plus a small warning that the details couldn't be read
and an invitation to fill in the title/tags/note themselves.

Duplicate link: if the client tries to save a link that is already saved, no
duplicate is created. Instead the app tells the client "You've already saved this
link — here it is" and points to the existing bookmark.

Feature: Saving errors and duplicates

  Scenario: Reject a malformed address
    Given the save field contains text that is not a valid http/https address
    When the client tries to save
    Then saving is blocked
    And an inline "that doesn't look like a web address" message is shown
    And nothing is added to the list

  Scenario: Save a link whose page details cannot be read
    Given a valid link whose page details cannot be read
    When the client saves it
    Then the link is still saved
    And its card shows the best available title and site
    And its card shows a warning that details could not be read, inviting manual entry

  Scenario: Prevent a duplicate save
    Given a link that is already saved
    When the client tries to save the same link again
    Then no duplicate is created
    And the app indicates the link is already saved and points to the existing one

## Assumptions
- Duplicate detection is by identical link (URL). (Confirmed by client behaviour.)
- Unreadable pages are kept rather than rejected. (Confirmed by client.)
- The invitation to "fill in the title/tags/note" implies a saved bookmark's
  fields can be edited — editing scope confirmed separately (see SCN-008).
