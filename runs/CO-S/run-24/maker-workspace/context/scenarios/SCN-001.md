Scenario ID: SCN-001
Title: Save a link and have its page details filled in automatically
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The user pastes a link into a single input and presses Save. Saving requires
only the link — no title typing. Immediately the link appears in the collection
in a brief "fetching" state, then settles into a card whose title, description,
and site icon are filled in automatically from the page (the user types none of
these).

Each card leads with icon + title + description (the primary recognition cues).
The web address and the saved date are shown together on one small, de-emphasised
line beneath. A place for tags sits under the description; when a link has no
tags it reads "No tags yet" (adding tags is explored separately). The newest
saved link appears at the top. A running count of saved links is shown above the
list.

## Gherkin
Feature: Save a link

  Scenario: Save a link with only the address
    Given the save box is empty
    When the user enters a link and presses Save
    Then the link is added to the collection
    And the input is cleared, ready for the next link
    And the new link appears at the top of the collection

  Scenario: Page details are filled in automatically
    Given the user has saved a link without typing a title
    When the link is added
    Then it first shows a temporary "fetching page info" state
    And it then displays an automatically obtained title, description and site icon
    And the user was not required to type the title, description or icon

  Scenario: Card layout emphasises recognition cues
    Given a saved link with its page details filled in
    Then the card shows the site icon, title and description prominently
    And the web address and saved date appear on one de-emphasised line beneath
    And a tag area appears under the description, reading "No tags yet" when empty

## Assumptions
- The application can obtain a page's title, description and icon from its
  address. (In the exploration prototype these were realistic stand-ins; the
  real application reads the actual page. Reliability/failure of this fetch is an
  edge case to explore.)
- A link missing some page details is an edge case to explore later.
- Newest-first ordering of the collection.
- Saving requires a non-empty address; format handling is an edge case to explore.
