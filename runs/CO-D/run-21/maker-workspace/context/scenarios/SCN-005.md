Scenario ID: SCN-005
Title: Prevent duplicate bookmarks for the same address
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user tries to save an address that is already saved, the app does not
create a second copy. It warns that the address is already saved, naming the
existing bookmark, and offers to open the existing bookmark for editing or to
cancel. "Same address" ignores domain capitalization, a leading "www.", and a
trailing slash, but a different path capitalization is treated as a genuinely
different page (and may be saved separately). There is no "keep both / force
duplicate" option.

## Gherkin
Feature: Duplicate prevention

  Scenario: Saving an equivalent address is recognized as a duplicate
    Given "https://developer.mozilla.org/en-US/docs/Web/JavaScript/Closures" is saved
    When the user tries to save "https://WWW.DEVELOPER.MOZILLA.ORG/en-US/docs/Web/JavaScript/Closures/"
    Then the app warns it is already saved and does not create a copy
    And it offers to open the existing bookmark for editing, or to cancel

  Scenario: A different path capitalization is a different page
    Given "https://developer.mozilla.org/en-US/docs/Web/JavaScript/Closures" is saved
    When the user saves "https://developer.mozilla.org/en-US/docs/Web/JavaScript/CLOSURES"
    Then it is saved as a separate bookmark

## Assumptions
- Equivalence: host case-insensitive, www-insensitive, trailing slash ignored;
  path is case-sensitive; query string preserved.
- No option to force-create a duplicate.
