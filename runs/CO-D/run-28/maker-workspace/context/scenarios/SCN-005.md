## Approved behaviour
The single search box also accepts a richer syntax so complex narrowing needs no
extra controls:
- #tag matches bookmarks carrying that tag.
- "quoted text" matches that exact phrase.
- AND, OR, NOT act as operators; parentheses group sub-expressions; adjacent
  terms are combined with implicit AND.
- AND/OR/NOT inside quotes are treated as ordinary words, not operators.
When a query is incomplete (e.g. an unbalanced parenthesis), the app shows a
gentle "search isn't complete yet" note and does not guess or silently show
wrong/empty results. Text terms found in results are highlighted.

## Gherkin
Feature: Advanced search syntax

  Scenario: Search by tag token
    When the client types #tagname
    Then only bookmarks carrying that tag are shown

  Scenario: Exact phrase search
    When the client types a "quoted phrase"
    Then only bookmarks containing that exact phrase are shown

  Scenario: Boolean combination with grouping
    When the client combines terms with AND, OR, NOT and parentheses
    Then results respect those operators and grouping

  Scenario: Operators in quotes are literal words
    When the client puts AND, OR, or NOT inside quotes
    Then they are searched as ordinary words, not treated as operators

  Scenario: Incomplete query feedback
    Given the client has typed an incomplete query such as an unbalanced parenthesis
    Then the app shows a "search isn't complete yet" note
    And it does not guess or silently show misleading results

## Assumptions
- Operator precedence: NOT before AND before OR; implicit AND between adjacent
  operands.
