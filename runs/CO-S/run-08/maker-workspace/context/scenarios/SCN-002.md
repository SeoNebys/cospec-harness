## Approved behaviour
Above the list is a single search box. As the client types, the list filters live
to show only links whose title, link address, or topic contains the typed text.
The matching text is highlighted within each result and a small "N links found"
count is shown. Searching "food" immediately surfaced the matching link. The
client confirmed that searching across title, address, and topic together in one
box feels natural, and that live filtering, highlighting, and the count are
helpful without getting in the way. This satisfies the primary "find a link
again" goal.

## Gherkin
Feature: Finding a link by searching

  Scenario: Search surfaces a matching link
    Given several links are saved
    When the client types "food" into the search box
    Then only links whose title, address, or topic contains "food" remain visible
    And the matching text is highlighted within each shown link
    And the number of matching links is displayed

  Scenario: Search with no matches
    Given several links are saved
    When the client types text that matches no link
    Then a "No links match" message is shown
    And it is worded differently from the empty (no links at all) state

  Scenario: Search updates live as the client types
    Given the search box is empty and all links are shown
    When the client types characters into the search box
    Then the visible list narrows after each character without a separate confirm action

## Assumptions
- Search matches title, link address, and topic together in one field.
- Matching is case-insensitive and matches partial text (substring).
- Results filter live on each keystroke (no Enter or button required).
- Matched links remain grouped under their topic headings.
