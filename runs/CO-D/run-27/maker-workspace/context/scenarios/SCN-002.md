Scenario ID: SCN-002
Title: Prevent duplicate saves using safe address matching
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client saves an address that safely matches an already-saved bookmark,
the app does not create a second copy. Instead it tells the client the link is
already saved and opens that existing bookmark for editing, highlighting it in
the list.

The "same link" rule normalises only what is safe: the scheme and host name are
compared case-insensitively, and a single trailing slash on the path is ignored.
Everything else is significant. Specifically these are treated as DIFFERENT links:
- http vs https
- www vs non-www (and any differing sub-address such as en. vs www.)
- differences in path capitalisation
- differences in query values, including a trailing slash inside a query value
  (e.g. ?ref=A vs ?ref=A/)

## Gherkin
Feature: Avoid duplicate bookmarks

  Scenario: Re-saving the same link opens the existing bookmark
    Given a bookmark for "https://site.com/Article?ref=A" is already saved
    When the client saves "https://SITE.com/Article/?ref=A"
    Then no new bookmark is created
    And the client is told the link is already saved
    And the existing bookmark opens for editing and is highlighted in the list

  Scenario: A path-capitalisation difference is a different page
    Given a bookmark for "https://site.com/Article?ref=A" is already saved
    When the client saves "https://site.com/article?ref=A"
    Then a new, separate bookmark is created

  Scenario: A different query value is a different page
    Given a bookmark for "https://site.com/Article?ref=A" is already saved
    When the client saves "https://site.com/Article?ref=A/"
    Then a new, separate bookmark is created

  Scenario: Scheme and www differences are different links
    Given a bookmark for "https://site.com/Article?ref=A" is already saved
    When the client saves "http://site.com/Article?ref=A"
    Then a new, separate bookmark is created
    When the client saves "https://www.site.com/Article?ref=A"
    Then a new, separate bookmark is created

## Assumptions
- Normalisation: lower-case scheme and host only; strip a single trailing slash on
  the path; preserve path and query exactly; a URL fragment is not used for matching.
