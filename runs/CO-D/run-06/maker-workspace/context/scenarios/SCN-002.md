Title: Add labels while saving, with type-ahead suggestions and no near-duplicates
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
During the pre-save review (SCN-001), the client can add one or more labels to the
bookmark. Adding labels works as follows:
- The client types into a label box; each confirmed label becomes a small removable
  pill. Removing a pill removes that label.
- As the client types, the app shows matching labels the client already has, so the
  client can tap an existing label rather than create a near-duplicate. Typing a
  fragment (e.g. "rec") surfaces existing matches (e.g. "recipes", "reference").
- Labels are matched case-insensitively and cannot be added twice. Typing "Recipes"
  when "recipes" already exists resolves to the existing "recipes" (with a gentle
  note) rather than creating a twin.
- If what the client types matches no existing label, a clear "+ create <label>"
  option lets them make a genuinely new one.
- "First spelling wins": the spelling used when a label is first created becomes its
  canonical name; later references file under that spelling regardless of the case
  typed.
Saved bookmarks display their labels as pills on the card.

## Gherkin
Feature: Labeling a bookmark at save time

  Scenario: Reuse an existing label via type-ahead
    Given the client is reviewing a bookmark before saving
    And the client already has a label "recipes"
    When the client types "rec" in the label box
    Then matching existing labels including "recipes" are suggested
    When the client taps "recipes"
    Then "recipes" is added as a label pill

  Scenario: Case-insensitive, no duplicate labels
    Given the client already has a label "recipes"
    When the client types "Recipes" and confirms
    Then no new label is created
    And the bookmark is filed under the existing "recipes"

  Scenario: Create a genuinely new label
    Given the client has no label matching "weeknight"
    When the client types "weeknight" and confirms the create option
    Then a new label "weeknight" is created with that spelling as its canonical name
    And it is added to the bookmark

  Scenario: Remove a label before saving
    Given the client has added a label pill
    When the client removes that pill
    Then the label is no longer attached to the bookmark

## Assumptions
- A label is a short free-text tag. No fixed vocabulary.
- Canonical spelling is fixed at first creation ("first spelling wins").
- Labels are shared across bookmarks (the same "recipes" is reused everywhere).
