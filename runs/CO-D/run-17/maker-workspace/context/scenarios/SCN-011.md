## Approved behaviour
A Sort control (a dropdown next to the search box) lets the client choose the
order of the shown links. Options: Newest first (default), Recently updated,
Oldest first, Title A–Z, Title Z–A. The chosen order applies to whatever is
currently shown — it combines with the active view (All / To read / Reference /
Archived), the search, and any active tag filters. "Recently updated" ranks by
the most recent meaningful activity on a link, which includes editing its fields,
changing its read/reference status, and archiving or restoring it. Sorting by
site is intentionally not offered. Remembering a default order is deferred to the
personal-preferences area; for now the order resets to Newest first each visit.

## Gherkin
Feature: Sorting

  Scenario: Reorder the shown links
    Given several links exist
    When the client chooses an order in the Sort control
    Then the shown links reorder accordingly

  Scenario: Sort combines with the current view and filters
    Given a view, search, or tag filter is active
    When the client changes the sort order
    Then only the currently shown links reorder, keeping the same membership

  Scenario: Recently updated reflects any meaningful activity
    Given a link that was added earlier
    When the client edits it, changes its read status, or archives/restores it
    And the order is "Recently updated"
    Then that link rises to the top

## Assumptions
- Sort options: Newest first (default), Recently updated, Oldest first,
  Title A–Z, Title Z–A. No sort-by-site.
- "Updated" is bumped by edits, read/reference status changes, and archive/restore.
- Default-order persistence belongs to the personal-preferences area (backlog #2).
