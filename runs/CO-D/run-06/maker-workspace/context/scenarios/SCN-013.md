Scenario ID: SCN-013
Title: Card visuals — site icon by the title and a compact page thumbnail for fast scanning
Type: Happy Path (promoted from non-functional backlog #1)
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark card carries light visuals so the list scans faster than a wall of text,
without pushing bookmarks apart.
- The site's icon (favicon) sits immediately before the title, where the eye already
  lands, so "where's this from" registers at the same moment as reading the title.
- A small page thumbnail sits on the RIGHT of the card. Text (title, description,
  labels) stays primary; the image is a visual anchor, not the focus.
- Cards stay compact so a good number fit on screen — chosen over a larger
  left-image "magazine" layout, because scanning a month's worth wants more on screen,
  not prettier-but-fewer.
- When a page has no available image, the card shows a calm placeholder tile (soft
  texture + the site's letter) rather than collapsing to a different shape. All cards
  keep the same shape so the list doesn't look ragged or jump while scrolling.

## Gherkin
Feature: Visual cards

  Scenario: A saved page with an image
    Given a bookmark whose page has an icon and a preview image
    Then its card shows the favicon before the title and a compact thumbnail on the right

  Scenario: A saved page without an image
    Given a bookmark whose page has no available preview image
    Then its card shows a calm placeholder tile in the same space
    And the card keeps the same shape as image-bearing cards

## Assumptions
- Favicon and page thumbnail are fetched while "reading the page" at save time
  (extends the metadata capture of SCN-001).
- Thumbnail size is the compact "A" layout (text-primary). Exact dimensions are a
  visual detail.
- Real assets could not be shown in the prototype (simulated with coloured
  stand-ins) — reason logged; layout/density was what was approved.
