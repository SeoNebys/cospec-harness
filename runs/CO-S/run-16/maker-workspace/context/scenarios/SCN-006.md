Scenario ID: SCN-006
Title: Archive a bookmark without deleting it
Type: Happy Path
Approval status: approved
Approval session: SESSION-006
Approval cycle: 1

## Approved behaviour

The client can archive a bookmark from its card. The bookmark leaves the main collection but remains whole in a dedicated Archive view, whose sidebar item shows the number of archived bookmarks. The application explicitly confirms that the bookmark was tucked away rather than deleted, so the client can safely set old links aside without losing them.

After comparing archive controls, the client selected the card's secondary-action menu because archiving is infrequent, the cards stay clean, and the extra deliberate step reduces accidental archiving.

## Gherkin

Feature: Set aside old bookmarks without losing them

  Scenario: Move a bookmark from the main collection to Archive
    Given a bookmark is present in the main collection
    When the user archives that bookmark from its card
    Then the bookmark is no longer shown in the main collection
    And the Archive count in the sidebar increases
    And the application confirms that the bookmark was archived rather than deleted
    When the user opens Archive from the sidebar
    Then the archived bookmark is shown with its saved details intact

## Assumptions

- Archiving changes the bookmark's collection state and does not create a copy.
- Archive is placed in the card's secondary-action menu rather than shown as a primary card button.
- The bookmark retains its title, source, preview, description, tags, and reading time.
- Restoring an archived bookmark is explored separately as an edge case.
