Type: Happy Path

## Approved behaviour

The search box accepts a small query language:
- `#tag` matches bookmarks carrying exactly that tag.
- A phrase in double quotes matches that exact phrase as ordinary text.
- Terms combine with AND, OR, NOT and parentheses for grouping.
- Adjacent terms with no operator combine as AND (both must match), so a plain
  word and a tag condition used together must both hold
  (e.g. `rome (#article OR #book)`).
- The operators AND, OR, NOT are case-insensitive when written bare
  (`or` behaves like `OR`); a boolean word placed in quotes (e.g. `"or"`) is
  treated as an ordinary search term, not an operator.
- All matching ignores capitalisation.
- A query that cannot be understood (e.g. unbalanced parentheses) shows a gentle
  "couldn't read that search" message rather than misbehaving.
All of the above still operate only within the current view (see SCN-008).

## Gherkin

Feature: Search bookmarks

  Scenario: Tag term
    When the user searches "#article"
    Then only bookmarks carrying exactly the "article" tag (in the current view) are shown

  Scenario: Exact phrase
    When the user searches a double-quoted phrase
    Then only bookmarks whose searched text contains that exact phrase are shown

  Scenario: Combined word and grouped tags with implicit AND
    When the user searches "rome (#article OR #book)"
    Then only bookmarks that contain "rome" AND carry the "article" OR "book" tag are shown

  Scenario: Exclusion
    When the user searches "rome NOT #book"
    Then rome-matching bookmarks that carry the "book" tag are excluded

  Scenario: Case-insensitive operators
    When the user writes operators in lower case (e.g. "rome (#article or #book)")
    Then the query behaves the same as with upper-case operators

  Scenario: Quoted operator is a literal term
    When the user searches '"or"'
    Then "or" is treated as an ordinary search word, not the OR operator

  Scenario: Unreadable query
    When the user enters a query with unbalanced quotes or parentheses
    Then a gentle "couldn't read that search" message is shown

## Assumptions
- Operator precedence: NOT before AND before OR; parentheses override.
- Adjacent terms imply AND.
