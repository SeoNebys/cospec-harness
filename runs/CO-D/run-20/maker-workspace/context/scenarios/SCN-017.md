Scenario ID: SCN-017
Title: Import and export a standard browser-bookmarks HTML file
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Export: produces a standard (Netscape) browser-bookmarks HTML file covering the
complete collection — including archived bookmarks — regardless of the current
search or view. Each entry retains its title, tags, and original saved date (and
notes). The file re-imports into browsers and back into the app.

Import: reads a standard browser-bookmarks HTML file and adds its links to the
existing collection. It retains titles, tags, and original saved dates where the
file provides them; when a saved date or tags are missing, it keeps what is
present and fills a missing date with today (no warning needed). Imported
bookmarks start as ordinary (not to-read, not archived). Duplicates — links that
match an already-saved page (same rule as saving) — are skipped, leaving existing
bookmarks untouched; a summary reports how many were added and skipped.

## Gherkin
Feature: Import / Export

  Scenario: Export the whole collection
    When the user exports
    Then a standard bookmarks HTML file is produced covering all bookmarks (including archived),
      retaining title, tags and original saved date, regardless of current search/view

  Scenario: Import adds and skips duplicates
    Given an existing collection
    When the user imports a standard bookmarks HTML file
    Then its links are added, retaining titles/tags/saved-dates where available
    And links already saved are skipped and existing bookmarks are unchanged
    And a summary reports the added and skipped counts

  Scenario: Missing fields on import
    Given an imported link with no saved date and no tags
    Then it is added with the available data and today's date, without a warning

## Assumptions
- Imported bookmarks start ordinary (not to-read, not archived).
- Duplicate detection reuses the saving rule (SCN-002).
