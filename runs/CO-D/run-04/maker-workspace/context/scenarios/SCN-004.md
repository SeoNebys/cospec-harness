Scenario ID: SCN-004
Title: Saving a link whose page name cannot be read
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the app cannot read a page's name/description at save time, the link is
still saved (never thrown away — the link itself is what the client cares about).
The card shows the website name in place of a title, plus a quiet note that the
name couldn't be read. The card remains fully clickable to open the page, and
the name/description can be filled in later by editing (see SCN-005).

## Gherkin
Feature: Unreadable page fallback

  Scenario: Auto-fetch of the page name fails
    Given the client saves a link
    When the app cannot read the page's name or description
    Then the link is still saved
    And the website name is shown in place of a title
    And a quiet note indicates the name couldn't be read
    And the card can still be clicked to open the page

## Assumptions
- Saving-anyway is preferred over refusing/warning loudly. (client confirmed)
