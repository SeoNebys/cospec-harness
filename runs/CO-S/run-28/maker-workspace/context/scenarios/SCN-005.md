Scenario ID: SCN-005
Title: Read-later queue — opt links in, view only the queue, mark read when done
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A top tab strip offers "All" and "To read", each showing a live count. The "To
read" view lists only links the user has flagged for reading.

Marking for reading is opt-in: in the All view each link shows a "☆ Read later"
toggle; clicking it puts the link in the reading queue ("★ In reading queue").
New links are NOT added to the queue automatically — the user chooses.

In the "To read" view each link shows a "✓ Mark read" action. Marking read removes
the link from the reading queue but keeps the bookmark in All (it is not deleted).

Tag browsing and search work within the reading queue (they narrow the queue, not
the whole library). An empty queue shows a clear message: "Your reading queue is
empty — mark a link 'Read later' and it will wait for you here."

## Gherkin
Feature: Read-later queue

  Scenario: View only the reading queue
    Given some links are flagged to read
    When the user opens the "To read" tab
    Then only flagged links are shown, and the tab shows their count

  Scenario: Add a link to the reading queue
    Given a link is not in the reading queue
    When the user clicks its "Read later" toggle
    Then the link appears in the "To read" view

  Scenario: New links are not auto-queued
    When the user saves a new link
    Then the link is not in the reading queue until the user opts it in

  Scenario: Mark a queued link as read
    Given a link is in the reading queue
    When the user clicks "Mark read"
    Then the link leaves the reading queue
    And the link still exists in the All view (not deleted)

  Scenario: Search and browse within the queue
    Given the "To read" view is active
    When the user applies a tag or a search
    Then only queued links matching that tag/search are shown

  Scenario: Empty reading queue
    Given no links are flagged to read
    When the user opens the "To read" tab
    Then a friendly empty-queue message is shown

## Assumptions
- "Read later" is a per-link flag; "mark read" clears that flag and does not delete.
- There is no separate "already read" archive view at this stage (read links simply
  remain in All). A distinct history of read items is not required.
