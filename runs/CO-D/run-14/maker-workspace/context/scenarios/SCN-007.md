Scenario ID: SCN-007
Title: Group and exclude exact tag criteria in a typed search
Type: Happy Path
Approval status: approved
Approval session: SESSION-007
Approval cycle: 1

## Approved behaviour
The client can write a single search expression using AND, OR, NOT, and parentheses. A `tag:name` criterion targets an exact tag rather than the same word in another bookmark field. Parentheses group alternatives, and NOT excludes matching bookmarks. The site shows a plain-language interpretation of the expression so the client can verify what it understood before trusting the results.

## Gherkin
Feature: Express precise bookmark searches

  Scenario: Group tag alternatives and exclude another tag
    Given the library contains bookmarks with varied searchable text and tags
    When the client searches for "Rome AND (tag:articles OR tag:books) AND NOT tag:travel"
    Then every result broadly matches "Rome"
    And every result has the exact tag "articles" or the exact tag "books"
    And no result has the exact tag "travel"

  Scenario: Do not confuse ordinary text with a tag criterion
    Given a bookmark contains the word "books" in its description
    But it does not have the tag "books"
    When the client searches using "tag:books"
    Then that bookmark is not included because of its description text

  Scenario: Show how a precise search was understood
    Given the client entered a search containing grouped, alternative, and excluded criteria
    When the search is applied
    Then a plain-language interpretation identifies the broad text, exact tags, grouping, and exclusion

## Assumptions
- `tag:name` is the notation for targeting a tag exactly.
- AND, OR, and NOT are available as search operators.
- Parentheses determine grouping.
- Search expressions and tag names are interpreted without regard to capitalization.
