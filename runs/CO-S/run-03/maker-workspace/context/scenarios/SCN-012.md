Scenario ID: SCN-012
Title: Group names are case-insensitive (no near-duplicate groups)
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Group names are treated case-insensitively. Typing "work" when a "Work" group
already exists attaches the existing group rather than creating a separate one; the
already-used spelling is kept. Leading/trailing whitespace is trimmed. The client
explicitly wanted this to avoid near-duplicate group clutter.

## Gherkin
Feature: Group name normalization

  Scenario: Differently-cased name reuses the existing group
    Given a group named "Work" is in use
    When the user adds a group typed as "work"
    Then the existing "Work" group is attached, not a new group

## Assumptions
- Matching is case-insensitive on the trimmed name; the first-seen spelling is the
  canonical display form.
