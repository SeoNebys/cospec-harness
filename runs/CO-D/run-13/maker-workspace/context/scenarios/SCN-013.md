Scenario ID: SCN-013
Title: Empty states and save error handling
Type: Edge Case (absence of data / errors)
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Empty states (calm, reassuring messages — client approved):
- New/empty library (All): "Your library is empty." with an invitation to paste
  a link.
- Unread empty: "Nothing unread — you're all caught up."
- Archived empty: "Nothing archived."
- No search results: "No <view> links match "<query>"."
- No links for a tag filter: a message naming the tag(s).

Save errors:
- Invalid address: pressing Save on something that is not a usable address shows
  a clear message ("That address doesn't look valid — please check it…") instead
  of a silent failure; nothing is saved.
- Unreachable / unreadable page: the page's details cannot be fetched, but the
  save is NOT lost — the review panel still opens, notes that details couldn't be
  read, and lets the client type the title/description themselves before adding.

The client approved the empty messages and the failed-save handling ("an
unreachable page should still be saveable with details I enter myself").

## Gherkin

Feature: Empty states and save errors

  Scenario: Empty library
    Given the library has no links
    Then a calm empty message invites the client to add one

  Scenario: No search results
    Given a search matches nothing in the current view
    Then a clear "no matches" message is shown

  Scenario: Invalid address
    When the client tries to save something that is not a usable address
    Then a clear message is shown and nothing is saved

  Scenario: Unreachable page still saveable
    Given a page's details cannot be fetched
    When the client saves its address
    Then the review panel opens noting details couldn't be read
    And the client can enter the title/description and add it

## Assumptions
- Detail retrieval failure is distinct from an invalid address: the former still
  allows a manual save (SCN-007), the latter is refused.
