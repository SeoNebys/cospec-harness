Scenario ID: SCN-001
Title: Quick-save a link with auto-filled page details
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The client pastes a web address into a single input at the top of the page and
presses Save. The new item appears immediately at the top of the list (newest
first) while its page details are being fetched, which the client found
reassuring. Within a moment the item auto-fills with:
- the page title,
- a short description,
- the site's own small icon (favicon), falling back cleanly to a letter badge
  when the real icon is unavailable or cannot load,
- a preview image when the page has one; when none is available the preview is
  simply omitted (icon still shown).

Duplicate handling: if the client pastes a link that is already saved, no second
copy is created. Instead the app brings up the existing bookmark by scrolling to
and highlighting it, with a message that it is already saved. Two addresses are
treated as the same link when they differ only by a `www.` prefix or a trailing
slash.

Client-added acceptance condition for the completed flow: surfacing the existing
duplicate must take the client directly into editing that bookmark, not merely
highlight it and leave the client to find an edit control. (Editing itself is
specified in a later scenario; this condition is carried forward to it.)

## Gherkin

Feature: Quick-save a link

  Scenario: Save a new link and have details auto-filled
    Given the bookmark list does not already contain the pasted address
    When the client pastes a web address and presses Save
    Then a new item appears immediately at the top of the list in a loading state
    And shortly after it shows the fetched title and short description
    And it shows the site's small icon, or a letter badge if the icon is unavailable
    And it shows a preview image if the page has one, otherwise no preview is shown

  Scenario: Preview image only when available
    Given a page that provides no preview image
    When the client saves that page
    Then the saved item shows the site icon but no preview image

  Scenario: Site icon fallback
    Given a site whose icon cannot be loaded
    When the item is displayed
    Then a letter badge is shown in place of the icon so the item never looks broken

  Scenario: Pasting an already-saved link does not create a duplicate
    Given the list already contains a bookmark for the pasted address
    When the client pastes that address and presses Save
    Then no second copy is created
    And the existing bookmark is scrolled to and highlighted with an "already saved" message
    And (completed flow) the client is taken directly into editing that bookmark

  Scenario: URL equivalence for duplicate detection
    Given a saved bookmark for "example.com"
    When the client pastes "www.example.com/" or "example.com/"
    Then it is treated as the same link and no duplicate is created

## Assumptions

- Newest-saved items appear at the top of the list.
- Each saved item shows title, description, web address, icon, and (when
  available) a preview image; no note/tags shown on this screen yet.
- Duplicate equivalence normalises the `www.` prefix and trailing slash.
- Page-detail lookup is simulated in the Phase 1 prototype.
