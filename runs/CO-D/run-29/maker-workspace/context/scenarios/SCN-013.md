Scenario ID: SCN-013
Title: Keep unusually long bookmark rows compact and expandable
Type: Edge Case
Approval status: approved
Approval session: SESSION-013
Approval cycle: 1

## Approved behaviour
An unusually long title and description are shortened in the collection so one bookmark does not dominate the screen. Four tags are shown initially, with a clear count for the remaining tags. Expanding that count reveals every saved tag. The complete title, description, and tags remain intact and available in the bookmark details.

## Gherkin
Feature: Scan bookmarks with unusually long content

  Scenario: Keep a long bookmark compact in the collection
    Given a bookmark has an unusually long title and description
    And it has more than four tags
    When the client views the collection
    Then the title and description occupy a limited number of lines
    And the first four tags are shown
    And the count of remaining tags is available to expand

  Scenario: Reveal all tags from a compact bookmark row
    Given a compact bookmark row has hidden remaining tags
    When the client expands the remaining-tag count
    Then every saved tag is shown
    And no bookmark content is discarded

  Scenario: Retain full content outside the compact collection row
    Given a bookmark is shortened in the collection
    When the client opens its details
    Then the complete title, description, and tags are available

## Assumptions
- The compact collection row shows four tags before the expansion control.
- Compacting affects presentation only and does not modify saved content.
