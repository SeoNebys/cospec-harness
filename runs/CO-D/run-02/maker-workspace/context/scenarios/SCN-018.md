Scenario ID: SCN-018
Title: Keep an automatic in-app copy of each page, with a manual Internet Archive option
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When a bookmark is saved, the app automatically keeps its own copy of the page —
a single self-contained page file — so preserving the page never depends on the
client remembering an extra step. If the address is a PDF, the app keeps the
actual PDF file rather than a page snapshot. The card shows a quiet "Saved copies"
line with a link to view the kept copy.

Separately and manually, the client may submit the page to the Internet Archive
(an outside service); once done, the card also links to the archive.org copy. The
two copies are independent. From the copies panel the client can refresh (remake)
the in-app copy, retry it if the automatic copy failed, and add the Internet
Archive copy at any time.

(In the Phase 1 prototype these copies are simulated; the real application performs
the fetching, storage, and Internet Archive submission.)

## Gherkin

Feature: Saved page copies

  Scenario: Automatic in-app copy on save
    When I save a bookmark
    Then the app automatically keeps an in-app copy of the page
    And for a PDF address it keeps the PDF file itself

  Scenario: View the kept copy
    Given a bookmark with an in-app copy
    Then its card links to view that copy

  Scenario: Manual Internet Archive submission
    Given a saved bookmark
    When I choose to save it to the Internet Archive
    Then the card also links to the archive.org copy
    And the in-app copy and the Internet Archive copy are independent

  Scenario: Refresh or retry the in-app copy
    Given the copies panel
    Then I can refresh the in-app copy, and retry it if the automatic copy failed

## Assumptions
- Whether to snapshot vs keep-PDF is decided by the address being a PDF.
- Internet Archive submission is always a deliberate, manual action.
- Storage/performance implications of keeping copies are a non-functional concern.
