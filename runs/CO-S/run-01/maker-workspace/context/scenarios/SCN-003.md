Scenario ID: SCN-003
Title: Organize and browse by tags; a link can carry multiple labels
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Links are organized with tags (labels), NOT single-home folders and NOT
automatic categorization. A single link can carry several tags, so it appears
when browsing under any of them (e.g. the Kyoto link is under both "Travel" and
"Japan"). A list of the client's tags is shown; clicking a tag filters the list
to links carrying that tag, with a heading/count reflecting the active tag.
Clicking a tag chip shown on a link also filters to that tag. Choosing "All"
clears the tag filter. Tag filtering and text search operate on the same list.

Decision rationale (client): multi-membership matters because much of what they
save fits more than one place; they prefer their own labels over automatic
filing they don't fully trust; a small amount of effort to add labels is
acceptable in exchange.

## Gherkin
Feature: Organizing and browsing by tags

  Scenario: A link belongs to multiple tags
    Given a saved link has been given more than one tag
    When the client browses by any one of those tags
    Then the link appears under each of its tags

  Scenario: Browse by clicking a tag
    Given the client has links carrying various tags
    When the client clicks a tag
    Then the list shows only links carrying that tag
    And the count/heading reflects the active tag

  Scenario: Clear the tag filter
    Given a tag filter is active
    When the client chooses "All"
    Then all saved links are shown again

## Assumptions
- Organization model is multi-tag (rejected: single-home folders; automatic
  categorization).
- Tag filter and text search apply to the same list together.
- (Pending exploration) HOW and WHEN a link gets its tags is not yet designed
  — see SCN-004 (to be explored next).
