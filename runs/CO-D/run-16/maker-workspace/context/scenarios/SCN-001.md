Scenario ID: SCN-001
Title: Save a link with auto-filled page details
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client pastes a web address into the Link field. The app automatically
fetches the page's details — title, a short description, a site icon, and a
preview image when the page provides one — and shows them in editable fields.
The client may adjust the title or description (and add tags/note) before
saving. Only the link is required; title/description are pre-filled but
optional to change. On saving, the bookmark appears at the top of the saved
list (newest first) showing its site icon, title, preview image, description,
and tags.

## Gherkin
Feature: Save a bookmark

  Scenario: Auto-filled details on pasting a link
    Given the client is on the bookmarks screen
    When the client enters a web address that is not already saved
    Then the app fetches the page's title, description, site icon, and preview
         image (when available)
    And it shows them in editable fields

  Scenario: Save with only a link required
    Given the auto-filled details are shown
    When the client optionally edits the title or description and saves
    Then a new bookmark is added at the top of the saved list
    And the saved item shows its site icon, title, preview image, description,
        and tags

  Scenario: Missing link blocks saving
    Given the Link field is empty
    When the client attempts to save
    Then no bookmark is created

## Assumptions
- New items appear newest-first at the top of the list (client approved).
- Title defaults to the link address if left empty.
- Real fetching of page metadata is required in implementation; the prototype
  simulated it with stand-in details.
