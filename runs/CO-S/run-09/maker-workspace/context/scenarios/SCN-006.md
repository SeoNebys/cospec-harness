Scenario ID: SCN-006
Title: Manage a reversible Read later shortlist
Type: Happy Path
Approval status: approved
Approval session: SESSION-006
Approval cycle: 1

## Approved behaviour
A labeled Read later action on a bookmark card marks the item for later, changes its visible status to Saved for later, confirms the action, and updates the Read later count in the main library sidebar. Opening that sidebar destination shows a dedicated shortlist containing the marked bookmark. Clicking Saved for later again removes the item from the shortlist, returns the count to zero, confirms the removal, and shows a clear empty state without deleting the bookmark from the main library.

## Gherkin
Feature: Read later shortlist

  Scenario: Mark a bookmark to read later
    Given the library contains a bookmark not currently marked for later
    When the person chooses the labeled Read later action
    Then the bookmark status changes to Saved for later
    And the app confirms that it was added to Read later
    And the Read later count increases by one

  Scenario: Open the Read later shortlist
    Given the person has marked a bookmark for later
    When the person opens Read later from the main library sidebar
    Then the app shows a dedicated Read later shortlist
    And the marked bookmark appears in that shortlist

  Scenario: Remove a bookmark from Read later
    Given the Read later shortlist contains one bookmark
    When the person chooses Saved for later on that bookmark
    Then the bookmark disappears from the Read later shortlist
    And the app confirms that it was removed from Read later
    And the Read later count returns to zero
    And the shortlist shows a clear empty state
    And the bookmark remains saved in the main library

## Assumptions
- Read later uses a labeled action rather than an icon-only control.
- Read later is part of the main library sidebar.
- The same status action toggles membership in the shortlist.
- Removing an item from Read later does not delete the bookmark.
