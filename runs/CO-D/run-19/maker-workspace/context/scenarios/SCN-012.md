Scenario ID: SCN-012
Title: Ignore known URL noise when preventing duplicates
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Duplicate checking treats section jumps and recognized tracking tags as noise, so a dressed-up version of an already-saved address returns to the existing highlighted card and opens its editor. Address details that can genuinely select different content remain significant and may be saved as a separate bookmark.

## Gherkin
Feature: Recognise the same page despite harmless address noise

  Scenario: Re-save a page with tracking tags and a section jump
    Given the base page address is already saved
    When the client saves the same address with recognized tracking tags and a section jump
    Then no duplicate bookmark is created
    And the existing card is brought into view, highlighted, and opened for editing

  Scenario: Save addresses whose differing details can select different content
    Given one page address is already saved
    When the client saves an address whose differing address details are not recognized as tracking noise or a section jump
    Then the address remains eligible to be saved as a distinct bookmark

## Assumptions
- Recognized tracking tags use a conservative allowlist rather than treating every value after a question mark as noise.
- URL fragments are ignored for duplicate identity.
