Scenario ID: SCN-009
Title: Save-time validation and auto-fill failure
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the entered text is not a valid web link (does not start with http:// or
https://), the Save button stays disabled and, after the user leaves the link
field, a short message explains why ("That doesn't look like a web link — it
should start with http:// or https://"). When the link is valid but its details
cannot be fetched automatically, the app shows a note ("Couldn't fetch details
for this link — type a title yourself, then save."), leaves the title/description
for the user to fill in, and still lets the user save the bookmark. A failed
automatic lookup never prevents saving the link.

## Gherkin
Feature: Robust saving

  Scenario: Invalid link is explained and blocked
    Given the user types text that is not a valid web link
    When the user leaves the link field
    Then a short message explains the link is not valid
    And the Save button remains disabled

  Scenario: Auto-fill failure still allows saving
    Given the user enters a valid link whose details cannot be fetched
    Then a note invites the user to type a title
    And the user can save the bookmark with a manually entered title

## Assumptions
- Validity check: the link must start with http:// or https://.
- Auto-fill is a convenience; its failure never blocks saving.
