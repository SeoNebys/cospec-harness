Scenario ID: SCN-008
Title: Saving a link whose page can't be read — never lose it
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the app cannot read a pasted page (dead link, blocking site, dropped connection), it
NEVER refuses to save and NEVER silently drops the link. It saves the link anyway, using
the web address itself as a stand-in title, marks it clearly with a "⚠️ Couldn't read this
page automatically — it's saved, give it a name so you'll find it" flag, and offers a
"Name it" button. The client called this the single most important call in the app: "the
one thing that would break my trust completely is pasting a link, walking away thinking
it's safe, and finding it silently vanished."

Approved bonus (optional): quietly retry once before giving up — but if it still fails,
keep the link. Never refuse to save.

## Gherkin
Feature: Saving when the page cannot be read

  Scenario: Page can't be read
    Given the page for a pasted link cannot be read
    When I save it
    Then the link is still saved
    And its address stands in as the title
    And it is flagged as needing a name with a "Name it" action

  Scenario: Never refuse to save
    Given repeated failure to read a page
    When I save the link
    Then the link is kept, not rejected

## Assumptions
- Fallback title is the web address; the client can rename via the edit/name flow.
- A single quiet background retry is acceptable but must not delay or block the save if it
  also fails.
