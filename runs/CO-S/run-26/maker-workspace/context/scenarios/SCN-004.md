Scenario ID: SCN-004
Title: Separate "to read" from "finished" and mark a bookmark's reading status
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Every bookmark has a reading status that is always exactly one of "to read" or
"finished", shown as a status pill on the card.

The client changes a bookmark's status with a single button on the card that
flips it between "to read" and "finished". After flipping, the bookmark's pill
updates and it moves to the corresponding group.

The client separates the two using switchable filter tabs at the top: "All",
"To read", "Finished", each showing a live count. Selecting a tab shows only
that group as a single focused list (one list at a time). This keeps the list
focused when there are many bookmarks.

Search and tag browsing (SCN-003) continue to work and apply within the selected
tab; the tab counts reflect the current search/tag filters.

Chosen interaction (from a 2-variant comparison): switchable status tabs — the
client selected this over two-groups-stacked-on-one-page.

## Gherkin

Feature: Reading status (to read / finished)

  Scenario: A bookmark always has one reading status
    Given a saved bookmark
    Then it is shown as either "to read" or "finished", never both and never neither

  Scenario: Flip status with one click
    Given a bookmark currently marked "to read"
    When the client clicks its status button
    Then the bookmark becomes "finished"
    And its status pill updates accordingly
    When the client clicks the status button again
    Then the bookmark becomes "to read" again

  Scenario: Focus on one status group via tabs
    Given bookmarks with a mix of statuses
    When the client selects the "To read" tab
    Then only "to read" bookmarks are listed
    When the client selects the "Finished" tab
    Then only "finished" bookmarks are listed
    When the client selects the "All" tab
    Then bookmarks of both statuses are listed
    And each tab shows a count of its bookmarks

  Scenario: Status tabs combine with search and tag filters
    Given a search term and/or an active tag filter
    When the client selects a status tab
    Then only bookmarks matching the search/tag filter AND that status are listed
    And the tab counts reflect the current search/tag filters

## Assumptions

- A bookmark's status is binary: exactly one of "to read" / "finished".
  (Confirmed by client.)
- Status is changed by a single toggle button per card. (Confirmed by client.)
- Separation uses switchable tabs (All / To read / Finished) with counts,
  showing one list at a time. (Chosen by client over grouped sections.)
- A newly saved bookmark defaults to "to read". (Confirmed by client during
  edge-case exploration.)
