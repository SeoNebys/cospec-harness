## Approved behaviour
Read-later is a lens over the same library, not a separate place. A view switch
at the top offers "Everything" and "To read" (with a live count of what's
waiting). "To read" shows only the links the client has flagged, drawn from the
same library; the search box and Topics bar still work inside the lens (e.g.
narrow to "just the work things I still need to read").

A link only enters the pile if the client flags it ("Read later") — nothing is
auto-added on save, because much of what the client saves is reference/kept
material, not reading. This opt-in is essential to the pile staying meaningful.

Status is tracked in three honest states: not-in-pile, "to read" (unread), and
"read" (dealt with). A dealt-with link keeps a quiet "✓ Read" badge and a "Read
again?" way back, so the client can always tell "still to read" apart from
"already handled" — one of the three original goals.

## Gherkin
Feature: Read-later lens

  Scenario: Flag a link to read later (opt-in)
    Given a saved link not in the pile
    When the client flags it "Read later"
    Then it gains an unread state and the To-read count increases
    And newly saved links are never auto-added to the pile

  Scenario: The To-read lens over the same library
    When the client switches to "To read"
    Then only unread links are shown
    And search and topic filters still apply within the lens

  Scenario: Dealt-with is distinguished from never-read
    Given a link marked read
    Then it shows a quiet "✓ Read" badge with a "Read again?" option
    And a link never flagged shows no such badge

## Assumptions
- Opt-in; no auto-add on save. (client confirmed)
- Three states; "read" badge kept but visually quiet. (client confirmed)
- Lens composes with search + topics. (client confirmed)
