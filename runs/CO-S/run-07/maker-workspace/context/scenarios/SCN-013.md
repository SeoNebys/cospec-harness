Scenario ID: SCN-013
Title: Prevent duplicate bookmarks for the same address
Type: Edge Case
Approval status: approved
Approval session: SESSION-013
Approval cycle: 1

## Approved behaviour
When the user tries to save an address that is already in the library, the app creates no second copy. It clearly explains that the link already exists and offers to show the existing bookmark so the user can review or update it. Addresses that differ only by a trailing slash count as the same link; genuinely different page addresses remain separate.

## Gherkin
Feature: Avoid duplicate bookmarks

  Scenario Outline: Detect an existing bookmark address
    Given the library already contains "https://example.com/page"
    And the user prepares <address> as a new bookmark
    When the user tries to save it
    Then no second bookmark is created
    And the app explains that the address already exists
    And the app offers to show the existing bookmark

    Examples:
      | address                     |
      | "https://example.com/page"  |
      | "https://example.com/page/" |

  Scenario: Keep genuinely different page addresses separate
    Given the library contains "https://example.com/page-one"
    When the user saves "https://example.com/page-two"
    Then a separate bookmark is created

## Assumptions
- Duplicate detection ignores one trailing slash.
- Other meaningful address differences identify separate pages.
- The existing bookmark can be edited through SCN-009.
