Scenario ID: SCN-003
Title: Find bookmarks via live search with tags, phrases, and boolean queries
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A single search box retrieves saved bookmarks. It filters the list live as the
user types (no need to submit). Matching is case-insensitive and searches across
all captured fields together: title, description, personal note, tags, site name,
and the full web address.

Query language (all approved):
- Bare words: substring match across all fields.
- Multiple words are combined (implicit AND).
- "#tag": matches specifically a tag with that name (not the word elsewhere).
- Clicking a tag pill on any result filters to that tag (equivalent to "#tag").
- "\"exact phrase\"": matches the quoted words only when they appear together.
- Boolean operators AND, OR, NOT and parentheses ( ) combine and group
  conditions, e.g. rome (#article OR #book).
- Operator words act as operators only when unquoted; quoting one (e.g. "OR")
  searches for the literal word instead.

Feedback and result presentation:
- A count line shows "N of M bookmarks match <query>" with a clear control.
- Each result highlights what the query actually matched: free-text (word/
  phrase) terms are highlighted where they occur in the text; a tag pill is
  highlighted only when it is the tag a "#tag" condition asked for (or contains
  a free-text term). Highlighting does not shade unrelated substrings.
- A small "matched in <fields>" line shows where each result matched.
- When nothing matches, a plain honest empty state is shown (no fabricated
  results).

## Gherkin

Feature: Search and retrieve bookmarks

  Scenario: Live case-insensitive search across all fields
    Given several saved bookmarks
    When the user types a word into the search box
    Then the list narrows live to bookmarks containing that word (any case)
      in the title, description, note, tags, site or full web address

  Scenario: Tag-specific search
    When the user searches "#focus"
    Then only bookmarks tagged "focus" are shown

  Scenario: Click a tag to filter
    When the user clicks a tag pill on a result
    Then the search becomes that tag and only bookmarks with that tag are shown

  Scenario: Exact phrase
    When the user searches "\"read later\""
    Then only bookmarks where those words appear together are shown

  Scenario: Boolean with grouping
    When the user searches "rome (#article OR #book)"
    Then bookmarks matching rome AND (tag article OR tag book) are shown

  Scenario: Negation
    When the user searches "rome NOT #book"
    Then rome bookmarks are shown except those tagged book

  Scenario: Quoted operator is a literal word
    When the user searches "\"OR\""
    Then results are those containing the literal text "or", and OR is not treated as an operator

  Scenario: Accurate match highlighting
    Given a query with a "#tag" condition and free-text terms
    Then only the matching tag pill and the actual text occurrences are highlighted
    And unrelated substrings are not highlighted

## Assumptions

- "#tag" matches a tag by exact name (case-insensitive).
- Implicit combination of adjacent terms is AND.
- Operator precedence: NOT binds tightest, then AND, then OR; parentheses override.
- The sample bookmark set used in the prototype was chosen by the facilitator
  only to demonstrate behaviour; it is not part of the requirement.
