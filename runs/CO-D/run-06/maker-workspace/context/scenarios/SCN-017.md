## Approved behaviour
A filter the client uses often can be saved and re-applied in one click.
- Once a filter is built, a "☆ Save this view" button appears in the filter bar (it
  is absent on a plain unfiltered list — same "hidden until relevant" principle as the
  exclude marker and all/any switch). The client names it (a name is suggested from
  the filter).
- Saved views live in a "Your views" list in the sidebar, directly above the labels —
  where the eye already goes to filter.
- Clicking a saved view snaps the entire filter back into place.
- A saved view captures the COMPLETE filter: included labels, the all/any mode,
  excluded labels, AND any typed search word. Clicking it restores words and labels
  together — not just the labels.
- A saved view is a LIVE filter: it re-runs against the current collection, always
  showing current matches, not a frozen snapshot.
- Each saved view can be removed when no longer used.

## Gherkin
Feature: Saved views

  Scenario: Save the current filter as a view
    Given the client has built a filter (labels and/or a search word)
    When the client chooses "Save this view" and names it
    Then it appears under "Your views" in the sidebar

  Scenario: A view remembers labels and the search word
    Given a saved view built from "recipes" + "dinner" + the word "chicken"
    When the client clicks that view
    Then the labels "recipes" and "dinner" and the search word "chicken" are all restored

  Scenario: A view is a live filter
    Given a saved view exists
    When the underlying bookmarks change
    And the client clicks the view
    Then it shows the current bookmarks that match, not a snapshot

## Assumptions
- Views store filter criteria, not a fixed list of bookmarks.
- Sort order is a separate control; a view restores filters (sort remains the user's
  current choice) unless later decided otherwise.
