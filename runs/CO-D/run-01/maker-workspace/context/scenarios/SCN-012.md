Scenario ID: SCN-012
Title: Delete a link the client no longer wants
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
From the Edit space, the client can delete a link they no longer want. Because
deleting is rare, permanent, and also discards the saved copy, it asks for a
single, clearly-worded confirmation ("Delete for good? Your saved copy goes
too.") with a confirm and a cancel. This one speed bump is welcome specifically
because the action is destructive — in contrast to the everyday duplicate-save
case (SCN-004), which must NOT nag. On confirmation the link is removed from the
list and a brief note confirms the deletion.

## Gherkin
Feature: Delete a link

  Scenario: Delete with confirmation
    Given the client opens a link's Edit space
    When the client chooses Delete and confirms
    Then the link and its saved copy are removed from the list
    And a brief confirmation note is shown

  Scenario: Cancel a deletion
    Given the client chose Delete
    When the client chooses to keep it instead
    Then nothing is deleted

## Assumptions
- Deletion is permanent and also removes the saved copy (stated in the prompt).
- Exactly one confirmation step; welcome here because destructive (contrast
  SCN-004 no-nag).
