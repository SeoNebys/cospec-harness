Scenario ID: SCN-003
Title: Find a link by searching across all of its details
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A search box above the saved-links list lets the client type words to find a
link. Searching matches against all of a link's details together — its title,
the "why" note, its tags, and its web address — so the client need not remember
where the word appeared. The list narrows as the client types. When multiple
words are typed, only links containing all of the words are shown (narrowing, not
"any"). Search works together with the tag filter: when a tag filter is active,
search narrows within the links carrying that tag. When nothing matches, a clear
"no links match" message is shown; the count line reflects the active search and
tag filter.

## Gherkin
Feature: Searching saved links

  Scenario: Search across all fields of a link
    Given several links are saved with various titles, notes, tags and addresses
    When the client types a word that appears in any of those details
    Then the list shows only links whose title, note, tags or address contain the word

  Scenario: All typed words must match
    Given the client has typed two words in the search box
    Then only links containing both words are shown

  Scenario: Search combines with an active tag filter
    Given the list is filtered by a tag
    When the client types a search word
    Then only links carrying that tag and matching the word are shown

  Scenario: No matches
    Given the client types a word that appears in no saved link
    Then a "no links match" message is shown
    And the count reflects zero matching links

## Assumptions
- Search matches title, note, tags, and address together.
- Multiple words are AND-combined (all must be present).
- Search narrows within any active tag filter.
- Matching is case-insensitive substring matching.
