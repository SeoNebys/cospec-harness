Scenario ID: SCN-004
Title: Find a saved link by searching a word or two
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A search box lets the user type a word or two; the list filters live as the user
types, with no button to press. Search matches against the link's title, its web
address, and its group names. Search spans ALL saved bookmarks regardless of which
group is currently selected — the client confirmed this is right because "half the
time I won't remember which group I put something in anyway". The result count
reflects the number of matches.

## Gherkin
Feature: Searching bookmarks

  Scenario: Filter as you type
    Given the user has saved bookmarks
    When the user types a word into the search box
    Then the list immediately shows only bookmarks matching that word

  Scenario: Search matches title, address, or group name
    Given a bookmark whose title, address, or group name contains the typed word
    When the user searches for that word
    Then that bookmark is shown

  Scenario: Search spans all bookmarks regardless of selected group
    Given the user is currently viewing a single group
    When the user searches for a word matching a bookmark in a different group
    Then that bookmark is still shown

## Assumptions
- Live (as-you-type) filtering, no submit button.
- Case-insensitive substring match (exact matching rules revisited in edge cases).
- Search overrides the current group view while a query is present.
