Scenario ID: SCN-010
Title: Graceful handling of missing data and invalid input
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Covers absence-of-data and invalid-input situations confirmed with the client:

- Invalid link: if the client tries to save something that is not a valid web
  address, saving is blocked with a gentle message ("That doesn't look like a
  valid link") and nothing is added. Empty input is likewise blocked ("Please
  paste a link first").
- Details can't be fetched: if the page's details can't be retrieved, the link is
  still saved (never lost), using a best-guess name derived from the address and
  no description; the client can then edit the title/description themselves
  (SCN-009).
- Empty welcome state: before any links exist, the screen shows a friendly "No
  links saved yet — paste a link above to add your first bookmark" prompt, with
  no search box or tabs shown yet.
- Empty search results: a search matching nothing shows a clear "No matching
  links" message (naming what was searched) rather than a blank screen.
- Empty tab states: the "To read" and "Archived" tabs, when empty, show their own
  plain-language empty messages.

## Gherkin
Feature: Missing data and invalid input

  Scenario: Block saving invalid input
    Given the save box contains text that is not a valid web address
    When the client presses Save
    Then nothing is saved
    And a message says the input does not look like a valid link

  Scenario: Save a link even when its details cannot be fetched
    Given the page details for a valid link cannot be retrieved
    When the client saves it
    Then the link is still saved with a best-guess name and no description
    And the client can edit its title and description afterwards

  Scenario: Empty welcome state for a brand-new user
    Given there are no saved links
    Then a welcome prompt invites saving the first link
    And no search box or tabs are shown

  Scenario: Empty search results
    Given the client searches for text that matches no link in the current tab
    Then a "no matching links" message is shown naming the searched text

  Scenario: Empty reading list / archive
    Given the "To read" or "Archived" tab has no links
    When the client opens that tab
    Then a plain-language empty message is shown

## Assumptions
- A valid link must have a host containing a dot; otherwise it is rejected.
- "Never lose the link" takes priority over having complete auto-filled details.
