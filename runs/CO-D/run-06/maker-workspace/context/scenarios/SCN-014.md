Scenario ID: SCN-014
Title: Saving stays forgiving — lenient link acceptance, graceful auto-fill failure, link is the only required thing
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The save flow degrades gracefully; the link is sacred, everything else is convenience.

Lenient link acceptance:
- A pasted address without "http(s)://" (e.g. "smittenkitchen.com/beans") is accepted;
  the app adds the missing scheme itself. The client should never have to type the
  formal address.
- Only input that genuinely isn't a link (a plain sentence, spaces, no domain) is
  blocked, with a RED inline message ("That doesn't look like a web address…"). No
  fetch, no junk bookmark.

Graceful auto-fill failure:
- When the page can't be read (unreachable/blocked/timeout), saving still proceeds.
  An AMBER notice ("Couldn't read this page automatically — you can still save it and
  fill in the details yourself") appears with a "Try again", and the editable fields
  open so the client can fill in what they want.
- "I can always stash the link" is preserved even when auto-fill fails.

The link is the only required thing:
- Title is NOT required. Saving with a blank title stores the bookmark with the web
  address as its name; the client can rename later (editing exists, SCN-006). This
  avoids friction at exactly the hurried moment auto-fill already failed.

Tone distinction (confirmed): RED = truly can't proceed (not a link); AMBER = "no
worries, carry on" (auto-fill failed but saving is fine).

## Gherkin
Feature: Forgiving save flow

  Scenario: Accept a link without a scheme
    When the client Adds "smittenkitchen.com/beans"
    Then it is accepted and treated as "https://smittenkitchen.com/beans"

  Scenario: Block input that is not a link
    When the client Adds "how to cook white beans"
    Then the save is blocked with a red "that doesn't look like a web address" message
    And no fetch or bookmark is created

  Scenario: Auto-fill fails but saving still works
    Given a link whose page cannot be read
    When the client Adds it
    Then an amber notice explains it and offers "Try again"
    And the editable fields open
    When the client saves
    Then the bookmark is saved

  Scenario: Title is optional
    Given the editable fields are open
    When the client saves with an empty title
    Then the bookmark is saved with the web address as its name

## Assumptions
- Scheme defaulting is to https.
- "Not a link" heuristic: no whitespace and a plausible dotted hostname.
