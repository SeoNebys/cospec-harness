Scenario ID: SCN-007
Title: Maintain a focused Read later list
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark card has a one-click clock action for adding it to Read later. Marking it changes the control's state, briefly confirms the action, and raises the Read later count in the sidebar. Read later is also available as a secondary switch inside bookmark details. Clicking Read later in the sidebar shows only marked bookmarks, changes the heading, and highlights that view. Within the Read later view, toggling the highlighted clock marks the bookmark as read, immediately removes it from the view, decreases the count, and confirms what happened.

## Gherkin
Feature: Read later list

  Scenario: Mark a bookmark to read later from its card
    Given a bookmark is not in Read later
    When the user clicks its clock action
    Then the clock visibly becomes selected
    And the app confirms the bookmark was added to Read later
    And the Read later count increases

  Scenario: Mark a bookmark from its details
    Given the user is viewing a bookmark's details
    When the user switches Read later on and saves
    Then the bookmark is included in Read later

  Scenario: View only bookmarks marked for later
    Given the library contains bookmarks marked for Read later
    When the user clicks Read later in the sidebar
    Then only marked bookmarks are shown
    And the heading is Read later
    And Read later is visibly selected in the sidebar

  Scenario: Mark a Read later bookmark as read
    Given the user is in the Read later view
    When the user toggles off a bookmark's highlighted clock
    Then the bookmark immediately disappears from the Read later view
    And the Read later count decreases
    And the app confirms it was marked as read and removed from the list

## Assumptions
- The card clock is the primary Read later interaction.
- The details switch is a secondary convenience and controls the same status.
- Marking an item as read removes its Read later status but does not delete the bookmark from the library.
