Scenario ID: SCN-009
Title: No duplicate links — go to the existing bookmark and edit it
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the client tries to save a link whose web address already exists anywhere in
the library (All bookmarks, Read later, or Archived), the app does not create a
second copy. Instead it takes the client to the existing bookmark: it switches to
the tab that holds it, clears any active search/tag filter, briefly highlights the
bookmark, and opens it in edit mode so the client can update it. A message
explains what happened and, if the existing one is archived (or in read later),
says so clearly. The save form is cleared.

## Gherkin
Feature: Preventing duplicate bookmarks

  Scenario: Attempt to save an address that already exists
    Given a bookmark with the same web address already exists
    When I try to save it again
    Then no second copy is created
    And I am taken to the existing bookmark, opened for editing
    And a message explains it already exists

  Scenario: Existing copy is in the Archived tab
    Given the existing bookmark is archived
    When I try to save the same address
    Then the app switches to the Archived tab and opens that bookmark for editing
    And the message indicates it is in the Archived items

## Assumptions
- Duplicate detection matches on the web address (case-insensitive), across all
  tabs including Archived. (Confirmed by client.)
- No "save anyway" option; duplicates are prevented, not merely warned. (Confirmed.)
