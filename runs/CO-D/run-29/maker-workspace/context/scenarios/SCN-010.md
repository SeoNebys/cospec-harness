Scenario ID: SCN-010
Title: Preserve a bookmark when page details cannot be retrieved
Type: Error Case
Approval status: approved
Approval session: SESSION-010
Approval cycle: 1

## Approved behaviour
When the app cannot retrieve page details, it still saves the submitted address immediately so the link cannot be lost. The address supplies a basic editable title, the app clearly states that details and a preview were unavailable, and the client can fill in the missing title or description immediately or return later.

## Gherkin
Feature: Save bookmarks when page details are unavailable

  Scenario: Save first when page-detail retrieval fails
    Given the client submits a valid address that the app cannot retrieve
    When page-detail retrieval fails
    Then a bookmark is immediately retained for the submitted address
    And the address is used as an editable fallback title
    And the app clearly shows that the details and preview were unavailable
    And the client can add missing details immediately or later

## Assumptions
- Failure to retrieve page details does not mean the submitted address is malformed.
- No preview placeholder is mistaken for a retrieved page image.
- Page-detail retrieval can be attempted again in a later cycle, but automatic retry behaviour is not part of this scenario.
