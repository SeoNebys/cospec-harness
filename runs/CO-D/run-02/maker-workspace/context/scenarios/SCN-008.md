Scenario ID: SCN-008
Title: Saving still works when a page can't be read, and links are required
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Saving leans on the app auto-reading the page; these are the paths for when that
strains.

A real link the app cannot read:
- The panel still appears. The site is filled from the address; the title is
  left empty with a gentle grey note: "Couldn't read this page automatically —
  pop in a title so you'll recognise it later. You can still save it."
- The client can type a title (and note/labels) and **save successfully**. A
  failed auto-read is a graceful hand-off, never a dead end.
- Nudging for a title here is protective, not merely polite: an untitled mystery
  link is exactly what goes missing later. Saving is still allowed either way.

Something that is not a link:
- If what is pasted is not a web address, a **kind amber nudge** explains a
  bookmark needs an address (like https://…) "to take you back to" — it says
  *why*, not just "invalid". Saving stays disabled until there is a real link.
- Missing "https://" is tolerated (the address is still recognised).

A bookmark must have a web address (confirmed design decision):
- This app is a home for **links**. Link-less, pure-text notes are out of scope
  — that is a different tool. The client's own words still live in the per-item
  note, which hangs off a real link (and stays searchable).

## Gherkin

Feature: Saving under strain

  Scenario: The page cannot be read
    Given the client pastes a valid link the app cannot read
    Then the panel appears with the site filled and the title empty
    And a gentle note asks for a title while allowing the save
    When the client types a title and saves
    Then the bookmark is saved

  Scenario: The pasted text is not a link
    When the client pastes something that is not a web address
    Then a kind nudge explains a link is needed and why
    And saving is not allowed until a real link is entered

  Scenario: A missing protocol is tolerated
    When the client pastes "smittenkitchen.com/olive-oil-cake" without https://
    Then it is still recognised as a link

  Scenario: Link-less notes are out of scope
    Then a bookmark cannot be saved without a web address

## Assumptions

- Auto-read failure degrades gracefully to manual title entry; save still works.
- A valid web address is required to save; missing protocol is auto-tolerated.
- Pure-text (link-less) notes are intentionally not supported.
