Type: Happy Path

## Approved behaviour

Opening the page vs. editing are clearly separated:
- Clicking a bookmark's title or anywhere on its card opens the original page in
  a new browser tab.
- A distinct, obvious "Edit" button on each card opens the editor.

The editor lets the client change all of: the web address, the title, the
description, a personal note, and tags. Saving updates the card in place and
briefly highlights it.

Web address editing: the address is an editable field. On save the app
recomputes the link's identity; if the edited address would collide with a
different existing bookmark, the change is blocked with a message rather than
creating a conflict.

Note formatting: notes accept simple Markdown and render it when displayed on the
card — bold, italic, links (http/https only), bullet lists, and inline code.
Headings, tables, and images are intentionally not supported; the client
confirmed this subset is enough.

Tags: entered as chips (type a word, press Enter or comma to make a chip; click ×
to remove; Backspace on an empty field removes the last chip). As the client
types, the app suggests tags already used elsewhere that match the typed text (up
to 6), selectable by mouse or ↑/↓ + Enter, so the client can reuse an existing
tag instead of creating a near-duplicate. Suggestions never invent new tags.

Duplicate entry (from SCN-001) resolves here: pasting an already-saved link opens
this editor for the existing bookmark directly.

## Gherkin

Feature: Edit a bookmark

  Scenario: Open the original page from the card
    Given a saved bookmark
    When the client clicks its title or card (not the Edit button)
    Then the original page opens in a new browser tab

  Scenario: Open the editor
    Given a saved bookmark
    When the client clicks its Edit button
    Then the editor opens showing the current address, title, description, note, and tags

  Scenario: Edit fields and save
    Given the editor is open for a bookmark
    When the client changes the address, title, description, note, or tags and saves
    Then the card is updated in place and briefly highlighted

  Scenario: Edited address collides with another bookmark
    Given two bookmarks A and B exist
    When the client edits A's address to match B's normalised address and saves
    Then the change is blocked with a message and no conflict is created

  Scenario: Note renders supported Markdown
    Given a note containing bold, italic, an http(s) link, a bullet list, or inline code
    When the note is shown on the card
    Then that formatting is rendered; unsupported constructs are shown as plain text

  Scenario: Reuse an existing tag via suggestion
    Given tags already exist on other bookmarks
    When the client types text matching an existing tag in the tag field
    Then matching existing tags are suggested and can be selected to avoid near-duplicates

  Scenario: Duplicate paste opens the editor
    Given the pasted link is already saved
    When the client pastes it and presses Save
    Then the editor opens directly for the existing bookmark

## Assumptions

- Edit is a separate button on the right of each card; card/title opens the page.
- Markdown subset: bold, italic, http/https links, bullet lists, inline code.
- Tag suggestions are drawn only from tags already in use, max 6, substring match.
- Note/tags are shown on the card (note as a highlighted block, tags as pills).
