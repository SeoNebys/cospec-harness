# Data Model: Personal Bookmark Manager

**Date**: 2026-09-17  
**Database**: SQLite with foreign keys, WAL, and ordered migrations

## Modeling Rules

- Integer primary keys are internal identifiers; user-facing meaning lives in explicit fields.
- UTC timestamps use one consistent sortable representation and are generated by the server.
- Boolean values are stored as `0` or `1` with `CHECK` constraints.
- User-facing spelling is preserved separately from normalized uniqueness/search keys.
- All foreign-key child columns used by cascades are indexed.
- Bookmark, tag, FTS, saved-view, and selection changes that form one user action commit in one transaction.

## Bookmark

Represents one unique saved web destination.

| Field | Type | Rules |
|---|---|---|
| `id` | integer | Primary key |
| `address` | text | Trimmed valid HTTP(S) destination retained for display/opening |
| `normalized_address` | text | Required, unique across active and archived bookmarks; derived by FR-005 rules |
| `address_revision` | integer | Starts at 1 and increments whenever the address changes; guards metadata races |
| `title` | text | Required display value; retrieved, user-authored, or address-derived fallback |
| `title_provenance` | enum | `fallback`, `retrieved`, or `user` |
| `retrieved_title_candidate` | nullable text | Latest retrieved alternative when a user title must not be overwritten |
| `description` | text | May be empty; retrieved or user-authored |
| `description_provenance` | enum | `fallback`, `retrieved`, or `user` |
| `retrieved_description_candidate` | nullable text | Latest retrieved alternative when a user description must not be overwritten |
| `icon_hash` | nullable text | Foreign key to a validated app-origin PNG; null uses the placeholder |
| `metadata_status` | enum | `pending`, `complete`, `partial`, `failed`, or `skipped_unsafe` |
| `metadata_error_code` | nullable enum | Friendly category such as timeout, denied destination, unsupported content, too large, or unavailable |
| `metadata_fetched_at` | nullable timestamp | Completion time of the last applicable attempt |
| `note_markdown` | text | Canonical user-authored note; empty by default |
| `note_plain` | text | Derived visible text used by search |
| `is_favorite` | boolean | Independent of reading/archive state; false by default |
| `is_unread` | boolean | True means Read Later; false by default |
| `archived_at` | nullable timestamp | Null means active; non-null means archived |
| `created_at` | timestamp | Immutable creation time |
| `updated_at` | timestamp | Refreshed by user-visible content/state changes and applied metadata |

### Bookmark Invariants

- `normalized_address` has a unique index. Application pre-checks improve UX; the constraint resolves races.
- A bookmark is in Read Later only when `is_unread = 1 AND archived_at IS NULL`.
- Archiving changes only `archived_at`; it never clears favorite or unread state.
- Restoring clears `archived_at`, so a retained unread bookmark reappears in Read Later.
- A metadata result may update a row only when its captured `address_revision` still equals the current value.
- A metadata result may update title or description only when that field's provenance is not `user`.
- Changing an address first checks uniqueness. On conflict, the edited bookmark remains unchanged.
- `note_plain` and the search index update in the same transaction as `note_markdown`.

### Bookmark State Transitions

```text
Reading:  read <──────────────> unread / Read Later
Archive:  active ─────────────> archived
          archived ───────────> active

Metadata: pending ────────────> complete
          pending ────────────> partial
          pending ────────────> failed
          pending ────────────> skipped_unsafe
          any non-pending ────> pending (address change or explicit refresh)

Deletion: active or archived ─> permanently removed
```

Reading and favorite transitions are independent from archive transitions.

## Bookmark Icon

Stores a safe, deduplicated site icon served only from the app origin.

| Field | Type | Rules |
|---|---|---|
| `content_hash` | text | Primary key generated from re-encoded bytes |
| `png_bytes` | blob | Validated, bounded, re-encoded PNG only |
| `width` | integer | Positive and within the configured icon bound |
| `height` | integer | Positive and within the configured icon bound |
| `byte_length` | integer | Positive and within the configured transfer/storage bound |
| `created_at` | timestamp | Cache creation time |

An icon row may be referenced by many bookmarks. Unreferenced icons may be removed by maintenance; losing an icon never loses a bookmark and falls back to the placeholder.

## Tag

Represents a reusable flat label.

| Field | Type | Rules |
|---|---|---|
| `id` | integer | Primary key |
| `display_name` | text | Trimmed user-facing spelling |
| `name_key` | text | Unicode-normalized, whitespace-normalized, case-folded unique key |
| `created_at` | timestamp | Creation time |

`name_key` is unique. A repeated spelling variant resolves to the existing tag.

## Bookmark Tag

Many-to-many relationship between bookmarks and tags.

| Field | Type | Rules |
|---|---|---|
| `bookmark_id` | integer | Foreign key to Bookmark, cascade on delete |
| `tag_id` | integer | Foreign key to Tag, cascade on delete |

The composite `(bookmark_id, tag_id)` is the primary key. An index on `(tag_id, bookmark_id)` supports exact tag expressions, multi-tag filters, and bulk tag actions. Tags left with no bookmark may be garbage-collected, but saved views preserve their own tag keys.

## Saved View

Stores live search/filter criteria, never bookmark result identifiers.

| Field | Type | Rules |
|---|---|---|
| `id` | integer | Primary key |
| `display_name` | text | Trimmed non-empty user-facing name |
| `name_key` | text | Unicode-normalized, case-folded unique key |
| `query_text` | text | Original validated search expression |
| `grammar_version` | integer | Starts at 1; migration point for future syntax changes |
| `scope` | enum | `active`, `read_later`, or `archived` |
| `favorite_filter` | nullable boolean | Null means any |
| `unread_filter` | nullable boolean | Null means any; scope rules still apply |
| `sort_order` | enum | `created_desc`, `created_asc`, `updated_desc`, or `title_asc` |
| `created_at` | timestamp | Creation time |
| `updated_at` | timestamp | Last rename or criteria update |

`name_key` is unique. The search expression must parse successfully before create/update. Opening a saved view reparses and evaluates current data.

## Saved View Tag

Stores one required tag filter for a saved view.

| Field | Type | Rules |
|---|---|---|
| `saved_view_id` | integer | Foreign key to Saved View, cascade on delete |
| `tag_key` | text | Preserved normalized tag criterion |
| `display_name` | text | Last saved display label |

The composite `(saved_view_id, tag_key)` is the primary key. `tag_key` deliberately does not reference the live Tag table: deleting the last use of a tag leaves the saved criterion intact and produces the specified editable empty result.

## Selection Set

An expiring, non-user-content snapshot used for safe bulk actions.

| Field | Type | Rules |
|---|---|---|
| `id` | text | Opaque random token primary key |
| `criteria_hash` | text | Hash of the view state that produced the selection |
| `selected_count` | integer | Count shown for confirmation |
| `created_at` | timestamp | Snapshot time |
| `expires_at` | timestamp | Short expiry; abandoned sets are deleted on startup and periodically |

Selection sets are not restored as user state after expiration and do not appear in backups as meaningful content.

## Selection Item

Materializes selection membership.

| Field | Type | Rules |
|---|---|---|
| `selection_id` | text | Foreign key to Selection Set, cascade on delete |
| `bookmark_id` | integer | Foreign key to Bookmark, cascade on delete |

The composite `(selection_id, bookmark_id)` is the primary key. An index on `bookmark_id` supports cascades. A view change deletes the current set; a bulk action consumes and deletes it in the same transaction.

## Bookmark Search Index

A contentful FTS5 virtual table whose `rowid` equals `bookmarks.id`.

| Column | Content |
|---|---|
| `title` | Search-normalized title |
| `address` | Search-normalized destination address |
| `description` | Search-normalized description |
| `note_plain` | Search-normalized visible note text |

The table uses the trigram tokenizer over already case-normalized text. Tags stay relational. Bookmark and FTS rows are inserted, updated, and deleted in one transaction, and integrity is checked in migration/maintenance tests.

## Schema Migration

Tracks ordered, immutable SQL migrations.

| Field | Type | Rules |
|---|---|---|
| `version` | integer | Primary key |
| `name` | text | Migration label |
| `applied_at` | timestamp | Successful application time |

Startup applies pending migrations transactionally before the server reports ready.

## Index Plan

- Unique: `bookmarks(normalized_address)`
- Listing: `(archived_at, created_at, id)`, `(archived_at, updated_at, id)`, `(archived_at, title_sort_key, id)`
- Status: `(archived_at, is_unread, created_at, id)`, `(archived_at, is_favorite, created_at, id)`
- Tags: unique `tags(name_key)`, `bookmark_tags(tag_id, bookmark_id)`, and its primary key
- Saved views: unique `saved_views(name_key)`, `saved_view_tags(tag_key, saved_view_id)`
- Selections: primary membership key and `selection_items(bookmark_id)`

The implementation must verify these with representative `EXPLAIN QUERY PLAN` output and the approved elapsed-time acceptance tests rather than relying on index presence alone.
