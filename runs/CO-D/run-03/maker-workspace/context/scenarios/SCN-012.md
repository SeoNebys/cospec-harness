Scenario ID: SCN-012
Title: Select multiple bookmarks and act on them together; select all that match
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Selection:
- Each bookmark row has an always-visible checkbox (makes multi-selection easy to
  discover). Ticking one or more reveals a group action bar showing the count.
- "Select all on this page" selects the loaded items. When all loaded items are
  selected, a banner offers "Select all N bookmarks that match <current view>",
  which selects the ENTIRE matching set across every page — respecting the current
  search, tag, and status/archive view, not only loaded items. "Clear selection"
  undoes it.

Group actions (apply to the whole selection, including select-all-matching):
- Add tags / Remove tags — using the SAME tag entry as single editing: removable
  pills with as-you-type suggestions drawn from previously-used tags, so bulk
  tagging cannot create inconsistent tag names.
- Mark read = set status Finished. Mark unread = set status To read.
- Archive the selected bookmarks.
- Delete the selected bookmarks — ALWAYS via a confirmation that clearly states
  the number being permanently deleted and points to Archive as the reversible
  alternative.

## Gherkin

Feature: Bulk selection and actions

  Scenario: Select some and see the action bar
    Given several bookmarks
    When the user ticks one or more checkboxes
    Then a group action bar appears showing the number selected and the available actions

  Scenario: Select all matching across every page
    Given a search/tag/status view with more matches than are loaded
    When the user selects all loaded items and chooses "Select all N that match"
    Then all N matching bookmarks are selected across every page
    And any group action applies to all N

  Scenario: Bulk add/remove tags reuses the standard tag entry
    Given a selection of bookmarks
    When the user adds or removes tags
    Then the tag entry offers as-you-type suggestions from previously-used tags
    And the change is applied to every selected bookmark

  Scenario: Bulk mark read / unread
    When the user chooses "Mark read" (or "Mark unread") for the selection
    Then every selected bookmark becomes Finished (or To read)

  Scenario: Bulk archive
    When the user archives the selection
    Then every selected bookmark is archived

  Scenario: Bulk delete requires a counted confirmation
    When the user deletes the selection
    Then a confirmation states the exact number to be permanently deleted
    And offers Archive as the reversible alternative
    And only on confirm are they permanently deleted

## Assumptions
- "Read/unread" maps exactly to the Finished/To read statuses (SCN-004).
- Select-all-matching operates on the server-side full match set, consistent with
  SCN-009 (operations span the whole collection).
