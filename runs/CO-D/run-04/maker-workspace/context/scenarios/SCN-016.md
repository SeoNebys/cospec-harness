Title: Keep a saved copy of every page (the safety net)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client saves a link, the app automatically keeps a copy of the page as
it was at that moment — silently, for every link, so the safety net is always
there without the client having to remember (you never know in advance which
link will die). Each card shows "✓ Saved copy kept — from [date]", and a "View
saved copy" action opens it.

The saved copy's core is a clean READABLE copy — the page's words and key images
— because when a page dies it is almost always the words the client mourns. A
VISUAL snapshot (a picture of the page as it looked) is a valued bonus for pages
where layout carries the meaning (designs, charts, infographics); if only one
can ship first, it is the readable copy.

When the live page is gone or changed, the card flags "⚠ Original no longer
reachable — your saved copy is safe", and viewing the copy shows a banner
("this is your saved copy from [date]"). Opening the live page in that state
honestly fails and points the client back to the saved copy.

Capture is BEST-EFFORT with honest labelling: pages behind a login/paywall or
highly interactive apps may be captured only partially, and the app says plainly
which copies are partial rather than pretending completeness.

Automatic capture is the default, with an escape valve: a setting to turn it off
and/or skip it for a particular link, for when storage genuinely bites.

## Gherkin
Feature: Saved copy safety net

  Scenario: A copy is kept automatically on save
    When the client saves a link
    Then a readable copy of the page is kept automatically
    And the card shows a saved-copy indicator with the date

  Scenario: The original dies but the copy survives
    Given a saved link whose live page is no longer reachable
    Then the card flags the original as unreachable
    And the saved copy still opens, marked as a copy from the saved date

  Scenario: Best-effort with honest labelling
    Given a page behind a login or paywall
    When its copy is only partial
    Then the app labels that copy as partial

  Scenario: Escape valve for storage
    Then the client can turn auto-capture off, or skip it for a given link

## Changed vs died (client confirmed — honesty)
The app reliably detects an *unreachable* (gone) page, but does NOT promise to
detect that a still-live page's *content* quietly changed (unreliable). Rather
than a false promise, the dated saved copy is always one click away, so if the
client ever notices a live page isn't what they remember, their copy from that
date is right there to check against.

## Re-saving a deleted link (client confirmed)
Once the undo window passes, deletion is final; saving that address again creates
a clean, fresh link — no ghost of the old one (old note/labels) creeps back.

## Assumptions
- Automatic, silent, on by default; off-switch + per-link skip. (client confirmed)
- Readable copy is the must-have; visual is a bonus, readable first. (client confirmed)
- Best-effort with honest labelling of partial copies. (client confirmed)

## Non-functional facets recorded (see non-functional-backlog.md)
- Storage growth; visual snapshots heavier than readable; capture reliability.
