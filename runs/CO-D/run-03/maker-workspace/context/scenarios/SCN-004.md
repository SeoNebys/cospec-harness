Scenario ID: SCN-004
Title: Separate "To read" from "Finished"; choose status when saving/editing
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Every bookmark has a reading status: "To read" or "Finished".

Viewing (approved arrangement — "Arrangement B"):
- The bookmark list has a switch with three views: To read, Finished, All.
- The app opens on "All" by default (the library as a whole).
- Each card shows a small status badge (To read / Finished); finished items are
  visually de-emphasised (e.g. struck-through title).
- The "To read" view shows only to-read items; "Finished" shows only finished;
  "All" shows everything.

Setting status:
- When saving a new bookmark and when editing later, the review/edit card offers
  an "Add to" choice between "To read" and "Finished". New saves default to
  "To read". A short line explains the effect of each choice.
- Each card has a "Mark finished" action (and, once finished, a "Move to To read"
  action to reverse it).

Movement:
- Marking a bookmark finished removes it from the "To read" view (it remains in
  "All" and appears in "Finished").
- Moving a finished bookmark back to "To read" restores it to the "To read" view.

## Gherkin

Feature: Reading status (To read vs Finished)

  Scenario: Library opens on All
    Given saved bookmarks with mixed statuses
    When the user opens the app
    Then the "All" view is shown with a To read / Finished / All switch
    And each bookmark shows its status badge

  Scenario: Choose status when saving
    Given the review-before-saving card
    Then an "Add to" choice offers To read or Finished, defaulting to To read
    When the user confirms the save
    Then the bookmark is created with the chosen status

  Scenario: Choose status when editing
    Given the user edits an existing bookmark
    Then the same To read / Finished choice is available and can be changed

  Scenario: Mark finished removes from To read view
    Given a to-read bookmark
    When the user marks it finished
    Then it no longer appears in the To read view
    And it appears in the Finished view and still in All

  Scenario: Move back to To read
    Given a finished bookmark
    When the user moves it back to To read
    Then it reappears in the To read view

## Assumptions

- Reading status is independent of tags and of the note.
- Archiving (keeping without cluttering the main list) is a separate concern,
  explored next; it is not the same as "Finished".
