Scenario ID: SCN-012
Title: Handle odd or missing input and unavailable page details
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client tries to save something that is not a valid web address, the save
is blocked and a helpful hint suggests the correct format; no broken bookmark is
created. A valid web address is always saved even when the page's details cannot
be collected (site unreachable, or a page offering no title/description/image):
the link is kept using the address as a fallback title, and the client can fill
in the title and description later. A bookmark with sparse details is presented
tidily — showing just the title and address, without empty gaps where a preview
image or description would be. The same address validation applies when editing a
bookmark's address.

## Assumptions
- "Valid" address means an http/https URL with a dotted hostname and no spaces
  (facilitator's working rule; client confirmed the block-invalid / save-valid
  behaviour).
- Page-detail collection failures are handled by saving anyway; this could not be
  reproduced in the offline prototype and was confirmed by description (recorded
  in the session log).
