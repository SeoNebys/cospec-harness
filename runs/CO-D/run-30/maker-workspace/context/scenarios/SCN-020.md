Scenario ID: SCN-020
Title: Reuse an existing label when capitalization differs
Type: Edge Case
Approval status: approved
Approval session: SESSION-020
Approval cycle: 1

## Approved behaviour

If the client attempts to create a label whose wording is identical to an existing label apart from capitalization, the picker selects the existing label instead of creating another. It explicitly tells the client which label was reused. Saving shows the canonical existing label on the card with no differently capitalized duplicate. The app does not attempt to merge labels whose actual wording differs.

## Gherkin

Feature: Organizing bookmarks with labels

  Scenario: Enter an existing label using different capitalization
    Given the label "Recipes" already exists
    And a bookmark currently has the label "Work"
    When the user attempts to create the label "recipes"
    Then the existing "Recipes" label is selected
    And the picker explains that the existing label was reused
    When the user saves
    Then the card shows "Work" and "Recipes"
    And no lowercase "recipes" label is created

  Scenario: Enter genuinely different label wording
    Given the label "Recipes" already exists
    When the user creates a label with different wording
    Then the app does not automatically merge it with "Recipes"

## Assumptions

- Label identity ignores capitalization but does not use semantic or singular/plural guessing.
