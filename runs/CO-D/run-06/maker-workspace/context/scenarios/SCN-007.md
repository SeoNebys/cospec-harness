Scenario ID: SCN-007
Title: Recognize a link I already saved (tracking-aware) and open it instead of duplicating
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client pastes and Adds a link they already have, the app does not create a
second copy. Instead it quietly opens the existing bookmark in the editor, with a
gentle green note: "You've already saved this link — here it is." No confirmation
prompt, no scolding — just land the client on the one they already have so they can
update it.

"Same link" is judged tracking-aware:
- Treated as the SAME page: differences in protocol (http/https), a leading "www.",
  a trailing slash, and known tracking parameters (e.g. utm_source, utm_medium,
  utm_campaign, utm_term, utm_content, gclid, fbclid, and similar).
- Treated as a DIFFERENT page: query parameters that change which page/content the
  client actually lands on (e.g. a video id "v=...", a page number, a search query).
  These are kept, not stripped.

So: strip obvious tracking clutter, but never chop meaningful query parts.

## Gherkin
Feature: Duplicate-link recognition

  Scenario: Re-pasting an already-saved link opens the existing bookmark
    Given a bookmark for "smittenkitchen.com/beans" already exists
    When the client Adds "smittenkitchen.com/beans"
    Then no new bookmark is created
    And the existing bookmark opens in the editor with a "you already saved this" note

  Scenario: Tracking parameters are ignored when matching
    Given a bookmark for "smittenkitchen.com/beans" already exists
    When the client Adds "smittenkitchen.com/beans?utm_source=newsletter&utm_campaign=spring"
    Then it is recognized as the same page and no duplicate is created

  Scenario: A meaningful query difference is a different link
    Given a bookmark for "youtube.com/watch?v=SAVED123" already exists
    When the client Adds "youtube.com/watch?v=DIFFERENT99"
    Then it is treated as a new, different bookmark

## Assumptions
- A maintained list of known tracking parameters is stripped; all other query
  parameters are preserved and significant for matching.
- Matching also normalizes protocol, leading "www.", trailing slash, and case.
