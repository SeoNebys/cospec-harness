Scenario ID: SCN-011
Title: Delete a link for good (with an undo beat)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
For a link that is genuine junk (mistake, typo), the client can delete it outright from the
manage area of the Edit panel (a red "🗑 Delete…", set apart on the opposite side from the
quiet "Put away"). The link disappears immediately and an Undo bar slides up at the bottom.
Clicking Undo restores the link exactly where it was. If the client does nothing, the
delete becomes permanent — which is what delete should mean.

The client explicitly preferred this Undo moment over a blocking "are you sure?" on every
delete ("being nagged on every delete would get old fast"). Firm requirement: the Undo bar
must LINGER long enough to actually be noticed — a comfortable few seconds, not a blink —
because the dangerous case is the accidental delete the client hasn't yet realised they
made.

## Gherkin
Feature: Deleting a link

  Scenario: Delete then undo
    Given a saved link
    When I delete it and then click Undo
    Then the link is restored to its previous position

  Scenario: Delete and let it stand
    Given I have deleted a link
    When the undo window passes without action
    Then the link is permanently removed

## Assumptions
- Undo window is a few seconds (comfortably noticeable); permanence after that is intended.
- Delete is distinct in placement and colour from "Put away" so the two are never confused.
