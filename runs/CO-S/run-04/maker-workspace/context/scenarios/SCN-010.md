Scenario ID: SCN-010
Title: Cards cope with partial details and very long text
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Boundary content is handled so the list stays tidy and scannable:
- A page returning no description: the card omits the description line entirely
  (no "no description available" placeholder).
- A page returning no preview image: the card shows a neutral placeholder area
  where the image would be, rather than looking broken.
- A very long title: wraps fully so it stays readable.
- A very long description: trimmed to about three lines on the card (the full
  text is retained underneath / in the data, just not all displayed), keeping
  cards a scannable size.
Client confirmed: trimming long descriptions is acceptable (scannability first),
and quietly omitting missing details is preferred (tidy, not broken).

## Gherkin
Feature: Robust card display for boundary content

  Scenario: Missing description
    Given a saved bookmark whose page had no description
    Then the card does not show a description line or placeholder text

  Scenario: Missing preview image
    Given a saved bookmark whose page had no preview image
    Then the card shows a neutral placeholder area instead of a broken image

  Scenario: Very long title
    Given a saved bookmark with a very long title
    Then the title wraps fully and stays readable

  Scenario: Very long description
    Given a saved bookmark with a very long description
    Then the card trims the displayed description to about three lines

## Assumptions
- Trimming is display-only; the full description is retained in the data.
- Missing fields are omitted quietly rather than shown as placeholders.
