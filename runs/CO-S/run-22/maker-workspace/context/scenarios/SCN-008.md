Scenario ID: SCN-008
Title: Handle empty or invalid link addresses when saving
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
If the client clicks Save with no address, an inline red message asks for a link
address and the address field is highlighted; nothing is saved. If the address is
present but not a valid web address, an inline red "that doesn't look like a valid
web address" message is shown and nothing is saved. If the client omits the
http/https prefix (e.g. "example.com/page"), the app forgives it and prepends
https:// so the link saves normally. These messages appear next to the form rather
than as browser pop-ups.

## Gherkin
Feature: Address validation on save

  Scenario: Saving with no address
    Given the address field is empty
    When the client clicks Save link
    Then an inline message asks for a link address
    And the address field is highlighted
    And nothing is saved

  Scenario: Saving an invalid address
    Given the address field contains text that is not a valid web address
    When the client clicks Save link
    Then an inline "invalid web address" message is shown
    And nothing is saved

  Scenario: Missing http/https is forgiven
    Given the client enters an address without http:// or https://
    When the client saves
    Then https:// is prepended and the link is saved normally

## Assumptions
- Validation requires a http/https address with a dotted hostname.
- Messages are shown inline, not as browser alerts.
- Missing scheme is auto-corrected to https://.
