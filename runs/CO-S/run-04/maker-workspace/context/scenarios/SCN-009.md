Scenario ID: SCN-009
Title: Saved links persist across sessions
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Saved links are durable. When the user closes the browser and returns later
(next day, next week, any time), every link they saved is still present, with its
custom name (if renamed) and in the same order as before. Nothing the user saved
ever disappears on its own. This is treated as a fundamental requirement: the app
is pointless if saved links can quietly vanish.

## Gherkin
Feature: Persistence of saved links

  Scenario: Links survive closing and reopening
    Given the user has saved several links, some with custom names
    When the user closes the browser and later reopens the app
    Then all previously saved links are still present
    And any custom names are preserved
    And the order is unchanged
    And nothing has disappeared

## Assumptions
- Persistence is on the user's own computer (single-device scope for this cycle).
- Cross-device access is out of scope for now (see non-functional backlog).
- The specific storage mechanism is a Phase 2 decision; the guarantee is that
  saved data is never silently lost.
