Scenario ID: SCN-002
Title: Reuse an existing bookmark when the same page is saved again
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When a person submits the address of an existing page, the app does not prepare or create a second copy. It recognizes the page when the pasted address differs only by a trailing slash, a jump to a section within the page, or advertising/tracking information. It announces that the bookmark is already in the library and opens the existing bookmark's current title and description for editing. Updating it changes that existing entry and confirms the exact updated values with wording that distinguishes an update from a newly saved bookmark. Genuinely different page paths on the same site remain different bookmarks.

## Gherkin
Feature: Avoid duplicate bookmarks

  Scenario: Open an exact duplicate for editing
    Given a bookmark already exists for a web address
    When the user submits that exact web address to save it again
    Then the app states that it is already in the library
    And the existing bookmark's title and description are opened for editing
    And no new bookmark is created

  Scenario: Update the bookmark reached through duplicate detection
    Given an existing bookmark was opened after its web address was submitted again
    When the user changes its title and updates the bookmark
    Then the existing bookmark contains the changed title
    And no new bookmark is created
    And the confirmation identifies the action as an update and displays the changed value

  Scenario Outline: Recognize superficial address differences as the same page
    Given a bookmark already exists for a page
    When the user submits that page's address with <difference>
    Then the existing bookmark is opened for editing
    And no new bookmark is created

    Examples:
      | difference                            |
      | an added or removed trailing slash    |
      | a jump to a section within the page   |
      | added advertising/tracking information |

  Scenario: Preserve genuinely different pages on the same site
    Given one page on a site is already bookmarked
    When the user submits an address with a genuinely different page path on that site
    Then it is treated as a different bookmark

## Assumptions
- Duplicate detection ignores trailing slashes, in-page section jumps, and recognized advertising/tracking information.
- A genuinely different page path remains distinct.
- The existing bookmark is opened directly in editing mode.
