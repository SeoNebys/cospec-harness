Scenario ID: SCN-007
Title: Delete a bookmark with confirmation; it disappears everywhere
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each saved link has a "Delete" action. Deleting is not immediate: it first asks
"Delete this bookmark?" with "Delete" and "Keep" choices, so a stray click
cannot lose a bookmark. Choosing "Keep" cancels. Choosing "Delete" permanently
removes the bookmark, and it disappears from everywhere — the main list, any
search/tag filter, and the read-later views and the "To read" unread count.

## Gherkin
Feature: Deleting a bookmark

  Scenario: Confirm before deleting
    Given a saved link
    When the client clicks "Delete"
    Then a confirmation asking "Delete this bookmark?" is shown
    And no deletion happens yet

  Scenario: Cancel a deletion
    Given the delete confirmation is shown
    When the client chooses "Keep"
    Then the bookmark remains unchanged

  Scenario: Confirm a deletion
    Given the delete confirmation is shown
    When the client chooses "Delete"
    Then the bookmark is permanently removed from the list

  Scenario: Deleting a read-later bookmark updates the read-later count
    Given a bookmark in the read-later list counted as "To read"
    When the client deletes it
    Then it no longer appears in any read-later view
    And the "To read" unread count decreases accordingly

## Assumptions
- Deletion requires an explicit confirmation step.
- Deletion is permanent (no separate trash/undo in this cycle).
