## Approved behaviour

### Non-address / blank input (rejected up front)
If the client tries to save text that is not a plausible web address (contains
spaces, or has no dotted host — e.g. "hello world", "banana"), the save is rejected
with a clear message and nothing is added. A blank save shows a gentle prompt to
paste an address. The app does not store standalone text notes; every saved item is
a link.

### Unreachable page (kept with a warning)
If the address is valid but the page cannot be reached when saving, the link is
still saved (never lost). Its card shows a warning strip stating the details and
saved copy aren't available yet, with a Retry action, and the copy indicator reads
"Copy unavailable". Opening the saved copy explains none exists yet and points to
Retry. The link is otherwise a first-class bookmark: it can be opened, tagged,
noted, added to the reading list, archived, edited, or deleted. Retrying re-attempts
the fetch and capture; on success the title, description, and preserved copy fill in.

## Gherkin
Feature: Error and unusual input on save

  Scenario: Reject non-address text
    When the client tries to save text that is not a plausible web address
    Then no item is added
    And a clear message explains it doesn't look like a web address

  Scenario: Blank save
    When the client saves with an empty box
    Then a prompt asks for a web address
    And nothing is added

  Scenario: Save an unreachable page
    Given a valid address whose page cannot be reached
    When the client saves it
    Then the link is saved
    And a warning shows details and saved copy aren't available, with Retry
    And the copy indicator reads "Copy unavailable"

  Scenario: Retry a failed capture
    Given a saved link whose capture failed
    When the client uses Retry and the page is reachable
    Then the title, description, and preserved copy are filled in
    And the warning is cleared

  Scenario: Failed-capture link is still fully usable
    Given a saved link whose capture failed
    Then the client can open, tag, note, add-to-reading-list, archive, edit, or delete it

## Assumptions
- Plausible-address check: no whitespace and a dotted host (or localhost); exact
  validation finalised in implementation.
- Capture failure covers unreachable pages; login-gated/large-page capture limits
  are recorded as non-functional considerations.
- No standalone (non-link) notes in this app.
