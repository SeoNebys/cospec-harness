Scenario ID: SCN-010
Title: Large library — Load more in batches, with search/filters/counts covering everything
Type: Edge Case (boundary — abundance)
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the current list has many links, only a batch (~25) is drawn at a time. A
"Load more" button at the bottom brings in the next batch and shows how many
remain (e.g. "Load 25 more (233 left)"). This is preferred over numbered pages.

Crucially, search, tag filters, sorting, and the counts operate over the ENTIRE
matching collection — not only the links currently loaded. So the result count
and tab counts reflect all matches, and loading more never changes what matches.

Changing view, search, tag filter, or sort resets the batch back to the first
~25. The client approved the ~25 batch size and the remaining-count on the button.

## Gherkin

Feature: Load large lists in batches

  Scenario: Only a batch is shown initially
    Given the current list has more than one batch of links
    Then only the first batch (~25) is displayed
    And a "Load more" control shows how many remain

  Scenario: Load more
    When the client chooses "Load more"
    Then the next batch is appended

  Scenario: Search and counts cover the whole collection
    Given only a batch is currently loaded
    When the client searches or filters by tag
    Then the results and counts reflect all matching links, not only the loaded batch

  Scenario: Changing view/search/filter/sort resets the batch
    When the client changes the view, search, tag filter, or sort order
    Then the list returns to showing the first batch

## Assumptions
- Batch size ≈ 25 (tunable).
- Counting/searching/sorting are independent of the batch window.
