Scenario ID: SCN-006
Title: Label a link, steered toward labels already used
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
In the edit pop-up, the client adds their own labels to a link. As they type a
label, labels they have already used elsewhere appear as clickable suggestions,
so an existing label is reused rather than a near-duplicate created. Typing a
genuinely new label offers a "+ create" option. Labels show as removable pills
in the editor and as small pills on the card. This deliberately protects the
library from fragmenting into near-duplicate topics ("recipes"/"recipe"), which
is the client's core fear.

## Gherkin
Feature: Label a link with suggestions

  Scenario: Reusing an existing label via suggestion
    Given the client has already used the label "recipes" on another link
    When the client types "rec" in the Labels field of a link's editor
    Then "recipes" is offered as a clickable suggestion
    And clicking it adds the existing label rather than a new one

  Scenario: Creating a genuinely new label
    Given the typed text matches no existing label
    When the client confirms it
    Then a new label is created and added to the link

## Assumptions
- Chosen "type with suggestions" over free-form/comma-list, to prevent
  near-duplicate topic fragmentation. (client confirmed, comparing 3 styles)
- Labels are stored lower-cased for matching.
