Scenario ID: SCN-009
Title: Deliberately create a new tag when no existing tag matches
Type: Edge Case
Approval status: approved
Approval session: SESSION-009
Approval cycle: 1

## Approved behaviour

When the client types a tag name and no existing tag matches, the inline suggestion clearly offers to create that tag rather than silently guessing. Choosing it creates and adds the tag in the same place. The first letter is tidied to uppercase for consistent presentation. Together with existing-tag suggestions, this lets the client deliberately grow the tag set without accidental duplicates.

## Gherkin

Feature: Add tags to bookmarks

  Scenario: Create and add a genuinely new tag
    Given a saved bookmark is ready to receive a tag
    And no existing tag matches the name the user types
    When the user types "travel" in the inline tag field
    Then an explicit "Travel — Create new tag" choice is shown
    When the user chooses that option
    Then a new tag named "Travel" is created
    And it is added beneath the bookmark
    And the user remains in the same context

## Assumptions

- Creating a tag is always an explicit choice, never a silent fallback.
- The first letter of a newly created tag is normalized to uppercase for display.
- Existing tag matching remains the preferred path when a match exists.
