Scenario ID: SCN-009
Title: Reject input that isn't a link; accept an address without a scheme
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client tries to save something that is not a plausible web address (for
example ordinary words containing spaces, or text with no dot), the app gently
refuses with a clear message ("That doesn't look like a link — check it and try
again") and does not proceed to the review step. A recognizable address typed
without a scheme (e.g. "example.org/page") is accepted and treated as an https
link.

## Gherkin
Feature: Link input validation

  Scenario: Reject text that isn't a link
    When the client enters text that is not a plausible address (spaces, or no dot)
    And tries to save the link
    Then a clear "that doesn't look like a link" message is shown
    And the app does not proceed to the details review step

  Scenario: Accept a scheme-less address
    When the client enters an address without "http://" or "https://"
    And the address is otherwise plausible
    Then the app accepts it and proceeds, treating it as an https link

## Assumptions
- "Plausible" means: has a scheme already, or has no spaces and contains a dot.
- This validation is about obvious non-links; it does not guarantee the page exists
  (an unreachable but well-formed link is handled by SCN-008).
