Scenario ID: SCN-001
Title: Save a link with automatically filled, editable details
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The client saves a link by pasting only its address. As soon as a valid address
is entered, a title and a short description are filled in automatically (read
from the linked page in the real app; simulated in the prototype). The client
can edit the title and description before saving, and can optionally add a
personal note in their own words — kept distinct from the page's description. On
saving, the link is added to the collection and appears at the top of the
saved-links list. Each entry shows a small site icon, the title (clickable,
opens the link), the page description, the client's personal note (when present,
shown in its own visually separate box labelled "Note"), the address, and the
saved date. The most recently saved link always appears first (newest-first
ordering). If the site icon cannot be loaded, a coloured letter tile is shown in
its place.

## Assumptions

- Auto-fill is triggered automatically upon entering/pasting the address, with
  no separate button (client confirmed this feels natural).
- In the real application, the title and description are read from the linked
  page; the prototype only simulates this to demonstrate the flow.
- The title and description are editable before saving.
- The site icon is retrieved from the site; a coloured letter-tile placeholder
  is shown if it cannot be loaded.
- Topics are NOT part of this scenario; entry display of topics is deferred to
  the "organise by topic" feature.
- The personal note is optional and is stored/displayed separately from the
  page-derived description.
