Scenario ID: SCN-005
Title: Assign tags on save with suggestions from existing tags
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When saving a bookmark, the user adds tags in a tag field. As they type, the
app suggests tags the user already uses that match what they are typing, so
they can click to reuse an existing tag rather than retyping it. If what they
type is not an existing tag, the app offers to create it as a new tag. Each
chosen tag becomes a small removable pill in the field. This nudges the user
toward reusing consistent tags and avoids near-duplicate tags (e.g. "recipes"
vs "recepies") that would silently re-split the collection — the exact problem
the user wants to avoid. Saving, searching, tag-browsing, and adding all live
together on one screen, and adding tags this way does not disturb the
previously approved save/search/browse behaviours.

## Gherkin
Feature: Tag entry with reuse suggestions

  Scenario: Existing tags are suggested as the user types
    Given the user has previously used some tags
    When the user types part of a tag in the tag field
    Then matching existing tags are offered for reuse
    And the user can add one by selecting it

  Scenario: Creating a new tag
    Given the user types text that is not an existing tag
    Then the app offers to create it as a new tag
    And selecting it adds it as a new tag

  Scenario: Chosen tags appear as removable pills
    Given the user has added one or more tags
    Then each tag is shown as a removable pill in the tag field
    And the user can remove a tag before saving

  Scenario: Existing behaviours still work alongside tag entry
    Given saving, search, and tag-browsing share one screen
    When the user adds a bookmark with tags
    Then saving, search, and tag-browsing all continue to behave as approved

## Assumptions
- Tag entry offers suggestions from existing tags and supports creating new
  ones (client chose this over unconstrained freeform entry).
- Consistency/dedup of tags is a user-facing goal, not just cosmetic.
- Case/whitespace normalization of tags is likely needed to fully prevent
  duplicates — deferred to edge-case exploration / Phase 2 detail.
