Scenario ID: SCN-010
Title: Long text is shortened in the list with Show more
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
In the list, a bookmark's title and description are clamped to about two lines,
and a long note shows a short preview. When a note is long or multi-line, a
"Show more" control expands it to the full, formatted note (bold, bullets, links),
toggling to "Show less". The full title and description remain available (in full)
when editing the bookmark. Search always uses the complete text, including the
parts that are visually collapsed.

## Gherkin
Feature: Readable long text

  Scenario: Clamp long fields in the list
    Given a bookmark with a very long title, description, and note
    When it is shown in the list
    Then the title and description are clamped to about two lines
    And the note shows a short preview with a "Show more" control

  Scenario: Expand and collapse a note
    When the user clicks "Show more" on a note
    Then the full formatted note is shown and the control reads "Show less"
    When the user clicks "Show less"
    Then the note collapses back to the preview

  Scenario: Search sees collapsed text
    Given text that is visually collapsed in the list
    When the user searches for a word only in that collapsed text
    Then the bookmark is still matched

  Scenario: Full text available when editing
    When the user edits a bookmark with clamped fields
    Then the full title and description are shown for editing

## Assumptions
- Clamp is ~2 lines for title/description; note shows a short preview.
