Scenario ID: SCN-006
Title: Reuse an existing bookmark instead of duplicating it
Type: Edge Case
Approval status: approved
Approval session: SESSION-006
Approval cycle: 1

## Approved behaviour
When the client submits a link that is already saved, the app detects it immediately rather than retrieving a new preview or creating another copy. The bookmark count remains unchanged. The app clearly explains that the page was already saved and takes the client to the existing bookmark, where it can be edited or opened.

## Gherkin
Feature: Prevent duplicate bookmarks

  Scenario: Submit a link that is already saved
    Given the collection already contains a bookmark for a web address
    And the collection has a known bookmark count
    When the user submits that web address to save it again
    Then no new bookmark is created
    And the bookmark count remains unchanged
    And the app explains that the page was already saved
    And the existing bookmark is shown with actions to edit it or open its page

## Assumptions
- Duplicate detection occurs when the web address is submitted, before metadata review.
- The existing bookmark is the authoritative copy.
