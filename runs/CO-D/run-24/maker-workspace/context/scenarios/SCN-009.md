Scenario ID: SCN-009
Title: Large collection and long content display
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Explored under the boundary-conditions perspective (very abundant data / very long
text) since the core goal is that the collection stays easy to return to as it
grows.

- The bookmark list is a single continuous, scrollable list — no pagination. The
  client prefers one searchable list over traditional pages for a personal
  collection.
- A very long title wraps neatly across lines without breaking the layout.
- A long description is trimmed to three lines on the card (with the full text
  always preserved and shown in the editor). The client confirmed trimming on the
  card is the right choice.
- Many tags on one card wrap onto multiple rows rather than overflowing.
- Long/unbroken web addresses wrap within the card.
- Search and sort remain responsive and usable with dozens of items.

## Gherkin

Feature: Scale and long content

  Scenario: Continuous list, no pagination
    Given many bookmarks
    When the client browses
    Then all shown bookmarks appear in one scrollable list with no pages

  Scenario: Long title wraps
    Given a bookmark with a very long title
    Then the title wraps across lines without breaking the layout

  Scenario: Long description trimmed on card
    Given a bookmark with a long description
    Then the card shows at most three lines
    And the full description remains available in the editor

  Scenario: Many tags wrap
    Given a bookmark with many tags
    Then the tags wrap onto multiple rows

## Assumptions

- No pagination; single scrollable list.
- Description clamped to 3 lines on cards; full text retained and editable.
- Titles, tags, and long URLs wrap rather than overflow.
