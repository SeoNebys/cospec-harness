Scenario ID: SCN-004
Title: Find a saved bookmark quickly by searching
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A single search box lets the user find a saved bookmark. As the user types,
results filter live (with each keystroke) and matching text is highlighted.
The search matches across the bookmark's title, description, link, and tags at
once. Search spans both the "To read" and "Finished" tabs, so reading status
never hides a bookmark the user is trying to find; a summary line reports how
many results were found across both tabs. Clicking a tag chip on any bookmark is
a shortcut that filters the list to bookmarks with that tag, shown as a
removable filter that can be cleared. When the search box is empty and no tag
filter is active, the list shows the currently selected tab as normal. The
client chose live "search-as-you-type" over a run-on-submit search because it is
faster when only part of a title or description is remembered.

## Gherkin
Feature: Find a bookmark by searching

  Scenario: Live search as you type
    Given saved bookmarks exist
    When the user types text into the search box
    Then the list filters to matching bookmarks with each keystroke
    And matching text is highlighted

  Scenario: Search matches multiple fields
    Given a search term appears only in a bookmark's description (or link, or tag)
    When the user searches for that term
    Then that bookmark is included in the results

  Scenario: Search spans both reading states
    Given a matching bookmark is in the "Finished" tab
    When the user searches from any tab
    Then the finished bookmark still appears in the results
    And the results summary counts matches across both tabs

  Scenario: Filter by clicking a tag
    Given a bookmark shows a tag chip
    When the user clicks that tag chip
    Then the list filters to bookmarks carrying that tag
    And a removable tag filter is shown
    When the user clears the tag filter
    Then the list returns to its previous view

  Scenario: Empty search returns to tab view
    Given the search box is cleared and no tag filter is active
    Then the list shows the currently selected tab's bookmarks

## Assumptions
- Multiple space-separated terms all must match (AND).
- Matching is case-insensitive and substring-based.
- Search and tag filter can combine.
- While searching, results are shown across both tabs (tab selection applies
  only when not searching).
