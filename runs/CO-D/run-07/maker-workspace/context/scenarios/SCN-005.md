Title: Find bookmarks by search and by clicking a tag
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client finds bookmarks in two combinable ways:

Clicking a tag: clicking a #tag chip on any bookmark filters the collection to
everything carrying that tag. Active tag filters are shown as chips at the top
with an × to remove each and a "Clear all"; selecting several tags narrows to
bookmarks that have all of them.

Search box: typing filters the collection live across the title, description,
tags, note, and site/link. The search supports an expression language:
- Capitalisation is ignored.
- #tag matches that specific tag (not the word wherever it appears).
- "quoted text" matches an exact phrase.
- AND, OR, NOT (recognised on their own, in any capitalisation) combine terms,
  with parentheses for grouping, e.g. rome AND (#article OR #book).
- Two adjacent terms with no operator mean AND (narrow together).
- A quoted operator such as "OR" is treated as ordinary searchable text.
The search box and any active tag filters narrow together (AND).

When there are no matches, a clear "No bookmarks match" message is shown instead
of a blank list, and a result count (e.g. "3 of 5") is shown.

If an advanced expression cannot be understood (e.g. unbalanced brackets, a
dangling operator), the app does not block the search: it falls back to a plain
text search AND shows a small non-blocking notice that the advanced expression
wasn't understood.

The client confirmed all of the above, including the operator rules, adjacent-
terms-mean-AND, quoted operators as literal text, and the non-blocking fallback
notice.

## Gherkin
Feature: Find bookmarks

  Scenario: Filter by clicking a tag
    Given a bookmark shows a #tag
    When I click that tag
    Then only bookmarks carrying that tag are shown
    And the active tag filter is shown with a way to clear it

  Scenario: Narrow by multiple tags
    Given one tag filter is active
    When I add another tag filter
    Then only bookmarks that have all active tags are shown

  Scenario: Case-insensitive search
    When I type a query in any capitalisation
    Then matching ignores capitalisation

  Scenario: Tag token, phrase, and boolean operators
    When I type an expression using #tag, "exact phrase", and AND/OR/NOT with
         parentheses
    Then the results honour those operators
    And a quoted operator word is treated as ordinary text
    And two adjacent terms are combined with AND

  Scenario: Search and tag filters combine
    Given a tag filter is active
    When I also type search text
    Then only bookmarks matching both are shown

  Scenario: No matches
    When a query matches nothing
    Then a clear "no matches" message is shown instead of a blank list

  Scenario: Malformed advanced expression
    When I type an expression that cannot be understood
    Then the search is not blocked
    And results fall back to a plain text search
    And a small non-blocking notice says the advanced expression wasn't understood

## Assumptions
- Search reaches title, description, tags, note, and site/link.
- #tag matching is an exact whole-tag match (case-insensitive).
- Operator precedence: NOT before AND before OR; parentheses override.
