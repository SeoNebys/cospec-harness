Scenario ID: SCN-014
Title: Reuse an archived bookmark when its page is saved again
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When a person submits the address of a page whose existing bookmark is in the Archive, the app does not create a new copy. It plainly identifies that the bookmark already exists in the Archive and opens its current details. The person can update it while leaving it archived or edit and restore that same bookmark to the active library. Restoring after an edit confirms that the existing bookmark was both restored and updated with the exact new value, with no second copy created.

## Gherkin
Feature: Avoid duplicates across the active library and Archive

  Scenario: Recognize an archived duplicate
    Given a bookmark for a page exists in the Archive
    When the user submits that page's address to save it again
    Then the app states that the bookmark already exists in the Archive
    And the existing bookmark's current details are opened
    And no new bookmark is created

  Scenario: Update an archived duplicate without restoring it
    Given an archived duplicate has been opened
    When the user edits it and chooses to keep it archived
    Then the existing archived bookmark is updated
    And no new bookmark is created

  Scenario: Edit and restore an archived duplicate
    Given an archived duplicate has been opened
    When the user changes its title and restores it to the library
    Then the existing bookmark is updated with the changed title
    And it moves from the Archive to the active library
    And the confirmation identifies both the restore and update
    And no new bookmark is created

## Assumptions
- Duplicate detection searches both the active library and Archive.
- An archived duplicate may be updated in place without being restored.
