Scenario ID: SCN-003
Title: Add, reuse, view, and remove bookmark labels
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Labels are visible as pills on each bookmark card. A client can quickly add a made-up label directly beneath a card. As the client types, existing labels that match are suggested; selecting a suggestion immediately reuses that label and avoids a near-duplicate. Labels can also be managed from the bookmark's full in-card editor. Selecting the × on a label pill removes it from that bookmark with a clear confirmation, but does not delete the reusable label from the rest of the library.

## Gherkin
Feature: Organise bookmarks with personal labels

  Scenario: Add a new label directly to a bookmark
    Given a bookmark card is shown in the library
    When the client chooses to add a label on the card
    And enters a new label
    Then the label is attached to that bookmark
    And the label remains visible as a pill on the card

  Scenario: Reuse an existing label from suggestions
    Given an existing label has previously been used in the library
    When the client begins typing matching text while adding a label
    Then the existing label is suggested and identified as existing
    When the client selects that suggestion
    Then the existing label is attached to the bookmark without requiring the full name to be typed
    And a near-duplicate label is not created

  Scenario: Manage labels while editing a bookmark
    Given a bookmark's in-card editor is open
    When the client adds a label and saves the changes
    Then the label appears as a pill on the updated card

  Scenario: Remove a label from one bookmark
    Given a bookmark card has a label pill
    When the client selects the × on that pill
    Then the label is removed from that bookmark
    And the client is told it was removed from this bookmark
    And the label remains available for reuse on other bookmarks

## Assumptions
- Label matching for reuse is case-insensitive.
- Removing the last use of a label does not itself delete the label from the reusable library.
- Management of the reusable label library as a whole is outside the approved behaviour so far.
