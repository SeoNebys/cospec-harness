Scenario ID: SCN-006
Title: Keep a separate read-later list via an additional marker
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Tabs across the top switch between "All" (the main library) and "Read Later".
On any bookmark, a "Read later" action marks it; the card then shows a "Read
later" badge and the Read Later tab shows a count. "Read later" is an ADDITIONAL
marker (confirmed): the bookmark stays in All AND appears in Read Later. Removing
the marker ("Remove from read later") takes it out of the Read Later list without
deleting the bookmark. Search and tag filters continue to work within the Read
Later view. When the Read Later list is empty, a guiding empty message is shown.

## Gherkin
Feature: Read-later list

  Scenario: Marking a bookmark for reading later
    Given a bookmark in the main library
    When the client chooses Read later on it
    Then the bookmark shows a Read later badge
    And it still appears in the All view
    And it also appears in the Read Later view
    And the Read Later tab count increases

  Scenario: Removing the read-later marker
    Given a bookmark marked read-later
    When the client chooses Remove from read later
    Then the bookmark no longer appears in the Read Later view
    And the bookmark still exists in the All view (not deleted)

  Scenario: Empty read-later list
    Given no bookmarks are marked read-later
    When the client opens the Read Later view
    Then a guiding empty message is shown

## Assumptions
- Read-later is an independent marker, not a move out of the main library.
- Search/filters apply within the Read Later view too.
