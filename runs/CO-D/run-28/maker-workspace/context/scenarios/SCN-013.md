Scenario ID: SCN-013
Title: Sort the list, with an explicit default and a temporary override
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A sort dropdown beside the search box offers: Newest first, Recently updated,
Oldest first, Title A–Z, Title Z–A. "Recently updated" surfaces bookmarks most
recently edited. Sorting applies within the current view and alongside search and
tag filters. The client sets an explicit Default sort in Settings, which the app
returns to on open. Changing the dropdown is a temporary override for the session
only and does not change the default; a note distinguishes "sorted by default"
from a "temporary sort," with a link to return to the default.

## Gherkin
Feature: Sorting with default and temporary override

  Scenario: Default sort applied on open
    Given the client has set a Default sort in Settings
    When the client opens the app
    Then the list is ordered by that default

  Scenario: Temporary override does not change the default
    Given the list is showing the default sort
    When the client picks a different option in the sort dropdown
    Then the list re-sorts for this session
    And the default is unchanged
    And reopening the app returns to the default sort

  Scenario: Return to default
    Given a temporary sort is active
    When the client uses the return-to-default link
    Then the list re-sorts to the default

  Scenario: Recently updated ordering
    Given the client edits a bookmark's details
    When the sort is Recently updated
    Then that bookmark appears at the top

## Assumptions
- A bookmark's "updated" time changes when its details (title, description, note,
  tags) are edited.
- Saved details are never silently overwritten if the source page changes later;
  refreshing details would be an explicit action (noted for a future cycle).
