Title: Search bookmarks with a query language
Type: Happy Path

## Approved behaviour

A search box filters the currently shown list (it respects the active tab, e.g.
searching within "To read" stays within to-read items). Results update as the
client types; a clear (×) button empties the search. When nothing matches, a
friendly "no matches" message is shown instead of a blank list.

Search is case-insensitive throughout. The query supports:
- Plain words: loose substring match across title, description, note, tags, and
  web address (e.g. "plan" finds "planning").
- Multiple words separated by spaces: implicit AND (all must match) — the simple
  everyday default.
- `#tag`: exact tag match only (matches a bookmark whose tag equals the name,
  not merely text containing that word); distinct from a plain word on purpose.
- `"quoted phrase"`: matches the exact phrase as ordinary text. Quoting a word
  that would otherwise be an operator (e.g. `"or"`) makes it a literal search word.
- Boolean operators `AND`, `OR`, `NOT` (recognised in any capitalization) and
  parentheses `( )` for grouping, e.g. `rome (#article OR #book)`, `rome NOT #book`.

Precedence: NOT binds tighter than AND, AND tighter than OR; adjacent terms are
implicitly ANDed. A malformed/partial query degrades gracefully rather than erroring.

## Gherkin

Feature: Search

  Scenario: Case-insensitive plain search
    Given bookmarks about "Rome"
    When the client searches "ROME" or "rome"
    Then the same bookmarks match regardless of case

  Scenario: Exact tag search
    Given a bookmark tagged "reading" and another with the word "reading" only in its title
    When the client searches "#reading"
    Then only the tagged bookmark matches

  Scenario: Exact phrase
    Given a bookmark whose text contains "quarterly report"
    And a bookmark containing "quarterly" and "report" separately
    When the client searches '"quarterly report"'
    Then only the bookmark with the exact phrase matches

  Scenario: Boolean grouping
    Given rome bookmarks tagged "article" and "book"
    When the client searches 'rome (#article OR #book)'
    Then rome bookmarks tagged either article or book match

  Scenario: Exclusion
    When the client searches 'rome NOT #book'
    Then rome bookmarks that are not tagged book match

  Scenario: Operator word as literal
    When the client searches 'or'
    Then "or" acts as the OR operator
    When the client searches '"or"'
    Then "or" is treated as an ordinary search word

  Scenario: Search respects the active tab
    Given the "To read" tab is active
    When the client searches
    Then only to-read bookmarks are considered

  Scenario: No matches
    When a query matches nothing
    Then a friendly "no matches" message is shown

## Assumptions

- Plain words are substring matches; `#tag` is exact tag match.
- Space = AND; precedence NOT > AND > OR; parentheses group.
- Search filters the active view (tab) and updates live; × clears it.
