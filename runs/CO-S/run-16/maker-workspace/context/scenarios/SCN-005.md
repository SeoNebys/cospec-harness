Scenario ID: SCN-005
Title: Mark and revisit a bookmark to read later
Type: Happy Path
Approval status: approved
Approval session: SESSION-005
Approval cycle: 1

## Approved behaviour

The client can mark a bookmark for later with one click from its card. The Read later item in the sidebar immediately shows how many bookmarks are waiting. Opening that dedicated view shows the marked bookmarks, while each one also remains in the main collection. The application confirms when a bookmark is added to the reading list.

After comparing card controls, the client selected a labeled action that reads "Read later" before marking and "In Read later" afterward, making both the action and current state explicit.

## Gherkin

Feature: Keep a reading list within the bookmark collection

  Scenario: Mark a bookmark and revisit it from Read later
    Given a bookmark is in the main collection and is not marked for later
    When the user marks that bookmark for later from its card
    Then the application confirms that it was added to Read later
    And the Read later count in the sidebar increases
    When the user opens Read later from the sidebar
    Then the dedicated view contains the marked bookmark
    And the bookmark remains in the main collection

## Assumptions

- Read later is a state on a bookmark, not a separate copy of it.
- The card control is a labeled one-click toggle whose wording reflects the current state.
- Removing a bookmark from Read later is explored separately as an edge case.
