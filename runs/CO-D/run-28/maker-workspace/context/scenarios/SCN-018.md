Scenario ID: SCN-018
Title: Keep a private local copy (or the PDF) and, optionally, a public Internet Archive copy
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark offers two distinct preservation options:
1. Private local copy — a self-contained saved copy the client can view even if the
   original goes offline. For a PDF link, the stored copy is the PDF file itself.
   Capture can be triggered manually per bookmark ("Save a local copy" / "Save the
   PDF"), shows a saving state, then "✓ Local copy (date)" with View and Update.
   Optionally, a Settings switch auto-saves a local copy whenever a bookmark is
   saved. Manual capture/update remains available regardless.
2. Public Internet Archive copy — before creating it, a clear warning states it
   creates a PUBLIC copy on archive.org visible to anyone, requiring explicit
   confirmation. Once created, it shows "✓ Internet Archive · Open archived"
   linking to the archived address.

If a capture fails (e.g. a login-only or unreachable page), it fails gracefully
with a clear reason and a Try again option; the bookmark itself is left completely
intact.

## Gherkin
Feature: Page preservation

  Scenario: Save a self-contained local copy of a page
    Given a saved bookmark for a normal page
    When the client saves a local copy
    Then a self-contained copy is stored, viewable offline, with a capture date

  Scenario: A PDF's local copy is the PDF itself
    Given a bookmark whose address is a PDF
    When the client saves a local copy
    Then the PDF file itself is stored

  Scenario: Auto-capture on save when enabled
    Given the auto-capture setting is on
    When the client saves a new bookmark
    Then a local copy is captured automatically

  Scenario: Public warning before Internet Archive copy
    When the client asks to create an Internet Archive copy
    Then a warning states it will be public on archive.org
    And it is only created after explicit confirmation

  Scenario: Capture failure leaves the bookmark intact
    Given a page that cannot be captured (e.g. requires sign-in or is unreachable)
    When the client attempts to save a local copy
    Then it fails with a clear reason and a retry option
    And the bookmark is unchanged

## Assumptions
- EXTERNAL-SERVICE DEPENDENCY: capturing a live page and creating an archive.org
  snapshot are server-side/external jobs. The Phase 1 prototype SIMULATES them; a
  real capture/archive was not performed and is not claimed. Real implementation
  and its validation are Phase 2 concerns, and archive.org availability must be
  handled honestly.
- Local copies are private to the user; Internet Archive copies are public.
