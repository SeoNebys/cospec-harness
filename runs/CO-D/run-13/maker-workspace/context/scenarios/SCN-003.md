Scenario ID: SCN-003
Title: Reading state and archiving as independent choices, with All / Unread / Archived views
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A saved link has two independent properties:
- read state: Unread or Read
- archive state: Active (in the library) or Archived (put away)

The library offers three views:
- All: every non-archived link, whether Read or Unread
- Unread: only non-archived links that are still Unread
- Archived: links that have been put away

Each entry shows its state as badges (Unread/Read; plus Archived in the archived
view). In the All view, Read items remain visible but are drawn slightly dimmed
so Unread items stand out; the client approved this.

Behaviour:
- A newly saved link starts Unread and Active (appears in All and Unread).
- Marking a link Read removes it from Unread but keeps it in All (now shown Read).
- Marking a Read link Unread returns it to Unread.
- Archiving removes a link from both All and Unread and places it in Archived;
  this is "putting away", NOT deleting.
- Restoring an archived link returns it to the active library, preserving its
  prior Read/Unread state.

Status is changed via clearly labelled buttons on each entry — "Mark read",
"Mark unread", "Archive", "Restore". This labelled-button style was chosen by
the client over (A) a status pill/menu and (C) a checkbox-plus-icon, because the
labels make each action immediately understandable and archiving is not confused
with reading state.

## Gherkin

Feature: Reading state and archiving

  Background:
    Given read state (Unread/Read) and archive state (Active/Archived) are independent

  Scenario: New link starts unread and active
    When the client saves a new link
    Then it is Unread and Active
    And it appears in the All view and the Unread view

  Scenario: Mark a link read
    Given an Active Unread link
    When the client marks it Read
    Then it no longer appears in the Unread view
    And it still appears in the All view, shown as Read

  Scenario: Mark a read link unread again
    Given an Active Read link
    When the client marks it Unread
    Then it appears in the Unread view again

  Scenario: Archive a link
    Given an Active link (Read or Unread)
    When the client archives it
    Then it no longer appears in the All or Unread views
    And it appears in the Archived view
    And it is not deleted

  Scenario: Restore an archived link preserves reading state
    Given an Archived link that was <priorState> before archiving
    When the client restores it
    Then it returns to the active library
    And its reading state is still <priorState>
    Examples:
      | priorState |
      | Unread     |
      | Read       |

## Assumptions

- View names: All, Unread, Archived. Reading label: "Read" / "Unread"
  (client confirmed these read correctly).
- Read items in All are visually de-emphasised (slight dimming) — client
  approved as helpful.
- Archived items are retained indefinitely until restored (deletion is a
  separate, not-yet-explored action).
