Scenario ID: SCN-004
Title: Organise a bookmark with tags (reuse existing or create new)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

While saving or editing a bookmark, the client applies their own tags in a Tags
field. They can tap an existing tag to apply it. As they type, the list of
existing tags narrows to those whose name contains what they typed (matching
anywhere in the word, not only the start), so a partly-remembered tag is easy to
find and reuse — avoiding near-duplicate labels. Typing a new name and pressing
Enter creates a fresh tag in the same box. Tags are stored lower-cased and
de-duplicated, so "Work" and "work" are the same tag.

Applied tags appear on the saved card as soft green pills beneath the
description, visually distinct from the quiet grey source line (they read as the
client's own labels, not as the site source). Tags can be changed later through
the same edit panel.

## Gherkin

Feature: Tagging a bookmark

  Scenario: Reuse an existing tag by tapping it
    Given I am saving or editing a bookmark and some tags already exist
    When I tap an existing tag in the Tags field
    Then that tag is applied to the bookmark

  Scenario: Narrow existing tags by typing
    Given some tags already exist
    When I type part of a tag's name in the Tags field
    Then the existing tags narrow to those whose name contains what I typed
    And I can tap one of the narrowed tags to apply it

  Scenario: Create a new tag
    Given the Tags field
    When I type a name that is not an existing tag and press Enter
    Then a new tag with that name is created and applied

  Scenario: Tags are normalised
    Given I enter a tag using different letter casing or a leading "#"
    When the bookmark is saved
    Then the tag is stored lower-cased with no duplicates

  Scenario: Tags shown on the card
    Given a bookmark has tags
    Then its card shows those tags as pills beneath the description
    And they are visually distinct from the site source line

## Assumptions

- Tag filtering uses substring matching anywhere within the tag name.
- Tags are lower-cased; a leading "#" is stripped; surrounding whitespace trimmed.
