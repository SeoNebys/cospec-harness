Scenario ID: SCN-006
Title: Saving a link already saved takes you to the existing bookmark to edit, not a duplicate
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the user saves a link that already exists in the collection, no duplicate is
created. Instead the app takes the user to the existing bookmark and offers to
edit it.

Sameness rule (URL normalization):
- Two links are "the same" when, after normalization, they are identical.
- Normalization ignores: the protocol (http vs https), a leading "www.",
  capitalization of the host, a trailing slash, the "#fragment", and a known list
  of tracking parameters (utm_source/medium/campaign/term/content, fbclid, gclid,
  ref, ...).
- Any OTHER query parameter is kept as significant, because it can genuinely
  change the page.

Active duplicate:
- A message states the link is already saved (with its title, save date and
  reading status) and that no duplicate was created; the existing bookmark is
  highlighted/scrolled to.
- An "Edit existing" action opens that bookmark in the full, normal editor
  (title, link/web address, description, tags, note, reading status), using the
  same tag-pill entry with as-you-type suggestions and the same formatted-note
  editor with live preview as normal editing. Saving updates the existing
  bookmark; it is never duplicated.

Archived duplicate:
- The message says the link is already saved and is currently in the Archive
  (with save date); no duplicate is created; it does not auto-restore.
- Both "Edit existing" and "Restore it" are offered. Edit opens the same editor;
  Restore brings it back (to To read) without duplicating.

## Gherkin

Feature: Duplicate link handling

  Scenario: Saving an already-saved link does not duplicate
    Given a bookmark for a link already exists
    When the user saves the same link (allowing for normalization differences)
    Then no new bookmark is created
    And the user is taken to the existing bookmark

  Scenario: Normalization treats equivalent URLs as the same
    Given a saved link "https://www.nytimes.com/a/b.html"
    When the user saves "nytimes.com/a/b.html?utm_source=x#top"
    Then it is recognized as the same link and not duplicated

  Scenario: Distinct query parameters are different links
    Given a saved link with query "?id=1"
    When the user saves the same path with "?id=2"
    Then it is treated as a different link and can be saved

  Scenario: Edit the existing bookmark from a duplicate save
    Given a duplicate save was detected for an active bookmark
    When the user chooses "Edit existing"
    Then the normal editor opens (pills + live-preview note) for that bookmark
    And saving updates it without creating a duplicate

  Scenario: Duplicate of an archived bookmark
    Given the existing bookmark is archived
    When the user saves the same link
    Then no duplicate is created and it is not auto-restored
    And both "Edit existing" and "Restore it" are offered

## Assumptions

- The tracking-parameter list is a known, maintainable set; unknown parameters
  are preserved.
- Sameness is by normalized URL only (not by title or content).
