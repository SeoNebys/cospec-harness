Title: Save and reuse named searches
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When a search is active, the user can save it under a name. A saved search stores
the complete query — search text plus included and excluded tags — and the view
it was created in. Saved searches appear as named chips; clicking one re-applies
the query and switches to its view in one click. A saved search is re-evaluated
against the user's current bookmarks each time it is opened (not a frozen list),
so newly saved bookmarks that match appear too. Each saved search can be removed,
and saved searches persist between visits.

## Gherkin

Feature: Saved searches

  Scenario: Save the current search
    Given an active search with text and/or included/excluded tags
    When the user saves it under a name
    Then it appears as a named saved-search chip

  Scenario: Reapply a saved search
    Given a saved search
    When the user clicks its chip
    Then its full query is re-applied and its view is selected
    And matches are recomputed from the current bookmarks

  Scenario: Remove a saved search
    When the user removes a saved search
    Then its chip disappears

  Scenario: Persistence
    Given saved searches exist
    When the user returns in a later visit
    Then the saved searches are still available

## Assumptions
- A saved search stores the query and the view it was created in.
- Matches are computed live from current bookmarks, not stored as a fixed list.
- Saved searches persist between visits.
