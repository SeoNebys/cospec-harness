Scenario ID: SCN-013
Title: Preserve saved bookmark details as an owner-controlled snapshot
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
After a bookmark is saved, its title, description, image, personal note, tags, and other saved details remain exactly as the person last approved them. Later changes at the original webpage never overwrite the saved version automatically. Pulling newer page-supplied details, if offered, must be a deliberate action that previews the proposed changes before the person chooses to apply them. Doing nothing always preserves the saved version.

## Gherkin
Feature: Preserve saved bookmark details over time

  Scenario: Original page changes after a bookmark is saved
    Given a bookmark contains details the user approved or edited
    When the original page later changes its supplied title, description, or image
    Then the saved bookmark remains unchanged
    And the user's title, description, note, tags, and other saved choices remain intact

  Scenario: Deliberately consider fresh page details
    Given the original page supplies details different from the saved bookmark
    When the user explicitly chooses to check for fresh page details
    Then the proposed changes are previewed before being applied
    And the saved bookmark changes only if the user deliberately accepts them

## Assumptions
- No background or automatic metadata refresh overwrites saved content.
- Doing nothing preserves the last approved saved state.
