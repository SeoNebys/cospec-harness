Title: Prevent duplicate links
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The app never keeps two copies of the same address. When the client tries to save
an address that is already saved, no second copy is created; instead the client
is told it already exists and the existing link is opened in the editor so it can
be adjusted (title, note, topics). Duplicate detection spans both the main
collection and the archive — if the existing link is archived, that is
recognised too and the client is told, and the link is opened for editing.
When editing a link, changing its address to one another saved link already uses
is refused with a message, and the change is not saved. Address comparison is
case-insensitive and ignores a trailing slash.

## Gherkin

Feature: Preventing duplicate links

  Scenario: Saving an address that is already saved
    Given a link with a given address is already saved
    When I try to save the same address again
    Then no second copy is created
    And I am told it already exists
    And the existing link opens in the editor

  Scenario: Duplicate recognised across the archive
    Given the existing link with that address is archived
    When I try to save the same address again
    Then it is recognised as already saved (noting it is archived)
    And the existing link opens in the editor

  Scenario: Editing to an address another link already uses
    Given I am editing a link
    When I set its address to one another saved link already uses
    Then I am told the address is already in use
    And the change is not saved

## Assumptions

- Address comparison is case-insensitive and ignores a trailing slash.
- The duplicate check covers both the main collection and the archive.
