Scenario ID: SCN-017
Title: Archive (separate from Finished), restore, and permanent delete
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Archiving a link hides it from the normal list AND from search results, keeping it only
in a separate "Archived" view. This is deliberately distinct from "Finished": finished
links remain part of the normal collection and searches, whereas archived links are
hidden but recoverable. The Archived view is reached from a clearly labelled control
that shows the archived count, and it is flagged as hidden-from-normal. From there the
user can restore a link, which returns it to the normal list. Deleting a link removes it
permanently and requires an explicit confirmation before anything is lost. Both archive
and delete are available per-link and as bulk actions.

## Gherkin
Feature: Archive and delete

  Scenario: Archive a link
    Given a link is in the normal list
    When the user archives it
    Then it no longer appears in the normal list or in search results
    And it appears in the Archived view

  Scenario: Archived is distinct from Finished
    Given a finished (read) link and an archived link
    When the user views the normal list and searches
    Then the finished link still appears but the archived link does not

  Scenario: Restore an archived link
    Given a link is archived
    When the user restores it from the Archived view
    Then it returns to the normal list

  Scenario: Delete permanently with confirmation
    Given a link is selected for deletion
    When the user chooses Delete
    Then a confirmation warns it is permanent
    And only after confirming is the link removed for good

## Assumptions
- Search and the status filter operate only over non-archived links (except within the
  Archived view).
- Delete cannot be undone; archive can.
