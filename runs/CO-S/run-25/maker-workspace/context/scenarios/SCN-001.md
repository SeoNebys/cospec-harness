## Approved behaviour
The client saves a page by pasting a single web address into a "Save a link" box
and confirming (button or Enter). The saved item appears immediately at the top
of the library. The app automatically fetches the page's real title and a short
description; while this happens the item shows a brief "fetching" state, then
fills in.

Each saved item shows, as primary information: the real title, a short
description, and the site icon. Secondary information (site name / address and
the saved time) is shown more quietly beneath. The newest saved item appears
first so the list is easy to scan.

Clicking the item's title (or the site name) opens the original page in a new
browser tab, so the client can revisit the bookmark.

The client can rename any saved item, overriding the auto-fetched title with
their own text.

## Gherkin
Feature: Save a link to the library

  Scenario: Save a link by web address
    Given the client is on the library screen
    When the client enters a web address into the "Save a link" box and confirms
    Then a new item appears at the top of the library
    And the app automatically retrieves the page's real title and short description
    And the item displays the title, description, and site icon as primary info
    And the site name/address and saved time are shown as secondary info

  Scenario: Open the original page from a saved item
    Given a saved item exists in the library
    When the client clicks the item's title or site name
    Then the original page opens in a new browser tab

  Scenario: Rename a saved item
    Given a saved item exists in the library
    When the client renames the item and provides a new title
    Then the item displays the client's chosen title instead of the auto-fetched one

## Assumptions
- The page title and description are obtained by an automatic fetch of the page
  (simulated in the prototype; real fetch deferred to implementation).
- Newest-first ordering in the library.
- Opening a bookmark uses a new browser tab.
- The web address is entered/pasted as plain text; if the scheme is omitted it is
  assumed to be https.
