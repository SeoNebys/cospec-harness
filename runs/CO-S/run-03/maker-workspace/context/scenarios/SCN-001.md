Scenario ID: SCN-001
Title: Save a link into the one place
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The user pastes or types a link into a single input at the top of the page and
saves it. The saved link immediately appears at the top of a list below. Each
saved item is displayed as a recognizable **title on top with the web address
underneath** — the client confirmed this display helps him recognize a link later
and asked to keep it. The user only provides the link itself; a readable title is
produced automatically (the user does not type a title).

## Gherkin
Feature: Saving a link

  Scenario: Save a pasted link
    Given the user is on the bookmarks page
    When the user enters a link and saves it
    Then the link appears at the top of the saved list
    And it is shown as a title with the web address underneath

  Scenario: Newest saved link appears first
    Given the user already has saved links
    When the user saves another link
    Then the newly saved link appears above the existing ones

## Assumptions
- A human-readable title is derived automatically from the link; the user is not
  asked to type a title when saving. (Consistent with what the client experienced:
  he only pasted a URL and a title appeared.)
- Newest-first ordering in the list (client saw and did not object; revisit if
  browsing/grouping changes the natural order).
- Title auto-derivation is faked in the prototype; the real source of the title
  (fetched from the page) is a technical detail deferred to implementation.
