Scenario ID: SCN-002
Title: Saving a link already saved does not create a duplicate
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client saves a link they have already saved, the app does not create a second
copy. Instead it shows a gentle "you already saved this one — here it is" message and
scrolls to the existing entry, highlighting it briefly so the client can see and tweak
it. The client approved this as "gentle, not scolding"; a firmer response (refusing
outright) was explicitly rejected as "bossy."

"Already saved" is judged by the page the link points to, not the exact text of the
address. Tracking/marketing junk added when a link is clicked from an email or social
media (e.g. utm_source, utm_medium, utm_campaign, fbclid, gclid, and similar) is ignored
when comparing. However, the parts of an address that genuinely pick *which* page is
meant (e.g. the identifier that selects which video) are kept — two genuinely different
pages must never be merged just because they look similar.

## Gherkin
Feature: Duplicate detection when saving

  Scenario: Saving the exact same link again
    Given I have already saved a link
    When I save that same link again
    Then no second copy is created
    And I see a gentle "you already saved this" message
    And the app scrolls to and briefly highlights the existing entry

  Scenario: Saving the same page with tracking junk appended
    Given I have already saved "bbc.com/news/world-report"
    When I save "bbc.com/news/world-report?utm_source=email&fbclid=xyz"
    Then the app treats it as the same page
    And no second copy is created
    And it takes me to the existing entry

  Scenario: Saving two genuinely different pages that look similar
    Given I have saved one video link
    When I save a different video link that differs only in its page-identifying part
    Then the app treats them as two separate links
    And both are kept

## Assumptions
- Comparison normalises the address by: dropping "www.", dropping a trailing slash, and
  removing a known set of tracking parameters, while keeping all other parameters.
- The highlight is a brief visual emphasis on the existing entry, then it fades.
