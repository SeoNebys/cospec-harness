Scenario ID: SCN-009
Title: Work through a persistent read-later pile without deleting bookmarks
Type: Happy Path
Approval status: approved
Approval session: SESSION-009
Approval cycle: 1

## Approved behaviour
The client can add an existing bookmark to Read later with one action from its library card. Read later is a persistent library section with a count and a focused list containing only queued bookmarks. The client can mark a queued bookmark as read; it immediately leaves the pile and the count decreases, while the underlying bookmark remains safely available in the main library.

## Gherkin
Feature: Manage a read-later pile

  Scenario: Add a bookmark to Read later
    Given a bookmark is in the library and not in Read later
    When the client adds it to Read later from its library card
    Then the bookmark is included in the Read later section
    And the Read later count increases

  Scenario: View only queued bookmarks
    Given some library bookmarks are in Read later and others are not
    When the client opens the persistent Read later section
    Then only queued bookmarks are shown

  Scenario: Mark a queued bookmark as read
    Given a bookmark is visible in Read later
    When the client marks it as read
    Then it leaves the Read later section
    And the Read later count decreases
    But the bookmark remains in the main library

## Assumptions
- Read later is a standing library section rather than a temporary filter that must be rebuilt.
- Adding to Read later is available directly on each library card.
- Completion uses a plainly labelled "Mark read" button rather than an unlabeled circle, so it cannot be mistaken for deletion.
- Marking an item as read does not delete it or move it out of the main library.
