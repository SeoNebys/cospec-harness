## Approved behaviour
### Import
The client brings their existing bookmarks in en masse from a browser's exported
bookmarks file (the universal .html export that Chrome/Firefox/Edge/Safari all
produce); pasting a list of links is also offered. Crucially, import PREVIEWS
and asks first: it shows how many bookmarks were found, across how many folders,
and how many are already in the library and will be SKIPPED (reusing the
duplicate rule, SCN-003) — nothing is added until the client confirms. Silent
bulk import is explicitly rejected.

An option (a checkbox, defaulted ON) turns the browser's folders into labels
(the "Cooking" folder becomes a `cooking` label), so the topic bar works from
the first moment instead of leaving hundreds of unsorted links. It can be turned
off to import flat.

Imported links KEEP their original save dates from the export file (browser
exports record each bookmark's original add-date). Today's date is only a
fallback for a link with no recorded date. This is essential so "Oldest first"
(SCN-014) digs into the client's real history rather than collapsing everything
to today.

### Export
Two formats, meaning two different safeties:
- Bookmarks file (.html): the universal format that opens in any browser — the
  anti-lock-in guarantee ("even if this app vanishes, my links live on").
- Full backup (.json): everything exactly as held here — titles, descriptions,
  personal notes, labels, read-later and set-aside states — so a full restore is
  possible after a lost/replaced computer.

## Gherkin
Feature: Import and export

  Scenario: Preview before importing
    When the client selects a bookmarks file
    Then a summary of count, folders, and duplicates-to-skip is shown
    And nothing is imported until the client confirms

  Scenario: Folders become labels (optional, default on)
    Given the folders-as-labels option is on
    When the import completes
    Then each imported link is labelled with its folder name

  Scenario: Imported links keep their original dates
    When bookmarks are imported
    Then each keeps its original save date from the export
    And "Oldest first" orders them by those original dates

  Scenario: Skip duplicates on import
    Then links already in the library are skipped, creating no duplicates

  Scenario: Export in two formats
    Then the client can download a universal .html bookmarks file
    And a full .json backup including notes, labels, and read-later/shelf state

## Assumptions
- Preview-and-confirm, never silent import. (client confirmed)
- Folders→labels optional, default on. (client confirmed)
- Original save dates preserved on import. (client confirmed)
- Both export formats wanted; neither alone is enough. (client confirmed)
