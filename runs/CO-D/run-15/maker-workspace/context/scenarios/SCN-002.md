Scenario ID: SCN-002
Title: Return to an existing bookmark instead of saving an exact duplicate
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the client attempts to save the exact address of a bookmark already in the collection, the app does not create another copy. It explains that the link is already saved, moves the existing item into view, and highlights that item so the client can immediately identify it.

## Gherkin

Feature: Avoid duplicate bookmarks

  Scenario: Save an address already in the collection
    Given the client is signed in
    And a bookmark with the exact page address already exists in the collection
    When the client pastes that exact address into the visible paste box and saves it
    Then the app does not create another bookmark
    And the app tells the client that the link is already saved
    And the app moves the existing bookmark into view
    And the app highlights the existing bookmark

## Assumptions

- This scenario covers an exact match of the saved address.
- Recognition of tracked address variations is covered separately by SCN-012.
- Editing the existing bookmark after arriving at it is covered separately by SCN-009.
