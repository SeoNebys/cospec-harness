# Cycle 1 goal

## Client statement

> Honestly, the way I do it now is a mess. I paste links into a notes file and I can never find anything later, and half the time I've saved the same page twice without realizing.
>
> So when this is finished, here's what I'd want to feel different:
>
> When I save a link, I shouldn't have to type out what it is — I'd want the app to go grab the page's title and a little description and the site's icon automatically, so my list actually looks like something I can read and recognize at a glance, not just a wall of raw web addresses. And if I try to save something I've already saved, I don't want a second copy — I'd expect it to just take me to the one I already have so I can update it.
>
> Then I need to actually *find* things again. I'd want to search across everything I've saved, and I'd want to label things so I can pull up, say, just my recipes or just my work stuff.
>
> And I want to manage them over time — mark some as "I'll read this later" and see just those, edit or delete ones I don't want, and tidy up in bulk when my list gets long.
>
> That's the heart of it for me.

## Confirmed direction

Create a bookmark app that replaces the client's notes-file workflow with a readable, searchable, organized collection; automatically identifies saved pages; prevents duplicate entries; and supports later reading, editing, deleting, and bulk cleanup.

## Interface form

> A web app makes the most sense to me. I mostly run into links while I'm at my computer browsing, so I'd want to just open it in my browser and have everything there. It's really only for me — it's my own personal collection, not something I need other people logging into.
>
> If it happens to work okay on my phone screen too, that's a nice bonus, but I'm not picturing a separate phone app or anything I'd install. Web is the priority.
