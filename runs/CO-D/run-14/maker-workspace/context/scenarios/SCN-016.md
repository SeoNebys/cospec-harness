Scenario ID: SCN-016
Title: Ignore recognized tracking parameters during duplicate detection
Type: Edge Case
Approval status: approved
Approval session: SESSION-016
Approval cycle: 1

## Approved behaviour
When a submitted address differs from a saved address only by recognized marketing or referral tracking parameters, the site treats it as the same bookmark and opens the existing entry for editing rather than creating a duplicate. Meaningful address parameters remain part of page identity, so genuinely different pages are never merged merely because their differences occur after a question mark.

## Gherkin
Feature: Recognize tracked variants of saved addresses

  Scenario: Ignore recognized tracking parameters
    Given the library contains a bookmark for "https://roaming.example/rome"
    When the client submits "https://roaming.example/rome?utm_source=newsletter&utm_campaign=autumn"
    Then the existing bookmark opens for editing
    And no second bookmark is created

  Scenario: Preserve meaningful address parameters
    Given two addresses differ by a parameter that is not recognized as tracking
    When the client saves both addresses
    Then they remain eligible to be stored as distinct bookmarks

## Assumptions
- Only a maintained set of recognized marketing and referral parameters is ignored.
- Parameters with unknown or content-bearing meaning are preserved.
- Ignored tracking parameters do not replace the stored original address.
