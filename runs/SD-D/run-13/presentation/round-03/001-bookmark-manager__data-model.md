# Phase 1 Data Model: Bookmark Manager

## Conventions

- Durable records use UUID strings unless noted otherwise.
- Timestamps are UTC Unix milliseconds and are emitted as ISO 8601 strings by the API.
- SQLite foreign keys, defensive mode, and WAL journaling are enabled.
- All writes use prepared statements; multi-table mutations use explicit transactions.
- User-visible text is stored in its authored form. Separate normalized values exist only for equality, search, and sorting.

## Bookmark

Represents one unique saved destination in either the active or archived collection.

| Field | Storage | Rules |
|-------|---------|-------|
| `id` | TEXT primary key | UUID generated by the server; immutable |
| `url` | TEXT | Required HTTP(S) address; maximum 4,096 characters; preserves the accepted user-facing form |
| `normalized_url` | TEXT unique | Required; produced by the approved duplicate algorithm; unique across active and archived rows |
| `title` | TEXT | Required after trimming; 1–300 characters |
| `description` | TEXT nullable | User-editable short description; maximum 2,000 characters |
| `notes_json` | TEXT | Validated rich-note document serialized as JSON; maximum 100 KiB |
| `notes_text` | TEXT | Server-derived plain-text projection used by search; never accepted as trusted client input |
| `favorite` | INTEGER | Boolean `0`/`1`; default `0` |
| `to_read` | INTEGER | Boolean `0`/`1`; default `0` |
| `archived_at` | INTEGER nullable | Null means active; a timestamp means archived |
| `icon_asset_id` | TEXT nullable foreign key | References `media_assets.id`; `ON DELETE SET NULL` |
| `preview_asset_id` | TEXT nullable foreign key | References `media_assets.id`; `ON DELETE SET NULL` |
| `metadata_refreshed_at` | INTEGER nullable | Last successful or partial metadata retrieval attached to this bookmark |
| `created_at` | INTEGER | Set once on insert |
| `updated_at` | INTEGER | Advanced on every user-visible mutation |

### URL normalization

The service validates with the WHATWG URL parser, but it does not use the parser's fully serialized `href` as the unique key because that would normalize additional path forms the approved specification leaves distinct.

1. Trim surrounding whitespace.
2. Parse and require `http:` or `https:`.
3. Lowercase only the scheme and host.
4. Remove port 80 for HTTP and port 443 for HTTPS.
5. Represent an empty path as `/`.
6. Preserve every other path, query, and fragment byte sequence as accepted, including case and query ordering.

The normalization module owns both validation and reconstruction and is covered by an equivalence/non-equivalence table. Metadata retrieval separately removes the fragment from the outbound request without changing the stored address or key.

### Rich-note document

The root is a `doc` containing only the following node types:

- `paragraph`
- `heading` at levels 2 or 3
- `text`
- `bulletList`
- `orderedList`
- `listItem`
- `blockquote`
- `hardBreak`

Only `bold`, `italic`, and `link` marks are accepted. Link marks require an absolute HTTP(S) destination and discard all unapproved attributes. Nesting depth, total nodes, text length, and serialized size are bounded. The server walks the validated tree to create `notes_text` with structural whitespace between blocks.

## Tag

Represents one reusable label still attached to at least one active or archived bookmark.

| Field | Storage | Rules |
|-------|---------|-------|
| `id` | INTEGER primary key | Server-generated |
| `name` | TEXT | Trimmed display form from first creation; 1–50 characters |
| `normalized_name` | TEXT unique | Unicode NFKC, surrounding whitespace removed, internal whitespace collapsed, case-folded |
| `created_at` | INTEGER | Set once |

Tags that differ only by normalization share one row. Orphan tags are removed after bookmark tag replacement or permanent deletion, so suggestions represent tags still used somewhere in the collection, including Archive.

## BookmarkTag

Many-to-many join between bookmarks and tags.

| Field | Storage | Rules |
|-------|---------|-------|
| `bookmark_id` | TEXT foreign key | References `bookmarks.id`; `ON DELETE CASCADE` |
| `tag_id` | INTEGER foreign key | References `tags.id`; `ON DELETE CASCADE` |

The composite `(bookmark_id, tag_id)` is the primary key. A bookmark accepts at most 20 unique normalized tags. Reverse lookup is indexed by `(tag_id, bookmark_id)`.

## MediaAsset

Stores a safe, immutable raster derived from an untrusted remote image.

| Field | Storage | Rules |
|-------|---------|-------|
| `id` | TEXT primary key | Lowercase SHA-256 digest of processed bytes |
| `mime_type` | TEXT | `image/png` for icons or `image/webp` for previews |
| `bytes` | BLOB | Processed static raster bytes; never original SVG/HTML |
| `byte_length` | INTEGER | Must equal BLOB length and remain under the processed-output cap |
| `width` | INTEGER | Positive; icons at most 128 pixels wide, previews at most 1,200 |
| `height` | INTEGER | Positive; icons at most 128 pixels high, previews at most 630 |
| `created_at` | INTEGER | Set once |

Identical processed bytes share a row. Assets are served only by digest through the application with an immutable cache policy, strong ETag, exact content type/length, and `nosniff`. An asset may be removed only when no bookmark or unexpired metadata draft references it.

## MetadataDraft

Represents the short-lived result of safe metadata retrieval before the user saves a bookmark.

| Field | Storage | Rules |
|-------|---------|-------|
| `id` | TEXT primary key | Random unguessable UUID |
| `source_url` | TEXT | Submitted address |
| `final_url` | TEXT | Final validated address after redirects; informational only |
| `title` | TEXT nullable | Extracted and bounded to 300 characters |
| `description` | TEXT nullable | Extracted and bounded to 2,000 characters |
| `icon_asset_id` | TEXT nullable foreign key | Staged processed icon |
| `preview_asset_id` | TEXT nullable foreign key | Staged processed preview |
| `warnings_json` | TEXT | Typed partial-failure codes, never raw internal errors |
| `created_at` | INTEGER | Set on retrieval completion |
| `expires_at` | INTEGER | 30 minutes after creation |

The draft does not own the user's edited title or description. It supplies suggestions and asset references only. Saving verifies that the draft is unexpired and corresponds to the normalized submitted address, then attaches its available assets in the same transaction as bookmark creation/update. Draft expiry never deletes an asset still referenced by a bookmark or another draft.

## Preference

Singleton record holding the approved persistent display preference.

| Field | Storage | Rules |
|-------|---------|-------|
| `id` | INTEGER primary key | Always `1` |
| `sort_field` | TEXT | One of `title`, `createdAt`, `updatedAt`; default `createdAt` |
| `sort_direction` | TEXT | One of `asc`, `desc`; default `desc` |
| `updated_at` | INTEGER | Last preference change |

Search text, view, and filters remain in the route URL and are not durable preferences.

## SchemaMigration

| Field | Storage | Rules |
|-------|---------|-------|
| `version` | INTEGER primary key | Monotonically increasing migration number |
| `name` | TEXT | Stable migration name |
| `applied_at` | INTEGER | Successful commit time |

Each migration is atomic. Application startup refuses to run against a schema newer than the application understands.

## Derived search document

For each list request, the server selects the current view and filters, joins tag names, and builds a bounded search document containing:

- title
- original web address
- description
- `notes_text`
- normalized tag names

Values are Unicode NFKC-normalized and case-folded for comparison. Ordinary terms and quoted phrases perform partial substring matching across any one field; different AND operands may match different fields. `tag:` predicates compare an exact normalized tag. The parsed expression is evaluated before stable sorting and pagination.

## State transitions

| Current state | Action | New state | Preserved information |
|---------------|--------|-----------|-----------------------|
| Active, read | Mark To read | Active, To read | All details, favorite, tags, timestamps except `updated_at` |
| Active, To read | Mark read | Active, read | All details, favorite, tags |
| Active | Archive | Archived; `archived_at` set | Read status, favorite, tags, notes, media |
| Archived | Restore | Active; `archived_at` cleared | Read status, favorite, tags, notes, media |
| Active or archived | Permanently delete after confirmation | Removed | Nothing; unreferenced tags/assets become cleanup candidates |

Archived bookmarks retain `to_read` but are not members of the To Read view. Restoration makes a preserved To read bookmark visible there again.

## Transaction boundaries

### Create bookmark

1. Validate input, note schema, tags, and normalized URL before opening the transaction.
2. Start an immediate transaction and re-check `normalized_url` for a friendly conflict target.
3. Insert the bookmark, resolving an unexpired matching metadata draft.
4. Upsert normalized tags and replace join rows.
5. Delete/consume the draft reference and commit.
6. If the unique constraint wins a race, roll back and return the existing bookmark identity.

### Update bookmark

Validate first, then atomically update the bookmark, enforce the same unique key, replace tags, attach any refreshed draft assets, and remove orphan tags. A conflict leaves the original bookmark unchanged.

### Archive, restore, and status toggles

Each is a conditional update that verifies the expected current state. It changes `updated_at` and returns the full updated bookmark. Idempotent repeats return the existing state without creating duplicate history.

### Permanent deletion

Delete the bookmark and cascading joins in one transaction, remove orphan tags, then delete only media assets that are unreferenced by both bookmarks and unexpired drafts.

## Indexes

- Unique `bookmarks(normalized_url)`
- `bookmarks(archived_at, created_at, id)`
- `bookmarks(archived_at, to_read, created_at, id)`
- `bookmark_tags(tag_id, bookmark_id)`
- Unique `tags(normalized_name)`
- `metadata_drafts(expires_at)`

Additional indexes require measured query evidence; the approved scale does not justify speculative indexing.
