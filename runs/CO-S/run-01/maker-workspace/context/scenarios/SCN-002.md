Scenario ID: SCN-002
Title: Saving a link that is already in the collection
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user saves a link whose address is already in the collection, the app
does not create a duplicate. Instead it loads the existing bookmark into the
editor at the top, shows a message explaining the link is already saved,
highlights the matching entry in the list and brings it into view, and changes
the action button to "Update bookmark". Pressing "Update bookmark" saves the
user's changes onto the existing entry in place; no second copy appears.

The same update mechanism is available directly: each saved bookmark has an
"Edit" affordance that loads it into the editor for updating.

Two links are treated as the same page when they share the same host and path
(and query), ignoring differences of protocol (http vs https), a leading
"www.", a trailing slash, and capitalisation of the host. (Client-confirmed as
sensible.)

## Gherkin
Feature: Avoid duplicate bookmarks

  Scenario: Saving a link that already exists
    Given a link is already saved in the collection
    When the user enters the same link (by the matching rule) and presses "Save bookmark"
    Then no duplicate entry is created
    And the existing bookmark is loaded into the editor
    And a message explains the link is already saved
    And the existing entry is highlighted and brought into view
    And the action button changes to "Update bookmark"

  Scenario: Updating the existing bookmark after a duplicate attempt
    Given the existing bookmark is loaded into the editor after a duplicate save attempt
    When the user changes any details and presses "Update bookmark"
    Then the existing entry is updated in place
    And the total number of saved bookmarks is unchanged

  Scenario: Editing a saved bookmark directly
    Given a bookmark is saved in the collection
    When the user activates its "Edit" affordance
    Then that bookmark is loaded into the editor
    And pressing "Update bookmark" updates it in place

  Scenario: Link matching rule
    Given a link is saved
    When another link differs only by protocol, a leading "www.", a trailing slash, or host capitalisation
    Then the two links are treated as the same page

## Assumptions
- Duplicate detection happens at save time (client stated "if I save a URL that's
  already in my collection").
- "Take me to the existing bookmark" is realised as: load into the top editor +
  highlight the list entry (client-confirmed over the alternative of inline edit
  in place).
