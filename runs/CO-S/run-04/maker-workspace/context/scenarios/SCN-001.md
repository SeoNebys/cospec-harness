Scenario ID: SCN-001
Title: Save a link and see it land in one place with a readable name
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
On the bookmarks page there is a single input at the top. The user pastes or
types a link and clicks "Save". The link is immediately added to the top of the
list (newest first). The app automatically determines the page's name and shows
that name as the headline for the item, with the original web address shown in
small, secondary text underneath. A running count of how many links are saved is
shown above the list. Determining the page name happens automatically without
the user typing anything; while it is being determined the item briefly shows a
"getting the page name" state.

## Gherkin
Feature: Saving a link

  Scenario: Save a link and see it in the list
    Given the bookmarks page with an empty saving box
    When the user enters a link and confirms saving
    Then the link appears at the top of the list
    And the app shows the page's name as the headline
    And the original web address is shown as secondary text beneath the name
    And the saved-links count increases by one

  Scenario: Page name is determined automatically
    Given the user has entered a link and confirmed saving
    When the app is determining the page name
    Then the item shows a temporary "getting the page name" state
    And once determined the readable page name replaces that state
    And the user is not required to type a name

## Assumptions
- The page name is obtained automatically from the link (no manual entry required).
- Newest saved link appears at the top of the list.
- The original web address is shown as secondary (small) text under the name.
- A count of saved links is displayed.
- (Prototype only) page-name lookup is simulated; real lookup is a Phase 2 concern.
