Scenario ID: SCN-007
Title: Prevent duplicate links and guide to the existing one
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client tries to save a link whose address matches one already saved, the
app does not create a second copy. It shows an amber notice naming the existing
link ("You already saved this link (…). It won't be saved twice.") with a "Go to
it" action. Choosing "Go to it" clears any active search, tag filter, and read
view, scrolls to the existing link, and briefly highlights it so the client can
find and edit that one instead. Address comparison ignores a trailing slash.

## Gherkin
Feature: Duplicate link protection

  Scenario: Saving an address that already exists is blocked
    Given a link with a given address is already saved
    When the client tries to save the same address again
    Then no second copy is created
    And a notice names the existing link and offers to go to it

  Scenario: Go to the existing link
    Given the duplicate notice is shown
    When the client clicks "Go to it"
    Then any active search, tag filter and read view are cleared
    And the existing link is scrolled into view and briefly highlighted

## Assumptions
- Duplicate detection is by address, ignoring a trailing slash.
- Duplicates are prevented, not merely warned (per client's decision).
- The same protection applies when editing an address (see SCN-006).
