Scenario ID: SCN-008
Title: Set aside and complete read-later bookmarks
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
While reviewing a bookmark before saving, the user can turn on Read later. The bookmark remains in the main collection and is also included in a permanent Read later view with a visible count, ordered newest first. From that view, the user can mark an item done; it leaves Read later and the count decreases, but the bookmark remains saved in the main collection.

## Gherkin
Feature: Reading list

  Scenario: Add a new bookmark to Read later
    Given the user is reviewing a new bookmark before saving
    When the user turns on "Add to Read later"
    And saves the bookmark
    Then the bookmark is included in Read later
    And the bookmark remains included in All bookmarks

  Scenario: Open the Read later collection
    Given multiple saved bookmarks are marked Read later
    When the user selects Read later
    Then only bookmarks marked Read later are shown
    And the number of waiting bookmarks is displayed
    And the bookmarks are ordered newest first

  Scenario: Mark a read-later bookmark done
    Given a saved bookmark is shown in Read later
    When the user marks it done
    Then it is removed from Read later
    And the Read later count decreases
    And the bookmark remains in All bookmarks

## Assumptions
- Read later is an on/off choice shown during bookmark review.
- Read later is a permanent one-click destination.
- Marking an item done does not delete its bookmark.
