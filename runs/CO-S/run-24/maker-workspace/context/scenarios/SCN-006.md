Scenario ID: SCN-006
Title: Saving a link whose page details can't be read automatically
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the app cannot automatically read a page's details (private page, login
wall, page down, or no published title), the link is still saved — it is never
refused. The card falls back to showing the **web address as the title**, with a
small, non-alarming notice that the details couldn't be loaded automatically. The
site icon may be left blank (a neutral placeholder) — that is acceptable.

The user can then **add a title themselves**, and may **optionally add a
description** as well; neither is required. Once the user provides a title it
replaces the address as the displayed title. A manually added title/description
behave the same as auto-filled ones (e.g. they are searchable).

## Gherkin
Feature: Saving when auto-fill fails

  Scenario: Auto-fill fails but the link is still saved
    Given the app cannot read a page's title or description
    When the user saves the link
    Then the link is saved (not refused)
    And the card shows the web address as the title
    And a notice explains the details couldn't be loaded automatically
    And a blank/placeholder icon is acceptable

  Scenario: User supplies a title manually
    Given a saved link whose details couldn't be loaded
    When the user adds a title
    Then the title replaces the address on the card
    And the title is searchable like any other

  Scenario: User optionally supplies a description manually
    Given a saved link whose details couldn't be loaded
    When the user adds a description
    Then the description is shown and searchable
    And adding a description is optional, not required

## Assumptions
- Manual title/description editing is at least available whenever auto-fill did
  not provide them. (Whether the user can also edit an auto-filled title/desc on
  any link at will is a smaller open point; treated as allowed and low-risk.)
- The failure notice is informational, not an error that blocks use.
