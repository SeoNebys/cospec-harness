Scenario ID: SCN-011
Title: Sort and page through a large collection
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The list can be sorted by date added (newest first — the default — or oldest
first) and by title (A–Z or Z–A). The complete result set is sorted (and filtered
by any active search) before the first page is shown. The list shows 20 items at a
time with a "Load more" control that reveals the next 20, and an indicator like
"Showing 20 of 200". The match count always describes the whole result set, not
just the visible page, and this holds after searching or filtering. Choosing a
default sort and a default page size is a later-cycle preference.

## Gherkin
Feature: Sort and paging

  Scenario: Default newest-first paging
    Given more than 20 bookmarks exist
    Then the newest 20 are shown first
    And a "Load more" control and "Showing 20 of N" indicator are shown

  Scenario: Load more
    When the user clicks "Load more"
    Then the next 20 results are appended

  Scenario: Sort the whole result set
    When the user changes the sort to Title A–Z
    Then the entire result set is reordered before the first page is shown

  Scenario: Count reflects the whole result set after search
    Given a search is active
    Then the shown count equals the total number of matches, not the visible page
    And sorting and paging apply to the matched results

## Assumptions
- Default sort: newest first. Default page size: 20.
- Configurable default sort and page size are later-cycle (L-08).
