Scenario ID: SCN-008
Title: Long titles/addresses wrap; saved bookmarks persist across sessions
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Very long titles and web addresses wrap neatly within the card onto multiple
lines so the client can read the full text, rather than being truncated with an
ellipsis or overflowing the card.

Saved bookmarks persist: when the client returns and reopens the app later, the
bookmarks they saved (with their titles, tags, and read-later/read status) are
still there. Closing the browser does not lose them.

## Gherkin
Feature: Boundary display and persistence

  Scenario: Long title and address wrap
    Given a bookmark with a very long title or web address
    When it is shown in the list
    Then the text wraps within the card and remains fully readable

  Scenario: Bookmarks persist across sessions
    Given the client has saved bookmarks
    When the client closes and later reopens the app
    Then the previously saved bookmarks, tags, and read-later/read status are
      still present

## Assumptions
- Full text is preferred over truncation for long titles/addresses.
- Persistence covers titles, tags, and read-later/read status, not only the URL.
- The persistence mechanism (storage technology) is an implementation concern
  decided in Phase 2; the requirement is only that data survives across sessions.
