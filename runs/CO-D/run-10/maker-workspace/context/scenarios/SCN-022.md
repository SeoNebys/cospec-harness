Scenario ID: SCN-022
Title: Import an existing browser bookmark collection safely
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Import is available from a compact Library tools menu beside Save a link rather than occupying the everyday sidebar. The user chooses a browser bookmark export file and reviews a summary before the library changes. The review identifies new bookmarks, pages already in the library, and entries that cannot be imported. Browser bookmark titles are retained, folder names become labels, nested folder names are all applied as labels, and each original saved date is preserved when the file provides one. A bookmark without a saved date uses the import date.

Duplicate pages are recognized using the same normalized-address rules as ordinary saving. An imported duplicate is not added again and does not overwrite the existing bookmark's user-edited title, description, labels, or note. Entries without a usable web address are skipped and reported. After confirmation, the new bookmarks appear in the library and a concise result reports imported, existing, and skipped counts.

## Gherkin
Feature: Import browser bookmarks

  Scenario: Review a browser bookmark file before importing
    Given the user chooses a browser bookmark export file
    When the app reads the file
    Then the user sees counts for new, already-present, and unusable entries
    And sees the folder names that will become labels
    And sees how many original saved dates can be preserved
    And nothing has yet been added to the library

  Scenario: Import new browser bookmarks with their organization and history
    Given the import review contains usable new bookmarks
    When the user confirms the import
    Then each new link and browser title is added
    And each browser folder name is added as a label
    And nested folder names are all retained as labels
    And an original saved date is preserved when present
    And an entry without a saved date uses the import date
    And the app reports how many bookmarks were imported

  Scenario: Keep existing personal details when an imported page is already present
    Given the import file contains a page already in the library
    When the user confirms the import
    Then no duplicate bookmark is created
    And the existing bookmark's title, description, labels, and note remain unchanged
    And the result reports that the page was already present

  Scenario: Skip an unusable imported entry transparently
    Given an entry in the import file has no usable web address
    When the user confirms the import
    Then that entry is not added
    And the result reports that it was skipped

## Assumptions
- The import file is a standard browser bookmark export file.
- When the same folder name appears more than once, it reuses one case-insensitive label.
