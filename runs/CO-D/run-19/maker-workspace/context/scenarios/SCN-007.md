Scenario ID: SCN-007
Title: Keep unfinished reading in a separate Read Later queue
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark card has a clearly labeled Read later button. Selecting it changes the button to a checked In Read later state, confirms the action, and updates the queue count. The side navigation includes a distinct Read later destination that displays only queued bookmarks. Selecting the same checked control removes a finished item from the queue without deleting it from All bookmarks. If the last queued item is removed, the view shows a reassuring all-caught-up state that explicitly says finished bookmarks remain safe in All bookmarks.

## Gherkin
Feature: Keep unfinished reading visible

  Scenario: Add a bookmark to Read Later
    Given a bookmark is not in the Read Later queue
    When the client selects its clearly labeled Read later button
    Then the button changes to a checked In Read later state
    And the client is told it was added
    And the Read Later count increases by one

  Scenario: Visit the focused Read Later queue
    Given at least one bookmark is marked for later
    When the client selects Read later in the side navigation
    Then only bookmarks marked for later are shown
    And All bookmarks remains available beside it in the navigation

  Scenario: Finish the last queued bookmark
    Given the Read Later queue contains one bookmark
    When the client selects its checked In Read later control
    Then the bookmark is removed from the queue
    And the Read Later count becomes zero
    And an all-caught-up empty state is shown
    And the finished bookmark remains available in All bookmarks

## Assumptions
- Read Later is a bookmark status, not a separate copy of the bookmark.
- Removing a bookmark from Read Later does not imply archiving or deleting it.
- The side navigation is preferred over top tabs because it can accommodate more destinations as the library grows.
