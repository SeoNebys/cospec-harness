Scenario ID: SCN-017
Title: Capture the page's preview image on save; show it in review and Edit only
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When saving, the system also collects the page's preview image (its social/
preview image) when one is available, alongside the title, description, and icon.

The preview image is shown:
- large in the save-review panel, and
- in the entry's Edit view.

It is NOT shown in the main list: the client asked the list to stay image-free
(thumbnails made it feel busier and could leave awkward blanks when an image
fails to load). The image is still captured and stored for entries that have one.

## Gherkin

Feature: Preview image

  Scenario: Capture preview image on save
    Given the client saves a page that has a preview image
    Then the preview image is collected and stored with the entry

  Scenario: Show the image in review and edit, not the list
    Given an entry has a preview image
    Then the image is shown in the save-review panel and the Edit view
    And it is not shown in the main list

  Scenario: Page without a preview image
    Given the client saves a page with no preview image
    Then the entry is saved normally with no image

## Assumptions
- Source is the page's declared preview image (e.g. og:image / twitter:image),
  resolved to an absolute address.
- A broken/failed image simply does not display.
