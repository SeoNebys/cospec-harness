Scenario ID: SCN-004
Title: Find a saved link with instant search and a query language
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A search box sits above the list. As the client types, the list filters instantly
(no button or Enter needed). Clearing the box immediately restores the full list.
Search looks through each bookmark's title, description, and address, ignoring
capitalisation.

The search box accepts a query language:
- Multiple ordinary words are combined with implicit AND (all must appear).
- Explicit AND, OR, NOT operators are supported (case-insensitive as operators).
- Parentheses group sub-expressions.
- A phrase wrapped in "double quotes" is matched as an exact contiguous phrase.
- An operator word placed inside quotes (e.g. "and") is treated as a literal search
  word, not as an operator.

When no bookmark matches, a clear "No saved links match …" state is shown. A count
of matching links is shown while a search is active.

## Gherkin
Feature: Find a saved link

  Scenario: Instant filtering as the client types
    Given several bookmarks are saved
    When the client types a word into the search box
    Then the list narrows to matching bookmarks without pressing a button
    When the client clears the search box
    Then the full list is restored immediately

  Scenario: Case-insensitive matching across fields
    Given a bookmark whose title, description or address contains "Rome"
    When the client searches "rome" or "ROME"
    Then that bookmark matches

  Scenario: Implicit AND across ordinary words
    When the client types two ordinary words
    Then only bookmarks containing both words are shown

  Scenario: Boolean operators and grouping
    When the client searches "rome AND book"
    Then only bookmarks containing both are shown
    When the client searches "css OR pets"
    Then bookmarks containing either are shown
    When the client searches "rome NOT book"
    Then bookmarks containing "rome" but not "book" are shown
    When the client searches "rome AND (article OR book)"
    Then grouping is respected

  Scenario: Exact phrase and quoted operator words
    When the client searches a phrase in double quotes
    Then only bookmarks containing that contiguous phrase match
    When the client searches "and" in quotes
    Then "and" is treated as a literal word, not the AND operator

  Scenario: No results
    Given a search matches no bookmark
    Then a clear "no matches" message is shown

## Assumptions
- Searchable fields for plain words are title, description, and address.
- `#tagname` matches actual tags (implemented — see SCN-006). A quoted "#word" is
  treated as literal text, not a tag.
- Note text will be included in search once notes exist (deferred; see
  context/exploration-notes.md).
