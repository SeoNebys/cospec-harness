Scenario ID: SCN-021
Title: Save a recognizable fallback when page details are unavailable
Type: Error Case
Approval status: approved
Approval session: SESSION-021
Approval cycle: 1

## Approved behaviour
When a valid link cannot provide page title, description, icon, or preview details, the app still saves it rather than losing something the person meant to keep. The fallback card uses the domain and full URL as recognizable context, clearly explains why details are missing, and offers both inline title-and-description editing and a retry action.

## Gherkin
Feature: Preserve links when page enrichment fails

  Scenario: Save a valid link whose page details cannot be collected
    Given the person enters a valid web address
    And the page details cannot be collected
    When the person saves the link
    Then the bookmark is still saved
    And the fallback card shows the page domain and full URL
    And the card explains that page details were unavailable
    And the person can edit the title and description inline
    And the person can retry gathering page details

## Assumptions
- The web address itself is valid and safe to retain.
- Retrying does not discard manual edits unless new details are deliberately accepted.
