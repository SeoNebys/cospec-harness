Title: Page through, sort, and remember preferences for large collections
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Within a view, the user can choose how many bookmarks are shown at once
(10, 25 or 50 per page) and move through them in groups with Previous/Next
controls and a readout of the form "Showing 1–10 of N · page X of Y". The user
can sort by date added (newest first or oldest first) or by title (A–Z or Z–A);
the default is newest first. The paging control appears only when there are more
bookmarks than fit on a page. Sorting and paging apply to the current view,
including within search results. The user's chosen sort order and page size are
remembered across visits; after a reload the view returns to page 1.

## Gherkin

Feature: Sort and page a collection

  Scenario: Page through a large collection
    Given a view with more bookmarks than the chosen page size
    Then only one page of bookmarks is shown with a Previous/Next control and a count readout
    When the user presses Next
    Then the following group of bookmarks is shown

  Scenario: Choose page size
    Given a view with many bookmarks
    When the user selects a different "per page" amount
    Then that many bookmarks are shown per page
    And the paging control disappears when everything fits on one page

  Scenario: Sort order
    When the user selects a sort of date added (newest/oldest) or title (A–Z/Z–A)
    Then the bookmarks in the current view are ordered accordingly

  Scenario: Preferences are remembered
    Given the user has chosen a sort order and page size
    When the user reloads the app
    Then the same sort order and page size are applied
    And the view starts on page 1

## Assumptions
- Sort options: date added (newest/oldest), title (A–Z/Z–A); default newest first.
- Page-size options: 10, 25, 50; default 10.
- Sort and page size are remembered; current page is not (resets to 1).
