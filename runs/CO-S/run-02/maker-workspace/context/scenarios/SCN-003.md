Scenario ID: SCN-003
Title: Find a saved link by searching as you type
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The user has a search box above their list of bookmarks. As they type, the list
narrows live with each keystroke (no need to press Enter). A bookmark matches
if the typed text appears in either its name or its link address, so a word the
user remembers that is buried in the URL still surfaces the bookmark. Matching
text is highlighted in the results. A running count reflects how many match.
When nothing matches, the screen says so, naming the search text. Clearing the
search restores the full list.

## Gherkin
Feature: Search saved bookmarks

  Scenario: List narrows live as the user types
    Given the user has several saved bookmarks
    When the user types text into the search box
    Then the list immediately narrows to bookmarks matching that text
    And no separate submit action is required

  Scenario: Match on either name or link address
    Given a bookmark whose search term appears only in its link address
    When the user searches for that term
    Then the bookmark appears in the results

  Scenario: No matches
    Given the user has saved bookmarks
    When the user searches for text that matches none of them
    Then the screen indicates there are no matches for that text

  Scenario: Clearing the search restores the full list
    Given the user has an active search narrowing the list
    When the user clears the search box
    Then the full list of bookmarks is shown again

## Assumptions
- Search is live/instant as the user types, not submit-on-Enter (client confirmed).
- Search matches against both the name and the link address (client confirmed).
- Matching text is highlighted in results (facilitator choice, shown; not objected).
- Full list ordering remains newest-first (carried from SCN-001).
