Scenario ID: SCN-012
Title: Find bookmarks in a large collection with long details
Type: Edge Case
Approval status: approved
Approval session: SESSION-012
Approval cycle: 1

## Approved behaviour
The bookmark list can contain at least 121 items and remain one scrolling list when unfiltered. Search immediately narrows the large list using the complete bookmark name and web address. Unusually long names can occupy up to two lines, while long addresses and collection names are visually shortened so cards remain tidy and readable; the complete underlying text still participates in search.

## Gherkin
Feature: Large bookmark collections and long details

  Scenario: Search a large bookmark collection
    Given the personal collection contains 121 bookmarks
    And one bookmark contains “accessibility” in its long name
    When the user searches for “accessibility”
    Then the list immediately narrows to that one matching bookmark
    And the result count is 1

  Scenario: Keep unusually long bookmark details readable
    Given a bookmark has an unusually long name, web address, and collection name
    When its card is shown
    Then the card remains tidy and readable
    And the name uses no more than two visible lines
    And the long address and collection name are visually shortened
    And search still checks the complete name and web address text

  Scenario: Browse the unfiltered large collection
    Given the personal collection contains 121 bookmarks
    And no search or collection filter is active
    Then the bookmarks are available in one scrolling list
    And search and collection filters remain available as the quick way to narrow it

## Assumptions
- A realistically large personal collection includes at least 121 bookmarks.
- Visual shortening does not modify the stored bookmark or collection text.
- The unfiltered list does not require pagination in this cycle.
