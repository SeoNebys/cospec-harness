Scenario ID: SCN-003
Title: Find bookmarks with live, structured search
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A single search box filters the list live as the user types, case-insensitive,
across title, description, note, address, and tags. The search supports a query
language: a bare word matches anywhere; "quoted text" matches an exact phrase;
#tag matches that exact tag only; AND / OR / NOT and parentheses combine terms;
placing terms next to each other means AND (all must match). AND/OR/NOT are
operators only when unquoted; a quoted operator word (e.g. "and") is treated as
literal text. A match count is shown.

## Gherkin
Feature: Search bookmarks

  Scenario: Live case-insensitive full-field search
    Given bookmarks exist
    When the user types "Closure"
    Then only bookmarks containing "closure" in any field are shown, live

  Scenario: Exact tag match
    When the user searches "#book"
    Then only bookmarks tagged exactly "book" are shown
    And a tag merely containing those letters is not matched

  Scenario: Exact phrase
    When the user searches "\"before the interview\""
    Then only bookmarks containing that exact phrase are shown

  Scenario: Boolean combination with grouping
    When the user searches "rome AND (#article OR #book)"
    Then bookmarks matching "rome" and tagged either "article" or "book" are shown

  Scenario: Implicit AND between a word and a tag
    When the user searches "rome #book"
    Then only bookmarks matching both "rome" and tag "book" are shown

  Scenario: Quoted operator treated as literal
    When the user searches "\"and\""
    Then "and" is matched as text, not interpreted as the AND operator

## Assumptions
- Tag search (#tag) is an exact, case-insensitive tag match.
- Word/phrase operands search all fields including tags.
