Scenario ID: SCN-014
Title: Prevent duplicate tags that differ only by capitalization
Type: Edge Case
Approval status: approved
Approval session: SESSION-014
Approval cycle: 1

## Approved behaviour
When a bookmark already has a tag and the person tries to add the same word with different capitalization, the app treats it as the same tag. It keeps one consistent label and explains that the tag is already selected instead of creating a near-duplicate.

## Gherkin
Feature: Keep bookmark tags consistent

  Scenario: Add a capitalization-only duplicate tag
    Given a bookmark already has the tag "design"
    When the person tries to add the tag "Design"
    Then the bookmark still has exactly one "design" tag
    And the app explains that the tag is already selected

## Assumptions
- Tag duplicate comparison is not affected by capitalization.
- The existing tag spelling is preserved when a duplicate is rejected.
