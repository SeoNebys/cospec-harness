Scenario ID: SCN-009
Title: Track what is still to read vs. done (read status)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Every bookmark has a read status that is a dedicated concept of its own, separate
from tags. A newly saved bookmark starts as "To read" and shows a "To read"
badge. The client can mark a bookmark as read and can mark it as still to read
again. Read bookmarks remain visible in the "All" view but are visually dimmed so
finished items recede. Top-level views — All, To read, Read — let the client
focus, each showing a count; these views combine with tag filters and search.
When there is nothing left to read, an "all caught up" empty state is shown.

## Gherkin
Feature: Read status

  Scenario: New bookmark starts as to-read
    When the client saves a bookmark
    Then it is marked "To read" by default

  Scenario: Mark read and unread
    Given a to-read bookmark
    When the client marks it as read
    Then it is shown as read (dimmed) and no longer in the "To read" view
    And the client can mark it as to-read again

  Scenario: Read items stay in All view
    Given a read bookmark
    When the client views "All"
    Then the read bookmark is still listed (dimmed)

  Scenario: Focus views with counts
    Then All, To read and Read views are available, each showing a count
    And these views combine with tag filters and search

  Scenario: All caught up
    Given no bookmarks are still to read
    When the client opens the "To read" view
    Then an "all caught up" empty state is shown

## Assumptions
- Read status is a first-class status, not a tag (client confirmed).
- New bookmarks default to "To read" (client confirmed).
- Read items remain visible in All, dimmed (client confirmed).
