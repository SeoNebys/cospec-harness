Scenario ID: SCN-001
Title: Save a new link with auto-filled details
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The user pastes a web address into the save bar and starts saving. The app reads
the page and presents a review panel with the title and description filled in
automatically, together with the site's small icon and, when the page has one, a
preview image. The user can adjust the title and description, add an optional
personal note, and add labels. Saving is marked "Read later" by default; the user
can turn that off before saving. On confirming, the link appears as a card at the
top of the list showing the site icon, title, description, labels, and a
"Read later" tag when set. The full address and the personal note are shown but
kept visually quiet. When the page has no preview image, the card shows no
thumbnail area and the text uses the full width.

## Gherkin
Feature: Saving a link

  Scenario: Save a link whose page has a preview image
    Given the save bar is empty
    When the user pastes a link whose page can be read
    And the app finishes reading the page
    Then a review panel shows the auto-filled title and description
    And the panel shows the site icon and the page's preview image
    And the "Read later" option is on by default
    When the user confirms the save
    Then a new card appears at the top of the list
    And the card shows the icon, title, description, any labels, and a "Read later" tag
    And the card shows a preview thumbnail

  Scenario: Save a link whose page has no preview image
    Given the user is saving a link whose page has no preview image
    When the app finishes reading the page
    Then the review panel shows the icon but no preview image
    When the user confirms the save
    Then the resulting card shows no thumbnail area and the text uses the full width

  Scenario: Adjust auto-filled details before saving
    Given the review panel shows auto-filled details
    When the user edits the title or description, adds a note, or adds labels
    And the user confirms the save
    Then the saved card reflects the user's edits

  Scenario: Turn off Read later before saving
    Given the review panel has "Read later" on by default
    When the user turns "Read later" off
    And the user confirms the save
    Then the saved card has no "Read later" tag

## Assumptions
- "Read later" defaults to on because most saved links are things still to read
  (client-confirmed).
- The site icon and preview image are collected from the page automatically; in
  the prototype they are simulated stand-ins.
- Saved links are ordered most-recent-first.
- Address and personal note are de-emphasised in the card (see NF-001).
