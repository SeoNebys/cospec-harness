Scenario ID: SCN-014
Title: Import and export standard browser-bookmark HTML
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client can export the library as a standard Netscape bookmark HTML file (the
format browsers use), carrying each link's title, address, tags, and saved date.
The client can import a browser bookmark HTML file; imported links retain their
title, address, tags, and original saved date (so an old bookmark shows its real
original date, not today's). Import skips entries whose address is already in the
library and entries that are not usable addresses, and reports a count of
imported and skipped. On import, each folder in a bookmark's path is converted
into a tag (merged with any tags from the file's TAGS attribute, de-duplicated),
while generic browser root folders (Bookmarks bar, Other bookmarks, etc.) are not
turned into tags. App-specific fields — personal note, reading state, archived
state — are not part of the standard format and are not expected to survive this
round-trip.

## Gherkin
Feature: Bookmark import/export

  Scenario: Export the library
    Given links exist
    When the client exports
    Then a standard bookmark HTML file downloads with each link's title, address, tags, and saved date

  Scenario: Import retaining title, tags, and original date
    Given a bookmark file with an entry dated years ago and tags
    When the client imports it
    Then the link is added with that title, those tags, and that original saved date

  Scenario: Folder paths become tags, generic roots skipped
    Given an imported bookmark filed under Work > Research inside "Bookmarks bar"
    Then it is tagged work and research
    And it is not tagged "bookmarks bar"

  Scenario: Duplicates and malformed entries are skipped with a count
    Given a bookmark file containing an already-saved address and a malformed entry
    When the client imports it
    Then those are skipped
    And the client is told how many were imported and how many skipped

## Assumptions
- Round-trip fields: title, address, tags, saved date (Netscape format:
  HREF, TITLE text, ADD_DATE, TAGS).
- Duplicate identity is the normalised address.
- Folder names in the path become tags; a fixed set of generic root folders is excluded.
- Notes, reading state, and archived state are intentionally not carried by the
  standard format (a full private backup would be a separate feature — see backlog).
