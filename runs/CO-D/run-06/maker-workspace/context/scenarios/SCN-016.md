Scenario ID: SCN-016
Title: Bring in existing bookmarks — browser import with folders-as-labels, sane read status, and preserved dates
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Day one must not be a blank slate. The client can bring in the bookmarks they already
have, so their scattered collection lands in one place at once. IN SCOPE for v1
(client and facilitator agree import is close to the heart of the goal, not a nicety).

Source:
- Primary: import the browser's exported bookmarks file (Chrome/Firefox/Safari/Edge).
- Easy extra: paste a batch of links (covers "forever-open tabs" the client can copy).
- Deferred someday (NOT v1): pulling from emails-to-self (genuinely harder) — named,
  not held up for.

On import the client sees a preview ("Found N bookmarks in M folders") and decides:
- Turn folders into labels (DEFAULT ON): each browser folder becomes a label
  ("Recipes" -> recipes), so years of loose sorting carry over instead of collapsing
  into one undifferentiated heap. Off = flat import.
- Read status (DEFAULT "already handled, except Read Later"): imported bookmarks come
  in as already-handled (NOT on the To-read pile), because dumping hundreds onto
  To-read would bury it and destroy its meaning on day one. EXCEPTION: a "Read Later"
  (to-read style) folder is brought in as unread, since those genuinely were to-read.
  The client may override to "all to-read".
- Duplicates: links already saved are skipped (no copies), using the same tracking-
  aware "same link?" matching as SCN-007.

Preserve original dates (client-insisted): each bookmark keeps its ORIGINAL saved date
from the browser file when present, falling back to the import date only when an item
has none — so newest/oldest sorting and the sense of history stay intact.

Metadata is enriched lazily: titles come from the browser file immediately; site
icons, thumbnails, and descriptions fill in gradually afterwards rather than blocking
on fetching hundreds of pages up front.

## Gherkin
Feature: Importing existing bookmarks

  Scenario: Import a browser bookmarks file with folders as labels
    Given the client chooses their browser's exported bookmarks file
    And "turn folders into labels" is on
    When the import runs
    Then each bookmark is created with a label matching its folder
    And bookmarks already saved are skipped as duplicates

  Scenario: Imported items do not flood the To-read pile
    Given the default read-status option
    When the import runs
    Then imported bookmarks are marked already-handled
    Except bookmarks from a "Read Later"-style folder, which are marked to-read

  Scenario: Original dates are preserved
    Given the browser file records an original saved date for a bookmark
    When it is imported
    Then it keeps that original date for sorting
    And items without a recorded date fall back to the import date

## Assumptions
- Browser bookmark files typically include title, URL, folder, and add-date.
- Lazy enrichment: icon/thumbnail/description fetched after import, over time.
