Scenario ID: SCN-011
Title: Empty states and invalid link input are self-explaining
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client should never hit a blank or broken-looking screen:
- New/empty library: shows "No bookmarks yet. Paste a link above to save your
  first one." (An entry path ?empty=1 exists in the prototype only to demonstrate
  this state.)
- Empty Read Later and empty Archive views each show their own guiding message.
- No search/filter matches: shows "No bookmarks match your search…" rather than
  an empty void.
- Invalid link input (e.g. "not a real link"): nothing is saved; a helpful
  message "That doesn't look like a valid link — please check it and try again."
  is shown. A light validity check (parses as an http/https URL with a dotted
  host, no spaces) is sufficient (confirmed).
- Empty save box: pressing Save does nothing.

## Gherkin
Feature: Self-explaining empty and invalid states

  Scenario: Empty library
    Given the client has no bookmarks
    Then a prompt invites saving the first link

  Scenario: Empty read-later / archive views
    Given no bookmarks in the current view (read-later or archive)
    Then a guiding empty message for that view is shown

  Scenario: No search matches
    Given a search or filter matches nothing
    Then a "no matches" message is shown

  Scenario: Invalid link rejected
    Given the client enters text that is not a valid link
    When the client presses Save
    Then nothing is saved
    And a helpful invalid-link message is shown

  Scenario: Empty input ignored
    Given the save box is empty
    When the client presses Save
    Then nothing happens

## Assumptions
- Validity check: http/https URL with a dotted hostname and no spaces (light).
- ?empty=1 is a prototype-only demonstration entry, not a product feature.
