Scenario ID: SCN-004
Title: Set aside and finish a bookmark in read later
Type: Happy Path
Approval status: approved
Approval session: SESSION-004
Approval cycle: 1

## Approved behaviour
The client used a plain + Read later button on a bookmark card. The card visibly changed to show it was in read later and the read-later count increased, while the bookmark remained in the main collection. Opening the separate read-later view showed only the bookmark that had been set aside. Marking it as read removed it from that pile without deleting it from the overall bookmark collection. The client selected the plain text button over the alternative controls presented.

## Gherkin
Feature: Read bookmarks later

  Scenario: Set aside a bookmark to read later
    Given a bookmark is visible in the main collection
    When the user selects + Read later on that bookmark
    Then the bookmark remains in the main collection
    And the bookmark visibly indicates that it is in read later
    And the read-later count increases

  Scenario: View the read-later pile
    Given one bookmark has been set aside to read later
    When the user opens the Read later view
    Then only bookmarks set aside to read later are shown

  Scenario: Mark a read-later bookmark as read
    Given a bookmark is visible in the Read later view
    When the user marks the bookmark as read
    Then the bookmark is removed from the Read later view
    And the bookmark remains in the main collection

## Assumptions
- The card action is presented as a plain + Read later button.
- Read later is a separate view of bookmarks, not a separate copy or storage location.
- Marking a bookmark as read only clears its read-later status.
