Scenario ID: SCN-019
Title: Recognize noisy variations of an existing bookmark address
Type: Edge Case
Approval status: approved
Approval session: SESSION-019
Approval cycle: 1

## Approved behaviour
Duplicate detection ignores known tracking additions and an on-page section marker, so saving a noisy variation points to the existing bookmark and leaves the count unchanged. Other address parts that may identify genuinely different content remain significant.

## Gherkin
Feature: Recognize equivalent bookmark addresses

  Scenario: Save an existing page with tracking and a section marker
    Given a bookmark exists for "https://developer.mozilla.org/en-US/docs/Web/JavaScript"
    When the person saves "https://developer.mozilla.org/en-US/docs/Web/JavaScript?utm_source=newsletter#examples"
    Then no second bookmark is created
    And the count remains unchanged
    And the existing bookmark is brought into focus

  Scenario: Preserve meaningful address details
    Given an address detail is not a known tracking addition or section marker
    When duplicate detection compares the address
    Then that detail remains part of the comparison

## Assumptions
- Known tracking parameters include common campaign and click identifiers.
- A section marker identifies a location within the same page, not a separate bookmark.
