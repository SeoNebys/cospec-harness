Scenario ID: SCN-009
Title: Avoid duplicate bookmarks while preserving meaningful address differences
Type: Edge Case
Approval status: approved
Approval session: SESSION-009
Approval cycle: 1

## Approved behaviour
Saving the exact address of an existing bookmark does not create another copy; it opens the existing bookmark for editing and clearly states that no copy was made. Different forms of the same page are also recognised when differences are harmless clutter such as `www`, a trailing slash, tracking values, or a jump-to-section fragment. In that case the existing clean saved address is preserved. An address value that genuinely selects different page content is retained and creates a separate bookmark.

## Gherkin
Feature: Prevent duplicate bookmarks

  Scenario: Save an exact duplicate address
    Given the collection already contains a bookmark for an address
    When the client saves that exact address again
    Then no second bookmark is created
    And the existing bookmark opens for editing
    And a message explains that no copy was made

  Scenario: Save a cluttered form of an existing address
    Given the collection already contains a bookmark with a clean address
    When the client saves the same page with harmless www, trailing-slash, tracking, or section-fragment differences
    Then no second bookmark is created
    And the existing bookmark opens for editing
    And its clean saved address remains unchanged

  Scenario: Save an address that selects genuinely different content
    Given the collection contains a bookmark for one page
    When the client saves a related address whose retained value selects different content
    Then a separate bookmark is created
    And that meaningful address value is retained

## Assumptions
- Known newsletter and advertising tracking values do not identify distinct content.
- A fragment that jumps within a page does not identify distinct content.
- Non-tracking address values are preserved because they may select distinct content.
