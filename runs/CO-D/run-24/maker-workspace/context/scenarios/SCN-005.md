Scenario ID: SCN-005
Title: Archive older links out of the way (non-destructive, recoverable)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Each active bookmark has an "Archive" action. Archiving moves the link out of
both "All" and "To read" and into a dedicated "Archived" tab (with a live count).
Archiving is non-destructive: the link is kept, just moved aside.

Archived items are fully searchable within the "Archived" tab using the same
search language as elsewhere. Each archived item has a "Restore" action that
returns it to the active list ("All"), where it appears again.

Archiving takes priority over "read later": an archived link that is also marked
to read later does not appear in the "To read" tab while archived.

## Gherkin

Feature: Archive

  Scenario: Archive a bookmark
    Given an active bookmark
    When the client clicks Archive
    Then it leaves "All" and "To read" and appears under "Archived"
    And the "Archived" count increases
    And it is not deleted

  Scenario: Archived items stay searchable
    Given archived bookmarks
    When the client searches within the "Archived" tab
    Then the same search language filters the archived list

  Scenario: Restore an archived bookmark
    Given an archived bookmark
    When the client clicks Restore
    Then it returns to "All"

  Scenario: Archive supersedes read-later
    Given a bookmark marked "read later" that is then archived
    When the client views "To read"
    Then the archived bookmark is not listed there

## Assumptions

- Archived items live under their own tab, excluded from "All" and "To read".
- Archive is per-card; Restore is available in the Archived view.
- Archiving never deletes.
