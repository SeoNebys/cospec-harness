Scenario ID: SCN-010
Title: Saving edge cases — forgiving address entry, mistyped address, unreadable page details
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

- Forgiving entry: if the client omits the scheme (e.g. "example.com/story"), the
  app adds "https://" automatically and proceeds.
- Mistyped / non-address input (e.g. "not a url", a single word): clicking
  "Get details" shows a red note "That doesn't look like a web address. Please
  check it and try again." No details are filled and the Save button stays
  unavailable, so nothing broken is saved.
- Page details cannot be read (a page the app can't reach): clicking "Get details"
  shows "We couldn't read this page's details automatically. You can still type a
  title and save it." The auto-collected title/description/preview are blank, but
  the client can type a title themselves and save the bookmark normally. Saving
  stays reliable even when a site won't cooperate.

## Gherkin
Feature: Robust saving

  Scenario: Address entered without a scheme
    Given I enter "example.com/story" without http/https
    When I request the page's details
    Then the address is treated as "https://example.com/story" and details are collected

  Scenario: Input is not a usable web address
    Given I enter text that is not a web address
    When I request the page's details
    Then a "That doesn't look like a web address" message is shown
    And no details are filled
    And the Save action remains unavailable

  Scenario: Page details cannot be read
    Given I enter a valid address for a page whose details cannot be read
    When I request the page's details
    Then a message explains the details couldn't be read
    And the automatic title, description, and preview are empty
    When I type a title myself
    Then I can save the bookmark

## Assumptions
- A missing scheme is assumed to be https.
- "Unreadable details" still permits a manual save as long as a title is entered.
