Scenario ID: SCN-012
Title: Near-duplicate addresses are treated as the same bookmark
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Addresses that differ only by a trailing slash, or only by http vs https, are
treated as the same bookmark, so re-saving one of these variants does not create
a duplicate — it opens the existing bookmark for editing (per SCN-008). When the
same site+path is saved via https after an http copy exists, the secure (https)
address is preferred/kept.

## Gherkin
Feature: Address normalisation for duplicate detection

  Scenario: Trailing-slash variant is the same bookmark
    Given a bookmark exists for site.com/page
    When the client saves site.com/page/ (only a trailing slash differs)
    Then it is recognised as the same bookmark, not a duplicate

  Scenario: http and https variants are the same bookmark
    Given a bookmark exists for http://site.com/page
    When the client saves https://site.com/page
    Then it is recognised as the same bookmark
    And the secure https address is kept

## Assumptions
- Normalisation for matching: scheme-insensitive, host lowercased, a single
  trailing slash on the path ignored; query string is significant.
