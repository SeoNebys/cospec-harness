Scenario ID: SCN-007
Title: Details lookup fails or link is not valid — saving is not blocked
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user presses "Get details" for a link whose details cannot be
retrieved, the app shows a clear message ("Couldn't get this page's details.
You can still add a title yourself and save.") and still opens the editor with
empty title/description so the user can type their own title and save normally.
A failed details lookup never blocks saving.

When the entered text is not a valid link address, "Get details" responds with a
gentle message ("That doesn't look like a link yet.") rather than an error.

## Gherkin
Feature: Robust saving

  Scenario: Details cannot be retrieved
    Given the user has entered a valid link whose page details cannot be fetched
    When the user presses "Get details"
    Then a message explains the details could not be retrieved
    And the editor opens with empty title and description
    And the user can type a title and save the bookmark

  Scenario: Entered text is not a valid link
    Given the "Paste a link" field contains text that is not a link address
    When the user presses "Get details"
    Then a gentle message indicates it is not a link yet
    And no bookmark is created

## Assumptions
- In the Phase 1 prototype the fetch and its failure are simulated.
- On fetch failure the site name is left blank and the user supplies the title.
