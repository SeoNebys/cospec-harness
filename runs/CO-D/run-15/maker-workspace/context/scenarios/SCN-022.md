Scenario ID: SCN-022
Title: Resume after an expired sign-in without losing unfinished work
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Normal visits keep the client signed in. If a sign-in has expired after a long idle period, the app asks the client to sign in again before showing the private collection. After successful sign-in, the client returns to the same view. Any note or bookmark edit that had not been saved is restored as unfinished text; it is not silently committed.

## Gherkin

Feature: Preserve context while protecting an expired private session

  Scenario: Remain signed in during normal visits
    Given the client previously signed in successfully
    And the sign-in remains valid
    When the client returns for a normal visit
    Then the private collection is shown without another sign-in prompt

  Scenario: Resume an unfinished edit after a long-idle sign-in expires
    Given the client has unsaved note or bookmark-edit text
    And the sign-in expires after a long idle period
    When the app next requires access to the private collection
    Then the client is asked to sign in again
    And the unfinished text is not saved automatically
    When the client signs in successfully
    Then the client returns to the same view
    And the unfinished text is restored for the client to finish, save, or discard

## Assumptions

- Expiry occurs after an unusually long idle period or an external session-invalidating event, not on every normal visit.
- Restoring unfinished text does not imply that the text was committed to the bookmark.
- The text-based confirmation reason is recorded in the facilitation session log.
