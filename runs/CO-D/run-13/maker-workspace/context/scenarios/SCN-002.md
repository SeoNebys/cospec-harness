Scenario ID: SCN-002
Title: Re-saving an existing address opens the existing entry (no duplicates)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When the client saves an address that is already in the library, the system does
not create a second entry. Instead it recognizes the existing entry, shows a
gentle notice at the top ("You already saved this — here it is"), and carries the
view to that existing entry, briefly highlighting it so the client can review it.

Two addresses are treated as the same link when they differ only by:
- scheme (http vs https)
- a leading "www."
- a trailing slash
(A URL fragment is also ignored for this comparison.)

A genuinely different page (different host or path) is saved as a new entry as
normal. The client confirmed this matches how they think about "the same link,"
and that the notice + highlight makes the outcome clear without being disruptive.

## Gherkin

Feature: Prevent duplicate saves

  Scenario: Re-saving the exact same address
    Given a link is already saved in the library
    When the client saves that same address again
    Then no new entry is created
    And a notice tells the client the link is already saved
    And the view moves to the existing entry and briefly highlights it

  Scenario: Re-saving an equivalent address variant
    Given a link is already saved in the library
    When the client saves an address that differs only by scheme, a leading
      "www.", a trailing slash, or a URL fragment
    Then it is treated as the same link
    And no new entry is created
    And the view moves to the existing entry and briefly highlights it

  Scenario: Saving a genuinely different page
    Given a link is already saved in the library
    When the client saves an address with a different host or path
    Then a new, separate entry is created

## Assumptions

- Duplicate identity key = host without leading "www.", + path without trailing
  slash, + query string; scheme and fragment ignored (client confirmed the
  scheme/www/slash part explicitly).
- "Carry to the existing entry" is realized as scroll-into-view + a brief flash
  highlight, plus a dismissable notice.
