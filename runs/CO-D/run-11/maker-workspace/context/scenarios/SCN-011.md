Scenario ID: SCN-011
Title: Delete a bookmark permanently, with confirmation
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Deletion permanently removes a bookmark and is clearly separate from archiving.
The delete action lives inside the bookmark's editor (reached via Edit), visually
set apart in red, rather than on every card, so it is deliberate. Choosing delete
asks for a confirmation that names the bookmark and warns the action cannot be
undone; cancelling makes no change, confirming removes the bookmark for good.

## Gherkin
Feature: Delete a bookmark

  Scenario: Delete requires confirmation
    Given a bookmark's editor is open
    When the client chooses "Delete permanently"
    Then a confirmation naming the bookmark and warning it cannot be undone is shown

  Scenario: Cancel delete
    Given the delete confirmation is shown
    When the client cancels
    Then the bookmark is not removed

  Scenario: Confirm delete
    Given the delete confirmation is shown
    When the client confirms
    Then the bookmark is permanently removed

## Assumptions
- Delete lives inside the editor, set apart in red (client confirmed).
- A confirmation is required every time (client confirmed).
