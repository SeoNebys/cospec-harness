Scenario ID: SCN-018
Title: Reject blank or malformed bookmark addresses without losing input
Type: Error Case
Approval status: approved
Approval session: SESSION-018
Approval cycle: 1

## Approved behaviour
Saving never begins from a blank field or ordinary text that is not a complete web address. The site gives a plain, specific correction, preserves exactly what the client typed, and creates no junk entry. A complete address beginning with http:// or https:// can proceed normally after the correction.

## Gherkin
Feature: Validate bookmark addresses before saving

  Scenario: Reject a blank address
    Given the save-address field is empty
    When the client continues
    Then the site asks them to paste a web address
    And no bookmark is created

  Scenario: Reject ordinary text without changing it
    Given the client entered text that is not a complete web address
    When they continue
    Then the site explains that a complete address beginning with http:// or https:// is required
    And the entered text remains unchanged
    And no bookmark is created

  Scenario: Proceed after correcting the address
    Given an invalid-address message is visible
    When the client replaces the input with a complete http or https address
    And continues
    Then page-detail gathering begins normally

## Assumptions
- Only http and https addresses can be bookmarked.
- The site does not silently add a protocol or otherwise rewrite malformed input to make it valid.
