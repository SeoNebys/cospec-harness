Scenario ID: SCN-020
Title: Preserved copy of a saved page (self-contained page or PDF)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When a bookmark is saved, the app automatically captures a preserved copy of the
page. The kind of copy is decided by the actual file the link returns (its
content type), not merely the address: a PDF is preserved as the PDF file, and
any other page is saved as a self-contained page. The client can open the
preserved copy later from the bookmark (even if the original later disappears).
If capture failed at save time (page could not be fetched), no copy exists and
the client is offered a "try to capture now" retry.

## Gherkin
Feature: Preserved page copy

  Scenario: Automatic capture at save
    Given the client saves a bookmark whose page can be fetched
    Then the app automatically captures a preserved copy
    And a page whose returned file is a PDF is preserved as a PDF
    And any other page is preserved as a self-contained page

  Scenario: File kind from actual content type
    Given a link that returns a PDF but does not end in ".pdf"
    When it is captured
    Then it is preserved as a PDF

  Scenario: Open the preserved copy later
    Given a bookmark with a preserved copy
    When the client opens the saved copy
    Then the preserved page or PDF is shown, independent of the original site

  Scenario: Retry after failed capture
    Given a bookmark whose page could not be fetched at save time
    Then no preserved copy exists
    And the client is offered a retry to capture it

## Assumptions
- File kind is determined by the returned content type in implementation; the
  prototype approximated this from the address.
- Capture is automatic at save time.
