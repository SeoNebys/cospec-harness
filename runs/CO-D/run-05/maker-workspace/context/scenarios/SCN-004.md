Scenario ID: SCN-004
Title: Put several labels on one link, reusing existing labels
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Inside a link's Edit panel there is a Labels area. The client can put more than one label
on the same link (e.g. "recipes" and "dinner ideas" together); a link is never forced to
have a single home. Existing labels show as chips with an "×" to remove one.

As the client types a label name, the app offers matching labels they already have, so
they can click to reuse "recipes" rather than accidentally creating a second near-duplicate
pile ("recipe" vs "recipes"). A "＋ Create" option appears only when what they typed is
genuinely new. Choosing an existing label reuses it exactly; the nudge to reuse never
forbids creating a truly new label. The client called this "the safety I wanted... nudges
me back without forbidding me."

Pressing Enter picks the top offered choice; Backspace on an empty input removes the last
label.

## Gherkin
Feature: Labelling a link

  Scenario: One link wears several labels
    Given I am editing a link labelled "recipes"
    When I add the label "dinner ideas" and press Done
    Then the link shows both "recipes" and "dinner ideas"

  Scenario: Reuse an existing label instead of duplicating
    Given I have a label "recipes"
    When I type "recipe" in the label area
    Then the app offers the existing "recipes" for me to reuse
    And a "Create" option only appears if what I typed is genuinely new

  Scenario: Creating a genuinely new label is still allowed
    Given no label matches what I typed
    When I choose "Create"
    Then a new label is created and applied

## Assumptions
- A label typed identical (case-insensitive) to an existing one reuses the existing one.
- Labels persist for reuse even if temporarily not applied to any link.
