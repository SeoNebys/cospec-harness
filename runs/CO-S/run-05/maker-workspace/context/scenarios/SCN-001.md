Title: Save a link by pasting it
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
From the main screen, the user pastes or types a link into a single input box
at the top and clicks "Save". The link is stored and immediately appears at the
top of a list below the input (newest first). Each saved link is shown as a
readable title, with the site name and a small site icon beneath/beside it. The
input clears and is ready for the next link, so saving several links in a row is
quick. Before anything is saved, the screen shows an empty-state message
inviting the user to paste a link.

The client confirmed this saving flow feels simple and "out of the way", and
that title + site name + icon is the right amount of information to recognise a
link without clutter. Newest-on-top ordering was confirmed.

    Given nothing has been saved yet
    Then the screen shows a message inviting the user to paste a link

## Assumptions
- The list item composition is title + site name + site icon (client confirmed).
- Ordering is newest-first (client confirmed).
- The only saving method is pasting/typing a link into a box (client confirmed
  as "exactly the out-of-my-way I wanted"). Other capture methods (e.g. a
  browser extension / one-click capture while browsing) are noted as a possible
  future interaction but not required now.
- The displayed title is currently auto-derived from the link. Whether the user
  wants to name/edit a title is NOT yet explored (candidate for later).
