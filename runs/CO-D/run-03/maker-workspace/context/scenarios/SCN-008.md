Scenario ID: SCN-008
Title: Long content stays readable; empty To-read / Archived views
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Long content (boundary condition):
- A bookmark with a very long title, description, note, many tags, and a long URL
  stays readable. The title wraps; the description is trimmed to about 3 lines on
  the card; tags wrap onto multiple rows; the URL wraps rather than overflowing.
- The full description (and full note) is always revealed when the bookmark is
  opened or edited — truncation is only on the card.

Empty views (absence of data):
- When the "To read" view has no items, a reassuring message ("You're all caught
  up — nothing left to read") is shown with a pointer to All / Finished, not a
  blank list.
- When the "Archived" view is empty, a gentle explanatory message is shown.

## Gherkin

Feature: Readability and empty views

  Scenario: Long content is trimmed on the card but full on open/edit
    Given a bookmark with very long title, description and note and many tags
    When it is shown as a card
    Then the description is trimmed to ~3 lines and all text wraps within the card
    And opening or editing the bookmark reveals the full text

  Scenario: Empty To read view
    Given no bookmarks have the "To read" status
    When the user opens the To read view
    Then a friendly "all caught up" message is shown

  Scenario: Empty Archived view
    Given no bookmarks are archived
    When the user opens the Archived view
    Then a friendly explanatory message is shown

## Assumptions
- ~3 lines is the card description clamp; exact line count is a display detail.
