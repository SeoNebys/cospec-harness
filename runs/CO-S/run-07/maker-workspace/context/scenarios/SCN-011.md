Scenario ID: SCN-011
Title: Reject an unusable web address without losing it
Type: Error Case
Approval status: approved
Approval session: SESSION-011
Approval cycle: 1

## Approved behaviour
When the user enters text that is not a complete HTTP or HTTPS web address, the app keeps the entered text in place, explains the problem beside the field in plain language, and does not continue to page details until the address is corrected.

## Gherkin
Feature: Validate a bookmark web address

  Scenario Outline: Block an unusable web address
    Given the user has entered <entry> in the web address field
    When the user asks the app to get page details
    Then the entered text remains in the field
    And an inline message asks for a full address beginning with HTTP or HTTPS
    And the app does not continue to the page details

    Examples:
      | entry          |
      | "bookmark"     |
      | "example.com"  |
      | "ftp://example.com" |

## Assumptions
- Only HTTP and HTTPS website addresses can be saved.
- Address validation occurs before attempting to retrieve page details.
