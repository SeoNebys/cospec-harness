Approval cycle: 1

## Approved behaviour

Archiving:
- Each active bookmark has an "Archive" action that removes it from the main
  views (To read / Finished / All) so it stops cluttering the library.
- Archived bookmarks are reached through a separate "Archived" entry (not part of
  the To read / Finished / All switch), which shows a reassuring note that they
  are kept, not lost.
- Archiving preserves the bookmark's reading status (To read or Finished). A
  "Restore" action returns the bookmark to the main list in that same status.
- Archive is a single, reversible action (no confirmation needed).

Deleting:
- A separate "Delete" action permanently removes a bookmark (with its tags and
  note). It is visually distinct from Archive (different colour, icon, wording).
- Delete requires a confirmation dialog that names the bookmark, states the
  action cannot be undone, and points the user to Archive if they only want it
  out of the main list. The user confirms ("Delete permanently") or cancels.

Search scope:
- Archived bookmarks do not appear in ordinary searches (searches over the active
  library).
- Searching from within the Archived view searches only archived bookmarks.

## Gherkin

Feature: Archive and delete

  Scenario: Archive removes from main views but keeps the bookmark
    Given an active bookmark
    When the user archives it
    Then it no longer appears in To read / Finished / All
    And it appears under the Archived entry with its reading status preserved

  Scenario: Restore returns it in the same status
    Given an archived bookmark that was Finished
    When the user restores it
    Then it returns to the main list as Finished

  Scenario: Delete requires confirmation
    Given any bookmark
    When the user chooses Delete
    Then a confirmation appears naming the bookmark and warning it cannot be undone
    And it suggests Archive as the reversible alternative

  Scenario: Confirm delete removes permanently
    Given the delete confirmation is shown
    When the user confirms
    Then the bookmark, its tags and note are permanently removed

  Scenario: Cancel delete keeps the bookmark
    Given the delete confirmation is shown
    When the user cancels
    Then nothing is removed

  Scenario: Archived excluded from ordinary search
    Given some archived and some active bookmarks
    When the user searches from the main library
    Then only active bookmarks can match

  Scenario: Archived view search is scoped to archived
    Given the user is in the Archived view
    When the user searches
    Then only archived bookmarks are searched

## Assumptions

- Archive is a boolean state independent of reading status and tags.
- Delete is the only destructive action and is always confirmation-gated.
