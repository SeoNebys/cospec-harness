Scenario ID: SCN-011
Title: Save an unreadable page with honest fallback details
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When a valid page address cannot be read for automatic details, the app still saves the link. It displays the known address and site, uses a plain fallback title, clearly says that details were unavailable, invents neither a description nor a preview, and directs the client to edit the bookmark manually.

## Gherkin

Feature: Preserve valid links when page details are unavailable

  Scenario: Save a valid link whose page details cannot be gathered
    Given the client provides a valid page address
    And the page cannot be read for automatic details
    When the client saves the link
    Then the bookmark is saved
    And the bookmark displays the known address and site
    And the bookmark displays a plain fallback title
    And the bookmark clearly states that page details were unavailable
    And no description or preview is invented
    And the client is directed to edit the missing details manually

## Assumptions

- The address itself is valid even though its page cannot be read.
- The fallback state is visibly distinguishable from successfully gathered details.
- Manual correction uses the editing behaviour approved in SCN-009.
