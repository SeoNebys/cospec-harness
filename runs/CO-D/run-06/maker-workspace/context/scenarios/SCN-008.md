Scenario ID: SCN-008
Title: Delete a bookmark permanently from the editor, with a brief Undo
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A bookmark can be permanently deleted, but only via a deliberate detour:
- The delete action lives only inside the editor (opened via a card's pencil),
  never as a button on list cards. The list stays about visiting; deleting means
  opening the bookmark first.
- Delete is placed apart from Save, styled as a subdued red "Delete this bookmark",
  so it is not triggered by accident.
- On delete, the bookmark is removed immediately and the editor closes; a clear
  "Deleted … Undo" bar appears for a few seconds. Clicking Undo restores the
  bookmark to where it was. If the bar times out, the deletion stands.
- Rationale (client): when clearing clutter they delete several in a row, so a
  confirm-every-time prompt would nag; an undo net is "forgiving, not fussy".

## Gherkin
Feature: Deleting a bookmark

  Scenario: Delete from the editor with undo available
    Given the editor is open for a bookmark
    When the client chooses "Delete this bookmark"
    Then the bookmark is removed immediately
    And an "Undo" is offered for a few seconds
    When the client clicks Undo within that time
    Then the bookmark is restored

  Scenario: Deletion stands after the undo window
    Given a bookmark was just deleted
    When the undo window passes without the client clicking Undo
    Then the bookmark is permanently gone

  Scenario: No delete on list cards
    Given the client is looking at the bookmark list
    Then there is no delete control on the cards themselves

## Assumptions
- "Delete" here means permanent removal (contrast with a gentler "set aside",
  being explored next).
- The undo window is a few seconds (exact duration is a non-functional detail).
