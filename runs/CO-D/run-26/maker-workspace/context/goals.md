# Business goal

## Cycle 1 — recorded SESSION-001 (2026-09-26)

## Goal statement (in the client's words)

> My bookmarks are scattered and have become a place where links disappear
> rather than something I can use. I want one personal collection where I can
> quickly save a link without much effort, then reliably find it again months
> later.

> When I save something, I'd like the app to fill in useful details from the
> page automatically, while still letting me adjust the title or description and
> add a few tags or a note. Later, my priorities are searching by anything I
> remember, browsing a topic by tag, and keeping a separate "read later" view so
> unfinished reading doesn't get mixed into everything else.

## Core of the goal

- The heart is **trust**: nothing gets lost, and it can always be found again
  months later.
- **Effortless saving** is the enabler — it is what makes the collection
  practical enough to keep using, not the end in itself.

## Confirmed direction

- **One personal collection** (single user, personal use).
- **Effortless capture**: paste/enter a link; the app auto-fills useful page
  details (e.g. title, description). The client can adjust title/description and
  add tags and/or a note.
- **Reliable retrieval**, three priorities:
  1. Search by anything the client remembers.
  2. Browse a topic by tag.
  3. A separate "read later" view.
- **"Read later" semantics** (explicitly confirmed):
  - It is a **status toggle** (on/off) on a bookmark.
  - The bookmark stays in the same single collection regardless of status.
  - A **separate view shows only unread items**.
  - Marking an item as read **removes it from the unread view** without
    deleting it or moving it out of the collection.

## Interface form

- **Web application, used in a browser on a computer** — this is the priority
  experience.
- Phone usability is a "would be helpful" bonus, not a priority. Recorded in the
  non-functional backlog for a later cycle.

## Scope note

- First cycle runs through acceptance of this scope. Requests that change or add
  approved scenarios are recorded for later cycles.
