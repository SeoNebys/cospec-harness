Title: A reading pile that keeps itself honest (unread → read state)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

"Things I mean to read" is a **state** a bookmark is in (unread, then read),
NOT a label. This is core: it is the second half of the client's original pain
("a place to park things I mean to read"). A plain label failed because it
relied on the client to peel it off by hand, so the pile would rot into an
untrustworthy heap. The reading pile must keep itself honest.

Flagging (one tap, no label fishing):
- While saving, a single checkbox "📖 I still need to read this" marks the new
  bookmark unread.
- An already-saved read item can be flagged unread from "Edit details", and also
  via a quiet one-tap "📖 to read" control on the card (added for symmetry with
  "mark read"; kept unobtrusive so the list stays scannable).

Seeing the pile (in one spot):
- A top-level "📖 To read (N)" pill sits near the "🗂 Set aside" tray, always
  showing how many are unread.
- Clicking it narrows the list to only unread items — "what I still owe myself".
- Search and the chosen order still work within the pile.

Clearing (one tap, self-cleaning):
- Each unread card shows a "📖 To read" badge and a one-tap "✓ mark read".
- Marking read drops the item out of the pile immediately and lowers the count.
- When the last unread is cleared, a quiet "You're all caught up 🎉" appears —
  the pile empties itself rather than silently filling with already-read items.
- Undo covers both marking read and adding to the pile.

## Gherkin

Feature: The reading pile

  Scenario: Flag while saving
    When the client ticks "I still need to read this" while saving
    Then the new bookmark is unread and counts toward the reading pile

  Scenario: See only the reading pile
    When the client opens the "To read" pile
    Then only unread bookmarks are shown
    And search and ordering still apply within it

  Scenario: Mark as read clears it from the pile
    Given an unread bookmark
    When the client taps "mark read"
    Then it leaves the reading pile
    And the pile count decreases

  Scenario: The pile empties itself
    Given the reading pile is being viewed
    When the last unread item is marked read
    Then an "all caught up" state is shown

  Scenario: Flag an old item to read again
    Given a read bookmark
    When the client taps "to read" on it (or ticks the box in Edit details)
    Then it re-enters the reading pile

  Scenario: Undo protects reading actions
    Given the client just marked something read or added it to the pile
    Then Undo is offered to reverse it

## Assumptions

- Unread is a per-bookmark state, independent of labels.
- The reading pile is a filtered view of unread items, composing with search and
  ordering (and excluding set-aside items).
- Flag/clear are each one tap; both are undoable.
