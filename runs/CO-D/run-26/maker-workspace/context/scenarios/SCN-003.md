Scenario ID: SCN-003
Title: Recognize a duplicate link and edit the existing bookmark instead
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client tries to save a link that is already in the collection, the app
recognizes it, clearly states that the client is updating the existing bookmark
rather than creating a duplicate, and opens that existing bookmark's details for
editing. Confirming updates the existing bookmark in place; no second copy is
created. Keeping a single copy per link is important to the client.

## Gherkin
Feature: Single copy per link

  Scenario: Saving an already-saved link opens it for editing
    Given a bookmark for a link already exists in the collection
    When the client enters that same link and starts saving
    Then the app recognizes the link as already saved
    And it shows a clear message that the existing bookmark is being updated
    And it opens the existing bookmark's details for editing

  Scenario: Editing updates the existing bookmark in place
    Given the existing bookmark is open for editing after a duplicate save attempt
    When the client changes any details and confirms
    Then the existing bookmark is updated in place
    And no duplicate bookmark is created

## Assumptions
- Two links count as the same when their address matches after ignoring "www.",
  a trailing slash, and letter case.
