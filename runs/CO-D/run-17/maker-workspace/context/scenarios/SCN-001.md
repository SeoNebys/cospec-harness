Scenario ID: SCN-001
Title: Save a link with auto-filled details, reviewed before confirming
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client pastes a web address (full URL or shorthand such as "nytimes.com")
into a single save box and presses Save. The app looks up the page and opens a
calm inline "Review & adjust" panel showing an auto-filled title, a short
description, a preview image when the page provides one, the site icon, the site
name, the domain, and today's save date. The title and description are editable
before confirming. Pressing "Save to library" adds the link as a card at the top
of the library (newest first); the card links to the correct page. Pressing
Cancel discards the draft without saving.

## Gherkin
Feature: Saving a link

  Scenario: Save a link and review auto-filled details before confirming
    Given the save box is empty
    When the client enters "nytimes.com" and presses Save
    Then the app looks up the page
    And a review panel shows an editable title and description, a preview image
      when available, the site icon, site name, domain, and today's save date
    When the client optionally adjusts the title or description and presses "Save to library"
    Then the link is added as the newest card in the library
    And the card opens the correct page "https://nytimes.com/"

  Scenario: Cancel a draft before saving
    Given a review panel is open for a looked-up link
    When the client presses Cancel
    Then nothing is added to the library

## Assumptions
- The auto-filled details are: title, description, site icon, preview image
  (when the page provides one), site name, domain, and save date.
- Shorthand addresses without a scheme are normalised to https://.
- New links appear at the top (newest first) as the approved default order.
- Preview image and site icon are real in production; the prototype simulated
  them as stand-ins (placement/presence approved, not artwork).
