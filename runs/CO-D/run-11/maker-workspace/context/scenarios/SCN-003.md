Scenario ID: SCN-003
Title: Prevent duplicate bookmarks for the same address
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Saving an address that is already bookmarked does not create a second copy.
Instead the app takes the client to the existing bookmark, highlights it, and
opens it for editing, with a message explaining why. The same protection applies
when editing a bookmark's address: if the new address already belongs to another
bookmark, the change is refused and the client is taken to that existing
bookmark. Addresses that differ only by a trailing slash are treated as the same
address.

## Gherkin
Feature: No duplicate bookmarks

  Scenario: Saving an already-saved address
    Given an address is already bookmarked
    When the client saves that same address again
    Then no new bookmark is created
    And the existing bookmark is highlighted and opened for editing
    And a message explains it was already saved

  Scenario: Editing an address to one that already exists
    Given two saved bookmarks
    When the client edits one bookmark's address to match the other's
    Then the change is refused
    And the client is taken to the existing bookmark with that address

  Scenario: Trailing slash ignored when matching addresses
    Given a bookmark saved for an address
    When the client saves the same address differing only by a trailing slash
    Then it is treated as the same address (no duplicate)

## Assumptions
- Duplicate matching ignores a trailing slash (client confirmed).
- On a duplicate save, the existing bookmark opens directly for editing (client
  confirmed this is the most helpful response).
