Scenario ID: SCN-003
Title: Pasting an already-saved link opens the existing bookmark to update (no duplicate)
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the client pastes a link that is already saved and presses Save, the app
does not create a second copy. Instead it goes straight to the existing
bookmark's edit screen (the same edit screen from SCN-002), pre-filled with the
current details, and the existing bookmark is highlighted in the collection. The
edit screen clearly states "Already saved — update existing bookmark" so the
client understands why they are there and does not think the save failed. Saving
updates the existing bookmark; Cancel leaves it unchanged. A link counts as the
same as an already-saved one when the address matches ignoring: http vs https, a
leading "www.", and a trailing slash. The client confirmed this "same link" rule
matches their expectation and that these small differences must not create
duplicates.

## Gherkin
Feature: Prevent duplicate bookmarks

  Scenario: Paste a link that is already saved
    Given a bookmark for a link is already in my collection
    When I paste the same link (allowing for http/https, leading www., or a
         trailing slash differences) and press Save
    Then no second copy is created
    And the existing bookmark's edit screen opens, pre-filled with its details
    And the edit screen clearly indicates "Already saved — update existing bookmark"
    And the existing bookmark is highlighted in the collection

  Scenario: Update the existing bookmark from that screen
    Given the existing bookmark's edit screen has opened for a duplicate paste
    When I change details and press Save
    Then the existing bookmark is updated
    And still no second copy exists

  Scenario: Cancel from that screen
    Given the existing bookmark's edit screen has opened for a duplicate paste
    When I press Cancel
    Then the existing bookmark is left unchanged
    And no second copy exists

## Assumptions
- "Same link" normalisation: case-insensitive; ignore http vs https, a leading
  "www.", and a trailing slash. Other differences (e.g. query strings, different
  paths) are treated as different links.
