Scenario ID: SCN-020
Title: Import existing bookmarks from the browser in bulk; export everything back out
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client is migrating away from a scattered browser pile, so a trustworthy,
honest bulk move-in is part of the first real build.

Import:
- The client exports a bookmarks file from their browser and chooses it in the
  app (a web app cannot read the browser directly; the file hand-off is accepted).
- All links are read in one go. A readable copy is kept for each page that is
  still alive (per SCN-015).
- Browser FOLDERS become labels (lowercased; a nested folder yields its own
  label), which the client can rename or drop later.
- Each bookmark keeps its ORIGINAL saved date from the file, so years of history
  survive intact (not collapsed into "imported today") and date-ordering is
  meaningful.
- Duplicates are skipped — both against what is already saved and repeats within
  the file (per SCN-004).
- A page reachable but unreadable now is still imported and flagged "needs a
  title" (per SCN-012); nothing is dropped.
- Links ALREADY DEAD before import are brought in with their known title and
  date but honestly flagged "original gone · no copy", greyed, and counted
  SEPARATELY from healthy ones — never dressed up as saved-and-safe.
- Progress is shown; large imports can run in the background while the client
  uses the app.
- A blunt, complete summary reports exactly what happened (brought in / skipped
  duplicates / needs-a-title / already-dead), so the client trusts the move
  without re-checking against their browser.

Export:
- One file containing everything — links, labels, notes, original dates, AND the
  saved readable copies — in a standard format any browser or this app can read.
- Exportable anytime; the client is explicitly not locked in.

## Gherkin
Feature: Import and export

  Scenario: Bulk import from a browser bookmarks file
    Given the client chooses a bookmarks file exported from their browser
    When the app imports it
    Then all links are brought in, keeping each one's original saved date
    And browser folders become (lowercased) labels the client can edit
    And a readable copy is kept for each page still alive
    And duplicates (existing or within the file) are skipped
    And a clear summary reports exactly what happened

  Scenario: A link that is already dead on arrival
    Given an imported link whose page is already offline
    Then it is imported with its known title and date
    And it is flagged "original gone · no copy" and counted separately
    And it is never shown as saved-and-safe

  Scenario: Export everything
    When the client exports
    Then a standard-format file is produced containing links, labels, notes,
         dates, and the saved copies
    And the client can do this anytime and is not locked in

## Assumptions
- File hand-off import path (browser export → choose file). (Approved — not a dealbreaker.)
- Folders → editable labels; original dates preserved; dead-on-arrival honestly flagged. (Approved.)
- Export includes saved copies, standard format, anytime. (Approved.)
