Scenario ID: SCN-018
Title: Keep my own copy of the page — automatic, readable, searchable, honest
Type: Happy Path (+ edge behaviour)
Approval status: approved (experience approved; back end blessed)
Approval session: SESSION-001
Approval cycle: 3

## Approved behaviour
The app keeps its own copy of each page so the saved content is mine and survives the
original site dying. This is the deepest expression of the project goal ("stop losing
things").

Automatic & quiet (non-negotiable):
- When a bookmark is saved, a copy is made automatically, quietly, in the background,
  for everything — no button, no waiting, no nagging. Saving stays a one-second action
  (SCN-001 unaffected). Asking-later is useless: by the time a link is dead it's too
  late, so capture happens at save.

What the copy is (first pass = "readable copy", flavour A):
- The page's readable content — its text and main images — kept in a clean reading
  view, with the client's note pinned on top. Pixel-perfect layout is explicitly NOT
  the goal (client doesn't miss it). Full visual/pixel snapshot (B) is deferred.

Seeing it & trusting it:
- Each card shows a quiet "✓ copy kept" marker. Where a page could NOT be captured
  (e.g. login/paywall), it plainly shows "no copy — couldn't capture" — honesty over
  false comfort; never falsely assure something is safe.
- "View saved copy" is available ANY TIME on every card, not only when the original
  fails — because the original may be offline or may have quietly changed, and the copy
  is the version the client actually wanted. A copy only reachable after a 404 is one
  the client can't trust exists.

Searchable (the most-valued part):
- The saved copy's text joins search by default. A word only deep inside the saved
  copy (e.g. "parmesan rind") surfaces the bookmark.
- Search must always show WHY it matched: when the match is only in the saved copy,
  the card shows a short highlighted snippet from the copy, so a match is never a
  mystery. (Extends SCN-003's "see why it matched".)

When there's no copy:
- The note is always kept regardless. The app offers to find a public archived copy
  (external, flavour C) as an automatic fallback — clearly labelled as living on
  someone else's service and possibly absent. (Auto-detecting a dead original and
  prompting is the separate parking-lot P4; here the copy is simply always available.)

## Gherkin
Feature: Keeping my own copy of a page

  Scenario: A copy is kept automatically on save
    When the client saves a bookmark
    Then a readable copy of the page is captured in the background without any extra step
    And the card shows a quiet "copy kept" marker once it succeeds

  Scenario: View my copy at any time
    Given a bookmark with a kept copy
    When the client chooses "View saved copy"
    Then the saved text and images are shown with the client's note on top
    And this works whether or not the original site is reachable

  Scenario: Saved copies are searchable, with the reason shown
    Given a bookmark whose saved copy contains "parmesan rind"
    And whose title, note, and address do not
    When the client searches "parmesan rind"
    Then the bookmark appears
    And the card shows a highlighted snippet from the saved copy explaining the match

  Scenario: A page that cannot be copied is handled honestly
    Given a page that cannot be captured (e.g. behind a login)
    When the client saves it
    Then the card shows "no copy — couldn't capture"
    And the client's note is still kept
    And the app offers to look for a public archived copy

## Assumptions / design
- Requires the server-side piece (shared with real auto-fill metadata, DD-2): capturing
  arbitrary page content can't be done from the browser alone. Client build uses a
  capture abstraction; production adds the fetch/extract service.
- First pass stores readable text + image references; storage grows with the collection
  (acceptable; lighter than pixel snapshots).
- B (pixel snapshot) and P4 (auto dead-link detection/prompt) remain deferred.
