Scenario ID: SCN-018
Title: Save useful searches as reusable collections
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The user can save the current search — including labels to include (`#label`) and
exclude (`NOT #label`) and any other query terms — as a named collection. Saved
collections appear as chips near the search; tapping one re-runs its search in one step,
and the collection matching the current search is highlighted as active. When the current
search is not already saved, a "Save this search" control lets the user name and save it.
A collection can be removed with a single ×; because removing a saved search deletes no
bookmarks, there is no confirmation dialog, but a brief Undo is offered to recover from an
accidental removal. Collections persist between sessions.

Each saved search re-runs against the current collection every time it is used — it stores
the search, not a frozen list — so its results reflect bookmarks added, edited, relabelled,
or archived since it was saved.

## Gherkin
Feature: Saved searches

  Scenario: Save the current search
    Given the user has entered a search (which may include and exclude labels)
    When the user chooses "Save this search" and gives it a name
    Then a named collection is created and shown among the saved searches

  Scenario: Re-run a saved collection
    Given saved collections exist
    When the user taps a collection
    Then its search is applied and the list updates to those results
    And that collection is shown as active

  Scenario: Remove a collection with undo
    Given a saved collection exists
    When the user removes it with the ×
    Then it no longer appears among the saved searches
    And no bookmarks are affected
    And a brief Undo is offered that restores the collection if used

  Scenario: A saved search reflects the current collection
    Given a saved collection with some results
    When bookmarks matching it are later added, relabelled, or archived
    And the user re-runs the collection
    Then the results reflect the current state, not a frozen list

## Assumptions
- A collection stores a name and a search query; include/exclude labels are expressed
  through the existing query language (`#label`, `NOT #label`).
- Collections are remembered between sessions.
