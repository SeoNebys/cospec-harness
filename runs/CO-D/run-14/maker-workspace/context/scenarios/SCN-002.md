Scenario ID: SCN-002
Title: Reuse an existing bookmark when the same address is saved again
Type: Edge Case
Approval status: approved
Approval session: SESSION-002
Approval cycle: 1

## Approved behaviour
When the client tries to save an address that is already in the library, the site explains that it has already been saved and opens the existing bookmark within the save flow. Existing details, including personal notes, remain available for adjustment. Saving changes updates that bookmark and leaves exactly one copy in the library.

## Gherkin
Feature: Prevent duplicate bookmarks

  Scenario: Open the existing bookmark for a repeated address
    Given one bookmark already exists for a web address
    And that bookmark has personal notes
    When the client submits the same web address again
    Then the site explains that the address is already in the library
    And the existing bookmark opens for editing with its notes intact

  Scenario: Update the bookmark found during duplicate detection
    Given the existing bookmark has opened during the save flow
    When the client changes its title and saves the changes
    Then the existing bookmark has the changed title
    And the library still contains exactly one bookmark for the address

## Assumptions
- Comparison is case-insensitive and ignores a single trailing slash.
- Addresses that differ in other ways, including tracking query information, are distinct for the approved behaviour.
- Editing the existing bookmark happens inside the save flow.
