Scenario ID: SCN-005
Title: Find bookmarks with a case-insensitive search query language
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The search box accepts a query language, evaluated case-insensitively:
- Plain words: loose (substring) match across title, description, note, URL, and
  (also acceptable) tags and site name.
- "Quoted phrases": exact-substring match of the whole phrase.
- #tag: EXACT tag match (an intentional tag lookup; #test does not match a tag
  named "testing"). Confirmed: exact for #tag, loose for plain words.
- Operators AND, OR, NOT and parentheses ( ) for precise/grouped queries.
- Adjacent terms without an operator combine with implicit AND.
The result count line reflects the active query. The search combines with tag
filter chips (both apply). A short hint below the box shows the available syntax.

## Gherkin
Feature: Search bookmarks with a query language

  Scenario: Case-insensitive word search
    Given bookmarks exist
    When the client searches "TEST"
    Then bookmarks containing "test" in any searched field are shown regardless of case

  Scenario: Exact tag lookup
    When the client searches "#frontend"
    Then only bookmarks with a tag exactly equal to "frontend" are shown

  Scenario: Boolean AND across a word and a tag
    When the client searches "testing AND #frontend"
    Then only bookmarks matching the word "testing" AND tagged exactly "frontend" are shown

  Scenario: OR
    When the client searches "css OR design"
    Then bookmarks matching either term are shown

  Scenario: NOT
    When the client searches "reference NOT #design"
    Then bookmarks matching "reference" but excluding those tagged "design" are shown

  Scenario: Grouping with parentheses and quoted phrase
    When the client searches "(css OR design) AND reference"
    Then grouping is respected
    And a quoted phrase like "test suite" matches only that exact substring

## Assumptions
- Searched fields: title, description, note, URL, tags, site name.
- #tag is exact; plain words are loose substring matches.
- Implicit AND between adjacent terms; precedence NOT > AND > OR.
- A malformed query falls back to a plain substring search.
