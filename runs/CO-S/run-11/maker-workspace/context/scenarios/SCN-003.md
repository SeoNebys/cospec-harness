Scenario ID: SCN-003
Title: Separate "to read" from "finished" without deleting
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Saved bookmarks are organised into two views shown as tabs: "To read" and
"Finished", each showing a count of the items it contains. A newly saved
bookmark starts in "To read" by default. Each bookmark has a control to mark it
finished, which moves it out of the "To read" tab into the "Finished" tab
(nothing is deleted). From the "Finished" tab, a bookmark can be moved back to
"To read". The client chose this tab/move model over a single list with a
per-item toggle and filter buttons, because it keeps the "To read" view focused.

## Gherkin
Feature: Track reading status of bookmarks

  Scenario: New bookmark starts as to-read
    Given the user saves a new bookmark
    Then the bookmark appears in the "To read" tab
    And it does not appear in the "Finished" tab

  Scenario: Mark a bookmark finished
    Given a bookmark is in the "To read" tab
    When the user marks it finished
    Then it is removed from the "To read" tab
    And it appears in the "Finished" tab
    And it is not deleted

  Scenario: Move a finished bookmark back to to-read
    Given a bookmark is in the "Finished" tab
    When the user moves it back to "To read"
    Then it appears again in the "To read" tab
    And it is removed from the "Finished" tab

  Scenario: Tab counts reflect contents
    Given bookmarks exist in both states
    Then the "To read" and "Finished" tabs each show the count of their items

## Assumptions
- Exactly two states: "To read" and "Finished" (binary).
- Default state on save is "To read".
- Marking finished/unfinished never deletes the bookmark.
- Each tab displays a count.
