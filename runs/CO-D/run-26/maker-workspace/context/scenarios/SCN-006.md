Scenario ID: SCN-006
Title: Separate "Read later" view with mark-as-read that keeps the bookmark
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The collection offers two views via a tab switch, each showing a count: "All
bookmarks" and "Read later". The "Read later" view shows only bookmarks whose
read-later status is on, keeping unfinished reading separate from everything else.
All bookmarks live in the single collection regardless of view.

Read-later status is changed with explicit verb buttons on each card:
- In any view, a bookmark that is not in read later shows "Save to read later",
  which turns the status on.
- A bookmark that is in read later shows "Mark as read", which turns the status
  off.

Marking a bookmark as read removes it only from the "Read later" view; the
bookmark remains in "All bookmarks" and is not deleted or moved out of the
collection. Search and tag browsing operate within the current view. When the
"Read later" view has nothing waiting, a friendly "You're all caught up" empty
state is shown.

## Gherkin
Feature: Read-later view

  Scenario: Switch to the Read later view
    Given the collection has some bookmarks marked read later
    When the client selects the "Read later" tab
    Then only bookmarks with read-later status on are shown
    And each tab shows a count

  Scenario: Mark a bookmark as read from the Read later view
    Given the "Read later" view is showing a bookmark
    When the client clicks "Mark as read" on it
    Then it is removed from the "Read later" view
    And it still appears in "All bookmarks"
    And it is not deleted or removed from the collection

  Scenario: Save a bookmark to read later from the full collection
    Given a bookmark in "All bookmarks" is not in read later
    When the client clicks "Save to read later" on it
    Then its read-later status turns on
    And it appears in the "Read later" view and its count increases

  Scenario: Search and tag browsing apply within the current view
    Given the "Read later" view is active
    When the client searches or browses a tag
    Then only read-later bookmarks matching that search/tag are shown

  Scenario: Empty read-later view
    Given no bookmarks are marked read later
    When the client opens the "Read later" view
    Then a friendly "all caught up" empty state is shown

## Assumptions
- The view switch is presented as two tabs with counts (client-confirmed).
- The label "Read later" is used (client-confirmed over "Unread").
- Read-later status can be turned on or off from any view via the verb buttons.
- Read-later status can also be set while saving a new bookmark (see SCN-001).
