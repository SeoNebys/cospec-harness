Scenario ID: SCN-009
Title: Saving still works when the page can't be read automatically
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
If the automatic page-detail lookup fails, saving is not blocked. The draft
opens with the site address used as a stand-in title, an empty description, and a
clear notice that the page couldn't be read automatically and the client should
add or correct the details. The client can fill in the details, add tags/note,
and save normally.

## Gherkin
Feature: Save resilience on failed lookup

  Scenario: Automatic lookup fails
    Given the client enters a link whose page cannot be read automatically
    When the client presses Add
    Then a draft opens with the site address as a stand-in title
    And a notice explains the page couldn't be read automatically
    And the client can complete and save the bookmark

## Assumptions
- A failed lookup is distinct from an invalid address (which is rejected before a
  draft opens — see SCN-011).
