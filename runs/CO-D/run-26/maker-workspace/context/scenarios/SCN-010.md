Scenario ID: SCN-010
Title: Empty states and long-content robustness
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The app shows clear, friendly states when there is no data, and stays readable
with unusually large content:
- A brand-new collection is empty and shows a "Nothing saved yet" invitation
  (a real new collection starts empty; sample data is prototype-only).
- A search or tag browse with no matches shows a clear "no matches" message
  (distinct from the malformed-query warning in SCN-004).
- The "Read later" view with nothing waiting shows the "all caught up" state
  (see SCN-006).
- A bookmark with a very long title, description, or note, and many tags, wraps
  cleanly within its card without overflowing or breaking the layout.

## Gherkin
Feature: Empty states and robustness

  Scenario: Empty collection
    Given the collection has no bookmarks
    Then a "Nothing saved yet" invitation is shown

  Scenario: No search or browse matches
    Given a valid search or an active tag
    When nothing matches
    Then a clear "no matches" message is shown

  Scenario: Very long content stays readable
    Given a bookmark with a very long title, description, or note and many tags
    Then its card wraps the content cleanly without overflowing the layout

## Assumptions
- A real new collection starts empty (client-confirmed); sample bookmarks exist
  only in the prototype for demonstration.
