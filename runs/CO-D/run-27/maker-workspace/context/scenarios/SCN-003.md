Scenario ID: SCN-003
Title: Edit a saved bookmark's title, description, and address
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
From any saved bookmark the client can open an editor and change its title,
description, and the saved address. Saving applies the changes to that bookmark in
the list. Correcting the address never overwrites the client's own title or
description (no automatic re-fetch). The address field only accepts a valid web
link (http/https); other text is rejected with a clear message and the editor stays
open. If a corrected address would collide with a different saved bookmark, saving
is blocked with a message identifying the clashing bookmark.

## Gherkin
Feature: Edit a saved bookmark

  Scenario: Edit title and description
    Given a saved bookmark exists
    When the client opens its editor, changes the title and/or description, and saves
    Then the bookmark in the list reflects the new title and/or description

  Scenario: Correct the address without losing my text
    Given a saved bookmark with a client-edited title and description
    When the client changes the address to a different valid web link and saves
    Then the bookmark keeps the client's title and description
    And the bookmark's address is updated

  Scenario: Reject an invalid address
    Given the bookmark editor is open
    When the client enters text that is not a valid http/https link and tries to save
    Then saving is refused with a clear message
    And the editor remains open

  Scenario: Prevent an edit from creating a duplicate
    Given two saved bookmarks with different addresses
    When the client edits one bookmark's address to safely match the other and saves
    Then saving is blocked with a message naming the clashing bookmark

## Assumptions
- Default on address change is to preserve the client's title/description.
- A separate explicit "refresh page details" action is deferred (see
  context/exploration-notes.md).
