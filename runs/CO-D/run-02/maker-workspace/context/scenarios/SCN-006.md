## Approved behaviour

Tidying must feel safe, or the client will hoard out of fear. There are two
clearly separated actions, both offered in "Edit details":

Set aside (the gentle one):
- Removes the item from the main list without destroying it.
- Set-aside items do **not** clutter searching or roundups — they are properly
  out of the way until the client goes looking.
- A small "🗂 Set aside (N)" tray indicator appears so the client knows things
  are tucked away, not lost.
- From the tray the client can **Bring back** an item to the main list, or
  **Delete for good**.

Delete for good (for genuinely dead items):
- Permanent removal, guarded by a "click again to be sure" confirmation.

Undo on both (what makes the client brave):
- After setting aside, bringing back, or deleting for good, a brief toast offers
  **Undo**, restoring the previous state — so an absent-minded click never
  costs anything.

## Gherkin

Feature: Tidying with set aside and delete

  Scenario: Set something aside
    When the client sets a bookmark aside
    Then it leaves the main list
    And it no longer appears in searches or roundups
    And a "set aside" tray shows it is tucked away, not gone

  Scenario: Bring something back
    Given a bookmark is set aside
    When the client brings it back from the tray
    Then it reappears in the main list

  Scenario: Delete for good is guarded
    When the client chooses "Delete for good"
    Then a confirmation is required before it is removed

  Scenario: Undo protects every tidy action
    Given the client has just set aside, brought back, or deleted a bookmark
    Then a brief Undo is offered
    When the client uses Undo
    Then the previous state is restored

## Assumptions

- Set aside is fully reversible and hides items from list/search/roundups.
- Delete for good is permanent (subject to the brief Undo window).
- Undo restores the immediately preceding action only.
