## Approved behaviour
For a link that is NOT junk but that the client is done with or that clutters the main
list, "Put away" tucks it out of sight while keeping it safe — a distinct middle ground
from deleting. Put-away links leave the main list AND are excluded from search AND from
label piles AND from the to-read pile — properly out of the client's face. They live in a
"🗄 Put away" back room, reachable in one click from the top-right and showing its own
count so it is never forgotten. From there the client can "↩ Put back" to restore a link
to normal, or delete it for good.

"Put away" sits in the same Edit/manage panel as Delete, but visually separated (quiet grey
vs. red, opposite sides) so "tuck away" and "destroy" are never mixed up. The client
confirmed this is exactly the "out of my face but never thrown out, and I can always dig it
back out" middle ground they wanted.

## Gherkin
Feature: Putting a link away

  Scenario: Put a link away
    Given a saved link
    When I put it away
    Then it leaves the main list
    And it does not appear in search results
    And it does not appear under any label or in the to-read pile

  Scenario: The back room
    Given links that are put away
    When I open the "Put away" area
    Then I see those links with a count
    And I can put any of them back to normal

## Assumptions
- Put-away is reversible at any time; it never alters the link's labels or read state.
- Putting away clears its to-read status (it shouldn't sit in a pile while hidden);
  putting it back does not automatically re-add it to to-read.
