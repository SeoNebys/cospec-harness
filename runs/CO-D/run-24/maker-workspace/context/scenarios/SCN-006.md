Scenario ID: SCN-006
Title: Permanently delete a bookmark with confirmation
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A permanent "Delete" action is available on every bookmark — both active and
archived. It is visually distinct (red) and separate from Archive so the
reversible and irreversible actions are not confused.

Clicking Delete opens a confirmation dialog that names the specific bookmark and
states plainly that deletion cannot be undone (unlike Archive). The client can
Cancel (nothing happens) or confirm ("Delete permanently"), which removes the
bookmark for good from wherever it was.

## Gherkin

Feature: Delete

  Scenario: Confirmation required before delete
    Given a bookmark (active or archived)
    When the client clicks Delete
    Then a confirmation dialog appears naming that bookmark and warning it cannot be undone

  Scenario: Cancel delete
    Given the delete confirmation is open
    When the client cancels
    Then nothing is removed

  Scenario: Confirm delete
    Given the delete confirmation is open
    When the client confirms
    Then the bookmark is permanently removed from all views

  Scenario: Delete available for archived items
    Given an archived bookmark
    When the client deletes it and confirms
    Then it is permanently removed

## Assumptions

- Delete is distinct from Archive (colour + separation) and available in every view.
- Deletion is irreversible and always confirmed via a named dialog.
