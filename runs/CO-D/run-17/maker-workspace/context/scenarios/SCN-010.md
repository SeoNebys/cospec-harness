Scenario ID: SCN-010
Title: Archive links (tidy away without deleting), restore, and deliberate delete
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Any link in the main library can be archived ("tidy away") from its card.
Archived links are absent from the All, To read, and Reference views and from
searches run in those views; they live in a separate Archived view. Archiving
does not delete: a link keeps its tags, note, reading state, and all details, so
restoring it from the Archived view returns it unchanged to the main library.
Search run within the Archived view searches only archived links. Permanent
deletion is possible only from the Archived view and requires a confirmation, so
a link cannot be lost by accident from the main library. The Archived view shows
a calm empty state when nothing is archived.

## Gherkin
Feature: Archiving and deletion

  Scenario: Archive a link
    Given a link is in the main library
    When the client archives it
    Then it disappears from All, To read, and Reference
    And it appears in the Archived view
    And the main-view searches no longer return it

  Scenario: Restore an archived link losslessly
    Given a link is archived with tags, a note, and a reading state
    When the client restores it from the Archived view
    Then it returns to the main library with all of those intact

  Scenario: Search within the Archived view
    Given several links are archived
    When the client searches in the Archived view
    Then only archived links are searched

  Scenario: Permanent deletion is deliberate and archive-only
    Given a link is in the Archived view
    When the client chooses Delete and confirms
    Then the link is permanently removed
    And no delete action is available from the main-library views

## Assumptions
- Archived state is independent of the reading/reference state and preserves all
  fields.
- Permanent delete is reachable only from the Archived view, behind a confirmation.
