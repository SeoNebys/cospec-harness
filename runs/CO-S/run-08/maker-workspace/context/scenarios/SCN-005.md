Scenario ID: SCN-005
Title: Delete a link with a confirmation step
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each link has a "Delete" button. Clicking it does not remove the link
immediately; instead the row shows a confirmation ("Delete "<title>"?") with a
red "Delete" and a "Keep" choice. Choosing "Delete" removes the link (and, if it
was the last link of its topic, that topic's button disappears). Choosing "Keep"
leaves the link unchanged. The client confirmed they prefer a confirmation before
permanent deletion.

## Gherkin
Feature: Deleting a link

  Scenario: Confirm deletion
    Given a saved link
    When the client clicks its "Delete" button
    Then a confirmation with "Delete" and "Keep" is shown in place
    When the client chooses "Delete"
    Then the link is removed from the list

  Scenario: Back out of deletion
    Given the deletion confirmation is shown for a link
    When the client chooses "Keep"
    Then the link remains unchanged in the list

  Scenario: Deleting the last link of a topic removes its button
    Given a topic that has exactly one link
    When the client deletes that link
    Then the topic's button no longer appears

## Assumptions
- Deletion always requires a confirmation step (no instant delete).
- Confirmation appears inline in the link's row.
- Removing the last link of a topic removes that topic's button; if that topic
  was the active filter, the view falls back to "All".
