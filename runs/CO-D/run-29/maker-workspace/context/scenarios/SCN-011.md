Scenario ID: SCN-011
Title: Distinguish repairable shortened addresses from malformed input
Type: Error Case
Approval status: approved
Approval session: SESSION-011
Approval cycle: 1

## Approved behaviour
A recognizable shortened web address without its leading `https://` is quietly completed and saved normally. Input that consists of ordinary words and cannot reasonably be understood as a web address is retained exactly as typed, creates no bookmark, and receives a clear inline correction message.

## Gherkin
Feature: Validate submitted bookmark addresses

  Scenario: Complete a recognizable shortened web address
    Given the client enters a recognizable web address without `http://` or `https://`
    When the client saves the bookmark
    Then `https://` is added to the address
    And the bookmark is saved normally

  Scenario: Reject input that cannot be understood as a web address
    Given the client enters ordinary words that are not a web address
    When the client tries to save the bookmark
    Then no bookmark is created
    And the exact entered text remains in the address box
    And a clear inline message explains how to correct it

## Assumptions
- A shortened address must still contain a plausible site name and ending before it can be completed automatically.
- The client can correct invalid input in place without retyping it.
