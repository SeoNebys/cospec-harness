Scenario ID: SCN-004
Title: Edit a saved link, including its address, without creating duplicates
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
In the editor for an existing saved link, the user can change the saved address as
well as the title, description, personal note, labels, and read-later status. If the
user changes the address to one that matches another bookmark they already have, the
app refuses to save the change, keeps the editor open, and explains that another
saved link already uses that address (naming it). The message also offers a quick
way to open that existing entry for editing instead. Changing the address to one
that does not collide saves normally. Blocking (not merging) was chosen so notes,
labels, and read status can never be silently overwritten.

## Gherkin
Feature: Editing a saved link safely

  Scenario: Edit fields of an existing link including the address
    Given the user is editing an existing saved link
    When the user changes the address, title, description, note, labels, or read-later status
    And the new address does not match any other saved link
    Then the changes are saved to that same link with no duplicate created

  Scenario: Edited address collides with another saved link
    Given the user is editing an existing saved link
    When the user changes the address to one that matches another saved link
    Then the change is refused and the editor stays open
    And a message explains that another saved link already uses that address
    And the message offers to open that existing entry for editing
    And no duplicate entry is created

  Scenario: Follow the offer to open the colliding entry
    Given the collision message is shown
    When the user chooses to open the existing entry instead
    Then the editor switches to that existing saved link

## Assumptions
- Address matching uses the same normalisation as SCN-003.
- On collision the app blocks the change rather than merging the two entries
  (client-confirmed: blocking avoids silently overwriting notes, labels, status).
