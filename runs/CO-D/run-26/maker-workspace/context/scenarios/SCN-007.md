Scenario ID: SCN-007
Title: Sort the list with a remembered default
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A single "Sort by" dropdown controls the order of the list, with four options:
Newest first (default), Oldest first, Title A–Z, and Title Z–A. The chosen order
applies consistently across the "All" and "Read later" views and together with
search results and tag browsing. The client's choice is remembered and restored
on the next visit (persisted preferred default). Newest first is the initial
default before any choice is made.

## Gherkin
Feature: Sort the collection

  Scenario: Default order is newest first
    Given the client has not chosen a sort order
    Then the list is ordered newest-added first

  Scenario: Change the sort order
    When the client selects "Title A–Z" from the sort dropdown
    Then the list is ordered alphabetically by title ascending
    And selecting "Oldest first" orders by date added ascending
    And selecting "Title Z–A" orders alphabetically by title descending

  Scenario: Sort applies across views and filters
    Given a sort order is chosen
    Then the same order applies in "All", in "Read later", and within search and
         tag-browse results

  Scenario: Remembered default
    Given the client has chosen a sort order
    When the client reloads or returns later
    Then the previously chosen sort order is restored

## Assumptions
- Four options exactly: Newest first, Oldest first, Title A–Z, Title Z–A (client-confirmed).
- The control is a dropdown (client-confirmed over a button row).
- Title comparison is case-insensitive natural text comparison.
- In the prototype the remembered default is stored locally in the browser; the
  real implementation persists the client's preferred default for their account.
