Scenario ID: SCN-012
Title: Recognize tracking variants as an existing bookmark
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When a pasted address differs from an existing bookmark only through obvious marketing-tracking additions, the app recognizes the same underlying page. It does not create another bookmark and returns the client to the existing item. Address differences that genuinely identify different page content remain separate bookmarks.

## Gherkin

Feature: Avoid duplicate bookmarks

  Scenario: Save a tracked variant of an already saved page
    Given a clean page address is already saved
    And a pasted address identifies that same page with an obvious marketing-tracking addition
    When the client saves the tracked address
    Then the app does not create another bookmark
    And the app tells the client that the page is already saved
    And the app moves and highlights the existing bookmark as in the exact-duplicate flow

  Scenario: Save an address that identifies genuinely different page content
    Given one page address is already saved
    And another address identifies genuinely different page content
    When the client saves the other address
    Then the app treats it as a separate bookmark

## Assumptions

- Only additions recognizable as page-independent marketing tracking are ignored for duplicate recognition.
- Address components that may change the actual page content are not discarded for duplicate recognition.
