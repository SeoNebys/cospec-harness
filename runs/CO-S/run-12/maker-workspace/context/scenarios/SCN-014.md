Scenario ID: SCN-014
Title: Reuse an existing tag despite spacing or capitalization differences
Type: Edge Case
Approval status: approved
Approval session: SESSION-014
Approval cycle: 1

## Approved behaviour
When the client creates a tag whose name differs from an existing tag only by capitalization or surrounding spaces, the app reuses the existing tag instead of creating a near-duplicate. All matching bookmarks remain grouped under the single existing tag.

## Gherkin
Feature: Prevent near-duplicate tags

  Scenario: Enter a tag name matching an existing tag after normalization
    Given an existing tag is named "reading"
    When the user creates a tag named " Reading "
    Then no new tag is created
    And the existing "reading" tag is applied
    And bookmarks using either entered form remain grouped under the existing tag

## Assumptions
- Tag comparison ignores letter capitalization and leading or trailing whitespace.
- The existing tag's displayed spelling is preserved.
