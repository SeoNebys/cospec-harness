Scenario ID: SCN-007
Title: Archive a bookmark to retain it without cluttering the main view
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
An "Archive" action on a bookmark moves it out of the main library. Archived
bookmarks disappear from the All view, from Read Later, and from ordinary
searches/filters (which operate on the current non-archive view), but are
retained and viewable under a dedicated "Archive" tab, each marked with an
"Archived" badge. Archiving does not delete the bookmark. In the Archive view,
the only action offered is "Restore to library" (confirmed sufficient), which
returns the bookmark to the All view. The Archive tab shows a count. When the
archive is empty, a guiding empty message is shown.

## Gherkin
Feature: Archive bookmarks

  Scenario: Archiving a bookmark
    Given a bookmark in the main library
    When the client chooses Archive
    Then the bookmark disappears from the All view
    And it does not appear in Read Later or in ordinary searches
    And it appears under the Archive tab with an Archived badge
    And the bookmark is not deleted

  Scenario: Restoring an archived bookmark
    Given an archived bookmark
    When the client chooses Restore to library from the Archive view
    Then the bookmark returns to the All view

  Scenario: Archive view offers only restore
    Given the Archive view is open
    Then each archived bookmark offers only a Restore to library action

  Scenario: Empty archive
    Given no bookmarks are archived
    When the client opens the Archive view
    Then a guiding empty message is shown

## Assumptions
- Archived is a move (exclusive from the main/read-later views), not a marker.
- Ordinary searches/filters operate within the current non-archive view, so they
  exclude archived items.
- Editing/tagging is not available while archived (restore first).
