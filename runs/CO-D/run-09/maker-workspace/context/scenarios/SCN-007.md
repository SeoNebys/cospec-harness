Scenario ID: SCN-007
Title: Refine a search with labels, phrases, and boolean operators
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
For more precise searches as the collection grows, the search box understands a small
query language:
- `#label` matches specifically that label (exact label, case-insensitive), not free
  text.
- A phrase in quotation marks (e.g. `"spaced repetition"`) matches that exact phrase.
- `AND`, `OR`, `NOT` combine conditions regardless of their capitalisation (`or`,
  `Or`, `OR` all work), and parentheses group them, e.g. `rome (#article OR #book)`.
- Ordinary adjacent words continue to mean "must contain all of these" (implicit AND).
- Putting an operator word in quotation marks (e.g. `"OR"`) searches for it as ordinary
  text instead of treating it as an instruction.
- Highlighting covers the positive (non-negated) terms of the query.
- If a query cannot be interpreted, the app falls back to a plain all-words search
  rather than failing.

## Gherkin
Feature: Precise search

  Scenario: Search a specific label
    Given saved links with various labels
    When the user types "#learning"
    Then only links carrying the "learning" label are shown

  Scenario: Search an exact phrase
    Given a saved link contains the phrase "spaced repetition"
    When the user types "spaced repetition" in quotation marks
    Then that link is shown

  Scenario: Combine conditions with OR and parentheses
    Given saved links with labels "javascript" and "learning"
    When the user types "(#javascript OR #learning)"
    Then links carrying either label are shown

  Scenario: Exclude with NOT
    Given saved links labelled "reading", one of which is also labelled "design"
    When the user types "#reading AND NOT design"
    Then the link also labelled "design" is excluded

  Scenario: Operators work regardless of capitalisation
    Given saved links with labels "reading" and "learning"
    When the user types "#reading or #learning" in lowercase
    Then it behaves the same as using OR in capitals

  Scenario: Treat an operator word as literal text
    Given the user wants to find the word "or"
    When the user types "or" in quotation marks
    Then it is searched as ordinary text, not treated as the OR operator

## Assumptions
- Operators (AND, OR, NOT) are recognised regardless of capitalisation; to use one as
  ordinary text, the user quotes it (e.g. "or").
- Precedence is NOT before AND before OR; parentheses override precedence.
- `#label` may also take a quoted multi-word label (`#"..."`).
- On an uninterpretable query the app falls back to a plain all-words search.
