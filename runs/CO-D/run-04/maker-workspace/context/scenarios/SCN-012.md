## Approved behaviour
The select-and-act motion from the pile is available in the main library too,
but kept out of the way: browsing "Everything" is clean by default, and a
"Select" toggle reveals checkboxes for tidying (whereas the To-read pile always
shows checkboxes, since processing is its purpose). With links ticked, a batch
bar offers: add a label to all of them at once (steered to existing labels via
suggestions, per SCN-006), flag them all "Read later", or delete them.

Deleting removes a link from the library entirely — a serious, irreversible
action, and the only one shown in a warning (red) colour, distinct from the
pile's gentle "Remove from pile" which keeps the link. Deletion is available for
a single link (red 🗑 on the card) and in bulk. The safety net is a brief Undo:
a deleted link (or batch) can be restored from an "Undo" bar for a few seconds,
then it is gone. No per-delete "Are you sure?" prompt and no long-term recycle
bin — when the client truly deletes, it is junk.

## Gherkin
Feature: Bulk tidy and delete

  Scenario: Batch-label several links
    Given "Select" is on in the library
    When the client ticks several links and adds a label
    Then the label (reused via suggestion if it exists) is applied to all of them

  Scenario: Delete a link with an undo net
    When the client deletes a link (singly or in bulk)
    Then it is removed from the library
    And an "Undo" bar appears briefly to restore it
    And after the bar fades the deletion is permanent

  Scenario: Delete is weighted differently from remove-from-pile
    Then only true deletion is shown in a red/warning colour

## Assumptions
- Library selection behind a "Select" toggle; pile checkboxes always on.
  (client confirmed)
- Brief Undo, no confirm dialog, no long-term recycle bin. (client confirmed)
- Only deletion wears the warning colour. (client confirmed)
- On a card, Delete is tucked behind a per-card "⋯" menu (rare + dangerous),
  while frequently-used actions (Read later, Set aside) stay visible; icon
  actions carry plain hover labels so nothing is a memory test. (client
  confirmed, p13)
