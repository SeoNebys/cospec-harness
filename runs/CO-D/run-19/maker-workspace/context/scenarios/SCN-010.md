Scenario ID: SCN-010
Title: Preserve a valid link when page details cannot be fetched
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
If a valid page cannot be reached for automatic details, the link is still saved rather than lost or rejected. A recognizable fallback card shows the site and original address, plainly states that details are unavailable, and offers Try again and Add details actions. Manual details use the established in-card editor.

## Gherkin
Feature: Save through metadata-fetch failures

  Scenario: Save a valid but unreachable page
    Given the client entered a valid web address
    And the page details cannot be fetched
    When the save attempt finishes
    Then the link is saved as a fallback bookmark card
    And the card shows its site and original address
    And the client is plainly told the page details could not be loaded
    And the client can retry fetching or add the title and description manually

## Assumptions
- A metadata failure does not make a syntactically valid HTTP or HTTPS address invalid.
- Retrying does not create another bookmark.
