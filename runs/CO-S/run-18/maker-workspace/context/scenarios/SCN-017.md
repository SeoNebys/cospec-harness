Scenario ID: SCN-017
Title: Keep unusually long bookmark content scannable
Type: Edge Case
Approval status: approved
Approval session: SESSION-017
Approval cycle: 1

## Approved behaviour
When a bookmark has an unusually long title, description, address, note, or many tags, its card remains compact enough to scan in a list. The stored content is not discarded. Long content is shortened only in the list view, and Show full note reveals the complete personal note on demand.

## Gherkin
Feature: Displaying unusually long bookmark information

  Scenario: Scan a bookmark with long information
    Given a bookmark contains unusually long page details, address, note, or tag set
    When the person views it in the bookmark list
    Then its card remains compact and scannable
    And the stored content remains intact
    And long content is shortened only for the list presentation

  Scenario: Reveal a complete long note
    Given a bookmark card shortens a long personal note
    When the person chooses Show full note
    Then the complete note is shown

## Assumptions
- Compact presentation does not change searchability of the complete stored content.
- Opening the original page still uses the complete saved address.
