Scenario ID: SCN-011
Title: Explain empty library and filtered states clearly
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A brand-new empty library shows a friendly explanation and a direct invitation to save the first link, while search and filtering controls are withheld until bookmarks exist. A text search with no matches explicitly says that only the current search matched nothing and explains that clearing or changing it returns the library. An empty Read later view explains that bookmarks appear after being marked, without suggesting the main library is empty. An empty Archive explains that it is a safe holding place until bookmarks are restored or permanently deleted.

## Gherkin
Feature: Empty bookmark states

  Scenario: Open a brand-new empty library
    Given the library contains no bookmarks
    When the user opens it
    Then a friendly empty state invites the user to save the first link
    And search and filtering controls are not displayed

  Scenario: Search with no matching bookmarks
    Given the library contains bookmarks
    When the user's search matches none of them
    Then the app says that no bookmarks match that search
    And it explains that clearing or changing the search brings the library back

  Scenario: Open an empty read-later view
    Given no bookmarks are marked to read later
    When the user opens the read-later view
    Then the app says that nothing is saved for later
    And it explains how to make bookmarks appear there

  Scenario: Open an empty archive
    Given no bookmarks are archived
    When the user opens the Archive
    Then the app says that the Archive is empty
    And it explains that archived bookmarks remain safe until restored or permanently deleted

## Assumptions
- Controls with no useful action are withheld from the brand-new empty library.
- Empty-state language distinguishes an empty subset from an empty whole library.
