Scenario ID: SCN-006
Title: Edit an entry — title, description, address, and a formatted personal note
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Each entry has an "✏ Edit" action opening an inline form with fields: Address,
Title, Description, and Your note. Save changes applies them; Cancel discards
every unsaved change.

Address editing:
- The address (URL) itself can be corrected.
- If the new address is invalid, the change is refused with a clear message.
- If the new address matches a link already saved elsewhere (same canonical
  identity as SCN-002), the change is refused with a message naming the existing
  entry ("already saved as …"); nothing is applied. No duplicate is created.
- Changing the address does NOT automatically re-fetch page details: the
  client's title, description, and note are kept as-is (they may contain
  deliberate edits). The client approved this as the safer default.

Title fallback: if the title is cleared, it falls back to the site name so an
entry is never nameless.

Personal note with formatting:
- The note supports simple formatting — headings, bold, emphasis, bulleted and
  numbered lists, and links — using Markdown-style marks
  (**bold**, # heading, - list, [text](url)). A hint shows the available marks.
- When viewing an entry, the note is rendered with that formatting and shown in
  a distinct block labelled "Your note", visually separate from the page's own
  fetched description.

## Gherkin

Feature: Edit a saved entry

  Scenario: Correct title and description
    Given an entry is open in the edit form
    When the client changes the title and/or description and saves
    Then the entry shows the corrected title and description

  Scenario: Clearing the title falls back to the site name
    Given an entry is open in the edit form
    When the client clears the title and saves
    Then the entry's title becomes the site name

  Scenario: Add a formatted note
    Given an entry is open in the edit form
    When the client writes a note using headings, bold, lists, or links and saves
    Then the note is shown on the entry with that formatting, distinct from the
      page description

  Scenario: Change the address to a new one
    Given an entry is open in the edit form
    When the client changes the address to a valid, not-yet-saved address and saves
    Then the entry adopts the new address
    And the client's title, description, and note are unchanged

  Scenario: Change the address to one already saved
    Given another entry already exists for address X
    When the client edits an entry's address to X (any equivalent variant) and saves
    Then the change is refused with a message naming the existing entry
    And no duplicate is created

  Scenario: Invalid address is refused
    Given an entry is open in the edit form
    When the client changes the address to something invalid and saves
    Then the change is refused with a message

  Scenario: Cancel discards changes
    Given an entry is open in the edit form with unsaved changes
    When the client cancels
    Then none of the changes are kept

## Assumptions

- Note formatting is a safe subset of Markdown; raw marks are stored, rendered
  on view. Links are restricted to http/https.
- Address equivalence for the duplicate guard reuses SCN-002's canonical key.

## Recorded enhancement (not yet built)
- An optional "Fetch details from the new address" action when the address is
  changed, which the client can invoke deliberately; it must NEVER overwrite the
  client's text automatically. (Client: "would be useful.")
