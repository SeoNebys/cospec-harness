Scenario ID: SCN-010
Title: Archive a bookmark (reversible) to keep it without cluttering the main view
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A bookmark can be archived to keep it without cluttering the working set.
Archived bookmarks are completely excluded from the main views (All, To read,
Read) and from normal search, and are not counted toward "To read". They are kept
in a dedicated Archive view, reached from its own entry in the top bar (showing a
count). Within the Archive view they remain searchable. Archiving preserves the
bookmark's tags, note and read status; a bookmark can be restored from the
archive back to the main list exactly as it was. Archiving is reversible and is
distinct from deletion.

## Gherkin
Feature: Archive a bookmark

  Scenario: Archive removes from main views and search
    Given a bookmark in the main list
    When the client archives it
    Then it no longer appears in All, To read or Read, nor in normal search
    And it is not counted toward "To read"

  Scenario: Archived bookmarks live in the Archive view and stay searchable there
    Given archived bookmarks
    When the client opens the Archive view
    Then the archived bookmarks are listed
    And searching while in the Archive view searches within the archive

  Scenario: Restore preserves everything
    Given an archived bookmark with tags, a note and a read status
    When the client restores it
    Then it returns to the main list with its tags, note and read status intact

## Assumptions
- Archive fully excludes items from main views and normal search (client
  confirmed).
- Archive is reached from its own top-bar entry (client confirmed).
