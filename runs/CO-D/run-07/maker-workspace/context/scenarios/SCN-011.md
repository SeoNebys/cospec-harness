Scenario ID: SCN-011
Title: Open the original page, edit the address, delete a bookmark
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Opening: clicking a bookmark's title or its image opens the original page in a
new browser tab.

Per-bookmark action layout: Edit and the read-status toggle (Mark as finished /
Move to To-read) are shown directly on each card because they are used often;
less frequent actions (Delete now, Archive later) live under a "More" menu, so
cards stay tidy as the action set grows.

Editing the address: the edit screen includes an editable "Address (link)" field
alongside title and description. Changing the address updates where the bookmark
points; existing details are kept (no silent re-fetch). If the new address is one
that is already saved (using the same-link rule from SCN-003), the change is not
applied and no duplicate is created — instead the client is taken to the existing
bookmark's edit screen with the notice "That address is already saved — here's
the existing bookmark", and the edited bookmark is left unchanged.

Deleting: a Delete action (under More) permanently removes a bookmark, and always
asks for confirmation first ("Delete permanently? This can't be undone."); Cancel
keeps the bookmark.

The client confirmed: Option B layout with the status button kept visible beside
Edit; open-in-new-tab; keeping details when editing the address; always
confirming permanent deletion; and duplicate prevention when editing an address.

## Gherkin
Feature: Per-bookmark actions

  Scenario: Open the original page
    When I click a bookmark's title or image
    Then the original page opens in a new browser tab

  Scenario: Edit the address, keeping details
    Given the edit screen is open for a bookmark
    When I change the Address field to a new, not-already-saved address and Save
    Then the bookmark points to the new address
    And its title, description, tags and note are unchanged

  Scenario: Editing an address into an already-saved one
    Given another bookmark already has the target address (same-link rule)
    When I change this bookmark's address to it and Save
    Then no duplicate is created
    And this bookmark is left unchanged
    And I am taken to the existing bookmark with a clear notice

  Scenario: Delete permanently with confirmation
    When I choose Delete from the More menu
    Then I am asked to confirm permanent deletion
    And confirming removes the bookmark
    And cancelling keeps it

## Assumptions
- Frequently used actions (Edit, status toggle) are visible; Delete/Archive are
  under "More".
- Address duplicate check reuses the SCN-003 same-link normalisation.
- Delete is irreversible (distinct from Archive, SCN-012).
