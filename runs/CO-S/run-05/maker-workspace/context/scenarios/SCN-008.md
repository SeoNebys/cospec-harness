Scenario ID: SCN-008
Title: Prevent duplicate labels regardless of capitalization
Type: Edge Case
Approval status: approved
Approval session: SESSION-008
Approval cycle: 1

## Approved behaviour

If the client enters a label that is already on the bookmark with different
capitalization, the existing label remains unchanged, no duplicate is created,
and an inline message explains that the bookmark already has that label.

## Gherkin

Feature: Organizing bookmarks with labels

  Scenario: Add a label that already exists with different capitalization
    Given a bookmark already has the label "learning"
    When the client tries to add the label "Learning"
    Then the bookmark still has exactly one "learning" label
    And the client is told that the label is already present

## Assumptions

- Label comparison ignores capitalization.
- The first-saved capitalization of a label remains visible.
