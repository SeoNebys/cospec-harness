Scenario ID: SCN-006
Title: Edit a saved link's address, title, note, and tags
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each saved link has an "Edit" action. Editing turns the link into a form with its
link address, title, "why" note, and tags editable in place. "Save changes"
applies the edits and returns the link to its normal display; "Cancel" leaves it
unchanged. The address is validated the same way as when saving: an empty or
invalid address is rejected with a message and not saved, a missing http/https is
forgiven by prepending https://, and changing the address to one already used by a
different saved link is rejected with a message so no duplicate is created. Tags
entered in the edit form are lower-cased and de-duplicated.

## Gherkin
Feature: Editing a saved link

  Scenario: Edit details of a link
    Given a saved link
    When the client clicks Edit, changes its address, title, note, or tags, and clicks Save changes
    Then the link is updated in place with the new values

  Scenario: Cancel editing
    Given the client is editing a link
    When the client clicks Cancel
    Then the link is left unchanged

  Scenario: Reject an invalid address while editing
    Given the client is editing a link
    When the client sets the address to something empty or invalid and saves
    Then an "invalid web address" message is shown and the change is not applied

  Scenario: Reject an address already used by another link
    Given two saved links with different addresses
    When the client edits one to the other's address and saves
    Then a message says another saved link already uses that address and the change is not applied

## Assumptions
- Editable fields: address, title, note, tags.
- Address edits reuse save-time validation and duplicate protection (SCN-007/008).
- Tags in the edit form are lower-cased and de-duplicated.
