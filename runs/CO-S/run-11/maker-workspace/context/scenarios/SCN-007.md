Scenario ID: SCN-007
Title: Edit a saved bookmark
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each saved bookmark has an "Edit" control that opens an inline editor. The user
can change the bookmark's web address, title, description, personal note, and
tags (tags use the same chip entry as saving), and can Save changes or Cancel.
Read-status (To read / Finished) is changed with the existing move control.
When saving edits: an invalid web address is rejected with a message and the
edit is not saved; changing the address to one that matches another existing
bookmark is blocked with "Another saved bookmark already uses this address."
After a successful edit the bookmark updates in place and briefly flashes.

## Gherkin
Feature: Edit an existing bookmark

  Scenario: Open the editor
    Given a saved bookmark
    When the user clicks its Edit control
    Then an inline editor shows its web address, title, description, personal note and tags

  Scenario: Save valid edits
    Given the editor is open with a valid web address
    When the user changes fields and saves the changes
    Then the bookmark is updated in place

  Scenario: Cancel edits
    Given the editor is open with unsaved changes
    When the user cancels
    Then the bookmark keeps its previous values

  Scenario: Reject an invalid web address
    Given the editor is open
    When the user enters an invalid web address and tries to save
    Then a message is shown and the edit is not saved

  Scenario: Block an address that collides with another bookmark
    Given another bookmark already uses a given web address
    When the user edits a bookmark to that same address and tries to save
    Then it is blocked with "Another saved bookmark already uses this address."

## Assumptions
- Editable fields: web address, title, description, personal note, tags.
- Read-status is changed via the move control, not the edit form.
- Address validation and duplicate rules match saving (SCN-006).
