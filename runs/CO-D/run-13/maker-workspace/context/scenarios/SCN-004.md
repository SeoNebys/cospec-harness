Scenario ID: SCN-004
Title: Organize with tags — visible on each entry, add/remove, filter the view by a tag
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Each saved link can carry tags, shown as small chips on the entry itself.

Adding a tag: an unobtrusive "＋ tag" control on the entry opens a small text
field; typing a word and pressing Enter (or clicking away) adds it as a chip.
As the client types, tags already used elsewhere are offered as suggestions.
Adding a tag that already exists on that entry (ignoring letter case) does not
create a duplicate.

Removing a tag: a small "✕" on the chip removes it from that entry.

Filtering: clicking a tag chip narrows the current view to links carrying that
tag. The tag filter applies WITHIN the current view (All / Unread / Archived) —
e.g. filtering "reference" while on Unread shows only unread links tagged
"reference". A small bar shows which tag is active and offers a control to clear
it (label: "Clear tag filter"). A newly saved link starts with no tags.

The client approved adding/removing tags, the existing-tag suggestions, keeping
the filter within the current view, and single-tag click-to-filter as a useful
quick filter. (Wording of the clear control corrected from "Show all tags" to
"Clear tag filter" at the client's request.)

## Gherkin

Feature: Organize links with tags

  Scenario: Tags are visible on an entry
    Given a saved link has one or more tags
    Then those tags are shown as chips on the entry

  Scenario: Add a tag with suggestions
    Given the client is adding a tag to an entry
    When the client types a tag name and confirms it
    Then the tag is added to that entry as a chip
    And previously used tags are offered as suggestions while typing

  Scenario: Adding a duplicate tag is ignored
    Given an entry already has the tag "reference"
    When the client adds "Reference" to the same entry
    Then the entry still has a single "reference" tag

  Scenario: Remove a tag
    Given an entry has a tag
    When the client removes that tag
    Then the tag no longer appears on the entry

  Scenario: Filter the current view by a tag
    Given the client is in a view (All, Unread, or Archived)
    When the client clicks a tag
    Then only links in that view carrying the tag are shown
    And the client can clear the tag filter to return to the full view

  Scenario: New link starts untagged
    When the client saves a new link
    Then it has no tags

## Assumptions

- Tag matching / de-duplication is case-insensitive; the tag is displayed as
  the client first typed it.
- Single-tag filtering approved here; multi-tag (AND) filtering is being
  explored next (see SCN-005).
