Type: Happy Path

## Approved behaviour
The bookmark collection belongs to a personal account and is kept centrally so
the user can reach the same collection from any device. On opening the app, the
user signs in with an email and password. Wrong credentials show an error ("That
email or password isn't right.") and do not grant access. After signing in, the
user sees their own bookmarks; all changes (saving, editing, tags, status,
archive, delete) are kept and are present again on the next visit and on other
devices after signing in. A Sign out control returns to the sign-in screen.

## Gherkin
Feature: Personal account and persistence

  Scenario: Wrong credentials are rejected
    Given the sign-in screen is shown
    When the user submits an incorrect email or password
    Then an error message is shown
    And the bookmarks are not revealed

  Scenario: Successful sign-in shows the user's bookmarks
    Given a registered account with saved bookmarks
    When the user signs in with the correct email and password
    Then the user's bookmark collection is shown

  Scenario: Changes persist across sessions and devices
    Given the user makes changes to their bookmarks
    When the user returns later or signs in from another device
    Then the same up-to-date collection is shown

  Scenario: Sign out
    Given the user is signed in
    When the user signs out
    Then the sign-in screen is shown again

## Assumptions
- Sign-in is email + password (simple, sufficient for a personal single user).
- Bookmarks are stored centrally (server-side), not only on one device.
- Each account sees only its own bookmarks.
- Session persists reasonably so the user is not asked to sign in on every action.
