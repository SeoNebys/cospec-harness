Scenario ID: SCN-004
Title: Find bookmarks with live, case-insensitive search and a precise query language
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A search box filters the collection live as the user types (no Enter needed),
case-insensitively. Matching words are highlighted in results, and a count shows
how many of the total bookmarks matched. Clearing the box restores the full list.

Search looks through each bookmark's title, description, and address; it also
includes notes and tags once those exist on an entry.

The search box supports a precise query language:
- "quoted phrases" match the exact phrase.
- AND / OR / NOT combine terms; parentheses group them.
- Between two plain words with no operator, the default is AND (all words must
  match).
- AND / OR / NOT are recognised regardless of capitalisation. Quoting is the one
  way to force one of these words to be searched as an ordinary term (e.g. "or").
- #tag matches by tag (active once tags exist).

## Gherkin
Feature: Find a saved bookmark

  Scenario: Live case-insensitive substring search
    Given several bookmarks are saved
    When the user types a word into the search box
    Then the list narrows live to bookmarks whose title, description, address,
      notes or tags contain that word, case-insensitively
    And matched text is highlighted and a match count is shown

  Scenario: Exact phrase with quotes
    When the user searches "roast chicken"
    Then only bookmarks containing that exact phrase match

  Scenario: Boolean combination with parentheses and exclusion
    When the user searches (kyoto OR chicken) NOT nytimes
    Then bookmarks matching kyoto or chicken, excluding those matching nytimes, are shown

  Scenario: Implicit AND between plain words
    When the user searches "css grid" without an operator
    Then only bookmarks containing both css and grid match

  Scenario: Operators are case-insensitive; quotes force a literal
    When the user searches kyoto or chicken
    Then it behaves the same as kyoto OR chicken
    When the user searches "or"
    Then the ordinary word "or" is searched instead of acting as an operator

## Assumptions
- Whole-word site name needs no special handling because it already appears in
  the address.
- #tag and note matching are wired into the same engine and activate once tags
  and notes exist (organising area).
