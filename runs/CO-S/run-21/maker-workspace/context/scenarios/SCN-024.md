Scenario ID: SCN-024
Title: Show a reassuring empty Read later pile
Type: Edge Case
Approval status: approved
Approval session: SESSION-024
Approval cycle: 1

## Approved behaviour
After the final queued bookmark is marked read, the Read later count becomes zero and the view positively states that the person is all caught up. It explicitly reassures them that completed links still exist in All bookmarks, so the empty pile reads as progress rather than deletion or failure.

## Gherkin
Feature: Finish the Read later queue

  Scenario: Mark the last queued bookmark as read
    Given exactly one bookmark remains in Read later
    When the person marks that bookmark as read
    Then the Read later count becomes zero
    And the view positively states that the person is all caught up
    And the view explains that completed bookmarks remain in All bookmarks
    And the bookmark still exists in All bookmarks

## Assumptions
- Read later remains available in navigation when its count is zero.
- The empty state replaces the list area, not the entire application navigation.
