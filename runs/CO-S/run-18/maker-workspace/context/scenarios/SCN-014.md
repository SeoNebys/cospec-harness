Scenario ID: SCN-014
Title: Recognize cosmetically different addresses as the same bookmark
Type: Edge Case
Approval status: approved
Approval session: SESSION-014
Approval cycle: 1

## Approved behaviour
Duplicate detection treats address variations that do not meaningfully change the page as the existing bookmark. This includes a trailing slash, a jump-to-section ending, and referral or tracking information. Address details that select genuinely different content, such as page two of a listing, remain separately saveable.

## Gherkin
Feature: Recognizing equivalent bookmark addresses

  Scenario Outline: Cosmetic address variation resolves to the existing bookmark
    Given the library contains a bookmark for a page
    When the person tries to save the same page with a <cosmetic variation>
    Then no new bookmark is created
    And the existing bookmark is shown

    Examples:
      | cosmetic variation              |
      | trailing slash                  |
      | jump-to-section ending          |

  Scenario: Content-changing address remains distinct
    Given the library contains a bookmark for one page or view
    When the person saves an address detail that selects genuinely different content
    Then a separate bookmark may be created

## Assumptions
- Known referral and tracking additions do not identify meaningful page content.
- Address details are preserved when needed to open the intended content, even if omitted for duplicate comparison.
