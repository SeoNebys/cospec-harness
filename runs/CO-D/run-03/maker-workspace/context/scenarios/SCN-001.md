Scenario ID: SCN-001
Title: Save a link with auto-filled details, review/correct before saving, and edit later
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

From a single readable page with a save box at the top and a list of saved
bookmarks below (newest first), the user saves a link with little effort:

1. The user pastes/types a link and presses Save (or Enter).
2. The app reads the page and automatically fills in its basic details:
   the page title, a short description, the site icon (shown next to the site
   name), and a preview image when the page provides one.
3. Before the save is finalised, the app shows an editable "Review before
   saving" card where the title and description are correctable. The user can
   confirm ("Save bookmark") or cancel.
4. On confirmation, the bookmark is added to the top of the list, showing the
   preview image, title, description, site icon + name, and the link.
5. Each saved bookmark can be edited later via an Edit control that opens the
   title and description for in-place editing, with Save changes / Cancel.

Honest handling of missing details (approved refinement):
- If the page provides no description, no text is invented: the description is
  omitted from the saved card and the description field is empty when editing.
- If the page provides no preview image, a clearly generic placeholder (or no
  image) is shown instead of a fabricated banner.

Note: the site icon and preview image are simulated placeholders in the Phase 1
prototype; the approved behaviour is that the real page's genuine icon/preview
are used in the implementation.

## Gherkin

Feature: Save a bookmark with auto-filled details

  Scenario: Save a link whose page provides full details
    Given the user is on the bookmarks page
    When the user enters a link and presses Save
    Then the app fetches the page's title, description, site icon and preview image
    And it presents an editable review card pre-filled with those details

  Scenario: Correct details before finalising the save
    Given a review card is shown with auto-filled title and description
    When the user edits the title and/or description and presses "Save bookmark"
    Then a new bookmark is added at the top of the list with the corrected details

  Scenario: Cancel a save under review
    Given a review card is shown for a link
    When the user presses Cancel
    Then no bookmark is added and the review card is dismissed

  Scenario: Edit a saved bookmark later
    Given a saved bookmark exists in the list
    When the user presses Edit, changes the title and/or description, and presses "Save changes"
    Then the bookmark shows the updated title and description

  Scenario: Page provides no description
    Given the user saves a link whose page has no description
    Then the saved card shows no description line
    And the description field is empty when editing that bookmark

  Scenario: Page provides no preview image
    Given the user saves a link whose page has no preview image
    Then the saved card shows a clearly generic placeholder instead of a preview image

## Assumptions

- Layout: one save box at the top, saved bookmarks listed below, newest first
  (explicitly approved by the client).
- "Basic details" = title, short description, site icon, preview image
  (explicitly approved).
- Real page icon/preview are used in implementation; prototype uses placeholders.
- A link without a scheme is treated as https.
