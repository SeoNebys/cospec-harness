Scenario ID: SCN-006
Title: Organise links with tags, tag filtering, and existing-tag suggestions
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Bookmarks are organised with tags: flexible labels where one bookmark can carry
several. Tags are added in the review step when saving and in the editor, by typing
a word and pressing Enter or comma; each becomes a removable chip. Tags are tidied
automatically: capitalisation is dropped, internal spaces become hyphens, and a
leading "#" the client types is ignored (so "Travel", "travel", "#travel" are the
same tag; "deep learning" becomes "deep-learning").

Each bookmark shows its tags as #chips in the list. Clicking a tag chip filters the
list by placing "#tag" in the search box, from which the search can be refined
further. The search query language matches "#tagname" against actual tags (not just
text), combinable with AND/OR/NOT and grouping.

While typing in the tag field, a suggestion dropdown offers already-used tags that
contain the typed text, ranked so tags that start with the typed text appear first.
Suggestions are drawn from tags across all of the client's bookmarks and exclude
tags already attached to the current bookmark. A suggestion is chosen by click or by
Up/Down + Enter; typing a brand-new tag and pressing Enter adds it as a new tag.

## Gherkin
Feature: Organise with tags

  Scenario: Add tags when saving and see them on the bookmark
    Given the client is at the review step or editor
    When the client types a word and presses Enter
    Then it becomes a tag chip, tidied (lower-case, spaces to hyphens, leading # removed)
    And after saving, the tag appears as a #chip on the bookmark in the list

  Scenario: One bookmark can hold several tags
    When the client adds multiple tags to a bookmark
    Then all of them are stored and shown

  Scenario: Filter by clicking a tag
    Given bookmarks with tags are shown
    When the client clicks a #tag chip on a bookmark
    Then the search box is set to "#tag" and the list filters to bookmarks with that tag

  Scenario: Search by tag with the query language
    When the client searches "#travel AND #article"
    Then only bookmarks carrying both tags are shown
    When the client searches "#travel OR #dev"
    Then bookmarks carrying either tag are shown

  Scenario: Existing-tag suggestions while typing
    Given the client has used tags across their bookmarks
    When the client types part of a tag in the tag field
    Then matching existing tags are suggested, those starting with the text first
    And tags already on the current bookmark are not suggested
    When the client chooses a suggestion by click or Up/Down + Enter
    Then that tag is added without retyping
    When the client types an unused word and presses Enter
    Then it is added as a new tag

## Assumptions
- Tag matching in suggestions is substring, ranked prefix-first.
- Suggestion vocabulary is the union of all tags on all bookmarks.
