Scenario ID: SCN-022
Title: Reusable saved searches
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client can save the current search as a reusable saved search. A saved
search stores the complete query — search text plus included (#tag) and excluded
(NOT #tag) tags. Saved searches appear as named star chips under the search box.
Clicking a chip reruns its query dynamically (matching whatever currently
qualifies). Each chip has a remove (✕) control. Naming uses a prompt pre-filled
with the query text. The Save action is available only when there is a query.

## Gherkin
Feature: Saved searches

  Scenario: Save the current search
    Given the client has entered a query (text and/or include/exclude tags)
    When the client saves it and names it
    Then a named saved-search chip appears under the search box

  Scenario: Rerun a saved search
    Given a saved-search chip exists
    When the client clicks it
    Then its full query (text + included/excluded tags) is applied
    And the list shows whatever currently matches

  Scenario: Remove a saved search
    Given a saved-search chip exists
    When the client clicks its remove control
    Then that saved search is removed

  Scenario: Save unavailable without a query
    Given the search box is empty
    Then the Save-search action is unavailable

## Assumptions
- A saved search stores a query, not a fixed list; results are recomputed on each
  run.
