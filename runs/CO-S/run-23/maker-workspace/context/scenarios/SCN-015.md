Scenario ID: SCN-015
Title: Prevent an edit from duplicating another bookmark's address
Type: Edge Case
Approval status: approved
Approval session: SESSION-015
Approval cycle: 1

## Approved behaviour
The client attempted to change one bookmark's address to an address already owned by another bookmark. The edit was not applied, both existing bookmarks remained unchanged, and a clear message identified the bookmark already using that address and returned attention to the address field. The client confirmed this extends duplicate protection consistently into editing.

## Gherkin
Feature: Edit bookmarks

  Scenario: Change a bookmark to an address already used by another bookmark
    Given two bookmarks have different addresses
    And one bookmark is open for editing
    When the user changes its address to the address of the other bookmark
    And saves the changes
    Then the edit is not applied
    And both bookmarks remain unchanged
    And the user is told which bookmark already uses the address
    And attention returns to the address field for correction

## Assumptions
- The same address-comparison rules used during saving also apply during editing.
- Conflicting bookmarks are not automatically merged.
