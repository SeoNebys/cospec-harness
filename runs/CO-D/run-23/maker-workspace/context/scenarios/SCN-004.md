Scenario ID: SCN-004
Title: Manage a Read later list without removing bookmarks
Type: Happy Path
Approval status: approved
Approval session: SESSION-004
Approval cycle: 1

## Approved behaviour
A bookmark can be placed in Read later either while it is first saved or later from an action directly on its card. It remains the same bookmark in the main library and also appears in the separate Read later view; no duplicate is created. From the Read later view, the person can mark the bookmark as read directly on its card. It then leaves Read later but remains in the main library. Clearing the final item shows a friendly all-caught-up state.

## Gherkin
Feature: Read later

  Scenario: Set a bookmark aside while saving it
    Given the person is saving a new web address
    When they mark it as Read later and save it
    Then the bookmark is added to the main library
    And the same bookmark appears in the separate Read later view

  Scenario: Set an existing bookmark aside
    Given a bookmark is already saved normally in the main library
    When the person chooses "Set aside to read" on its card
    Then that bookmark's status changes to Read later
    And the same bookmark appears in the Read later view
    And no duplicate bookmark is created

  Scenario: Mark a bookmark as read
    Given a bookmark appears in the Read later view
    When the person marks it as read on its card
    Then it is removed from the Read later view
    And it remains in the main library

  Scenario: Finish the Read later list
    Given one bookmark remains in the Read later view
    When the person marks it as read
    Then the Read later view shows that everything is caught up

## Assumptions
- Read later is a separate view in the sidebar.
- Read-later bookmarks also remain visible in the main library.
- Actions to set aside or mark as read are available directly on bookmark cards.
- Setting an existing bookmark aside changes its state rather than copying it.
