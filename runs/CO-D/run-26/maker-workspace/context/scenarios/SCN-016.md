Scenario ID: SCN-016
Title: Save and reuse named search/tag filters (include and exclude tags)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client can save a useful filter to return to later. A saved filter remembers a
name, search text, a set of included tags, and a set of excluded tags. It does not
remember which tab (All / Read later / Archived) is active — the tab describes
where a bookmark currently sits, whereas the saved filter describes the subject to
return to; the same saved filter can be applied within whichever view is active.

When creating a saved filter, dedicated "Include tags" and "Exclude tags" pickers
are provided, each offering suggestions from existing tags; a "Search text" field
still accepts the full search expression for those who prefer it. Applying a saved
filter restores its search text and its included/excluded tags and shows only
bookmarks that match: containing all included tags and none of the excluded tags,
plus any search text. A banner shows the active include/exclude constraints with a
way to clear them. Saved filters appear as named chips, persist across visits, and
each can be removed.

## Gherkin
Feature: Saved filters

  Scenario: Create a saved filter with include/exclude tag pickers
    Given the client opens "Save current filter"
    Then there are Include tags and Exclude tags pickers with existing-tag suggestions
    And a Search text field that accepts the full search expression
    When the client names it and saves
    Then it appears as a named chip and persists across visits

  Scenario: Apply a saved filter
    When the client applies a saved filter
    Then only bookmarks containing all its included tags and none of its excluded
         tags (and matching its search text) are shown
    And a banner shows the active include/exclude constraints with a clear control

  Scenario: Saved filter is independent of the active tab
    Given a saved filter is applied
    When the client switches between All, Read later, and Archived
    Then the same include/exclude/search filter applies within that view
    And the saved filter itself does not store or change the tab

  Scenario: Remove a saved filter
    When the client removes a saved filter's chip
    Then it is deleted and no longer offered

## Assumptions
- A saved filter stores: name, search text, included tags, excluded tags (client-confirmed).
- The active view/tab is not part of a saved filter (client-confirmed).
- Include = all must be present; Exclude = none may be present; combined with search text.
- In the prototype, saved filters persist locally in the browser; the real app
  persists them for the client's account.
