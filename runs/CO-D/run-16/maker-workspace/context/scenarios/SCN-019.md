Scenario ID: SCN-019
Title: Notes support Markdown, rendered when viewed
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A bookmark's note is written in Markdown and stored as the original Markdown
text. On a bookmark card, notes are hidden behind a "Note" button that keeps the
list clean; clicking it expands the note rendered with formatting. Supported
Markdown: headings, bold, italic, bullet lists, numbered lists, block quotes,
inline code, fenced code blocks, and links. The Edit view always shows the
original raw Markdown so it can be edited unchanged. Rendering is safe: raw HTML
in the note is escaped, not executed, and only http/https links are linkified.

## Gherkin
Feature: Markdown notes

  Scenario: View a note rendered
    Given a bookmark whose note contains Markdown
    When the client opens the note via the "Note" button
    Then the note is displayed with its formatting applied
    (headings, bold, italic, bullet and numbered lists, block quotes,
     inline and fenced code, links)

  Scenario: Editing preserves original Markdown
    Given a bookmark with a Markdown note
    When the client opens it for editing
    Then the note field shows the original Markdown text unchanged

  Scenario: Safe rendering
    Given a note containing raw HTML or a non-http link
    When the note is rendered
    Then the HTML is escaped rather than executed
    And only http/https links are turned into clickable links

## Assumptions
- Notes remain hidden by default (behind the Note button), not always shown.
- Markdown subset as listed above.
