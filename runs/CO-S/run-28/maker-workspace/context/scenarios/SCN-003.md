Scenario ID: SCN-003
Title: Organize links with multiple tags and browse by tag, with tag suggestions
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A saved link can carry several tags at once (not a single folder). When saving, the
user types tags in a comma-separated field. As the user types, existing tags that
match the current fragment are suggested below the field, each showing how many
links already use it, ordered most-used first; clicking a suggestion reuses that
exact tag (guarding against near-duplicate tags). Saved links show their tags as
chips.

Browsing: a "Browse" row shows every tag with a count, plus an "All" option.
Clicking a tag (either in the Browse row or a chip on a saved link) filters the
list to links carrying that tag and updates the section heading to "Tagged #x".
Clicking "All" clears the filter.

After saving a new link, any active tag filter is cleared and the view returns to
"All" so the newly saved link is visible.

Chosen from two compared alternatives:
- Version A (one folder per link) — rejected
- Version B (multiple tags per link) — CHOSEN (links often belong to several
  categories at once)

## Gherkin
Feature: Organize and browse by tag

  Scenario: Save a link with multiple tags
    Given the user is saving a link
    When the user enters several comma-separated tags and saves
    Then the saved link shows each tag as a chip

  Scenario: Suggest existing tags while typing
    Given existing tags are in use
    When the user types a fragment in the tag field
    Then matching existing tags are suggested, most-used first, each with its count
    And choosing a suggestion inserts that exact existing tag

  Scenario: Browse by a tag from the Browse row
    Given links with various tags exist
    When the user clicks a tag in the Browse row
    Then only links carrying that tag are shown
    And the section heading reflects the selected tag

  Scenario: Browse by a tag from a saved link
    Given a saved link shows its tag chips
    When the user clicks one of its tag chips
    Then the list filters to links carrying that tag

  Scenario: Clear the filter after saving
    Given a tag filter is active
    When the user saves a new link
    Then the filter is cleared and the view returns to All so the new link is visible

## Assumptions
- Tags are stored/compared in lower case to avoid case-based duplicates.
- A link may be saved with no tags (untagged) — refinement deferred to edge cases.
- Suggestion ordering is by descending usage count (client preferred over alphabetical).
