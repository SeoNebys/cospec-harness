Scenario ID: SCN-025
Title: Keep a valid link when page details are unavailable
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When a valid link's page details cannot be retrieved, the link is still saved rather than lost. Its fallback card honestly identifies the site and address, marks the details as unavailable, and lets the person either add missing details manually or retry gathering them later.

## Gherkin
Feature: Saving bookmarks

  Scenario: Save a valid link whose page details cannot be retrieved
    Given the person enters a valid web address
    And the page details cannot currently be retrieved
    When they save the bookmark
    Then the link is added to the collection
    And its fallback card identifies the site and address
    And it is marked "Details unavailable"
    And no title, description, or image is invented
    And actions are available to edit the details or try gathering them again

## Assumptions
- Failure to retrieve page details does not imply that the address itself is invalid.
- Retrying later updates only automatically gathered fields and preserves personalized fields.
