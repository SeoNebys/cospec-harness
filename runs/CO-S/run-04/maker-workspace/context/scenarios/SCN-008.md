Scenario ID: SCN-008
Title: Saving a link that is already saved (duplicate)
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user saves a link that is already in the list, the app does not create a
second copy. Instead it tells the user "you already saved this one" and draws
attention to the existing entry by flashing/highlighting it and scrolling it into
view, so the user can see where it already lives. The total count is unchanged.

## Gherkin
Feature: Preventing duplicate links

  Scenario: Detect a duplicate on save
    Given a link that is already saved
    When the user saves the same link again
    Then no second copy is created
    And the app indicates the link was already saved
    And the existing entry is highlighted and scrolled into view
    And the saved-links count is unchanged

## Assumptions
- Duplicate detection ignores trivial differences (scheme, trailing slash, case).
- The precise URL-normalisation rules are a Phase 2 detail.
- No duplicates are ever kept (confirmed: duplicates would just clutter).
