Scenario ID: SCN-005
Title: Change a saved bookmark after the fact
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The client can change any saved bookmark later, and the effort matches the size
of the change (the client's framing: "inline touch for the little tidies, a
fuller editor for the meatier bits").

Everyday little tidies, in place on the card:
- The client clicks the note text directly and edits it; clicking away saves it.
- Labels can be dropped (a small × on each) and added (a "＋ label" that nudges
  toward existing labels so near-duplicates aren't created), right on the card.
- These require no panel and keep the client "in the flow".

Meatier changes, via a fuller editor ("Edit details"):
- Each card has an "Edit details" control opening a pre-filled editor.
- Here the client can change the title, the page summary, and the labels/note.
- The client can also fix **the link itself** — for a page that moved or an
  address saved wrong. If the new link already belongs to another bookmark, the
  change is blocked with an explanation (no accidental collisions).
- The real web address is shown **here**, where the client is looking closely —
  not on the main list (which stays clean with the readable name only). This
  satisfies the client's trust requirement from SCN-001.

Re-paste lands on the existing item ready to edit:
- When the client re-pastes a link they already have (SCN-004), they are taken
  into "Edit details" for that item, ready to act on their new thought — not
  merely shown it.

## Gherkin

Feature: Editing a saved bookmark

  Scenario: Tweak a note in place
    When the client clicks a card's note and edits it
    And clicks away
    Then the new note is saved and shown on the card

  Scenario: Add and drop labels in place
    When the client drops a label via its × or adds one via "＋ label"
    Then the card's labels update immediately
    And an added label reuses an existing one when it matches

  Scenario: Change the meatier fields in the editor
    Given the client opens "Edit details" for a bookmark
    When the client changes the title or the page summary and saves
    Then the card reflects the change

  Scenario: Fix a link that moved
    Given the client opens "Edit details"
    When the client changes the link to a new address that no other bookmark uses
    Then the bookmark now points at the new address

  Scenario: Do not let a fixed link collide with another bookmark
    Given another bookmark already uses a given link
    When the client edits this bookmark's link to that same link
    Then the change is blocked with an explanation

  Scenario: See the real address only when looking closely
    Then the real web address is shown in "Edit details"
    And the main list shows only the readable site name

  Scenario: Re-paste lands ready to edit
    Given the client re-pastes a link they already saved
    Then they are taken into "Edit details" for the existing bookmark

## Assumptions

- Inline edits cover note and labels; the editor covers title, page summary,
  link, note and labels.
- Editing the link keeps duplicate-safety (no two bookmarks share a link).
- The real address lives in the editor / close-up, never on the list.
