Scenario ID: SCN-011
Title: Edit any field, permanently delete, and open a bookmark by clicking it
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark card offers actions. The read-later action stays visible on the card
because it is used often; Edit and Delete (and further actions added later) live
behind a "⋯ More" menu to keep cards tidy.

Editing: choosing "Edit" opens the details form pre-filled, including an editable
Address field alongside title, description, tags, note, and read-later. Saving
updates the existing bookmark in place (no duplicate). If the edited address would
collide with another existing bookmark's address, the app warns and blocks the
save.

Deleting: choosing "Delete" is permanent and asks for a single clear confirmation
("Delete this permanently?") that is easy to cancel. Confirming removes the
bookmark for good. (Archive, added separately, is the safer reversible option.)

Opening: clicking anywhere on a card (except a button, link, tag, or menu) opens
the original page in a new tab, giving a generous click target. Clicking a tag
still browses that tag and clicking a control still performs its own action.

## Gherkin
Feature: Manage a bookmark

  Scenario: Edit any field in place
    Given a saved bookmark
    When the client opens "Edit" from its "⋯ More" menu
    And changes the address, title, description, tags, or note
    And saves the changes
    Then the existing bookmark is updated in place with no duplicate created

  Scenario: Prevent an address collision on edit
    Given two bookmarks A and B exist
    When the client edits A's address to equal B's address
    And tries to save
    Then the app warns that another bookmark already uses that address
    And the save is blocked

  Scenario: Permanent delete with confirmation
    When the client chooses "Delete" from a bookmark's "⋯ More" menu
    Then a single clear "Delete this permanently?" confirmation is shown
    And cancelling keeps the bookmark
    And confirming removes it permanently

  Scenario: Open the original page by clicking the card
    When the client clicks a card away from any button, link, tag, or menu
    Then the original page opens in a new browser tab
    And clicking a tag instead browses that tag
    And clicking a control instead performs that control's action

## Assumptions
- Per-card action presentation: read-later visible; Edit/Delete in a "⋯ More" menu
  (client-confirmed).
- A single inline confirmation is sufficient for permanent delete, given archive
  is the safer reversible choice (client-confirmed).
- Whole-card click opens the link (client-confirmed).
