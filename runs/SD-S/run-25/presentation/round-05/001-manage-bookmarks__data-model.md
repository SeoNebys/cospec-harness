# Data Model: Personal Bookmark Manager

**Date**: 2026-09-26  
**Source**: [Approved specification](spec.md)

## Overview

SQLite is the durable source of truth. The model separates bookmark details from reusable, case-insensitive tags. Library view state is represented in the browser URL and is not persisted in the database.

## Bookmark

Represents one saved web resource.

| Field | Storage | Required | Rules |
|---|---|---:|---|
| `id` | text | Yes | UUID generated by the server; immutable primary key |
| `url` | text | Yes | Trimmed absolute HTTP(S) URL, at most 4,096 characters; no embedded username/password |
| `url_key` | text | Yes | Normalized key used for duplicate warnings; indexed but not unique |
| `title` | text | Yes | Trimmed, 1–300 Unicode code points |
| `description` | text | Yes | Empty string or trimmed text up to 2,000 Unicode code points |
| `reading_state` | text | Yes | `untracked`, `to_read`, or `read`; defaults to `untracked` |
| `created_at` | text | Yes | UTC ISO-8601 timestamp assigned once by the server |
| `updated_at` | text | Yes | UTC ISO-8601 timestamp changed on each successful update |

### URL normalization

The server parses the submitted URL once with the WHATWG URL parser, trims surrounding whitespace, requires `http:` or `https:`, rejects credentials, and serializes the canonical form for storage. `url_key` additionally removes the fragment because it is not part of the network resource used for duplicate detection. Path and query remain significant. Scheme/host casing and default-port normalization come from the URL parser.

Examples:

| Submitted URL | Stored URL | Duplicate key |
|---|---|---|
| `HTTPS://Example.COM:443/docs#intro` | `https://example.com/docs#intro` | `https://example.com/docs` |
| `https://example.com/docs?lang=en` | same canonical form | `https://example.com/docs?lang=en` |

Two rows may share `url_key` after the user explicitly acknowledges the duplicate warning.

### Reading-state transitions

```text
untracked ──mark To Read──> to_read ──mark Read──> read
    ▲                         ▲                     │
    └────mark Untracked───────┴────mark To Read────┘
```

- A new bookmark defaults to `untracked` unless the create request specifies another state.
- `to_read` membership is the sole criterion for the Read Later view.
- Moving to `read` or `untracked` removes the bookmark from Read Later but never deletes it.
- Any state may transition to any other valid state through edit or the focused reading-state action.

## Tag

Represents a reusable organizational label.

| Field | Storage | Required | Rules |
|---|---|---:|---|
| `id` | text | Yes | UUID generated by the server; immutable primary key |
| `display_name` | text | Yes | Trimmed first-entered spelling, 1–40 Unicode code points |
| `normalized_name` | text | Yes | Trimmed, Unicode NFKC-normalized, lowercased key; unique |

`Design`, ` design `, and equivalent Unicode compatibility forms resolve to one tag. The original display spelling is preserved until the tag becomes unused and is removed.

## BookmarkTag

Associates bookmarks with tags.

| Field | Storage | Required | Rules |
|---|---|---:|---|
| `bookmark_id` | text | Yes | Foreign key to Bookmark, cascading on delete |
| `tag_id` | text | Yes | Foreign key to Tag, cascading on delete |

The pair is the primary key, preventing the same normalized tag from appearing twice on one bookmark. A bookmark may have at most 20 tags. Tags left with no bookmarks after an update or deletion are removed in the same transaction.

## SchemaMigration

Tracks applied schema changes.

| Field | Storage | Required | Rules |
|---|---|---:|---|
| `version` | integer | Yes | Monotonically increasing primary key |
| `name` | text | Yes | Human-readable migration identifier |
| `applied_at` | text | Yes | UTC ISO-8601 timestamp |

## Relational Shape

```text
Bookmark 1 ─────< BookmarkTag >───── 1 Tag
```

Initial indexes:

- `bookmarks(url_key)` for duplicate lookup.
- `bookmarks(reading_state, created_at, id)` for the Read Later default order.
- `bookmarks(created_at, id)` for newest/oldest sorting.
- `bookmark_tags(tag_id, bookmark_id)` for tag filtering.
- The unique index on `tags.normalized_name` enforces case-insensitive tag identity after application normalization.

## Mutation Invariants

1. Create/update bookmark details and all tag associations in one transaction.
2. Validate and normalize every value before executing SQL; also enforce required values and reading-state/tag-length checks in the database.
3. Use prepared statements for every user-controlled value.
4. On update, exclude the current bookmark ID from duplicate lookup.
5. If another bookmark has the same `url_key` and `allowDuplicate` is false, roll back and return the existing bookmark summary.
6. If any tag or association operation fails, the bookmark mutation rolls back completely.
7. After successful deletion or tag replacement, remove tags that no longer have associations.
8. `created_at` never changes; `updated_at` changes only after a successful mutation.

## Derived Query Model

The API returns each bookmark with its ordered tag array; association rows are not exposed directly.

Query processing follows this order:

1. Select `all` bookmarks or only `reading_state = 'to_read'`.
2. If tags are selected, retain bookmarks associated with every normalized selected tag (AND semantics).
3. If a search term is present, match it case-insensitively against title, URL, description, or any tag display name.
4. Sort by newest (`created_at DESC`), oldest (`created_at ASC`), or title (normalized title ascending). Add `id ASC` as a deterministic tie-breaker.
5. Return `{ items, total }` and obtain the available tag list separately from `GET /api/tags`.

## Non-persisted View State

The client encodes the following in URL query parameters:

- `view`: `library` or `read-later`
- `query`: current search text
- `tag`: zero or more selected normalized tag names
- `sort`: `newest`, `oldest`, or `title`

This state changes presentation only and never mutates a bookmark.
