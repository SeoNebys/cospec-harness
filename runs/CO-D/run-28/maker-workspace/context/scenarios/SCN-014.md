Scenario ID: SCN-014
Title: Permanently delete a bookmark, distinct from reversible archiving
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each bookmark has a Delete action that permanently removes it. Delete is placed
apart from the everyday actions (Edit / Read later / Archive), visually subdued
(grey, turning red on hover) so it is not pressed casually. Pressing Delete asks
for inline confirmation ("Delete permanently? This can't be undone" with Delete
permanently / Keep); only on confirmation is the bookmark removed for good. This
is clearly distinct from Archive, which merely hides-and-keeps and is reversible.

## Gherkin
Feature: Permanent delete

  Scenario: Delete requires inline confirmation
    Given a saved bookmark
    When the client presses Delete
    Then an inline confirmation appears warning it cannot be undone
    And the bookmark is not yet removed

  Scenario: Confirm permanent deletion
    Given the delete confirmation is shown
    When the client confirms
    Then the bookmark is permanently removed

  Scenario: Cancel deletion
    Given the delete confirmation is shown
    When the client chooses Keep
    Then the bookmark remains unchanged

## Assumptions
- Delete is permanent and not recoverable (distinct from archive).
- Delete stays on the item but is de-emphasised and separated from routine
  actions.
