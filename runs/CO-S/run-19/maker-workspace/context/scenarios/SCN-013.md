Scenario ID: SCN-013
Title: Save an unreadable page with manually entered details
Type: Error Case
Approval status: approved
Approval session: SESSION-013
Approval cycle: 1

## Approved behaviour

When a valid page cannot be read, the app saves nothing automatically and explains that the page may require a sign-in or block saved copies. The client can retry or choose to enter a title and description manually. The address and manual details are saved only after the client approves that fallback, and the resulting bookmark is clearly marked as having no saved page copy.

## Gherkin

Feature: Save a page that cannot be read

  Scenario: Offer a manual fallback without pretending a copy was captured
    Given the user enters a complete web address
    And the page cannot be read
    When the app finishes trying to retrieve the page
    Then no bookmark is saved automatically
    And the app explains possible reasons for the failure
    And the user can retry
    And the user can choose to enter page details manually
    When the user enters a title and description
    And chooses "Save without a copy"
    Then a bookmark is saved with the address and entered details
    And the bookmark is marked "No saved page copy"

## Assumptions

- An unreadable page may require sign-in or prevent page capture.
- Manual fallback captures the address, title, and description but not readable page content.
- The fallback requires explicit client approval before saving.
