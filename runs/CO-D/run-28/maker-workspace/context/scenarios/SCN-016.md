Scenario ID: SCN-016
Title: Select multiple bookmarks and act on them together
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Each item has a selection checkbox. When one or more are selected, a sticky action
bar shows the count and offers bulk actions: add a tag, remove a tag, mark read
later, mark as read, archive, unarchive, and delete (with a single permanent-delete
confirmation covering the whole selection). "Select all shown" selects exactly the
bookmarks matching the current search, tag filters, and view (not the entire
collection); it toggles to deselect. A Clear control empties the selection.

Selection persistence rule: after a bulk action, the selection is kept only if
every affected item still matches the current search/tags/view; if an action
pushes items out of view (archive, unarchive, delete, marking as read while in
To read, removing a tag that is the active filter, etc.), the selection clears.
Tag add/remove updates each affected bookmark's "updated" time.

## Gherkin
Feature: Bulk actions

  Scenario: Bulk add and remove a tag, keeping selection in view
    Given several bookmarks are selected and remain in the current view
    When the client adds or removes a tag in the action bar
    Then the tag change applies to all selected
    And the selection is preserved

  Scenario: Select all shown respects the current scope
    Given a search, tag filter, or view is limiting the list
    When the client chooses Select all shown
    Then exactly the currently matching bookmarks are selected

  Scenario: Selection clears when items leave the view
    Given selected items are shown
    When a bulk action (archive, unarchive, delete, or mark-as-read in To read) removes them from the current view
    Then the selection is cleared

  Scenario: Bulk permanent delete with one confirmation
    Given several bookmarks are selected
    When the client chooses Delete and confirms
    Then all selected bookmarks are permanently removed

  Scenario: Both read states available in bulk
    Given several bookmarks are selected
    Then the client can bulk mark them read later or mark them as read

## Assumptions
- "Mark as read" means clearing the read-later mark.
- Bulk delete uses the same permanent-delete semantics as single delete (SCN-014).
