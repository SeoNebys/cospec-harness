Scenario ID: SCN-008
Title: Error states — non-link input blocked; unreadable page still saveable
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Invalid input: if what the client tries to save is not a web address at all
(e.g. "hello world"), saving is stopped with a clear inline explanation — "That
doesn't look like a link. Paste a web address like https://example.com." —
and nothing is added. The message clears as soon as the client edits the input.

Unreadable page: if the client pastes a genuine link but the page's details
cannot be read automatically, saving is NOT blocked. The preview still opens with
a non-blocking notice ("We couldn't read this page's details automatically…"),
a best-effort title guessed from the address, and the client can fill in the
title, description, tags, or a note before saving.

The client confirmed: genuine non-links should be stopped with a clear
explanation, but a valid link must never become unsaveable just because its page
details couldn't be collected; the non-blocking notice with a chance to fill in
details is the right way forward.

## Assumptions
- "Is a link" check: has a domain-like address (with a dot) or an http(s) prefix;
  it is a lightweight plausibility check, not a guarantee the page exists.
- Auto-fill failure is presented as an informational notice, never a blocking
  error.
