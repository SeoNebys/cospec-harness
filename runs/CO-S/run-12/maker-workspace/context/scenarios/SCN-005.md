Scenario ID: SCN-005
Title: Manage a focused read-later list
Type: Happy Path
Approval status: approved
Approval session: SESSION-005
Approval cycle: 1

## Approved behaviour
The client can mark a bookmark to read later directly from its collection card using a clearly labelled control. The control visibly changes state, a brief confirmation appears, and the Read later count increases. Opening Read later shows only waiting bookmarks. There, each card offers a clearly labelled Mark as read action; using it removes the bookmark from Read later while retaining it in the main collection.

## Gherkin
Feature: Read bookmarks later

  Scenario: Add a bookmark to Read later from the collection
    Given a bookmark is visible in the main collection and is not in Read later
    When the user selects its Read later control
    Then the control visibly indicates that the bookmark is in Read later
    And a brief confirmation is shown
    And the Read later count increases

  Scenario: View bookmarks waiting to be read
    Given one or more bookmarks are in Read later
    When the user opens Read later from beside the collection
    Then only bookmarks waiting to be read are shown
    And each shown bookmark offers a Mark as read action

  Scenario: Mark a waiting bookmark as read
    Given a bookmark is visible in Read later
    When the user marks it as read
    Then it leaves the Read later list
    And the Read later count decreases
    But the bookmark remains in the main collection

## Assumptions
- Read later is a status on a bookmark rather than a separate copy.
- Read later is available beside the main collection and tag filters.
- The chosen collection-card control uses explicit text rather than an unexplained icon.
