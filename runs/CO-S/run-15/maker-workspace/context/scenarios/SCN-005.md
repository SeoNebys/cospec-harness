Scenario ID: SCN-005
Title: Edge cases — empty states, failed title fetch, invalid input
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Empty states are explained rather than blank. When no links exist at all, the
list shows a "get started" message. When a view or search yields nothing, a
context-appropriate message is shown: an empty read-later ("To read") view
explains how to add items; an empty "Read" view explains finished links will
appear there; an empty search result says nothing matches and to adjust or
clear the search.

If a page's title cannot be fetched, the link is still saved: it falls back to
showing the web address as its name and displays an amber note that the title
couldn't be fetched and can be renamed. The save is never blocked by a failed
title fetch.

Clearly invalid input (text that is not a usable web address) is rejected at
save time with an inline message, and no broken entry is created.

## Gherkin
Feature: Graceful empty, failure, and invalid states

  Scenario: No links at all
    Given no links have been saved
    Then the list shows a get-started message

  Scenario: Empty read-later view
    Given no links are in the read-later list
    When the client opens the "To read" view
    Then a message explains how to add links to read-later

  Scenario: Empty read view
    Given no read-later links are marked read
    When the client opens the "Read" view
    Then a message explains finished links will appear there

  Scenario: Search with no matches
    Given an active search or tag filter
    When no link matches
    Then a "no links match" message is shown

  Scenario: Title fetch fails
    Given a link whose page title cannot be fetched
    When the client saves it
    Then the link is saved with the web address shown as its name
    And an amber note says the title could not be fetched and can be renamed

  Scenario: Invalid input rejected
    Given the save box contains text that is not a usable web address
    When the client tries to save
    Then the save is refused with an inline message and no entry is created

## Assumptions
- A failed title fetch never blocks saving.
- "Clearly invalid" means the text cannot be interpreted as a web address even
  after prepending a scheme.
