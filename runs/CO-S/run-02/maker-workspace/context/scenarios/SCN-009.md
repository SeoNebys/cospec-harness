Scenario ID: SCN-009
Title: Large collections are handled by search/tags, not pagination
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the collection grows large (hundreds of bookmarks), the list simply
scrolls; there are no page numbers or "next page" controls. The intended way to
cope with volume is to narrow down with search and/or by clicking a tag, rather
than scrolling through everything. This matches how the user expects to work:
"If I've got hundreds, I'm not going to scroll forever anyway — I'd just search
or click a tag to narrow it down."

## Gherkin
Feature: Coping with a large collection

  Scenario: Many bookmarks
    Given the user has a large number of bookmarks
    When the user opens the app
    Then the full list is scrollable with no pagination controls
    And the user narrows the list using search or a tag rather than paging

## Assumptions
- No pagination; scrolling + search/tags is the coping mechanism (client
  confirmed).
- Any performance/responsiveness concern at very large counts is a
  non-functional matter for Phase 2, not a behavioural one.
