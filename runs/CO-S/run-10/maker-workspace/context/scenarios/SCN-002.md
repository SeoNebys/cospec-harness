Scenario ID: SCN-002
Title: Find a saved link again by searching
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

From the main screen, above the list of saved links, the client types words into
a search box. The list narrows live as each character is typed (no need to press
Enter), showing only links that match, with the matched words highlighted. A
count of matching links is shown. If nothing matches, the client sees a clear
"no matching links" message naming what was searched. Clearing the search
returns the full list.

A link matches when the typed words appear in its title, site name, web address,
or description. Multiple typed words all have to be present (each word narrows
further). The client confirmed this search scope and live filtering directly
address the main frustration of not being able to re-find a saved link when the
exact title is not remembered.

The client also expects that once notes are added to a link, the note text will
be searchable in the same way (see Related scenarios / Assumptions).

## Gherkin
Feature: Find a link by searching

  Scenario: Live filtering as the client types
    Given the client has several saved links
    When the client types a word into the search box
    Then only links whose title, site name, web address, or description contain
         that word remain visible
    And the matched words are highlighted
    And the results update without the client pressing Enter
    And the number of matching links is shown

  Scenario: Multiple words narrow the results
    Given the client has typed one search word
    When the client types an additional word
    Then only links that contain all of the typed words remain visible

  Scenario: No links match the search
    Given the client has typed a search word
    When no saved link matches that word
    Then the client sees a message stating nothing matched the typed text

  Scenario: Clearing the search restores the full list
    Given the client has an active search that is filtering the list
    When the client clears the search box
    Then the full list of saved links is shown again, newest first

## Assumptions
- Searchable fields are: title, site name, web address, description. When notes
  are introduced, note text will also be searchable (client-stated expectation).
  Whether tags are searchable is to be confirmed when tags are introduced.
- Search is live (filter-as-you-type), case-insensitive, all-words-must-match.
- Search operates over the currently held set of links.

## Related scenarios
- SCN-001 (links being searched are those saved via the save flow)
- Future: notes feature must extend searchable fields to include note text.
