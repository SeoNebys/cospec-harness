Scenario ID: SCN-007
Title: Label bookmarks in the client's own words and group/find by label
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client applies labels to a bookmark using their OWN free-text words (not a
fixed menu), typed and confirmed one at a time; a label can be removed. While
typing, the app suggests labels the client has already used, so near-duplicates
("cooking"/"Cooking"/"recipes") are avoided. A single bookmark can carry MORE
THAN ONE label (things don't always fit in one box).

All of the client's labels are shown in a Labels row above the list. Clicking a
label narrows the list to the items filed under it (grouping). Clicking a label
on a card does the same. "All" clears the grouping. Search also matches label
text.

## Gherkin
Feature: Label and group bookmarks

  Scenario: Add free-text labels of the client's own choosing
    Given the client is editing a bookmark
    When the client types a label word and confirms it
    Then that label is attached to the bookmark
    And previously used labels are suggested as the client types
    And the client can attach more than one label to the same bookmark

  Scenario: Group by clicking a label
    Given the client has labelled several bookmarks
    When the client clicks a label in the Labels row or on a card
    Then only bookmarks carrying that label are shown
    And clicking "All" restores the full list

## Assumptions
- Labels are free text, deduplicated via as-you-type suggestions. (Approved.)
- Multiple labels per bookmark. (Approved.)
- Labels displayed as a clickable row above the list. (Approved.)
- Seed items were pre-labelled only for the demo.

## Design note (client insight)
Topic labels (WHAT a thing is) are distinct from STATUS (where the client is with
it). "read later" was mis-modelled as a topic label; status ("to read" and, by
analogy, "archived") gets its own treatment. See SCN-010 and SCN-008.
