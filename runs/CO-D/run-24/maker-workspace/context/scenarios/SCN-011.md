Scenario ID: SCN-011
Title: One shared personal collection across devices, behind a simple sign-in
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The client has a single bookmark collection that is the same on every device
(computer and phone). Saving, editing, read-later, archiving, and deleting on one
device are reflected when the client opens the app on another device — it is one
collection that follows them, not separate per-device sets. Bookmarks persist
between visits (they are still there when the client returns).

Access is behind a simple, private sign-in. This is a single-user personal tool:
no team accounts, no sharing, no user administration.

Confirmed via discussion (text) rather than a prototype, because cross-device
behaviour cannot be reproduced in a single prototype instance (reason logged in
context/session-log.md). Sign-in strength/mechanism is a non-functional detail
recorded in context/non-functional-backlog.md.

## Gherkin

Feature: Shared personal collection

  Scenario: Collection follows the user across devices
    Given the client is signed in on device A and saves a bookmark
    When the client signs in on device B
    Then the same bookmark is present in the collection on device B

  Scenario: Persistence between visits
    Given the client has saved bookmarks
    When the client closes and later reopens the app
    Then the bookmarks are still present

  Scenario: Private access
    Given the app requires sign-in
    When an unauthenticated visitor opens it
    Then the collection is not accessible until signed in

  Scenario: Single-user scope
    Then there are no team accounts, sharing, or user administration features

## Assumptions

- One account = one collection = one user (the client).
- All bookmark operations act on the single shared collection.
- "Simple" sign-in: personal-grade, not enterprise; details in the NF backlog.
