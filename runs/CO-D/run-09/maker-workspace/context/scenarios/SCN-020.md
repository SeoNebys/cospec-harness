Scenario ID: SCN-020
Title: Preserve a viewable copy of a saved page (and optional Internet Archive)
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When saving (or editing) a link, the user can choose to keep a viewable copy of the page,
so it stays readable even if the original changes or disappears. This is on by default. For
a link that is a PDF, the copy retains the PDF itself. The user can also optionally choose to
save a public copy to the Internet Archive.

The kept web-page copy is self-contained, so it stays viewable even if the original changes or
disappears; a PDF copy retains the PDF itself. The Internet Archive option clearly states that
it creates a PUBLIC copy before the user enables it.

On a card, a preserved copy is reachable via a "Saved copy" action (labelled "Saved PDF" for
PDFs) that opens the kept copy, and, when an Internet Archive copy was made, an "Internet
Archive" link opens the public snapshot. If no copy was kept, a "Save a copy" action lets the
user capture one later.

If capturing a copy fails (e.g. a page that can't be read), the bookmark is still saved, and
the card offers a clear "Copy didn't save — Try again" action to retry the capture later.

## External-service dependency (honest note)
Capturing a real page copy and submitting to the Internet Archive depend on network/external
services and are a build-time concern; some pages may block archiving. In the prototype these
copies are simulated to settle behaviour — no real capture is performed.

## Gherkin
Feature: Preserved copies

  Scenario: Keep a viewable copy on save
    Given the "keep a viewable copy" option is on (the default)
    When the user saves a link
    Then a preserved copy is kept and a "Saved copy" action appears on the card

  Scenario: Retain a PDF
    Given the saved link is a PDF
    When a copy is kept
    Then the copy retains the PDF itself and is labelled accordingly

  Scenario: Optionally save to the Internet Archive
    Given the user turns on "save to the Internet Archive"
    When the link is saved
    Then an "Internet Archive" link to the public snapshot appears on the card

  Scenario: Capture a copy later
    Given a saved link has no preserved copy
    When the user chooses "Save a copy"
    Then a preserved copy is kept and becomes reachable from the card

  Scenario: The Internet Archive option warns it is public
    Given the user is about to enable "save to the Internet Archive"
    Then it is made clear that this creates a public copy before it is enabled

  Scenario: Capture fails but the bookmark is kept
    Given "keep a viewable copy" is on
    And the page cannot be read/captured
    When the user saves the link
    Then the bookmark is still saved
    And the card offers a clear "Try again" action to retry the copy later

## Assumptions
- "Keep a viewable copy" defaults to on; Internet Archive defaults to off.
- The kept page copy is self-contained (viewable independent of the original); PDFs retain
  the PDF file.
- Real capture and archiving happen at build time, subject to external-service limits.
