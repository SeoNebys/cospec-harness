Scenario ID: SCN-001
Title: Quickly save a link and have its real page title appear automatically
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

From the main view, the user pastes or types a web address into a save box at the
top and presses "Save link". The saved link appears immediately at the top of the
"Recent" list. It first shows a brief "reading the page's title" placeholder, then
the page's real title fills in automatically — the user never has to type a title.
Each saved item shows: the page title (as a clickable link to the address), the
web address beneath it, and when it was saved. Before anything is saved, the main
view shows a clear empty state ("Nothing saved yet"). The main view is a single
"Recent" list, newest first.

## Gherkin
Feature: Save a link

  Scenario: Empty state before anything is saved
    Given the user has saved no links
    When the user opens the main view
    Then a "Recent" area shows an empty-state message inviting a first save

  Scenario: Save a link and see the real title fill in automatically
    Given the user is on the main view
    When the user enters a web address and presses "Save link"
    Then the link appears immediately at the top of the "Recent" list
    And it briefly shows a "reading the page's title" placeholder
    And the page's real title then appears automatically without the user typing it
    And the item shows the title (linking to the address), the address, and when it was saved

  Scenario: A newer save appears above earlier ones
    Given the user has already saved at least one link
    When the user saves another link
    Then the newest saved link appears at the top of the "Recent" list

## Assumptions
- The page title is obtained by the app reading the target page (in the prototype
  this is simulated; live fetching is an implementation concern for Phase 2).
- The main view is a single reverse-chronological "Recent" list at this stage
  (categories, read-later, archive filtering explored in later scenarios).
- "Saved just now" style relative time is acceptable; exact time formatting not
  yet confirmed (non-functional/detail).
