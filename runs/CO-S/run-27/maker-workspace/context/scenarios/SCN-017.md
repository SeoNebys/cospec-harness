Scenario ID: SCN-017
Title: Retry saving without losing bookmark details
Type: Error Case
Approval status: approved
Approval session: SESSION-017
Approval cycle: 1

## Approved behaviour
If storing a bookmark fails after its page details have been retrieved, the app keeps the entered address, fetched title and description, and tags in place. It plainly explains the failure and offers Try again. Retrying can save normally without requiring any information to be re-entered.

## Gherkin
Feature: Recovering from bookmark save failures

  Scenario: Retry a failed save
    Given a valid bookmark with fetched details and tags is ready to save
    When storing the bookmark fails
    Then the address, title, description, and tags remain unchanged
    And the app plainly explains that saving failed
    And the app offers Try again
    When the person tries again and storing succeeds
    Then the bookmark is saved normally

## Assumptions
- A failed save does not clear or reset the save form.
- Retry uses the same retained details.
