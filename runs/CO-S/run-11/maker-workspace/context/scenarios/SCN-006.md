Scenario ID: SCN-006
Title: Prevent duplicate saves and go to the existing bookmark
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user saves a link that is already saved, the app does not create a
second copy. Instead it shows a note ("You've already saved this — here it is…"),
navigates to the existing bookmark — switching to whichever tab it is in
(including Finished) and clearing any active search/tag filter — highlights it
with a brief flash, and opens it ready to edit so the user can add a tag or
change its status. Two links are considered the same when their web addresses
match after: lowercasing the domain only, and ignoring a single trailing "/".
Capitalisation in the path (and the rest of the address) is significant, because
it can identify a genuinely different page.

## Gherkin
Feature: Avoid duplicate bookmarks

  Scenario: Saving an already-saved link
    Given a bookmark with the same web address already exists
    When the user saves that link again
    Then no second copy is created
    And a message explains it is already saved
    And the app navigates to the existing bookmark, switching to its tab if needed
    And the existing bookmark is highlighted and opened for editing

  Scenario: Domain case and trailing slash are ignored
    Given a bookmark "https://github.com/pallets/flask" exists
    When the user saves "https://GitHub.com/pallets/flask/"
    Then it is recognised as the same bookmark

  Scenario: Path capitalisation is significant
    Given a bookmark "https://github.com/pallets/flask" exists
    When the user saves "https://github.com/pallets/Flask"
    Then it is treated as a different page and saved as a new bookmark

## Assumptions
- Sameness rule: lowercase domain, ignore one trailing slash, keep path/query case.
- On duplicate, the existing item is opened in edit mode.
