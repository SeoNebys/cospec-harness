Scenario ID: SCN-002
Title: See what each item is at a glance, and round up everything of one kind
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Each bookmark card shows small labels ("recipe", "work", "reference", "read
later") so the client can tell at a glance what a thing is.

Near the search box there is a row listing **all** the labels the client has
used across their whole collection. This row is itself valuable: it reminds the
client what kinds of things are even in there, since they will not remember
every label they have made.

Rounding up a kind:
- Clicking a label in the top row gathers exactly the items **filed under** that
  label; the clicked label stays lit so it is clear what is being shown.
- Clicking a label on a card does the same roundup, and simultaneously lights
  the matching button in the top row ("more like this" from a card you are
  already looking at).
- Only one label is active at a time in this version. (Gathering by two labels
  at once is explicitly parked for later — see SCN-003 candidate.)

Clean roundups (the key trust point):
- A roundup gathers only items the client actually **filed** under that label —
  never items that merely contain the word somewhere in their text. Labels round
  up what you *put* somewhere; the search box catches what things *say*. These
  are two different jobs, deliberately kept separate.
- Demonstrated: filing an item under "reference" makes it appear in the
  "reference" roundup even if the word never appears in its title/description;
  typing "reference" in the search box would not surface that item.

Narrowing within a roundup:
- While a roundup is active, typing in the search box narrows *within* that kind
  (e.g. round up "recipe", then type "pasta" to see only pasta recipes). The
  label roundup and the text search combine (both must hold).

Getting back to everything:
- While a roundup is active, a clear, visible "show all again" exit is shown so
  the client is never left feeling stuck. (Clicking the lit label again also
  releases it, but an explicit visible exit is required — the client got stuck
  looking for a way out without it.)

## Gherkin

Feature: Labels — seeing kinds and rounding them up

  Background:
    Given each bookmark has one or more labels the client filed it under
    And a label row near the search box lists every label used across the collection

  Scenario: Labels are visible on each item
    Then each bookmark shows its labels as small chips

  Scenario: The label row shows the whole vocabulary
    Then the label row lists every distinct label the client has used

  Scenario: Round up a kind from the label row
    When the client clicks a label in the row
    Then only bookmarks filed under that label are shown
    And that label is shown as active

  Scenario: Round up a kind from a card
    When the client clicks a label on a card
    Then only bookmarks filed under that label are shown
    And the matching label in the row is shown as active

  Scenario: Roundups are by filed label, not by text
    Given a bookmark filed under "reference" whose text never contains "reference"
    When the client rounds up "reference"
    Then that bookmark is included
    When instead the client types "reference" in the search box
    Then that bookmark is not surfaced by the text search

  Scenario: Narrow within a roundup
    Given the client has rounded up "recipe"
    When the client types "pasta" in the search box
    Then only recipe bookmarks that also match "pasta" are shown

  Scenario: Get back to everything
    Given a roundup is active
    Then a visible "show all again" exit is shown
    When the client uses it
    Then all bookmarks are shown again and no label is active

## Assumptions

- One active label at a time (single-kind roundup). Multiple simultaneous labels
  are parked as a future candidate.
- The label row reflects the labels actually present in the client's collection.
- Label roundup = exact membership of filed labels; text search = word matching
  (per SCN-001). The two combine when both are active.
- Where labels come from (i.e. how an item gets filed under a label) is defined
  by the saving flow, not yet explored.
