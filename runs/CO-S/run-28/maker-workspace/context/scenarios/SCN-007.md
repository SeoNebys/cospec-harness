Scenario ID: SCN-007
Title: Permanently delete a bookmark, with confirmation, distinct from archiving
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Permanent deletion is reachable from inside the "edit this bookmark" form (via the
pencil), as a red "Delete" button visually separated from Save/Cancel. It is not a
button on every card, so it cannot be triggered accidentally — the user must open
the bookmark to delete it. Delete is available from any view, including the Archived
tab.

Clicking Delete opens a confirmation dialog that: names the exact bookmark to be
removed, states the action is permanent and cannot be undone, and steers the user
toward Archive as the reversible alternative ("keep it but hide it"). Cancel (or
Escape, or clicking outside) aborts with nothing removed. "Delete permanently"
removes the bookmark entirely and updates all counts.

## Gherkin
Feature: Delete a bookmark

  Scenario: Reach delete deliberately
    Given a saved link is shown
    When the user opens its edit form
    Then a clearly separated "Delete" action is available

  Scenario: Confirm before deleting
    Given the user clicked Delete
    Then a confirmation dialog names the bookmark, warns it is permanent, and points to Archive as the reversible alternative

  Scenario: Cancel a deletion
    Given the delete confirmation is shown
    When the user cancels (button, Escape, or clicking outside)
    Then nothing is removed

  Scenario: Delete permanently
    Given the delete confirmation is shown
    When the user confirms deletion
    Then the bookmark is removed entirely and counts update

  Scenario: Delete an archived bookmark
    Given a bookmark is archived
    When the user opens its edit form in the Archived tab and confirms deletion
    Then the bookmark is permanently removed

## Assumptions
- Deletion is irreversible (no trash/undo in this cycle). Archive remains the
  reversible option. A trash/undo could be a later addition (see LCR-003).
