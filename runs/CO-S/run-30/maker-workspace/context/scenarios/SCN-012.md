Scenario ID: SCN-012
Title: Avoid duplicate labels that differ only by capitalization
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When a bookmark already has a label and the client tries to add the same label with different capitalization, the app keeps the single existing label rather than adding a near-duplicate. An inline explanation says that the bookmark already has that label.

## Gherkin
Feature: Keeping labels distinct

  Scenario: Add a differently capitalized version of an existing label
    Given a bookmark already has the label "learning"
    When the client tries to add the label "Learning"
    Then the bookmark still has one "learning" label
    And no additional label chip is created
    And an inline explanation says the bookmark already has that label

## Assumptions
- Label identity is case-insensitive.
- The existing label's displayed capitalization is preserved.
