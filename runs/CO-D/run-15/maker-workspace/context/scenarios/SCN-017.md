Scenario ID: SCN-017
Title: Confirm before replacing details for a different page
Type: Edge Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

When an edited address appears to identify a genuinely different page, the app warns the client and asks how to handle saved details rather than replacing them silently. If the client chooses details from the new page, the app refreshes the title, description, site identity, and preview while preserving the client's tags, formatted note, and read-later state.

## Gherkin

Feature: Correct bookmark details

  Scenario: Replace the address with a genuinely different page
    Given a bookmark has page-derived details
    And the bookmark has client-added tags, a formatted note, and a read-later state
    When the client changes the address to one that appears to identify a genuinely different page
    And attempts to save the edit
    Then the app warns that the address appears to be a different page
    And the app asks how to handle the saved details

  Scenario: Use details from the new page
    Given the app has warned that an edited address appears to be a different page
    When the client chooses to use details from the new page
    Then the app gathers and displays the new page's title, description, site identity, and preview
    And the client's tags, formatted note, and read-later state remain unchanged

## Assumptions

- The app can distinguish a cleaned-up address for the same page from an address that appears to identify a different page.
- No page-derived details are overwritten for a different-page edit without the client's confirmation.
