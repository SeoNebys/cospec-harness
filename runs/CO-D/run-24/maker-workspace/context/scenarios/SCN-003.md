Scenario ID: SCN-003
Title: Mark links to read later and view them separately
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Each bookmark card has a "Read later" toggle button. Toggling it on marks the
bookmark, lights the button, shows a "To read" flag on the card, and increments a
live count on the "To read" tab.

Two tabs at the top of the list switch the view: "All" (everything) and "To read"
(only marked items, with a count). The "To read" tab is a filtered view, not a
separate storage location.

Un-marking (toggling the button off) is how the client says "I've read this": the
item leaves the "To read" view but remains saved and visible under "All".

When the "To read" view is empty, an explanatory empty state is shown telling the
client how to add items to it.

## Gherkin

Feature: Read-later

  Scenario: Mark a bookmark to read later
    Given a saved bookmark that is not marked
    When the client clicks its "Read later" button
    Then the bookmark is flagged "To read" and the "To read" tab count increases

  Scenario: View only read-later links
    Given some bookmarks are marked to read later
    When the client opens the "To read" tab
    Then only marked bookmarks are shown

  Scenario: Un-mark after reading
    Given a bookmark marked to read later
    When the client toggles its button off
    Then it is removed from the "To read" view
    And it remains saved and visible under "All"

  Scenario: Empty read-later view
    Given no bookmarks are marked to read later
    When the client opens the "To read" tab
    Then an empty state explains how to add items to it

## Assumptions

- Marking gesture is a per-card toggle button; state shown by button style + flag.
- "All" vs "To read" are tabs with a live count; "To read" is a filter, not a
  separate store.
- Un-marking never deletes or hides the bookmark from "All".
