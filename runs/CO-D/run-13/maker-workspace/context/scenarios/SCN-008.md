Title: Strong search within the current view, with a query language
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

A search box searches the client's links and shows a result count.

Scope: search runs WITHIN the current view (All / Unread / Archived). Archived
links are excluded from an All or Unread search because they are intentionally
put away; they surface only when searching from the Archived view. Switching
views re-runs the same query in the new view's scope — it does not discard the
search.

Fields searched (for ordinary text): title, description, tags, note, site name,
and address.

Query language:
- Ordinary words: case-insensitive; several words must ALL match (implicit AND).
- "exact phrase": text in quotes matches as a contiguous phrase.
- #tag: matches a link carrying that tag EXACTLY (whole tag, case-insensitive) —
  not the same as the word appearing in text.
- Boolean operators AND, OR, NOT and parentheses for grouping, e.g.
  rome (#article OR #book). Precedence: NOT binds tightest, then AND, then OR;
  parentheses override.
- The operator words AND/OR/NOT are treated as operators when unquoted; to search
  for one of these as a literal word, put it in quotes (e.g. "and").

Matches of ordinary text terms are highlighted in the results. Clearing the box
(✕) or having an empty box returns to the normal view.

The client approved all of the above, confirming exact-tag matching (partial tag
matching could surprise) and the operator precedence.

## Gherkin

Feature: Search the library

  Scenario: Search is scoped to the current view
    Given a link is archived
    When the client searches for one of its words from the All view
    Then it does not appear
    When the client switches to the Archived view with the same query
    Then it appears

  Scenario: Switching views keeps the query
    Given a search query is entered
    When the client switches view
    Then the same query is applied within the new view

  Scenario: Ordinary multi-word search matches all words
    When the client searches "css layout"
    Then only links containing both words (in any searched field) match

  Scenario: Exact phrase
    When the client searches "progressive disclosure" in quotes
    Then only links containing that contiguous phrase match

  Scenario: Tag token matches a whole tag
    When the client searches #reference
    Then only links carrying the tag "reference" match

  Scenario: Boolean operators and grouping
    When the client searches web AND (css OR ux)
    Then links matching web and (css or ux) match, per NOT>AND>OR precedence

  Scenario: Operator word as a literal
    When the client searches "and" in quotes
    Then "and" is treated as ordinary text, not an operator

## Assumptions

- #tag is exact (whole tag), case-insensitive.
- Result highlighting covers positive ordinary/phrase terms (not tag tokens or
  NOT-negated terms).
