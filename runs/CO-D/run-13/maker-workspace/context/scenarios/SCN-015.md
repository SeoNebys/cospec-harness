Scenario ID: SCN-015
Title: Multi-select bulk actions, including "select all matching"
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The client can select several links (a checkbox per entry) and act on them
together. A "Select all (N)" control selects the ENTIRE set matching the current
view, search, and tag filters — not only the loaded batch.

While a selection exists, a bulk action bar shows the count and offers:
Mark read, Mark unread, Archive (or Restore in the Archived view), Add tag…,
Remove tag…, and Delete… . Bulk delete requires its own confirmation.

Safety rule (client requirement): changing the view, the search, or the tag
filters CLEARS the current selection, so a later bulk action can never affect
links that are now hidden. Applying a bulk action also clears the selection.

## Gherkin

Feature: Bulk actions

  Scenario: Select several and act
    Given several links are selected
    When the client chooses a bulk action (read/unread/archive/restore/add tag/remove tag)
    Then the action is applied to all selected links
    And the selection is cleared

  Scenario: Select all matching
    Given a view/search/tag filter is active
    When the client chooses "Select all"
    Then every link matching the current view, search, and tags is selected
      (not only the loaded batch)

  Scenario: Bulk delete requires confirmation
    Given several links are selected
    When the client chooses "Delete" and confirms
    Then all selected links are permanently deleted

  Scenario: Changing view/search/tags clears the selection
    Given a selection exists
    When the client changes the view, the search, or the tag filters
    Then the selection is cleared

## Assumptions
- Bulk tag add/remove takes a single tag name at a time.
- "Select all" operates on the full matching set from SCN-010.
