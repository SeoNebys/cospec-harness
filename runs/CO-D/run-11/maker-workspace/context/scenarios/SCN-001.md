Scenario ID: SCN-001
Title: Quickly save a link with auto-filled page details
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The client pastes a web address into the capture box and saves it. The new
bookmark appears at the top of the saved-links list (newest first). On saving,
the app fills in the page's real details automatically — its title, a short
description, the site icon, and a preview image — whenever the page provides
them. The client does not have to type a title to save; capture is fast.

Note: in Phase 1 the prototype simulates page details for a few example links,
because it cannot reach live sites. The approved behaviour is that these details
come from the actual saved page in the real application.

## Gherkin
Feature: Capture a link

  Scenario: Save a new link and see it enriched at the top of the list
    Given the client has entered a web address in the capture box
    When the client saves the link
    Then a new bookmark is added at the top of the saved-links list
    And the bookmark shows the page's title, description, site icon and preview
        image when the page provides them
    And the client was not required to type a title

  Scenario: Web address is required to save
    Given the capture box is empty
    Then saving is not available until a web address is entered

## Assumptions
- Newest saved bookmark appears first in the list (client confirmed).
- Title is optional at capture; if absent it is taken from the page (client
  confirmed the page's real title, not merely the site name).
- Page details are read from the actual page in the real app; the prototype
  simulates them for example links only.
