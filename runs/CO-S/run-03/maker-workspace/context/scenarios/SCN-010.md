Scenario ID: SCN-010
Title: Prevent duplicate links and point to the existing one
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
When the user saves a link that is already saved, the app does not create a second
copy. Instead it shows a note ("you've already saved this link") and briefly
highlights the existing bookmark in the list so the user can find it. The client
strongly endorsed this — avoiding duplicate clutter is central to why he's building
the app.

## Gherkin
Feature: Preventing duplicates

  Scenario: Saving an already-saved link
    Given a link is already in the user's bookmarks
    When the user tries to save the same link again
    Then no duplicate is created
    And the app highlights the existing bookmark and says it was already saved

## Assumptions
- Duplicate detection compares links after light normalization (case-insensitive,
  ignoring a trailing slash). Exact normalization rules (e.g. treating http vs
  https, www vs non-www as same) are an implementation detail to settle later; the
  approved behaviour is "don't duplicate, point to the existing one".
