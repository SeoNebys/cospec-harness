Scenario ID: SCN-017
Title: Save a search (with its included/excluded tags and view) for reuse
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The client can save the current search for reuse. A saved search captures exactly
what is in the search box — words, phrases, included tags (#tag) and excluded tags
(NOT #tag) — together with the view it was made in (Collection, Reading list, or
Archive). The client names it; the default name is the query text.

Saved searches appear as named chips beneath the search box. Clicking a chip
re-applies that search and returns to the view it was saved in (a search saved in
the Archive reopens in the Archive; one saved in the Reading list reopens there).
The × on a chip removes it. Applying a saved search does not change the current
sort order.

## Gherkin

Feature: Saved searches

  Scenario: Save the current search
    Given an active search (which may include or exclude tags)
    When I choose Save and give it a name
    Then it is stored as a named saved search shown beneath the search box

  Scenario: Apply a saved search restores query and view
    Given a saved search made in a particular view
    When I click its chip
    Then its exact query is applied
    And I am returned to the view it was saved in
    And the current sort order is unchanged

  Scenario: Remove a saved search
    When I click the × on a saved-search chip
    Then that saved search is removed

## Assumptions
- A saved search stores query + view, not sort order (sort stays as the client's
  current/preferred order).
