Scenario ID: SCN-003
Title: Find a saved link again — browse the list or search
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The saved links are shown as one scrollable list (newest first), each
recognizable by its readable name, so the user can browse and spot a link by
eye. Above the list is a search box. As the user types into it, the list filters
live (no button press) to only links that match. Matching is done against both
the link's name and its web address, so a keyword present only in the address
still surfaces the link. The matching portion of the text is highlighted so the
user can see why each result appeared. The count line reflects how many of the
total links currently match (e.g. "3 of 14 links"). When nothing matches the
current text, the list shows a "no links match" message instead of results.
Clearing the search box restores the full list.

## Gherkin
Feature: Finding a saved link again

  Scenario: Browse the full list
    Given several saved links
    When the user opens the bookmarks page
    Then all saved links are shown as one scrollable list, newest first
    And each link is identifiable by its readable name

  Scenario: Search filters the list live
    Given several saved links
    When the user types text into the search box
    Then the list immediately narrows to links whose name or address contains the text
    And the matching portion of each result is highlighted
    And the count reflects how many links match out of the total

  Scenario: Search matches the address too
    Given a link whose name does not contain the search text but whose address does
    When the user searches for that text
    Then the link still appears in the results

  Scenario: No matches
    Given a search text that matches no saved link
    When the user finishes typing it
    Then a "no links match" message is shown instead of results

  Scenario: Clearing the search
    Given an active search that is filtering the list
    When the user clears the search box
    Then the full list is shown again

## Assumptions
- Search matches against both the name and the address (confirmed helpful).
- Search is live/incremental with no explicit search button.
- Matches are highlighted to show why a result appeared.
- The default (no search) list is the browse view, newest first.
