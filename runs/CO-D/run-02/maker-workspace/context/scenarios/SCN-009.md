Scenario ID: SCN-009
Title: Nudge the order of the list, and have it remembered
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

The plain list has a sensible default order with a quiet way to change it.

- Default order is **newest first** — the freshest saves greet the client at the
  top, matching what they are most likely reaching for.
- A small, unobtrusive "Order" dropdown sits by the count. It offers:
  - Newest first (default)
  - Oldest first
  - By name (A–Z) — an alphabetical index to run the eye down
- The choice is **remembered between visits** (the client does not re-set it each
  time). This persistence is what makes it a real convenience.
- The chosen order applies to **whatever is on screen** — the full list, a
  search result, or a roundup — not only the unfiltered list. Anything else
  would feel half-finished.
- No heavier grouping is wanted; roundups (SCN-002) already do the "gather a
  kind" job, so the plain list just needs a nudgeable sort.

## Gherkin

Feature: Ordering the list

  Scenario: Default newest-first
    Given the client opens the list without searching or rounding up
    Then bookmarks are shown newest first

  Scenario: Change the order
    When the client chooses "By name (A–Z)" or "Oldest first"
    Then the list reorders accordingly

  Scenario: The order is remembered
    Given the client chose an order
    When the client returns later
    Then the same order is applied without re-setting it

  Scenario: Order holds across search and roundups
    Given the client chose an order
    When the client searches or rounds up a label
    Then those results honour the chosen order too

## Assumptions

- Three orders: newest, oldest, by name. Newest is the default.
- The preference is stored and reused across visits.
- Ordering applies to the currently displayed set, filtered or not.
