Scenario ID: SCN-005
Title: Keep a reading list as an opt-in lens over the library
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
The library offers two views via tabs: "Library" (the everyday view of all saved
links) and "Reading list" (only links the client has lined up to read).

A newly saved link goes into the Library only; it does NOT enter the reading list
automatically. The client opts a link in by marking it "Read later," which adds a
"To read" flag and increases the reading-list count.

The Reading list view shows only flagged links. From there the client can mark a
link as read; this removes it from the reading list but does NOT delete it — the
link remains in the Library. When the reading list has no links, a friendly empty
state is shown instead of a blank screen.

Search works within the currently selected view.

## Gherkin
Feature: Reading list

  Scenario: New link stays out of the reading list
    Given the client saves a new link
    Then the link appears in the Library
    And the link is not in the reading list

  Scenario: Add a link to the reading list
    Given a saved link that is not in the reading list
    When the client marks it "Read later"
    Then the link shows a "To read" flag
    And the reading-list count increases
    And the link appears in the Reading list view

  Scenario: Mark a reading-list link as read
    Given a link is in the reading list
    When the client marks it as read
    Then the link is removed from the reading list
    And the link still exists in the Library

  Scenario: Empty reading list
    Given no links are marked to read
    When the client opens the Reading list view
    Then a friendly empty-state message is shown

## Assumptions
- Reading list is a flag/lens over the single library, not a separate store.
- "Mark as read" is non-destructive (removes from list only).
- Search applies within the active view.
- View selection is via tabs at the top of the library.
