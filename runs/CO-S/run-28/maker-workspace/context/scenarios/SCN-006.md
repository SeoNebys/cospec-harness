Scenario ID: SCN-006
Title: Archive links out of the normal view, with a separate place to find and restore them
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Each link in the normal views shows an "Archive" action. Archiving removes the link
from All, from the "To read" queue, and from normal searches — it surfaces only in
a dedicated "Archived" tab. Archived links are not deleted.

The "Archived" tab lists archived links and supports search and tag browsing within
it. Each archived link shows a "↩ Restore" action that returns it to All (and out
of the archive).

Archive and restore are single-click with no confirmation prompt, because the
action is fully reversible. An empty archive shows: "Nothing archived — archive a
link to tuck it away here without deleting it. You can restore it anytime."

## Gherkin
Feature: Archive links

  Scenario: Archive a link
    Given a link is in the normal view
    When the user clicks "Archive"
    Then the link no longer appears in All, To read, or normal search
    And it appears in the Archived tab

  Scenario: Search/browse only inside the archive
    Given archived links exist
    When the user is in the Archived tab and searches or picks a tag
    Then only archived links matching are shown

  Scenario: Restore an archived link
    Given a link is archived
    When the user clicks "Restore"
    Then the link returns to All and leaves the archive

  Scenario: No confirmation needed
    When the user archives or restores a link
    Then the action happens immediately with no confirmation prompt

  Scenario: Empty archive
    Given no links are archived
    When the user opens the Archived tab
    Then a friendly empty-archive message is shown

## Assumptions
- Archiving is a per-link flag independent of the read-later flag; an archived link
  retains its read-later flag but is hidden from the queue until restored.
- Archived is distinct from deleted (deletion explored separately).
