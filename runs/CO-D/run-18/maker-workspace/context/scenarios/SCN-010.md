Scenario ID: SCN-010
Title: Recover safely from invalid or unreachable bookmark addresses
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Submitting malformed text instead of a complete web address does not show a bookmark preview or allow a broken entry into the library. An inline message beside the address field explains the problem and gives an example of a complete address. If the address is valid but its page does not respond, the app explains that distinction and offers Retry or manual entry. Manual saving requires a title, permits an optional description, and saves the valid address without fetched details.

## Gherkin
Feature: Handle bookmark-address errors

  Scenario: Reject malformed address text
    Given the save form is open
    When the user submits text that is not a complete HTTP or HTTPS web address
    Then no preview is shown
    And no bookmark is saved
    And an inline message explains that a complete web address is required
    And the message provides an example of a valid address

  Scenario: Recover when a valid page does not respond
    Given the user submits a valid web address
    When the page does not respond while details are fetched
    Then the app explains that the address is valid but the page did not respond
    And the user can retry fetching the details
    And the user can enter a required title and an optional description
    And the user can save the bookmark manually with that valid address

  Scenario: Prevent a nameless manual bookmark
    Given the page did not respond and the manual-entry form is displayed
    When the user tries to save without a title
    Then the bookmark is not saved
    And focus remains on the title needed to continue

## Assumptions
- Bookmark addresses must use HTTP or HTTPS.
- A description is optional when saving manually, but a title is required.
