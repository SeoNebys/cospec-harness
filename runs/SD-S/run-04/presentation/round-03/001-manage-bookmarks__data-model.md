# Data Model: Personal Bookmark Manager

## Conventions

- Identifiers are opaque UUID strings generated by the service.
- Timestamps are UTC instants serialized as ISO 8601 strings.
- Every user-owned lookup is scoped by `user_id`; knowing another record's identifier grants no access.
- Text length rules count Unicode characters after trimming, not storage bytes.
- Foreign keys are enabled. Multi-record mutations are transactional.

## User

Represents one account and the ownership boundary for all collection data.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Primary key, immutable |
| `email` | string | Original display form, 3–254 characters |
| `normalized_email` | string | Trimmed and case-folded; unique |
| `password_hash` | string | Versioned scrypt parameters, salt, and derived key; never returned |
| `created_at` | timestamp | Set once |
| `updated_at` | timestamp | Updated when account credentials change |

Relationships: one user owns many sessions, bookmarks, and tags. Deleting a user cascades to those records.

## Session

Represents a revocable authenticated browser session.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Primary key |
| `user_id` | UUID | Required foreign key to User |
| `token_digest` | string | Unique digest of opaque cookie token; raw token is never stored |
| `created_at` | timestamp | Set once |
| `last_seen_at` | timestamp | Advanced with bounded write frequency |
| `expires_at` | timestamp | Idle-expiry boundary |
| `absolute_expires_at` | timestamp | Cannot be extended |

Validation: expired sessions are rejected and eligible for cleanup. Logout deletes the matching session.

## Bookmark

Represents a saved web destination.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Primary key, immutable |
| `user_id` | UUID | Required owner foreign key |
| `url` | string | Trimmed absolute HTTP(S) address, maximum 2,048 characters |
| `normalized_url` | string | Canonical comparison value; indexed but not unique |
| `title` | string | Trimmed, 1–300 characters |
| `notes` | string | Trimmed, 0–5,000 characters; empty string allowed |
| `is_favorite` | boolean | Defaults to false |
| `status` | enum | `active` or `archived`; defaults to `active` |
| `archived_at` | timestamp/null | Required only while archived |
| `created_at` | timestamp | Set once and used in default ordering |
| `updated_at` | timestamp | Updated for any bookmark or tag association change |

Relationships: a bookmark belongs to one user and has zero to twenty tags through BookmarkTag.

Invariants:

- `status = active` implies `archived_at = null`.
- `status = archived` implies `archived_at` is set.
- A normalized URL may repeat only after the user explicitly continues past a duplicate warning.
- Archived items are excluded from active queries and duplicate warnings.

State transitions:

```text
new ──create──> active ──archive──> archived ──restore──> active
                    │                   │
                    └────delete─────────┴────delete──> permanently removed
```

Deletion is terminal and cascades to BookmarkTag rows. There is no soft-delete state beyond archive.

## Tag

Represents a reusable, user-owned label.

| Field | Type | Rules |
|---|---|---|
| `id` | UUID | Primary key |
| `user_id` | UUID | Required owner foreign key |
| `name` | string | Trimmed display spelling, 1–40 characters |
| `normalized_name` | string | Case-folded with internal whitespace collapsed |
| `created_at` | timestamp | Set once |

Constraints: `(user_id, normalized_name)` is unique. The spelling from the existing record is reused when a variant is submitted. Orphaned tags may remain available for reuse and can be cleaned up later without affecting feature behavior.

## BookmarkTag

Joins bookmarks and tags.

| Field | Type | Rules |
|---|---|---|
| `bookmark_id` | UUID | Foreign key; cascade on bookmark deletion |
| `tag_id` | UUID | Foreign key; cascade on tag deletion |

Primary key: `(bookmark_id, tag_id)`. Service validation ensures both records have the same `user_id` and caps each bookmark at twenty tags.

## SchemaMigration

Tracks applied schema changes.

| Field | Type | Rules |
|---|---|---|
| `version` | integer | Primary key, monotonically increasing |
| `name` | string | Human-readable migration name |
| `applied_at` | timestamp | Set when transaction commits |

## Derived API Views

### Bookmark summary

Bookmark fields returned to the client plus:

- `domain`: display-safe hostname derived from `url`.
- `tags`: ordered array of `{ id, name }`.

### Tag summary

Tag identity and display name plus active/archived counts for the current collection view. Counts are derived, not stored.

### Page cursor

Opaque encoding of the final row's `(created_at, id)` tuple. Cursors are tied to descending creation order and are not database offsets.

## Indexes

- `users(normalized_email)` unique.
- `sessions(token_digest)` unique and `sessions(expires_at)` for cleanup.
- `bookmarks(user_id, status, created_at DESC, id DESC)` for collection paging.
- `bookmarks(user_id, status, normalized_url)` for duplicate checks.
- `bookmarks(user_id, status, is_favorite, created_at DESC)` for favorite filtering.
- `tags(user_id, normalized_name)` unique.
- `bookmark_tags(tag_id, bookmark_id)` in addition to its composite primary key.

## Search Semantics

- Search text is trimmed and compared case-insensitively as a literal partial match, with SQL wildcard characters escaped.
- A bookmark matches when the query occurs in title, original URL, notes, or any attached tag name.
- Multiple selected tags use intersection semantics: the bookmark must contain every requested tag.
- Search, tags, and favorite filters are combined with AND.
- The selected lifecycle view (`active` or `archived`) is always mandatory and cannot span both states.
