Title: Search bookmarks with a precise query language
Type: Happy Path
Approval status: approved
Approval session: SESSION-001

## Approved behaviour

A search box filters the bookmarks live as the user types. Matching is
**case-insensitive** and, for bare words, searches across the **title,
description, note, tags, site and the link (URL)**. Each card shows the URL as a
subdued line so URL matches are visible. Matched text is highlighted.

The search supports a **query language**:
- **Quoted phrases** — `"slow living"` matches the exact phrase.
- **`#tag`** — restricts to bookmarks that have that exact tag (as opposed to a
  bare word, which matches the term anywhere, including within a tag).
- **Boolean operators** `AND`, `OR`, `NOT` (case-insensitive), with **`( )`
  parentheses** for grouping — e.g. `(reading OR essays) NOT design`. Adjacent
  terms without an operator are combined with AND.

When a query is **incomplete or malformed** (common during live typing), the
search box indicates it could not read the query and **gently falls back to a
plain-text match** of the typed text, rather than showing an error or an empty
result. This was preferred over blocking results until the query is valid.

The search combines with the active view and tag filter (see SCN-006).

## Gherkin
Feature: Bookmark search query language

  Scenario: Case-insensitive bare-word search across fields
    When the user searches "SOLNIT"
    Then bookmarks containing "solnit" in any searched field are shown regardless of case

  Scenario: URL match
    When the user searches "react.dev"
    Then the bookmark whose link contains "react.dev" is shown

  Scenario: Exact phrase
    When the user searches for a quoted phrase
    Then only bookmarks containing that exact phrase are shown

  Scenario: Tag-restricted term
    When the user searches "#reading"
    Then only bookmarks that have the tag "reading" are shown

  Scenario: Boolean and grouping
    When the user searches "(reading OR essays) NOT design"
    Then only bookmarks matching that boolean expression are shown

  Scenario: Malformed query falls back gracefully
    Given the user is mid-typing an incomplete query such as "(dev OR"
    Then the search indicates it could not read the query
    And it falls back to matching the typed text as plain text

## Assumptions
- Search is live (updates as the user types).
- Bare words match anywhere including tags; #tag matches the tag exactly.
- Malformed queries fall back to plain-text matching, not an error/empty state.
