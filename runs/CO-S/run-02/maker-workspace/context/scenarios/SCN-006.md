Scenario ID: SCN-006
Title: Handle saving problems without losing or duplicating links
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
Malformed addresses are not saved, and the saving box remains open with a clear correction message. A valid address is still saved when its page details cannot be retrieved, using the site address as a temporary title and noting that details can be edited later. When an address is already saved, no duplicate is created; the app explains this and highlights the existing bookmark.

## Gherkin
Feature: Safe bookmark saving

  Scenario: Reject a malformed address
    Given the saving box is open
    When the user enters text that is not a complete HTTP or HTTPS address
    And tries to save it
    Then no bookmark is created
    And the saving box remains open
    And the app explains that a complete web address is required

  Scenario: Save a valid address when page details are unavailable
    Given the user entered a valid web address
    And the page details cannot be retrieved
    When the user saves the bookmark
    Then the bookmark is created
    And its site address is used as a temporary title
    And the app explains that details are unavailable and editable later

  Scenario: Avoid saving a duplicate address
    Given a bookmark with an address already exists
    When the user tries to save the same address again
    Then no second bookmark is created
    And the app explains that the address is already saved
    And the existing bookmark is highlighted

## Assumptions
- Complete HTTP and HTTPS addresses are valid inputs.
- Failure to retrieve page details does not invalidate an otherwise valid address.
- Bookmark addresses are unique within the collection.
