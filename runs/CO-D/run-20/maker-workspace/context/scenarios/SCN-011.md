Title: Saving error and fallback (invalid address; page details unavailable)
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Invalid address: if the text in the save box is not a plausible web address,
saving is not performed. A gentle inline notice explains it doesn't look like a
web address, and the text the user typed is kept in place so they can correct it.

Page details unavailable: automatic fetching of a page's title/preview is helpful
but not required. When details cannot be loaded, the review panel opens in a
fallback mode that states the details couldn't be loaded, shows "No preview", and
lets the user save the bookmark anyway with a title they type. If they save
without typing a title, the address itself is used as the title.

## Gherkin
Feature: Saving errors and fallback

  Scenario: Invalid address is not saved and input is preserved
    Given the save box contains text that is not a plausible web address
    When the user clicks Save
    Then nothing is saved
    And an inline notice explains it is not a web address
    And the typed text remains in the box for correction

  Scenario: Save a page whose details could not be loaded
    Given a valid address whose page details cannot be fetched
    When the user clicks Save
    Then the review panel opens in fallback mode stating details could not be loaded
    And shows "No preview"
    And the user can save it anyway with a manually entered title

  Scenario: Fallback title defaults to the address
    Given the fallback review panel is open
    When the user saves without entering a title
    Then the bookmark's title defaults to the address

## Assumptions
- The prototype simulates fetch failure via a trigger address; production detects
  a real fetch failure.
