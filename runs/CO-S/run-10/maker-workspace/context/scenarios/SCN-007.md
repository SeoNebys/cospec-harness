Scenario ID: SCN-007
Title: Delete a link permanently, with confirmation
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour

Each link (active or archived) has a "Delete" action. Because deletion is
permanent, clicking Delete shows an inline confirmation ("Delete this link
permanently? This can't be undone.") with Delete and Cancel. Cancel keeps the
link unchanged; confirming removes the link entirely from all views and counts.
The client confirmed delete is permanent and that the confirmation step is
appropriate.

## Gherkin
Feature: Delete a link

  Scenario: Confirmation is required before deleting
    Given a saved link
    When the client clicks Delete
    Then an inline confirmation asking to confirm permanent deletion is shown
    And the link is not yet removed

  Scenario: Cancel keeps the link
    Given the delete confirmation is showing for a link
    When the client cancels
    Then the link remains unchanged

  Scenario: Confirm removes the link permanently
    Given the delete confirmation is showing for a link
    When the client confirms deletion
    Then the link is removed from all views and counts
    And it cannot be restored

## Assumptions
- Delete is available on both active and archived links.
- Deletion is permanent (distinct from archive, which is recoverable).
- A single inline confirmation step guards deletion.
