Scenario ID: SCN-006
Title: Find a saved link by searching
Type: Happy Path
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
A search box lets the user find saved links by typing. Results filter live as the
user types. The search looks across the whole bookmark — title, description, the
user's personal note, labels, and the web address — so a half-remembered word finds
a link wherever that word lives. Matching ignores capitalisation. When several
ordinary words are typed, they narrow the results (a bookmark must contain all of
them). Matching words are highlighted in each result so the user can see why it
matched. A running match count is shown while searching. When nothing matches, a
calm "no bookmarks match" state is shown rather than an alarming error. Clearing the
search restores the full list.

## Gherkin
Feature: Finding a saved link

  Scenario: Find by a word that is not in the title
    Given saved links exist whose labels or descriptions contain a word
    When the user types that word in the search box
    Then all links containing that word anywhere (title, description, note, labels, or address) are shown
    And the matching word is highlighted in each result

  Scenario: Search ignores capitalisation
    Given a saved link contains the word "reading"
    When the user types "Reading"
    Then the link is still found

  Scenario: Multiple ordinary words narrow the results
    Given several saved links exist
    When the user types two words separated by a space
    Then only links that contain both words are shown

  Scenario: No matches
    Given saved links exist
    When the user types a word that appears in none of them
    Then a calm "no bookmarks match" state is shown

  Scenario: Clearing the search
    Given a search is active
    When the user clears the search
    Then the full list is shown again

## Assumptions
- Live filtering happens on each keystroke.
- A match count is shown while a search is active.
