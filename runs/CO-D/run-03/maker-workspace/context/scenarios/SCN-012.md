Scenario ID: SCN-012
Title: When auto-capture fails, save the link anyway and let the client fill in details
Type: Error Case
Approval status: approved
Approval session: SESSION-001
Approval cycle: 1

## Approved behaviour
If the app cannot read a page automatically, it still SAVES the link (never
refuses — refusing would lose the link, and frictionless saving is essential). It
flags that it couldn't read the page, drops the client into editing, and nudges
them (a visible "needs a title" marker) to add a title/summary so the item stays
findable. An item lacking a title shows a clear "needs a title" state in the list.

## Gherkin
Feature: Capture failure

  Scenario: Save a link the app cannot read
    Given the client saves a link whose page cannot be read automatically
    Then the link is still saved
    And the app indicates the page could not be read
    And the client is dropped into editing to add a title and summary
    And an item without a title is visibly marked as needing one

## Assumptions
- Never block saving on a capture failure. (Approved — "spot on".)
