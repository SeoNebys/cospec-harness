Scenario ID: SCN-010
Title: Reuse an existing bookmark instead of saving a duplicate
Type: Happy Path
Approval status: approved
Approval session: SESSION-010
Approval cycle: 1

## Approved behaviour
When a person attempts to save an address that is already in the collection,
the app detects the duplicate from the address before fetching or reviewing
page details. It does not add another bookmark or change the collection count.
Instead, it brings the existing bookmark into view, highlights it, and explains
that it was already saved.

## Gherkin
Feature: Prevent duplicate bookmarks

  Scenario: Attempt to save an address already in the collection
    Given a bookmark for a web address already exists in the collection
    When the person attempts to save the same web address
    Then no new bookmark is created
    And the collection count remains unchanged
    And the existing bookmark is brought into view and highlighted
    And the person is told that the address was already saved
    And page details are not fetched for a second bookmark

## Assumptions
- Exact matching of a previously saved address is checked before page-detail retrieval.
- The existing bookmark remains unchanged when the duplicate attempt is detected.
- Bringing the existing bookmark into view is preferable to showing only an error.
